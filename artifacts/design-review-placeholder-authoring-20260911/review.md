## A. Scores and evidence

### PPT quality: 6/10

The direction should eliminate model transcription errors when the substitution contract is complete, while leaving HTML/CSS composition with the model (`D:48-70`). That is a credible response to the recorded run-17 integrity failure and run-23 title-binding failure (`R:128,144-146`). However, the proposed run tokens cannot preserve arbitrary emphasis within one projected prose run: the projection is derived from text delimiters, not rich-text style boundaries (`B/services/source_content/source_runs.py:76-100,214-254`), whereas today's binder accepts nested text inside one owner (`B/services/source_content/text_stamping.py:117-126`). Removing browser integrity checks and automatically flagging visibility would also weaken the current publication boundary (`B/services/authored_presentation_generation.py:2875-2911`). Published runs already flag 7, 17, 11, 18, and 13 of 35 slides: 66/175 = **37.7%**, with a **20.0%-51.4%** range (`R:39-44,127-142`). Substitution may prevent unusable repair candidates and reduce some flags, but it does not repair the measured geometry bottleneck; the independent local-fit report records only one resolved and one improved slide among 35 flagged slides (`docs/layout-repair-open-source-review-20260911.md:70-80`). Better fidelity is plausible; equal or better emphasis, layout, and flagged-slide rate are unverified.

### Speed: 6/10

Early token validation can save a render of an invalid candidate and reduce transcription retries; it does not make a new provider attempt free in latency. The five published decks average **748.82 seconds** (median **754**, range **715-775**), or **21.39 seconds per slide amortized across a deck**; this is throughput, not single-slide author latency (`R:18,22,127,131,142`). The 13 recorded runs consumed **11,986.1 seconds**, including **8,242.0 seconds in failed runs**; that is **2,397.22 seconds of historical work per publication**, not a forecast for current code (`R:18-22,127-144`). The large avoidable cost is failure/retry work. Net output-token savings remain unknown: tokens replace source text but add identifiers, delimiters, wrappers, and possibly more spans, while the prompt still carries source text (`D:48-68`). No provider-usage/timing receipt files were found in the inspected run-11 through run-23 directories, and the inspected published final-status JSONs exposed no token counts. Run-11's audit explicitly says `timingReceiptFilePresent=false` (`artifacts/authored-full-product-validation-20260910/run-11/08-audit.json:29-34`); run-15 lost its timing receipt (`R:106-109`). Chromium visibility and capacity still need real text and a capture, and putting a new capture before every checkpoint could increase work (`B/services/authored_presentation_pipeline.py:737-776,792-844`; `B/services/authored_composition_policy.py:1516-1547`). A percentage speedup is not supportable from this evidence.

### Architecture: 5/10

A common admission function plus a checked receipt is a good enforcement point, and a text-only binding table does not require a new layout engine (`D:88-111`). The proposal keeps the model as designer, unlike the withdrawn ordinary-generation migration to server-owned layout (`docs/generation-quality-root-cause-and-composer-architecture-20260904.md:453-465`); this also respects the earlier HTML visual-authority boundary without reviving its dual-output machinery (`docs/authored-semantic-dual-output-architecture-20260822.md:12-25,40-55`). But the gate signature omits source/attempt/policy identity, the producer inventory omits important post-author mutations, and “substitute once” has no contract for already-substituted checkpoints or repair candidates (`B/services/authored_checkpoint_state.py:291-313`; `B/services/authored_presentation_pipeline.py:777-844`; `B/services/authored_presentation_generation.py:2520-2603`). Its retry change conflicts with bounded physical-call accounting, and its rollout bundles parser and provider behavior changes before the placeholder switch (`D:115-120,137-146`). Centralization is valuable; the current proposal does not yet make it safe.

## B. Problems, ranked by severity

### P1-1. “Integrity, missing, and order failures cannot occur” is not a valid publication argument

**Verified:** `D:59-65` replaces browser text checks with token presence/order. The existing browser result checks actual rendered text, deterministic QID identity and uniqueness (`B/services/source_content/browser_readback.py:410-445,702-714`), binds the capture to exact HTML and valid font/probe telemetry (`:754-773`), and checks deck source-unit/reading-order mapping (`B/services/source_content/browser_readback_inspection.py:58-77`). A per-slide token inventory cannot prove that the final deck has the right page order, capture, or source revision. The current final gate explicitly rejects missing, integrity, order, and diagnostic failures (`B/services/authored_presentation_generation.py:2881-2902`).

**Inference:** A correct substitution followed by an unvalidated mutation, incorrect QID owner, stale capture, or wrong slide association still produces bad published evidence. Browser integrity is an inexpensive comparison over telemetry already needed for visibility; deleting it saves no demonstrated Chromium pass. Keep it as an independent assertion even after removing search-based binding.

### P1-2. Substitution contexts and the post-substitution security boundary are undefined

**Verified:** `D:92-93` applies policy before inserting text. Current admission limits source bytes, NULs, text bytes, DOM size/depth, and attributes (`B/utils/renderer_isolation.py:179-207,320-324,352-374`). Those limits can change after text or wrapper insertion. `D:57-63` does not define whether tokens are allowed in attributes, CSS, comments, hidden content, or only text nodes, nor whether inserted source text is rescanned.

**Inference:** HTML escaping is appropriate for an HTML text node but is not a universal CSS/attribute substitution strategy. A source string containing token syntax could be expanded twice by a recursive replacement implementation. A whole-block token and overlapping range tokens can each appear once while duplicating source characters. Specify text-node-only recognition, a nonrecursive pass over the original parsed nodes, a server-controlled ID table, exact disjoint interval coverage, and final expanded-byte policy checks. Fail on invalid spans and literal token residue in model-owned syntax. Preserve a literal token-looking source string as source data.

### P1-3. The admission lifecycle has no representation or evidence-reuse contract

**Verified:** An author checkpoint is persisted before illustration (`B/services/authored_presentation_pipeline.py:768-776,792-820`); illustration is followed by source image validation and text stamping (`:821-844`). VQA applies role normalization/local fit, selects HTML/PNG/metrics together, and checkpoints the selected version (`B/services/authored_presentation_generation.py:2520-2603`). `complete_stage` currently accepts optional HTML, PNG, metrics, revision, attempt token and fencing token, with a PNG requirement for render evidence (`B/services/authored_checkpoint_state.py:291-313`). The proposal instead says every checkpoint gets one fully substituted, browser-observed Admission (`D:90-106`).

**Inference:** Re-admitting expanded HTML as if it were token HTML causes every token to appear missing; persisting token HTML through existing consumers exposes placeholder characters to capture/capacity/export. Requiring full visibility at the author checkpoint also precedes image materialization and duplicates later capture. A receipt with only an HTML digest cannot distinguish the same HTML checked against another manifest/policy or a stale worker. The design must distinguish token authoring input, expanded HTML, and final captured evidence within one gate implementation, and pin manifest/projection/policy versions, slide/unit identity and fenced revision. Reuse metrics only on exact expanded-HTML/capture identity. Centralize predicates, not every stage's timing into one mandatory early render.

### P1-4. Flag-only admission is broader than the existing policy

**Verified:** `D:98-103` makes visibility `flag_only` whenever terminal fallback is on. Actual activation also requires a strict DOM profile and excludes exact reconstruction (`B/services/authored_terminal_slide_policy.py:36-60`). At final readback, visibility is allowed only on slides already flagged by terminal fallback; unflagged visibility still fails (`B/services/authored_presentation_generation.py:2875-2904`). The recorded policy expressly retains `passed=false`, `verified=false`, and `integrityVerified=true` for visibility-only publication (`.spec-memory/decisions/authored.verbatim-flagged-publish.2.json:14-21`).

**Inference:** Applying the proposal's table literally would turn any hidden/clipped substituted text into publishable output and potentially skip bounded layout repair. Carry terminal eligibility and prior admitted flags as explicit gate context; preserve separate repair-candidate rejection and terminal publication decisions. Substitution guarantees characters in the document, not their legibility.

### P1-5. Free overload retries break physical-call bounds and durable accounting

**Verified:** `D:115-120` moves retries into the bounded provider call and says overload does not consume an author attempt. That adapter intentionally disables SDK retries to avoid a second physical request under one admission (`B/utils/provider_idempotency.py:301-319,339-345,376-401`). The selected accepted decision still describes two physical author ordinals per operation attempt (`.spec-memory/decisions/authored.provider-attempt-budget-per-operation-attempt.1.json:7-21`), while inspected current code allows **three**, explicitly reserving the third for rescue (`B/services/authored_checkpoint_state.py:203-230`). It fences reservations, rolls previous-attempt cost into totals, and makes same-ordinal replay idempotent (`:232-280`). This ledger/code difference is a verified reconciliation item, not permission to remove the bound. Cooldown state is explicitly job-scoped, not account-shared (`B/services/authored_batch_policy.py:75-93,191-242`).

**Inference:** A hidden retry loop can exceed both reservation accounting and the operation deadline, especially where transport idempotency is unsupported (`B/utils/provider_idempotency.py:290-298`). Share classification and scheduling, but preserve an explicit physical-call ceiling, reservation per request, cancellation, total deadline and usage accounting. A quota pause also needs durable resume/reset-time semantics; merely renaming a slide failure is insufficient. Do not classify every bridge exception as transient: the current generic bridge code can also represent nonrecoverable statuses (`B/utils/provider_idempotency.py:160-162,422-425`; `B/services/authored_batch_policy.py:30-38`).

### P1-6. Repair paths can emit source text again, or reject otherwise valid expanded candidates

**Verified:** VQA full reauthor builds fresh content from `contents[i]` and critique and calls the author (`B/utils/llm_calls/author_vision_qa.py:610-649`). Patch prompts expose observed text snippets (`B/utils/llm_calls/author_slide_patch_prompt.py:63-81`), and the generic patch contract includes `setText` (`B/utils/llm_calls/author_slide_patch_contracts.py:131-145`). Structural repair currently applies source-specific checks before candidate capture (`B/utils/llm_calls/author_structural_repair_loop.py:236-267`). Source candidate validation re-stamps and requires byte-identical sealing, then verifies browser readback (`B/services/authored_generation_quality_gate.py:38-58`; `B/services/authored_presentation_generation.py:1507-1557`).

**Inference:** Updating only the initial author prompt leaves reauthoring able to produce ordinary text HTML and leaves the old search binder in the admission path. Do not remove the source-safe patch restrictions. Give every HTML-generating repair/rescue the same token contract; allow geometry/style patches on expanded HTML only when source-owned text and IDs remain unchanged and final evidence is renewed. Rendered screenshots/text can remain diagnostic input, explicitly unavailable as output text. Do not reverse-engineer tokens by searching rendered strings again.

### P2-1. Run granularity is not emphasis granularity

**Verified:** `D:55-56,164-166` implies that projected run tokens preserve intra-block emphasis. Projection consumes raw text and creates delimiter-based runs, with normalized offsets, optional markers and presentational separators (`B/services/source_content/source_runs.py:70-100,110-127,214-254,417-419`). It has no bold/italic/color boundaries. Today's whole-element ownership includes nested text (`B/services/source_content/text_stamping.py:117-123`).

**Inference:** A single sentence such as “Reduce the processing time significantly” cannot bold only “processing time” using one atomic run token. Conversely, forcing one element per run can alter wrapping and QID counts. Measure emphasis spans within projected runs, not merely blocks containing multiple elements. Prefer whole-block/coalesced tokens where possible; if substring emphasis is required, specify a bounded exact character-range partition within a run, grapheme-safe boundaries, unchanged parent binding identity, and explicit browser consumer compatibility. This is text addressing only, with no server-chosen layout. Also decide how original hard line breaks, spaces, marker-only lines, pipes and optional markers are reconstructed instead of claiming raw byte preservation from normalized projections.

### P2-2. Order, duplicates, furniture, and legitimate repeated text need separate rules

**Verified:** `D:59-61` appears to impose global DOM token order. Current browser code records within-block DOM deviations rather than rejecting them (`B/services/source_content/browser_readback.py:673-698`; `B/services/source_content/browser_readback_inspection.py:176-188`); the deck-unit/outline order remains separately checked (`:58-77`). The binder tolerates bounded exact duplicate headers/page numbers, binding the first (`B/services/source_content/text_stamping.py:22-24`). Prompts demand a literal formatted page marker, except for cover/none/company-standard cases (`B/utils/llm_calls/author_slide_prompt.py:395-422`); source numbering overrides the deck header choice (`B/services/authored_presentation_generation.py:1558-1569`). The source-presence ledger and later flag-only ledger have differing order language, so a strict new order rule must be reconciled explicitly (`.spec-memory/decisions/source-content.verbatim-presence-contract.1.json:7,26-29`; `.spec-memory/decisions/authored.verbatim-flagged-publish.2.json:15-21`).

**Inference:** Equating DOM order with visual order restricts model layouts without proving visual reading order. Equal text from two distinct source blocks requires two occurrence IDs; a repeated decorative header must not silently satisfy two source occurrences or be treated as missing text. Define a source/furniture distinction and controlled occurrence aliases if repetition is legitimately authorized; never mint extra source occurrence counts for decoration. Source-owned page numbers should use source tokens, while generated furniture follows the existing header contract. Maintain the exact page count and order regardless of DOM choices.

### P2-3. QID ownership, semantic roles, capacity and Hybrid consumers are under-specified

**Verified:** The binder stamps a deterministic QID for a binding ID and supplies missing title/body semantic roles (`B/services/source_content/text_stamping.py:459-480`; `B/services/source_content/source_stamp_dom.py:206-225`). Readback requires unique expected QIDs and exact run partitions (`B/services/source_content/browser_readback.py:410-445,675-714`). Capacity counts browser-owned title/body characters and QIDs (`B/services/authored_composition_policy.py:1516-1547`). Hybrid preserves differently styled runs and hard breaks; it distinguishes browser soft wraps from authored hard breaks (`N/lib/authored-hybrid/native-text-runs.ts:10-32`; `N/lib/authored-hybrid/pptx-text-integrity.ts:19-38`).

**Inference:** “Stamp exactly as today” is insufficient when two tokens share an element, a token has nested emphasis owners, or wrappers inherit different semantic roles. Define the owner, role, QID and parent-run aggregation algorithm. All character/fit gates must see expanded text. Keeping Hybrid implementation out of scope is reasonable; assuming no compatibility effect from changed HTML/text-run boundaries is not. A generated Fidelity artifact alone cannot validate Hybrid text fidelity, nor can the old run-11 Hybrid result validate placeholder output (`R:136`).

### P2-4. HTML5 parsing does not replace semantic normalization or preserve all policy behavior

**Verified:** Existing normalization strips disallowed CSS, treats hidden bound text differently from unbound hidden elements, removes title line breaks, and strips name attributes (`B/utils/authored_html_normalize.py:10-44,162-212`). The renderer rejects duplicate attributes before accepting their values (`B/utils/renderer_isolation.py:193-207`). `D:74-86` replaces these operations with parsing, serialization and unchanged policy.

**Inference:** Parsing alone does not turn disallowed `content` CSS into allowed CSS; removing the explicit stripper can restore run-13-style rejection. Tree normalization may lose duplicate-attribute evidence before the policy sees it. Parser correction is also not equivalent to blanket deletion of every void closing tag. Choose and pin document/fragment/namespace behavior, retain raw-input limits and duplicate findings, and specify semantic rewrite rules on the parsed tree. Track rule receipts with bounded details. A new serializer can change HTML digests and therefore capture reuse even where pixels do not change (`B/utils/renderer_isolation.py:352-380`; `B/services/source_content/browser_readback.py:754-773`). Browser-equivalence remains a validation obligation, not an automatic property of a parser label.

### P2-5. Shadow and deletion criteria do not establish safe replacement

**Verified:** `D:130-146` asks historical text HTML to pass token validation, shadows before the token prompt switch, and ships parser/provider changes alongside centralization. Historical raw-text output contains no required placeholder tokens by definition (`D:48-63`). Existing sealed-text admission relies on re-stamping byte equality (`B/services/authored_generation_quality_gate.py:38-58`); old checkpoints resolve stage HTML with an author fallback (`B/services/authored_checkpoint_html.py:34-62`).

**Inference:** A shadow gate with mandatory tokens will reject all legacy output; one without that requirement only tests centralization, not placeholder behavior. Converting old HTML using the binder tests an adapter and excludes precisely the difficult binder failures. Five successful new runs cannot prove safe deletion of readers needed for unfinished or resumed legacy jobs. Version the checkpoint representation and pin the mode per operation; keep compatibility until those jobs/rollback scope expire. Split shadow admission parity, adversarial token fixtures, and prospective matched-input product comparison. Do not claim same-output shadow equivalence after the model prompt changes.

### P2-6. Receipt schemas and public error handling remain separate consumers

**Verified:** E4 requires four flag fields and bounds optional keys and reason lengths (`B/services/authored_generation_timing_receipt_e4.py:270-355`); run-15 published but lost that receipt (`R:106-109`). The final source receipt intentionally adds `integrityVerified` separately (`B/services/authored_presentation_generation.py:2903-2912`). `D:107-111` proposes unmodified unknown-code propagation and one policy vocabulary, but not schema migration or mapping.

**Inference:** An Admission object cannot simply replace existing flagged entries. Map it into the established quality/timing/operation contracts, preserving counts and bounded reasons and keeping detailed evidence behind digests. Unknown internal failures should remain diagnosable through a bounded stable code plus evidence reference, not arbitrary exception strings. Checking attribute-name coverage alone does not establish role values, ownership, flag-shape compatibility, or timing receipt durability.

## C. Specific improvements, reasons and cost

Costs are relative implementation/review scope, not measured engineering estimates. These are proposed design amendments only.

| Change | Reason | Cost |
| --- | --- | --- |
| Retain browser text/QID/capture and whole-deck order assertions; remove only search-based binding in the new mode | Resolves P1-1 while reusing the visibility capture | Low-to-medium; predicate reuse and receipt mapping, no justified extra browser pass |
| Specify text-node-only, nonrecursive token expansion and exact disjoint coverage; reapply resource/policy limits after expansion | Resolves P1-2; rejects unknown IDs, overlap, injection contexts and oversized expansions before capture | Medium; bounded parser/substitution contract and adversarial fixtures |
| Define versioned token-input/expanded-HTML/captured-evidence states, all handled by one admission service with explicit immutable context | Resolves P1-3 without a new layout representation or duplicated source truth | High; checkpoint, resume, repair and capture plumbing |
| Bind receipts to source manifest/projection, slide/unit/order, policy, expanded HTML, capture identity and fenced revision | Prevents cross-source reuse and stale admissions | Medium; use existing checkpoint/bundle authority, do not create a second publication system |
| Preserve the existing terminal-eligibility rule and keep repair rejection distinct from publication flagging | Resolves P1-4; flag-only remains review-required and source-integrity strict | Low-to-medium; mode table and consumer mapping |
| Centralize overload classification first; explicitly bound/reserve physical retries and reconcile the current two-versus-three ordinal contract | Resolves P1-5; avoids invisible requests and retry storms | High; provider scheduling, deadlines, attempt records and durable quota-pause lifecycle |
| Feed the token contract through single/batch author, rescue and full reauthor; protect text ownership on geometry/style patches | Resolves P1-6; the model cannot reintroduce generated source text | Medium-to-high; shared prompt context and existing repair adapters |
| Supply a compact block/run table with full source text, exact lengths, line breaks, marker semantics and break/emphasis boundaries; leave all geometry to the model | Layout needs actual content width and grouping, not the visual width of an ID; resolves P2-1 | Medium; extra input tokens and a bounded emphasis-range contract if evidence requires it |
| Prefer coalesced tokens, specify a single measured parent owner for inline spans, preserve hard breaks, and distinguish source occurrences from furniture | Resolves P2-1 through P2-3 without forcing a fixed template or layout vocabulary | Medium; readback/capacity/Hybrid compatibility cases |
| Retain normalization semantics in an explicitly enumerated DOM rewrite pass, with raw-input diagnostics and post-expansion policy | Resolves P2-4; avoids reopening previously repaired failure shapes | Medium-to-high; parser behavior, security-sensitive review and canonicalization compatibility |
| Roll out centralization with the old representation first; then parser, then token mode, then separately bounded provider changes | Resolves P2-5 and makes failures attributable | Medium; separate switches/receipts, lower rollback risk |
| Require receipt completeness, flagged/layout nonregression, real Fidelity publication, legacy resume, and the bound 43-page/96-occurrence case before removal | Addresses missing acceptance evidence rather than equating deck completion with quality | Medium-to-high validation cost; do not regenerate until narrow fixtures justify it |

The proposed acceptance report should distinguish three experiments: (1) same stored expanded HTML and the same metrics for old/new gate verdict parity; (2) synthetic token-form fixtures and final expanded bytes for substitution correctness, including run-23's short title class; (3) new, identically configured input runs for product quality, wall time, token usage and flags. Only the third measures a changed authoring prompt. Failed historical binder cases should be negative fixtures, not silently converted success cases. This separation follows the representation mismatch in P2-5 and does not require a new generation engine.

A first measurement task should obtain authoritative raw provider-output usage and capture counts if they exist outside the inspected run directories, recording absence honestly. Compute net token delta with the actual output tokenizer, including ID/wrapper overhead and retries; do not subtract source characters from reported tokens. For speed attribution, retain author-call time, queue/cooldown time, distinct expanded HTML digests captured, checkpoint reuse, local-fit candidate captures, and complete E4 receipts. Existing evidence is insufficient to populate those columns (`R:106-109`; `B/services/authored_generation_timing_receipt_e4.py:104-145,270-355`).

## D. Verdict

**Adopt with the listed changes. The single most important reason is that text substitution is a useful construction guarantee, but the proposed removal of rendered integrity verification confuses construction with proof of the final published artifact.** Keep the independent final assertion, formalize the representation boundary, and preserve the model's HTML/CSS design authority. The remaining changes should reduce transcription-related deck failures without reviving Deck IR, source-native, SlideSpec, or Composer.
