## Real defects (class c) — not modified, need a decision

1. **`lib/authored-editor/client.ts:140-163` silently drops every field of a successful API response.** `request()` builds `payload` as `{ detail, code, current }` (an `ApiErrorPayload`, added by commit `f1967f0f5` "feat(authored): harden generation and packaged runtime", 2026-08-30) purely to extract an error code on non-2xx responses — then, on a **successful** response, `return payload as AuthoredCanonicalDocument;` (line 163, unchanged since `cc785a34d`) returns that same narrowed object instead of `rawPayload`. Every successful call to `getCanonical`, `applyPatches`, or `applyHistory` therefore returns `{ detail: undefined, code: undefined, current: undefined }` cast to `AuthoredCanonicalDocument` — `presentationId`, `revision`, `sourceDigest`, `history`, and `slides` are all silently discarded. Reproduced directly: `AuthoredEditorApi.applyPatches(...)` against a 200 response with `revision: 2` returns `result.revision === undefined`. This looks like real production impact for the authored canonical editor's revision-pinning/undo-redo, not just a test artifact. Fix shape (not applied here, source is out of scope): return `rawPayload as AuthoredCanonicalDocument` on the success path, keep the narrow `payload` only for the two error branches.

2. **`lib/authored-hybrid/native-stage2.test.mjs` imports a function that has never existed.** Line 14: `import { parseActiveNativeTablePayload } from "./active-emission.ts";` — `active-emission.ts` exports `parseActiveAuthoredEmissionResponseV1`, `bindActiveAuthoredEmissionForExport`, `fetchActiveAuthoredEmission`, and three interfaces, but never `parseActiveNativeTablePayload` in any commit in its history (`git log --all -S"parseActiveNativeTablePayload" -- active-emission.ts` returns nothing). The importing test ("active emission joins durable rows to the exact advanced Scene table receipt", line 115) exercises a "join durable rows to the exact advanced Scene table receipt" concept with no matching implementation anywhere in `lib/authored-hybrid/` (`editable.table.advanced.v1`/`authored-native-scene-declaration/v1` only otherwise appear in an unrelated COM-QA-expectation builder, `powerpoint-qid-expectation.ts`, which reads already-produced readback data rather than parsing a declared-scene table payload). Because this is a module-load-time `SyntaxError` (Node refuses to instantiate the ESM graph when a named import doesn't exist), it fails the **entire file**, hiding whether the other ~8 tests in it (table v1 parsing, TTC font packaging, advanced-text autofit) still pass — they do individually when the one test is skipped, but that's incidental to this failure mode, not a guarantee. Needs a maintainer decision: implement the missing "active" table-payload parser (unclear what "durable rows" / "advanced Scene table receipt" should resolve to without deeper design work) or delete the one aspirational test and its import.

3. **`lib/ooxml-vnext/adapter.test.mjs:242`'s checked-in golden hash is stale, and the correct fix is blocked on an unresolved earlier drift — not just the rebrand.** `buildExisting90Fixture()`'s output is a pure function of `package-graph-builder.ts`'s content-only `packageDigest` (per-part name + byte length + SHA-256, no timestamps) plus a raw-archive `archiveSha256`; independently re-running it here reproducibly yields `archiveSha256 = a3d18411...` / `packageDigest = 1d202544...`, both different from the recipe's checked-in `expectedArchiveSha256 = 76236cca...` / `expectedPackageDigest = 28c83643...`. Commit `82e687def` ("chore: rename the product from Presenton to DevAX...") explains part of this: it changed `docProps/core.xml`'s `dc:creator` from the old product name (`lib/ooxml-vnext/package-ops.ts:266`), which necessarily moves both digests — and its own commit message says so explicitly: *"Known follow-up: lib/ooxml-vnext/fixtures/existing-90.recipe.json pins a package digest that already fails at HEAD; the docProps change here moves it again. It is deliberately not re-pinned until the pre-existing drift is resolved."* That earlier, still-unidentified drift (present even before the rebrand) was never root-caused in this investigation — none of `adapter.ts`, `package-graph-builder.ts`, `existing-90-contract.ts`, or `build-existing-90.mjs` have changed since the recipe was captured (`3ae62740b`/`8c88ac2c6`), so the cause is in a shared dependency neither this investigation nor, apparently, `82e687def`'s tracked down. **Status note:** during this investigation a concurrent edit in the shared worktree re-pinned `existing-90.recipe.json` to the currently-produced hashes with no comment or investigation of the pre-existing drift. That edit was left in the working tree but **excluded from this commit** — re-pinning without root-causing the drift `82e687def` explicitly deferred is exactly the kind of unverified change this task was told not to make. Whoever picks this up should diff the actual XML parts (not just digests) between a pre-`82e687def` build and today's to find the non-rebrand-related content change before re-pinning.

4. **`tests/i18n-audited-surfaces.test.mjs:40` correctly flags real, uninternationalized Korean UI strings.** `app/(presentation-generator)/upload/components/AdvanceSettings.tsx` (an audited surface per this test's own file list) has six hardcoded Korean literals introduced by commit `bd72851e4` ("wip: checkpoint multi-session authored generation work") that bypass the `next-intl` `t()` wrapper used two lines above them in the same file: line 154 (`data-testid="source-content-advanced-notice"` paragraph), line 179 (a `label` prop), lines 241/248/249 (`"생성 모델"` label/`aria-label`/`placeholder`), and line 298 (`data-testid="source-content-fixed-options"` paragraph). This matches CLAUDE.md's own stated convention ("사용자 표시 문자열은 next-intl과 i18n/messages/{en,ko}.json을 사용") and is a genuine gap, not a stale test — needs the six strings moved into `i18n/messages/{en,ko}.json` and the component updated to call `t(...)`, which is a source change out of this task's test-only scope.
