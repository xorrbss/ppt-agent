# 공통 결함 최소 수정 및 프롬프트 효과 분리

## 승인 범위

Sol medium 생성 모델을 유지한다. 기존 산출물을 먼저 재사용해 결함 발생 단계를 확인하고, 근거가 있는 공통 원인 1~2개만 수정한다. 검출 개선을 화면 품질 개선으로 계산하지 않는다. 기존 파일과 사용자 변경을 보존한다.

## 단계

1. 기존 42개 검수 결과에서 대표 실패 및 정상 대조군을 선정한다. 최초 HTML, 정규화, 보정, 최종 렌더의 증거를 구분한다.
2. 현재 검사기로 저장 측정값을 재판정한다. 과거 검사 결과를 현재 코드의 결함으로 단정하지 않는다.
3. 가장 작은 공통 수정과 기존 보정 기능을 동일 HTML에서 평가한다. 내용 삭제, 이미지 숨김, 임의 수치 변경은 허용하지 않는다.
4. 화면 품질 개선과 정상 대조군 무퇴행이 확인된 경우에만 기존/개선 프롬프트와 기존/개선 보정의 효과를 분리한다. 생성 HTML은 보정 비교에 재사용한다.
5. 유망한 조합만 반복하고, 튜닝에 사용하지 않은 문서 10페이지 및 실제 PPTX를 확인한다. 앞 단계 실패 시 후속 생성으로 확대하지 않는다.

## 역할

- Astra medium: 원인 분석, 수정 범위 판정, 기존 보정 재현.
- Sol medium: 직접 연결된 코드 추적과 최소 수정.
- Sol low: 실험 계측 및 증거 보존.
- Astra low: 후속 독립 시각/내용 검수. 구현 단계가 끝나면 순차 투입한다.

## 계측 계약

전체 시간은 실제 보정·렌더·검사를 포함하는 최상위 단조시계 경계로 잰다. 파일 복사 시간, 단계별 시간 합, 기존 결과에서 복구 불가능한 시간은 전체 처리시간으로 표시하지 않는다. 최초 생성 품질과 최종 품질을 따로 집계한다. 실패, 미확인, 신규 검출과 신규 수정도 구분한다.

## 초기 사실

이전 시험은 fit=False였다. 현재 검사기에 카드 탈출 검사가 이미 존재하므로 신규 검사기를 중복 개발하지 않는다. 최초 18개 저장 HTML/측정값을 현재 검사기로 재판정한 결과 과거 판정과 같았으며, case-01/C의 내부 박스가 외부 카드 경계를 벗어나는 사례는 여전히 누락됐다. 구체적인 수정과 품질 효과는 별도 실행 증거로 확정한다.
