## Local OCR follow-up

No additional model call was made. Tesseract 5.4.0.20240606 was installed with the pinned `UB-Mannheim.TesseractOCR` winget package. The current shell did not receive a PATH update, so the evaluator's standard Windows install-path discovery was verified. The base installation contained `eng` and `osd`; a non-committed `.test-runtime` directory was populated with pinned `tessdata_fast` 4.1.0 `eng` and `kor` files whose SHA-256 values are documented in the README. After hash verification, `kor.traineddata` was installed into the system tessdata directory. The final system language list was `eng`, `kor`, and `osd`.

The final five-slide self-test OCRed both source and render images, ten local OCR executions total, in 3.13 seconds (0.627 seconds/slide). OCR inspection reported `tesseract v5.4.0.20240606`, requested/available languages `kor+eng`, and ready status. Aggregate source-vs-render results were raw CER 0.0306, normalized CER 0.0306, deletion-based missing rate 0.0056, and exact line-break rate 0.40. Raw exact preservation was Korean 1.0000, English 0.9776, digits 0.9524, and symbols 0.9600. These synthetic sources contain deliberately injected render defects, so the figures validate metric sensitivity rather than establish a release threshold.

## Follow-up verification

The Windows verification was repeated with `tesseract v5.4.0.20240606` and the
installed `eng`, `kor`, and `osd` languages. Five synthetic source/render pairs
made ten local OCR calls in 2.91 seconds (0.58 seconds/slide), with raw and
normalized CER 0.0306, deletion-based missing rate 0.0056, exact line-break rate
0.40, and raw Korean/English/digit/symbol preservation of 1.0000/0.9776/0.9524/
0.9600. Model calls were zero. The tracked repository contains no exact source
image/deck suitable as a representative real Korean sample, so this remains a
synthetic-only evaluation and is not presented as real-material validation.

The local Windows renderer/cache benchmark submitted 90 concurrent identical,
deterministic Korean/English HTML requests: one uncached Chrome render produced
one stable PNG in 0.33 seconds (271.6 logical requests/second); model and OCR calls
were zero. This validates in-flight cache coalescing only. A WSL Linux
distribution was present, but it had no `uv` runtime, so the comparable Linux
backend test was not run and remains a CI/operational follow-up.

The earlier planning observation of roughly 1,215 seconds for a 90-slide live
path was retained as a cost/time warning, not rerun as a billable benchmark. The
deterministic call contract is one initial comparison per reviewed slide for
`analyze_only`; `analyze_and_fix` adds a final comparison only for candidates that
actually changed (N initial comparisons plus at most N final comparisons), with
author/revision calls accounted for separately. No 90-slide live VQA run was
attempted in this follow-up.

Before the system `kor` file was installed, running the same check against the base system tessdata produced `language_missing`, `missing_languages:kor`, an unavailable text metric, and process exit status 3. It did not fall back to manifest or HTML text. After installation, a five-slide system-tessdata run without `--tessdata-dir` completed in 3.17 seconds with the same aggregate OCR metrics and zero model calls. The explicit manifest-mode deterministic check also passed with five slides and zero model calls.

## Deterministic local self-test

Five source/render pairs completed in 0.48 seconds (0.096 seconds/slide), with zero model calls. Assertions verified perfect-text CER=0, a deliberate character error produces CER>0, a deliberate line-break change fails exact line-break comparison, a shifted object lowers bounding-box IoU, and all model call counters remain zero.

Aggregate fixture metrics: pixel similarity 0.9914, edge similarity 0.9994, mean CER 0.0089, exact line-break rate 0.60, and mean stable-ID bounding-box IoU 0.9923. These values intentionally include injected defects and are a harness check, not a product-quality baseline.

## One-slide live smoke

The explicitly selected OpenAI smoke completed the existing exact path end-to-end in 18.37 seconds. Logical calls were author=1, initial source-vs-render comparison=1, revision=1, and final comparison=1. The candidate was accepted because the final structured critique had a strictly lower deterministic defect score. The selected render measured pixel similarity 0.8816 and edge similarity 0.9853. HTML-visible-text proxy CER was 0.80 and exact line-break match was false; because OCR was unavailable, these text figures should not be treated as visual OCR accuracy.

An earlier command was given a one-second shell timeout during setup. Its child process continued after the shell returned and completed a separate Codex-backed one-slide run, then overwrote the same report path. That unintended run took about 120.02 seconds, used the same four logical calls (one each), accepted its revision, and measured pixel similarity 0.9910, edge similarity 0.9918, proxy CER 0.4444, and non-exact line breaks. No process remained afterward. The harness now uses an exclusive output lock and report-specific artifact directory to prevent this overlap/overwrite failure mode.

Per instruction, evaluation was not expanded to five slides. The durable JSON at `.test-runtime/exact-reconstruction-eval/live-smoke-1-report.json` contains the later Codex run because of the overwrite described above; the OpenAI result is retained here from its completed stdout summary. Runtime artifacts are not source-controlled.

## Remaining measurement risk

OCR output still depends on font rendering, segmentation mode, traineddata family, and raster quality. Keep the engine version, language data hashes, language selection, and page segmentation mode fixed before comparing runs. Pixel/edge scores are sensitive to font rasterization and do not by themselves prove semantic correctness. Stable-ID object IoU is available only when an external extractor or fixture supplies corresponding object boxes.
