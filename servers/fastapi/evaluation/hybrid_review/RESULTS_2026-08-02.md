# Authored hybrid-review benchmark - 2026-08-02

## Scope

This run measures the deterministic/local portion of the authored-slide hybrid
review on the current Windows development machine. It uses real headless-Chrome
rendering and browser metrics, local DOM inspection, structured patch application,
montage generation, and the routing-policy calculation.

No live LLM or VQA request was made. `model_calls` was `0`; therefore this result
does **not** claim live-provider latency, billing, or end-to-end visual acceptance.
The planned VQA counts below are calculated from the routing plans emitted by this
run, not guessed provider measurements.

Command:

```powershell
uv run python scripts/benchmark_authored_hybrid_review.py --output .test-runtime/authored-hybrid-review-benchmark-final.json
```

The clean single-slide result meets the 5–10 second target. The deliberately
clipped slide was correctly detected, and the model produced one allowlisted
`setStyle` action. That candidate reduced deterministic issues from two to one but
did not fully resolve the visible overflow. The comparison VQA returned
`unchanged`, so the strict acceptance gate rejected it. This is an important
quality result rather than a successful repair-latency result: the normal service
would next take its bounded full-reauthor fallback, which was not invoked in this
cost-capped live gate.

The eight-slide live route completed without promotion or unusable results. It made
three underlying image-review requests instead of eight full-resolution requests,
a 62.5% reduction, while retaining a global montage and two deterministic random
audits. The montage and the audit requests were issued in two batch invocations.

A calibration attempt with a context string that described a "latency benchmark"
instead of the visible business slide was excluded from the clean representative
measurement: VQA treated that input mismatch as a content problem. This reinforces
that production review contexts must remain derived from actual slide content.

retries, and refuses a request before exceeding the configured ceiling. The run
used the normal user-config hydration path while serializing no credential value,
prompt body, or model response body.

This run is a quality-safety finding, not a successful acceptance benchmark:

- The nominally clean synthetic fixture had zero deterministic issues, but VQA
  returned one medium `placeholder` issue. Its 27.46-second cold total does not meet
  the 5-10 second clean target and shows that cold browser startup plus VQA variance
  must be separated from warm production latency.
- The defective fixture began with medium clipping and high overflow on one stable
  `data-qid`. The patch model returned one allowlisted `setText` action.
- After the patch, deterministic inspection still reported the same medium clipping
  and high overflow. Nevertheless, comparison VQA returned no issues and the then-
  current service acceptance function classified the candidate as `improved`.
- Therefore image comparison alone was not a sufficient adoption guard. A candidate
  retaining a baseline high-severity deterministic defect must be rejected or sent
  to fallback, even when comparison VQA reports improvement.

The self-test deliberately disables full-HTML reauthoring, so no fallback latency
or quality claim is made. One earlier instrumentation attempt stopped after three
provider generation requests because the result sanitizer referenced an incorrect
local-issue field. It produced no benchmark result and is excluded from the timing
table, but it is included for cost transparency: this validation campaign consumed
seven provider generation requests in total (3 aborted + 4 successful). No further
live rerun should be made merely to validate the deterministic adoption guard; its
post-fix behavior can be verified with the recorded before/candidate reports and
automated service tests.

### Post-fix deterministic replay

The shared acceptance policy now applies the local gate to structured-patch and
full-fallback candidates. The benchmark uses the same policy. Replaying the exact
recorded local shape (medium clipping plus high overflow retained on the same QID)
returns `(False, "local_high_remaining")`, even when the visual comparison is clean.

```powershell
uv run pytest -q `
  tests\unit\test_authored_quality_modularization.py::test_local_gate_rejects_retained_high_issue_even_when_vqa_is_clean
```

Result: `1 passed in 4.37s`. The default zero-model benchmark also passed after the
fix: two deliberate local issues became zero, the eight-slide clean deck had zero
local suspects and planned three initial VQA requests, and the 10/11-slide boundary
plans each planned four. No post-fix live call was made, so this is a deterministic
safety verification rather than a new provider-latency measurement.

## Routing result

The clean-fixture routing plans produced the following initial requests. Old
full-detail is the previous one-detail-VQA-call-per-slide route. Planned is the
sum of the actual montage and deterministic clean-audit detail calls in the emitted
route; it is not a live-model observation.

| Deck | Montage batch sizes | Montage VQA | Detail/audit VQA | Planned initial VQA | Old full-detail VQA | Fewer planned calls |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 8 slides | 8 | 1 | 2 | 3 | 8 | 62.5% |
| 10 slides | 6, 6 (2-slide overlap) | 2 | 2 | 4 | 10 | 60.0% |
| 11 slides | 6, 6 (1-slide overlap) | 2 | 2 | 4 | 11 | 63.6% |

The 10-slide deck is covered by slides 1-6 and 5-10; the 11-slide deck by slides
1-6 and 6-11. Thus every selected slide remains in a 6-9-up global-consistency
montage, including both formerly unpartitionable boundaries. Local suspects always
go to full-resolution detail VQA. Deterministic clean-slide audits remain enabled;
a failed audit promotes its batch, and failures in the configured number of affected
batches promote the full selected deck.

## Remaining live validation

The earlier warm clean-slide observation met the latency target, but the later
reproducible cold self-test did not. Browser-startup variance therefore remains to
be isolated with repeated cold/warm samples before claiming the target generally.
One representative eight-slide hierarchical route was measured. A successful live
local-patch acceptance, the intentionally slower structural fallback, audit-failure
promotion, and 10/11-slide live-provider boundaries remain unmeasured. Their
deterministic policies and failure behavior are covered by automated tests, but no
end-to-end latency claim is made for those paths.
