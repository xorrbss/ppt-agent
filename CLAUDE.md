# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Presenton is an open-source, self-hostable AI presentation generator (Gamma/Beautiful AI alternative). It generates editable slide decks from prompts or uploaded documents, renders them with HTML+Tailwind templates, and exports to fully-editable PPTX and PDF. It ships as a Docker image and an HTTP API (plus an MCP server).

**This repository is a fork** (`bitbucket.org/ibizsoftware/devax-ppt`) of `github.com/presenton/presenton`, maintained independently: it no longer tracks or verifies against upstream (the compatibility ledgers, byte-parity check, intake monitor, and `.github/` were removed 2026-10-22). The fork has diverged substantially: Korean UI, Windows-native operation without Docker, a Korean-business template set, and a large second generation pipeline (see "Two generation pipelines" below). This fork is **web-only**: it does not ship or support the upstream Electron desktop shell (there is no `electron/` directory here). Measured 2026-11-02 (excluding tests): `servers/fastapi` ~1,770 source files / ~520k lines (471 modules sit directly under `services/`), `servers/nextjs` ~720 files / ~140k lines; plus ~1,030 and ~160 test files.

## Architecture: one product, two runtimes

The same FastAPI backend + Next.js frontend pair is what the whole product is built from. Understand this first — almost every file lives in one of these two servers:

- **`servers/fastapi/`** — Python 3.11 FastAPI backend (managed by `uv`). All generation logic, LLM/image provider abstraction, persistence, and PPTX/PDF export live here. ~33 endpoint modules and ~96 service modules.
- **`servers/nextjs/`** — Next.js 16 (App Router) frontend + thin API proxy layer. The slide editor, built-in templates, and Redux state live here.
- **`scripts/` + root `start.js`** — `start.js` is the Docker container entrypoint. It boots **nginx (port 80)** as a reverse proxy in front of **Next.js (3000)** and **FastAPI (8000)**, plus a standalone **MCP server (8001)**, and writes `app_data/userConfig.json` from env vars. PPTX/PDF export no longer uses upstream's downloaded `presentation-export` runtime (removed 2026-10-22); it runs in the fork's own isolated export workers (see "Export 경로"). `scripts/presenton-local-proxy.mjs` and `scripts/start-local-stack.ps1` provide the equivalent single-origin routing and process orchestration for a native (non-Docker) Windows run — see `RUNNING-LOCAL.md`.

Supporting top-level directories that are easy to miss:

- **`contracts/chat-first-workspace/v1/`** — checked-in JSON contracts for the workspace API (bootstrap/assets, commands/receipts, errors/runtime, timeline projection). Verified from both the Python and TypeScript sides.
- **`compatibility/slide-master/`** — the only survivor of the former upstream-drift ledgers: a reproducibility harness for the vendored SVG→PPTX conversion dependency. The SQLite/PostgreSQL support contract that used to live in `compatibility/README.md` is now `docs/database-compatibility.md`.
- **`docs/`** — 63 dated design documents and operational runbooks (`*-YYYYMMDD.md`). There is **no index**; it reads as an append-only archive. It is nonetheless the most accurate description of the slidespec/workspace subsystem — better than this file was before, and worth grepping before designing anything in that area.
- **`document-extraction-liteparse/`**, **`tessdata/`** — bundled document parsing runtime and offline OCR data (eng + kor).

Request path in Docker: browser → nginx:80 → (`/api/v1/*` → FastAPI, everything else → Next.js). Inside the container, Next.js reaches FastAPI directly via `FAST_API_INTERNAL_URL` (default `http://127.0.0.1:8000`) rather than bouncing through nginx.

## Two generation pipelines

**The upstream "outline → pick a React template → fill content" flow no longer exists here.** `POST /presentation/generate` accepts a `strategy` field (`models/generate_presentation_request.py`) typed `Optional[Literal["authored", "svg"]]`: omit it or pass one of the two literal values; anything else is a validation error. An omitted strategy resolves to **svg** (`services/generation_core/admission/strategy.py`), falling back to authored only for a source restyle with a page-size/orientation override or a request svg admission would reject. `endpoints/presentation_generate.py` branches on it into two live generation paths, and `services/presentation_profiles.py` (`PRESENTATION_DRIVER_REGISTRY`) is the single source of truth for which persisted-identity fields resolve to which driver:

| strategy | driver_id | What it does |
|---|---|---|
| `authored` | `authored` | An LLM writes raw HTML/CSS per slide (`services/generation_core/authoring/author_slide.py`), stored as `slides.html_content`. A DB check constraint enforces `slides.ui` XOR `slides.html_content`, so authored slides bypass any template schema entirely. |
| `svg` (default) | `svg-v1` | Admitted through `services/svg_generation_admission.py`, stored as `slides.svg_content`. |

A **legacy row generated by a driver this registry no longer claims** (a pre-2026-09-25 Template V2 deck is the only one that currently exists) fails `resolve_presentation_driver` with `unsupported_presentation_driver`. The read paths in `api/v1/ppt/endpoints/presentation_crud.py` treat that as data, not a bug: `GET /presentation/all` marks that one row `UnsupportedPresentationListItem` instead of failing the whole list, and `GET /presentation/{id}` returns a 422 with that error code rather than an uncaught 500.

What was retired, and what of it remains:

- **`legacy` / `adaptive`** (React layout components under `app/presentation-templates/`, Zod-typed schemas) were removed with the legacy presentation sources (commit `b11a92e62`). No layout groups, schema extraction, or `/api/template` layout route exist any more.
- **`template_v2`** was fully removed 2026-09-25 (`chore/remove-template-v2-20260925`, ~20 commits, both servers). Nothing of it remains, on either the generation or the read/export side: the strategy literal and its request fields, the Template V2 studio and PPTX-import pipeline (`templates/v2/`, `services/template_v2_service.py`), the endpoints (`structured_templates.py`, `structured_template_imports.py`, `template_v2_compat.py`), the driver-registry entry, the frontend studio/render/AST/export-fidelity trees, and the `presentation_generation_jobs.template_v2_target` column (dropped by Alembic revision `f432fc854225`) are all gone. A deck a removed Template V2 driver generated can no longer be opened or exported — see the legacy-row handling above — only listed (as an unsupported marker) and deleted. `templates/native_ui/` and `templates/pptx_safety/` under `servers/fastapi/templates/` are unrelated survivors rescued out of the deleted `templates/v2/` tree because they turned out to be generic (the native `slide.ui` schema every deck uses, and the zip-bomb-safe PPTX reader, now used only by `scripts/public_service_malicious_corpus_evidence.py`); do not mistake either for template_v2 remnants.
- The bundled **Korean business template packages** (root `templates/`, `servers/fastapi/templates/packages/`, `contracts/template_package/`) were deleted in the same removal, since only the retired React-template pipeline consumed them. The fork's pre-styled starting point is now the **SVG user template** (`services/svg_templates/`, `api/v1/ppt/endpoints/svg_templates.py`): a user registers a PPTX as a style-only or framed template and generates svg decks from it with `svg_template_pin` + `svg_template_mode`; new admissions are gated by `SVG_USER_TEMPLATES_ENABLED` (default off). In a framed template the header title and the "number | chapter › title" path become per-page dynamic text (long titles shrink, then are cut); templates published before that must be registered again.
- **Never build generation on reusing original template pages as skeletons** (copying a source page's body shapes or layout and swapping only text, table values or chart data; fixed-slot or Deck IR slot schemas; Design Pack source frames under any name). Deck IR, Design Packs and fixed-slot filling took that route and failed repeatedly; this is a user decision (`.spec-memory/decisions/generation.no-source-skeleton-reuse.1.json`). The original-level goal (`authored.generation.original-level-visual-acceptance`) stands; reach it by composing page bodies, not by refilling source pages.
- **Design packs** (`generation_mode="registered-template"` + `design_pack_pin`, the authored source-native route) were removed on 2026-11-03: their only successful run was rated the quality floor in `docs/generation-quality-root-cause-and-composer-architecture-20260904.md`. A request with that mode now fails with `registered_template_removed`; the digest-sealed generation-route receipt keeps its `designPackPin`/`source-native` fields so earlier operations still validate and export.
- Five LLM providers — **fireworks, together, lmstudio, ollama, custom** — now have an empty `presentationDrivers` in `constants/provider_registry.json`: template-v2 was their only generation driver, and no access was granted to replace it (a deliberate decision, not an oversight). `cerebras` is also driver-less but for an unrelated, pre-existing reason predating this removal.
- **Composer** (server-owned deterministic composition for `source_content_restyle`, formerly behind the `COMPOSER_RESTYLE_ENABLED` flag, `services/composer/` and `scripts/composer_*.py`) was removed on 2026-09-08. Restyle operations now always take the authored reflow path in `services/source_content/pipeline.py`, which was the default behavior.

Four fork-specific terms you will meet constantly in `services/`:

- **authored** — LLM-written slide HTML (above).
- **slidespec** — a canonical, versioned, normalized-0-to-1 geometry IR (`models/slidespec_v1.py`): content nodes, a recursive layout tree, and constraint kinds with hard/soft strength. Authored HTML is imported into a SlideSpec, inspected, repaired via a constraint solver plus LLM-proposed *closed-operation* repair plans (never raw HTML edits), then published back through a content-addressed store.
- **authored-hybrid** — the **export** strategy. `servers/nextjs/lib/authored-hybrid/browser-source.ts` is injected into headless Chrome to measure every element so the assembler can emit **native OOXML shapes** over a transparent raster backplate. This is why exported PPTX is genuinely editable rather than a screenshot.
- **workspace** — a chat-first control plane: its own DB tables (conversations, messages, assets, operations, operation events, outbox, receipts, artifacts), an event-sourced timeline, idempotent commands, an outbox dispatcher and lease fencing. Endpoints in `endpoints/workspace.py`, UI in `app/(presentation-generator)/presentation/workspace/`.

These are **additive**: upstream `presentation`/`slide` tables survive and the new tables are sidecars. Feature gates (all default-off / conservative):

- The workspace is no longer gated: neither the backend nor the frontend reads `CHAT_FIRST_WORKSPACE_ENABLED` / `NEXT_PUBLIC_CHAT_FIRST_WORKBENCH_ENABLED` any more, and generation/export always run as workspace operations. `docker-compose.chat-first-canary.yml` still runs the canary on ports 5050–5052 with a ClamAV-equipped image.
- `SLIDESPEC_*` rollout knobs live in `services/slidespec_rollout_policy.py` (import shadow, repair shadow/canary/apply, all-slides).

**Status check before you trust this pipeline:** `docs/slidespec-production-quality-speed-analysis-20260805.md` records a real 90-slide run where 23 slides were flagged and, initially, **0 repairs were applied**. Its section 7 records the follow-up: human labelling found 5 real defects and 18 false positives (78%), and all 5 real defects were then repaired and verified. SlideSpec never runs during generation: it runs only from the manual quality review, only for authored decks (`services/slidespec_rollout_policy.py`), so the default svg path never uses it. Treat detector precision as the open problem, and read that document plus `docs/slidespec-operations-replay-runbook-20260805.md` before changing anything in `services/slidespec_*`.

## Running & developing

**Docker (simplest full-stack run).** Compose services are `production`, `production-gpu`, `development`, `development-gpu`:
```bash
docker compose up development          # hot-reload dev (Dockerfile.dev, source bind-mounted)
docker compose up production           # production image (Dockerfile)
```
App is served at http://localhost:5000. Provider keys come from a `.env` next to `docker-compose.yml` (see the long env table in `README.md`).

**Per-service (fastest iteration on one server):**
```bash
# Backend — APP_DATA_DIRECTORY is REQUIRED or start.js/server.py throws
cd servers/fastapi && uv sync
uv run python server.py --port 8000           # FastAPI app object is api.main:app
uv run python mcp_server.py --port 8001        # MCP wrapper over the OpenAPI spec

# Frontend
cd servers/nextjs && npm install
npm run dev                                     # localhost:3000; set NEXT_PUBLIC_FAST_API / FAST_API_INTERNAL_URL to reach the backend
```

## 이 포크: Windows 네이티브 + 한글 (`RUNNING-LOCAL.md` 참고)

업스트림 `presenton/presenton`을 포크하여 한글 UI와, Docker 없이 Windows에서 **web** 앱을 네이티브로 실행하는 데 필요한 수정을 추가한 버전이다. 이 포크는 web-only이며 Electron 데스크톱 셸을 제공하지 않는다(`electron/` 디렉터리 없음). 위의 업스트림 기준 Docker 안내도 여전히 동작하지만, 여기서의 일상 개발은 Docker 없는 경로를 사용한다.

- **한글 UI / 기본값:** 앱 화면(chrome)이 번역되어 있고, 기본 프레젠테이션 언어는 한국어다(`upload/components/UploadPage.tsx`). API 값, 프로바이더/모델 ID, 로직 리터럴은 영어로 유지한다. 사용자 표시 문자열은 `next-intl`과 `i18n/messages/{en,ko}.json`을 사용하고, 새 감사 대상 화면은 `tests/i18n-audited-surfaces.test.mjs` 및 `npm run check:i18n` 게이트에 포함한다.
- **단일 오리진 프록시 (로컬에서 nginx 대체):** `node scripts/presenton-local-proxy.mjs`가 `nginx.conf`를 그대로 반영하여 `http://localhost:5000` → Next.js:3000 / FastAPI:8000 / MCP:8001로 라우팅한다. 포트는 `PROXY_PORT`/`NEXT_PORT`/`FASTAPI_PORT`/`MCP_PORT` 환경변수로 바꾼다. 브라우저 프론트엔드는 단일 오리진을 전제로 하므로, web 플로우에서는 (raw `npm run start`가 아니라) 이 프록시를 실행한다.
- **Windows 백엔드는** `APP_DATA_DIRECTORY` **와** `USER_CONFIG_PATH` **둘 다 필요**하며, uvicorn은 `--reload false`로 실행한다(이 포크에서 reloader 비활성화). 리로더가 없으므로 백엔드 코드를 바꾸면 프로세스를 직접 재시작해야 한다.
- **기존 `app_data`를 재사용해 업그레이드할 때는** `MIGRATE_DATABASE_ON_STARTUP=true` **를 반드시 설정한다.** 이 값이 정확히 `"true"`가 아니면 마이그레이션이 조용히 건너뛰어지고, 새 DB는 `create_db_and_tables()`로 생성되기 때문에 오류 없이 스키마만 어긋난다.
- **Export 경로:** PPTX/PDF 내보내기는 `export.pptx`/`export.pdf` 워크스페이스 오퍼레이션으로 격리 워커가 실행한다. 요청 안에서 내보내던 `utils/export_utils.py`와 그것이 쓰던 `/pdf-maker?exportSession=` 쿠키 전달은 제거되었다. 생성 요청의 `export_as`는 `services/presentation_generation_export_chain.py`가 완료 시점에 같은 오퍼레이션을 연결한다.
- **자동화 CLI:** `scripts/ppt-agent.mjs`는 `POST /api/v1/ppt/presentation/generate`(svg는 항상 `/generate/async` + 상태 폴링)를 호출하는 의존성 없는 Node 18+ 클라이언트다(기본 한국어). 동기 `/generate`는 durable job이 없어 svg를 `422 svg_generation_requires_async_route`로 거절하므로, 동기 호출은 `--strategy authored`일 때만 쓴다. 단건 또는 `--batch <파일>`, `--slides <n|auto>`, `--async`, `--strategy svg|authored`, `--common-header uniform|free`, `--language`, `--template`, `--style`, `--tone`, `--verbosity`, `--web-search`, `--toc`, `--no-title`, `--export pptx|pdf`, `--base`/`--ui-base`, `--user`/`--password`, `--out <디렉터리>`, `--timeout` 지원. `--export`는 생성 응답의 `export_operation_id`를 따라가 워크스페이스 아티팩트를 내려받는다(예전의 `/app_data/exports/` 경로 방식 아님). `DISABLE_AUTH` 백엔드 대상에서는 자격 증명이 필요 없다. 재시도·재개 기능은 없으므로 배치 중간 실패 시 전체를 다시 돌려야 한다.

## FastAPI backend internals

- **Entry/routing:** `server.py` → `api/main.py`. Routers: `api/v1/ppt` (the bulk), `api/v1/auth`, `api/v1/admin`, `api/v1/async_tasks`, `api/v1/webhook`, and `api/v1/mock` (registered conditionally). REST endpoints live under `api/v1/ppt/endpoints/` — 44 modules including `presentation_generate.py`, `presentation_crud.py`, `presentation_share.py`, `presentation_versions.py`, `workspace.py`, `authored.py`, `outlines.py`, `slide.py`, `theme.py`/`theme_generate.py`, `images.py`, `icons.py`, `fonts.py`, `files.py`, `file_decompose_jobs.py`, `conversations.py`, `svg_templates.py`, `asset_gateway.py`, `source_content.py`, plus provider auth modules (`openai.py`, `anthropic.py`, `google.py`, `ollama.py`, `codex_auth.py`).
- **Auth:** `api/middlewares.py`. `SessionAuthMiddleware` treats **every** `/api/` and `/app_data/` path as protected; the only exemptions are `/api/v1/auth/` and the token-only public share prefix. `/docs`, `/openapi.json`, `/redoc` are explicitly protected, not exempt. Auth decisions run on the **normalized** path so dot-segment traversal cannot ride an exemption. `DISABLE_AUTH=true` bypasses the whole middleware (used for single-user local/dev runs).
- **Generation pipeline** (routes in `endpoints/presentation_generate.py`, body in `services/presentation_generation_pipeline.py`): parse inputs (`services/documents_loader.py`, `services/liteparse_service.py`) → outline (`utils/llm_calls/generate_presentation_outlines.py`) → strategy branch (see "Two generation pipelines") → per-slide authoring (`services/generation_core/authoring/author_slide.py`, `author_slide_svg.py` for svg) → images (`services/image_generation_service.py`) → persist (`models/sql/*`) → export as the `export.pptx`/`export.pdf` workspace operation (see "Export 경로").
- **Background workers** run **in-process** inside FastAPI via `api/lifespan.py`: presentation-generation dispatcher, workspace operation runner + outbox dispatcher, workspace cleanup/asset/event maintenance, export retention sweeper. Some can be externalized — see `get_workspace_operation_worker_mode()`.
- **LLM provider abstraction:** `utils/llm_provider.py` + `utils/llm_config.py` wrap the `llmai` library and select among 15 providers (`enums/llm_provider.py`). Image providers are in `enums/image_provider.py` (10, including local ComfyUI/Open WebUI and a `DISABLE_IMAGE_GENERATION` placeholder path). Add provider logic here, not in endpoints.
- **Persistence:** SQLModel models in `models/sql/` (26 modules). Multi-tenant scoping is applied centrally, not per query: `services/database.py:109` installs a `do_orm_execute` hook that applies `with_loader_criteria` to owner-scoped models — do not hand-roll owner filters. Alembic migrations in `alembic/`, run on startup when `MIGRATE_DATABASE_ON_STARTUP=true` (orchestrated by `migrations.py`). `DATABASE_URL` accepts any async SQLAlchemy URL; falls back to SQLite under app data.
- **Errors:** `api/error_handling.py` provides a centralized error envelope with request IDs for HTTPException, validation errors, and unhandled exceptions. Prefer it over ad-hoc try/except in endpoints.
- **Configuration:** `constants/settings_registry.json` is the authoritative registry for managed/public provider settings and generates the shared Compose/docs surfaces via `npm run generate:settings-registry`; CI checks drift with `npm run test:settings-registry`. Runtime reads use `utils/get_env.py`, while some legacy direct `os.getenv` call sites remain outside it. New managed knobs must be registered first and consumed through the existing access layer. Per-instance runtime keys are persisted in `app_data/userConfig.json` (written by `start.js`); they are only writable when `CAN_CHANGE_KEYS != "false"`. Single-admin auth lives in `utils/simple_auth.py`.
- **Runtime settings synchronization:** external API and standalone worker processes share the database-backed monotonic revision described in `docs/runtime-settings-multiworker-sync.md`. PostgreSQL is the cluster profile; SQLite remains a local/multiprocess profile. Do not add request-time file/DB reads or transmit setting values in refresh notifications.

## Next.js frontend internals

- **App Router** under `app/`, grouped by segment: `(presentation-generator)/` holds the dashboard, upload/outline flows, and the slide **editor** at `presentation/page.tsx?id=<uuid>`; `presentation/workspace/` holds the chat-first workbench; `(export)/` and `p/` serve rendering and public share pages. Inline editing components such as `PresentationRender.tsx` live in `(presentation-generator)/components/` (the Tiptap-based `TiptapText`/`EditableText` chain and `EditableLayoutWrapper` were removed as dead code in 2026-09).
- **Built-in slide templates:** `app/presentation-templates/` holds no React layout groups any more in this fork (the upstream `general/`, `Code/`, `Education/`, `Report/`, `pitch-deck/`, `neo-*` groups are absent, and the fork's former groups were removed in earlier cleanups). The `generate:layout-schemas` script, `layouts.generated.json`, and `lib/compile-template-schema.ts` were removed on 2026-09-05 as dead code. Do not reintroduce a layout group without also restoring the schema-extraction pipeline.
- **Backend calls:** typed API clients in `app/(presentation-generator)/services/api/*.ts` call `/api/v1/*`. URL resolution (`utils/api.ts`) and the auth/forwarding middleware (`proxy.ts`) decide same-origin vs. direct-FastAPI based on `FAST_API_INTERNAL_URL`/`NEXT_PUBLIC_FAST_API`. Route handlers under `app/api/*` are thin proxies; `/api/export-presentation` only admits an export as a workspace operation.
- **State:** Redux Toolkit in `store/` — slices `presentationGeneration`, `presentationGenUpload`, `userConfig`, `undoRedo`.
- **UI:** Tailwind + shadcn/ui (`components/ui/`, config in `components.json`); charts via a vendored Chart.js (`public/vendor/chart-4.5.1`, loaded through `lib/chart-browser.ts`), not Recharts. TipTap, Recharts and Mermaid are gone (code and npm dependencies); do not reintroduce them without an importer. The application chrome is intentionally light-only: there is no appearance theme provider, toggle, or `dark:` contract. Presentation/deck themes (including dark deck designs) are a separate content feature. UI locale conventions are documented in `docs/ui-localization.md`.

## Conventions & gotchas

- Next.js build artifacts go to **`.next-build`**, not `.next` — the Dockerfile and `next.config.mjs` depend on this. (Fidelity tests override it via `PRESENTON_TEST_NEXT_DIST_DIR` to isolate their distDir per run; normal builds must leave it unset.)
- Running FastAPI (directly or via `start.js`) **requires `APP_DATA_DIRECTORY`**; generated files, uploads, fonts, exports, and `userConfig.json` all live under it. Missing it on the direct `server.py` path fails with an unhelpful `TypeError` rather than a named error.
- Export is fork-owned end to end: authored PPTX/PDF via `workers/public_export_worker.py` (+ the `public-hybrid-export-worker.mjs` hybrid assembler), master-pinned decks via the OOXML vNext worker, svg via `execute_svg_workspace_export`. There is no external export runtime to sync; a leftover local `presentation-export/` directory from an old checkout is ignored and can be deleted.
- When changing public LLM/image config knobs, keep four places consistent: `utils/get_env.py`, `start.js` (`setupUserConfigFromEnv`), `docker-compose.yml`, and the env table in `README.md`. This invariant is already violated for many fork-added variables (`SLIDESPEC_*`, `CHAT_FIRST_*`, `AUTHORED_*`, `EXPORT_RETENTION_DAYS`, `CHROME_PATH`) — do not add to the backlog.
- **FastAPI calls back into Next.js over HTTP** for export and rendering, not for layout schemas (the old `templates/get_layout_by_name.py` → `/api/template` callback is gone with the React layouts). The live callbacks, all resolved from `NEXT_PUBLIC_URL`/`NEXT_INTERNAL_URL`: `services/authored_vnext/integration/worker.py` posts to `/api/internal/ooxml-vnext` with a bearer `AUTHORED_VNEXT_OOXML_WORKER_TOKEN`; `utils/slide_capture_batch.py` screenshots `/pdf-maker?id=…` only when `AUTHORED_RENDERER_LEGACY_ENABLED` is set. `proxy.ts` no longer exempts `/api/template` (nothing serves it) — its only exemptions are `/api/v1/auth/`, `/api/health`, `/api/v1/ppt/presentation/public/`, and `/api/csp-report`. `/pdf-maker` left the middleware matcher with the export-session cookie hand-off.
- `node scripts/check-structural-layering.mjs` (wired into `test:next-ci` as `check:structural-layering`) is the structural gate that replaced the removed file-size ratchet: it forbids `servers/fastapi/utils/**` importing `services`, `services/**` importing `api`, `models/**` importing `services`/`api`, a `globals()[...] =` injection anywhere under `servers/fastapi/` (the pattern the ratchet's mechanical splits used to shrink files), and `servers/nextjs/lib|store` importing `@/app/`. Each rule's violations are frozen in `scripts/structural-layering-allowlist.json`, which may only shrink — the check fails on a new, unlisted violation and also fails if a listed entry no longer violates or no longer exists. Run `--write` only to remove entries that have genuinely been fixed; never to bank a new one.
- **SVG deck pictures and icons come from the asset offer** (`services/generation_core/assets/offer.py`). Figure icons are picked per deck by one LLM call (`utils/llm_calls/select_deck_icons.py`) from the style's vendored icon family (`servers/fastapi/assets/icon_families/<id>/`: Lucide, Tabler outline, Phosphor regular/fill/duotone; digest-checked manifests and licences; `icon_family` on the style YAML, default by category), composed in the bundled library's layout (`icon_pack/families.py`); the old 300-icon library (`assets/infographics/monochrome-v1`, not copied into the Docker image) is only the fallback, and icons are never generated by an image provider. `SVG_ILLUSTRATION_MODE` (`off`/`vector`/`hybrid`, internal knob) has the model draw scenes, cover/section pictures, step pictures and before/after pairs as contract SVG (`vector_offer.py`, validated by `vector_illustration.py`). The slide contract admits round `stroke-linecap`/`stroke-linejoin`; the flattener keeps multi-colour paints, opacity and holed compound paths. Read `docs/svg-illustration-icon-pilot-20261103.md` before changing any of it.
- **SVG generation needs a durable job and worker settings.** The synchronous `POST /presentation/generate` refuses svg (`422 svg_generation_requires_async_route`); use `/generate/async` (`scripts/ppt-agent.mjs --async`). A non-codex provider also needs its model in `PUBLIC_PROVIDER_PRICING_CATALOG`, and generation/export need the artifact store and trusted-worker settings listed in `servers/fastapi/scripts/fake_llm_e2e/README.md`; in Docker, the opt-in `multi-export` compose profile and `scripts/build-public-worker-image.sh` wire them (`docs/multi-process-compose-runbook-20260906.md` section 9). That harness runs the whole svg pipeline with a fake LLM and no provider key.
- **Content structure policy** (`utils/content_structure_policy.py`, tables and connectors) is opt-in via the internal knob `CONTENT_STRUCTURE_POLICY_SCOPE` (`off` by default; measured worse when on, see `docs/content-structure-policy-20261104.md`).
- **Judge svg template generation changes on several runs** with `servers/fastapi/scripts/svg_template_eval/` (README there); a single run varies too much to tell. Use `run_eval.py matrix` (inputs x templates, results saved after every run, `--resume`, `recover` from a database) and `run_eval.py decide` (paired per cell; a verdict only beyond the judge's noise). Judge version 2 (`judge.py`) needs score-5/score-1 anchors and is calibrated against human scores on the real deck's template only; scores of different judge versions are not comparable.
- **Template body composition** (`services/svg_templates/body_composition.py`): a framed template registered with it gives template-redesign authors the template's page composition grammar and one or two structural outlines of its own body pages per page (no source text). `SVG_TEMPLATE_BODY_EXEMPLARS` (internal) defaults to `on` after a paired measurement (`docs/template-body-composition-20261105.md`); `SVG_TEMPLATE_COMPONENT_STYLE` stays off. Templates registered before it must be registered again to benefit. `SVG_TEMPLATE_OUTLINE_SECTIONS` (the template's key-message line and `###` sub-sections in the outline, `utils/svg_template_outline.py`) and `SVG_TEMPLATE_VISUAL_GUIDANCE` (the template's body vocabulary instead of the anti-decoration guidance line) and `SVG_TEMPLATE_STEP_PICTURES` (model-drawn step pictures, the vector `spots` part, for template-redesign decks while `SVG_ILLUSTRATION_MODE` is off) are internal knobs. After the paired measurement on 2026-11-05 (`docs/template-a-visuals-progress-20261105.md`) outline sections defaults to `on` (it raised the judge's hierarchy on the real-deck template without lowering acceptance on a second template; `off` disables it); visual guidance and step pictures moved nothing and stay off.
- Live-test gotchas: a broad `pytest` run can kill a local PostgreSQL/backend started for live tests, and `DISABLE_AUTH=true` also blocks `/api/v1/auth/setup` (create the admin first, then restart with it).
- Honor the global instructions in the user's `~/.claude/CLAUDE.md` (auto-loaded every session; do not duplicate its contents here).
