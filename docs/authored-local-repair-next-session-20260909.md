# 새 세션 실행 지시: Authored 국소 보정 구현 및 실패 문서 검증

- 작성일: 2026-09-09
- 작업 저장소: `C:\project\PPT-agent\ppt-agent`
- 기준 설계: [Authored 국소 보정 고도화 v1.1](authored-local-repair-design-20260909.md)
- 사용자 요청: 이 설계대로 새 세션에서 난이도별 모델을 사용하는 멀티 에이전트로 개발하고, 2026-09-09에 실패한 실제 문서로 검증까지 수행한다.
- 이 파일은 실행 인계다. 새 대화 생성, 제품 구현, 실패 문서 재실행을 이미 완료했다는 뜻이 아니다.

## 1. 새 세션의 목표

설계를 반복 제안하는 데서 멈추지 말고, 기준 설계를 읽고 필요한 제품 코드를 구현·통합한 뒤 실제 실패 문서로 검증한다.
별도 범위 확장이 필요한 경우를 제외하면 이미 요청된 구현·검증에 대해 다시 승인받지 않는다.
현재 지침과 실제 코드가 우선이며, 기존 사용자 변경·다른 작업·서버·DB·산출물을 보존한다.
소스·상세 로그를 화면에 출력하지 않는다. 진행 상황과 결과·수정 파일·검증 산출물만 간결하게 보고한다.

## 2. 반드시 지킬 동작

1. Authored HTML 생성을 유지한다. Deck IR/source-native 생성 엔진이나 수동 SlideSpec 전체 엔진을 이식하지 않는다.
2. 보정에 실패해도 출력 가능한 원본이 있으면 해당 페이지를 검토 표시와 함께 포함하여 문서를 완성한다.
3. 보정 성공, 원본 보존, 문서 생성 완료, 품질 통과를 각각 구분한다.
4. 실패 후보의 내용·PNG·metrics·receipt를 정상 원본으로 둔갑시키지 않는다. 독립 원본의 identity와 출력 가능 여부를 확인한다.
5. 원본도 출력할 수 없거나 파일 출력 자체가 실패한 경우에만 실제 생성 실패로 처리한다. 누락 페이지를 숨기거나 빈 페이지로 채우지 않는다.
6. 대상 글자만 필요에 따라 9pt까지 축소한다. 전체 슬라이드 축소를 하지 않는다.
7. 기존 v1.4의 9pt/최대 10% 정책과 설계의 추가 축소 허용 정책을 버전으로 구분한다. 과거 receipt를 재해석하지 않는다.
8. 공간·폰트 후보를 같은 원본에서 비교한다. 공간 후보를 무조건 먼저 확정하는 기존 편향을 바로잡는다.
9. 정상 페이지·내용·수치·읽기 순서·일정의 가로 위치·보호 푸터를 보존한다.
10. 사용자가 작업을 취소하면 원본 fallback을 이유로 취소를 무시하지 않는다.

브라우저와 Python이 공유하는 폰트 정책은 주 에이전트가 하나의 계약으로 조정한다.
사용 가능한 모델이 다르면 실제 사용 모델을 보고하고, 사용하지 않은 모델이 검토했다고 말하지 않는다.

## 4. 오늘 실패한 문서 식별

여기서 '오늘'은 새 세션 시작 날짜가 아니라 **2026-09-09**다.
사용자가 마지막에 일반 생성으로 실행하다 실패한 문서를 찾는다. 과거 성공한 run49 재실행으로 임의 대체하지 않는다.

식별 순서:

1. 해당 날짜의 실행 결과·서버 로그에서 실패 operation/job/presentation ID를 찾는다.
2. 현재 실제 서버·DB 경로를 확인하고 해당 ID의 durable 상태·checkpoint와 대조한다.
3. 입력 파일, 요청 설정, 생성 mode/reference mode, style, 장수, provider/model과 실패 단계를 고정한다.
4. 실패 페이지의 보정 전 HTML·자산·baseline 또는 복원 가능한 checkpoint를 확보한다.
5. 원본·설정·HTML 해시, 확보 위치, 실패 코드, 미확인 범위를 검증 manifest에 기록한다. 비밀 설정 값은 기록하지 않는다.

`artifacts/authored-run49-exact-rerun-20260909/result.md`는 20장 게시 성공과 7·14·16페이지 검토 표시의 과거 증거다.
이 디렉터리 자체에는 원본 HTML/metrics fixture가 없으므로 정확한 HTML replay 자료라고 취급하지 않는다.
선행 문서에 기록된 7·16페이지 복구와 14페이지 보존 결과도 이번 실행의 성공 증거로 재사용하지 않는다.

실패 문서가 여러 개면 operation·시각·입력·설정으로 대조한다. 끝내 구분되지 않을 때만 사용자에게 식별에 필요한 한 가지를 묻는다.
원본을 찾지 못했는데 합성 사례나 다른 문서를 '오늘 실패 문서'로 보고하지 않는다.
실제 PostgreSQL 경로를 SQLite fixture 실행으로 대체하여 제품 경로 검증 완료라고 주장하지 않는다.

## 5. 구현 순서

1. 기준 설계와 현재 코드를 비교한다. 기존 후보 평가·원복·공간 계산을 재사용한다.
2. `font_floor_unfit`에 합쳐진 후보 소진·상대 축소 제한·측정 실패를 분리하고 후보 및 commit의 구체 거절 증거를 보존한다.
3. 원본 출력 가능 여부를 후보 품질 승인과 분리한다. 보정 예외가 worker·checkpoint·최종 gate에서 다시 전체 실패가 되지 않도록 연결한다.
4. scope·보호 경계와 공유 공간을 확인한 뒤 공간-only 우선 tier와 조기 commit을 수정한다.
5. 새 폰트 정책을 브라우저·Python 승인·출력 경계에 일치시킨다. 구 정책과 새 정책 receipt를 구분한다.
6. 선택한 원본 또는 변경본의 HTML·PNG·metrics·출력 revision을 일치시키고 완료·품질 상태를 별도 집계한다.
7. 영향을 받는 서버만 기존 포트·환경을 유지해 필요한 시점에 reload/restart한다. 관련 없는 프로세스는 그대로 둔다.

핵심 파일은 기준 설계 §11을 따른다. 새 큐·DB·보정 엔진을 만들거나 전체 저장소를 리팩터링하지 않는다.
원인 확인 없이 보존 한도를 풀거나, 현재 경고 allowlist에 모든 실패 코드를 추가하는 것으로 끝내지 않는다.

## 6. 검증 실행과 완료 기준

이번 요청에는 실제 실패 문서 검증이 포함돼 있다. 변경층의 좁은 검증과 해당 문서의 실제 제품 경로·최종 출력 확인을 수행한다.
전체 테스트·린트·빌드를 관성적으로 모두 실행하지 않는다. 반복 검증은 코드 변경이나 새 근거가 있는 경우에만 수행한다.

### 6.1 재현과 비교

- 먼저 확보한 실패 HTML을 실제 local-fit/admission 진입점으로 재생해 기존 실패를 확인한다.
- 후보 선택 개선은 기존 폰트 정책을 고정해 비교하고, 추가 9pt 축소 효과는 새 정책 비교로 분리한다.
- 같은 입력·요청 설정으로 제품 생성부터 파일 출력까지 확인한다. 원본 문서 만들기와 일반 생성 설정을 임의로 바꾸지 않는다.
- HTML replay는 같은 HTML의 보정 비교이며, 새 provider 생성은 다른 HTML이 나올 수 있는 제품 경로 확인이다. 두 결과를 구분한다.
- 기존 실패 산출물·게시물은 보존하고 별도의 실행 ID와 산출물 경로를 사용한다.
- 보정 실패가 재현되지 않으면 제한된 failure injection으로 원본 보존·문서 완성 경로를 추가 확인하고 실제 자연 발생과 구분한다.

### 6.2 필수 결과

- 출력 가능한 원본이 있는 보정 실패·timeout·검증 불확실은 원본 페이지를 포함해 요청 장수·순서대로 문서 완성.
- 정상 페이지의 불필요한 보정 0, 보정 성공 후보의 내용·수치 손실과 새 blocking 결함 0.
- 보정 성공 후보는 9pt 및 적용 정책을 준수. 원본 경고 전달의 품질 미달은 성공으로 숨기지 않음.
- 파일 실제 생성·열림·슬라이드 수·선택 페이지 revision 확인. 해당 출력 방식의 폰트/가시성 readback 수행.
- 사용자 화면은 '문서 생성 완료 / 정상 N · 자동 수정 N · 검토 필요 N'과 페이지별 핵심 이유만 표시.
- 원본도 사용할 수 없거나 파일 쓰기 실패면 실제 실패를 유지. 사용자 취소 존중.

최종 보고에는 구현 요약, 실제 입력·실행 ID, 요청/출력 장수, 자동 수정·검토 페이지,
보정 결과와 문서 완성 결과, 실제 PPTX 경로, 검증 범위와 미확인 항목을 간결하게 포함한다.
HTML 테스트만 통과한 상태를 실제 문서 검증 완료라고 보고하지 않는다.

## 7. 인계 시점의 상태

설계 v1.1과 이 실행 지시를 작성했다. 제품 코드는 이 인계 준비에서 수정하지 않았다.
새 대화 세션을 여는 도구는 현재 세션에 없으므로 사용자가 새 세션에서 이 파일을 실행 지시로 제공해야 한다.
기존 스킬 `compiled-spec-memory`는 PowerShell 7 실행 요건 때문에 기록되지 않았다.
자동 기록 불가를 이유로 이미 승인된 구현·검증 자체를 중단하거나 개발 환경을 무단 설치하지 않는다.
