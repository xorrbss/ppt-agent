# SVG PPT 공통 상단 헤더 설계

상태: 설계 검토 개선안, 누락 제목 일괄 준비 및 복구 연결 구현 완료. 선택 검증과 실제 제목 준비 호출을 확인했으며, 실제 5페이지 PPTX의 최종 검증·사용자 디자인 평가·릴리스 승인은 남아 있다. 대상은 새로 생성하는 SVG 기반 편집형 PPT다. 기존 문서의 자동 수정이나 실행 중인 작업의 규칙 변경은 포함하지 않는다.

## 목표와 확정 범위

사용자가 선택한 방향은 문서 안에서 상단을 하나의 패턴으로 통일하고, 본문은 LLM이 내용에 맞게 자유롭게 구성하는 것이다. 아래 항목은 사용자 합의 범위이며 구현 방식과 수치는 이후 항목의 제안이다.

- 제목의 시작 위치, 정렬, 서체, 크기, 굵기와 색상을 문서 단위로 통일한다.
- 제목은 최대 2줄이며 1줄인 페이지도 같은 본문 시작선을 사용한다.
- 기본 상단 구성은 제목 하나다. 분류명, 부제와 구분선은 문서 전체 설정으로 선택한다.
- 기본 적용 대상은 표지를 포함한 모든 페이지다. 표지나 섹션 페이지의 예외는 명시적으로 선택한 경우에만 허용한다.
- 본문의 표, 차트, 구성도, 화면 설명과 정보 배치는 내용에 따라 달라질 수 있다.
- 긴 제목을 처리할 때 특정 페이지의 글자만 작게 만들거나 필수 의미를 삭제하지 않는다.
- 생성, 후보 수정과 재개는 확정된 공통 헤더를 유지한다.

이번 설계는 헤더에 필요한 작은 설정과 페이지별 제목만 추가한다. 본문을 새 IR이나 전체 레이아웃 모델로 바꾸지 않는다.

## 현재 코드에서 확인한 문제와 재사용 지점

`author_slide_svg.py`는 제목의 위치와 시각적 비중을 페이지 내용에 맞게 고르도록 하고, title slots와 bands도 선택적 참고로 취급한다. 이 지침은 본문 자유도에는 맞지만 상단의 강제 통일과 충돌한다.

기존 `AuthoredHeaderContract`와 `authored_header_contract_service.py`에는 문서 단위 서체, 간격과 헤더 규칙이 있다. 다만 현재 v2는 실제 줄 수에 따라 페이지별 band 높이를 달리하며 기본적으로 COVER와 SECTION을 제외한다. SVG 작성 경로에서는 이 계약을 사용하지 않는다. 이 모델을 그대로 연결해도 같은 본문 시작선과 전 페이지 적용을 보장하지 못한다.

SVG에는 `svg_master_furniture.py`의 서버 합성 및 증거 생성 경로와 `svg_contract.py`의 최종 합성 지점이 있다. 브랜드 요소의 소유권과 원본 근거는 그대로 유지하면서 공통 헤더도 이 서버 합성 체계에 연결한다. 기존 furniture의 긴 text 자동 축소 동작은 페이지 제목에 사용하지 않는다.

현재 `SlideOutlineModel`에는 content만 있고 독립적인 title 필드가 없다. 따라서 제목이 이미 별도 확정되어 있다고 가정하지 않는다. 정상 개요 작성과 입력 문서 처리에서 제목을 준비하는 작은 연결 작업이 필요하다.

## 문서 단위 헤더와 페이지 제목

### 소유권과 저장 위치

헤더의 기하·서체·색상은 서버가, 제목 문구는 기존 개요/문구 작성 경로가 담당한다. LLM은 헤더의 좌표나 스타일을 변경하지 않는다.

기존 서체·색상 스펙과 측정 함수를 재사용하는 SVG 전용 어댑터를 둔다. HTML/Authored v2의 가변 높이 동작을 바꾸거나 v2라는 이름으로 다른 의미를 저장하지 않는다.

| 데이터 | 저장·결합 제안 |
| --- | --- |
| 공통 헤더 정책 | `svg_style_snapshot.common_header`, 작은 버전 설정 `svg-common-header/v1` |
| 헤더 스타일 | canvas, 실제 font identity, 색상, 여백, 제목 상자, 줄간격, 본문 시작선, 선택 요소와 적용 범위 |
| 페이지별 제목 | 기존 authored_outline JSON의 별도 메타데이터로 페이지 index 및 원문 근거와 연결 |
| 페이지 제목의 실제 줄바꿈 | 확정 제목에 대해 서버가 계산하고 페이지 제목 증거에 저장 |
| 결합값 | 공통 설정 digest, 제목 digest, canvas/font 측정 버전과 최종 헤더 SVG digest |

제목 문구를 스타일 YAML이나 브랜드 토큰에 저장하지 않는다. 스냅샷 저장은 기존 JSON과 CAS 경로를 사용하며 별도 DB 테이블을 기본안으로 추가하지 않는다. DTO 직렬화/복원에서 페이지 제목 메타데이터가 누락되지 않는지 구현 시 확인한다.

### 제목 준비

정상 개요 작성 호출에서 페이지 제목을 함께 준비한다. content에 포함된 원문 사실은 그대로 유지하고 별도 title은 표시 제목 역할만 갖는다. 문구 정책을 동일하게 적용하며 제목 자체에 원문 없는 성과·인과·확정 표현을 추가하지 않는다.

외부 slides_markdown 입력은 명시적이고 의미 있는 페이지 제목을 먼저 사용한다. 순서 표시만 있는 제목, 여러 후보, 제목이 없는 입력은 단순한 첫 줄 잘라내기로 확정하지 않는다. 기존 개요 준비 경로에서 제목을 정리하거나 사용자 지정 제목을 사용한다. 기존 개요 호출에 함께 준비할 수 없는 누락 제목은 문서 단위 일괄 준비 최대 1회로 제한하며 페이지마다 별도 호출하지 않는다. 입력 용량/예산 안에 한 번에 처리할 수 없거나 결과가 불명확하면 미확정 사유를 보고하고 자동 반복하지 않는다. 실제 추가 호출은 기존 승인된 계획/예산에 포함하며 추가 호출 0회로 보고하지 않는다. 별도의 페이지별 헤더 디자인 LLM 호출은 기본 경로에 넣지 않는다.

본문에서 제목 문구가 삭제되어도 그 문구에만 있는 사실이 사라지면 안 된다. 개요의 원문 텍스트는 보존하며 공통 제목과 본문의 의미 중복만 기존 문구 처리에서 정리한다.

## 공간과 시각 규칙

상단 20% 같은 고정 비율 대신 실제 canvas와 사용 가능한 제목 폭, 서체의 glyph 폭/높이와 줄간격으로 계산한다. canvas의 픽셀과 PPTX 물리 단위 변환은 기존 규칙을 사용한다.

문서의 모든 제목을 같은 폭과 서체로 측정해 필요한 제목 줄 수를 먼저 결정한다. 우선 핵심 주제를 제목에 두고 상세 조건은 근거와 연결된 실제 본문에 보존해 1줄 공간을 검토한다. 원문 인용·사용자 지정 고정 제목은 임의로 줄이지 않는다. 이 단계 후에도 필요한 제목이 2줄이면 문서 전체에 2줄 공간을 예약한다. 각 페이지는 제목 첫 줄이 같은 위치에서 시작하며 1줄 제목을 개별적으로 중앙 정렬하지 않는다. 2줄 선택 전 알려진 필수 표·차트·본문의 가독성 하한과 남은 영역을 확인하고, 슬롯 확대만으로 본문 부족을 해결한 것으로 판정하지 않는다.

문서의 본문 시작선은 제목 슬롯 하단, 선택 요소 높이, 공통 간격과 브랜드 예약 영역으로 한 번 계산한다. 분류명·부제 슬롯을 사용하기로 했으면 해당 페이지의 문구가 비어도 슬롯 공간은 유지한다. 구분선 위치와 길이도 문서 안에서 고정한다.

헤더 배경색을 포함한 공통 색상과 대비를 확정한다. 본문 배경이나 시각 강조가 달라도 상단 제목의 가독성과 색상은 유지한다. 기존 로고가 상단에 있으면 소유권이 확인된 예약 영역을 제외해 제목 폭을 계산하고 로고를 덮지 않는다. 푸터와 페이지 번호 예약도 보존한다.

### 긴 제목

1. 원문의 핵심 대상과 주제를 유지하며 기존 문구 작성 경로에서 제목을 다듬는다. 상세 조건을 제목에서 옮길 경우 원문 근거와 연결해 읽을 수 있는 본문에 보존하며, 필수 사실·부정·승인 조건을 생략하지 않는다. 고정 제목과 인용은 유지한다.
2. 같은 서체와 크기로 자연스러운 위치에서 최대 2줄로 배치한다. 띄어쓰기와 글자 단위 폭을 측정하며 단어 수만으로 판단하지 않는다.
3. 초기 확정 전에 여전히 맞지 않으면 문서 전체 제목 폭과 슬롯을 조정한다. 제목 크기 변경은 사용자가 정한 크기나 가독성 하한을 지키는 문서 전체 결정이어야 한다.
4. 본문 공간의 가독성까지 만족할 수 없으면 해당 제목/페이지를 미확정으로 보고한다. 잘라내기, 말줄임표, 숨김, 특정 페이지 글자 축소로 통과시키지 않는다.

제목과 헤더는 첫 본문 작성 전에 확정한다. 작성이 시작된 뒤에는 한 페이지 때문에 전체 문서의 헤더를 자동으로 바꾸지 않는다. 전체 헤더 변경은 별도의 명시적 문서 수정이며 영향을 받는 페이지의 재검증과 revision 변경을 함께 처리한다.

### 원자적 확정

현재 스타일을 먼저 저장하는 경로를 그대로 두고 제목을 나중에 추가하지 않는다. 기존 job 소유권/CAS 검증 아래 확정 제목, 줄바꿈, 공통 헤더와 스타일 snapshot을 하나의 트랜잭션에서 저장한다. 하나라도 불완전하면 본문 dispatch를 시작하지 않는다. 재개는 전체 결합이 있는 확정 데이터를 읽으며 제목만 저장된 상태나 digest 충돌을 새 기본값으로 보완하지 않는다. 기존 outline content와 title 메타데이터의 직렬화·worker 복원도 이 경계에 포함한다.

## 생성과 합성 흐름

| 순서 | 담당과 동작 |
| --- | --- |
| 1 | 정상 요청의 공통 상단 설정, canvas, 기존 스타일/브랜드 예약과 적용 가능한 원본 모드를 확인 |
| 2 | 기존 개요/문구 경로에서 페이지별 제목 준비, 제목/원문 연결 검증 |
| 3 | 모든 제목을 측정해 공통 슬롯과 본문 영역 확정, 제목 메타데이터와 스타일 스냅샷을 원자적으로 고정 |
| 4 | LLM에 공통 헤더 미리보기/규칙과 본문 허용 영역을 전달하여 본문 작성 |
| 5 | 서버가 확정 제목과 공통 SVG 헤더를 합성하고 실제 렌더링 검증 |
| 6 | 통과한 동일 SVG를 미리보기·게시·PPTX 내보내기에 사용 |

본문은 원래 canvas 좌표를 사용한다. 본문 전체를 아래로 강제 이동하거나 축소하지 않는다. 제목 영역은 시작부터 예약한다. body-only SVG에 필요한 작은 영역/역할 표식을 전달하되 내부 본문 도형·그룹 구조와 배치를 제한하는 새 스키마를 만들지 않는다.

공통 헤더의 그룹 ID와 제목 ID는 시스템 소유다. 작성 결과에 시스템 헤더를 위조한 그룹이 있으면 거부하고 서버 결과를 기준으로 검증한다. 본문이 상단에 자체 제목을 다시 그리거나 공통 제목을 중복 출력하면 해당 본문만 수정한다. 본문의 실제 소제목·표 제목까지 문자열이 같다는 이유로 일괄 삭제하지 않는다.

서버 공통 헤더는 `svg_master_furniture`의 합성 지점에 연결하지만 원본 템플릿에서 추출한 요소로 가장하지 않는다. 기존 source/master furniture와 generated common header의 origin과 digest를 구분한다. 일반 furniture의 text 자동 축소를 공유하지 않고 strict title 측정과 줄바꿈을 사용한다.

## 검증, 수정과 재개

합성 전에 본문이 예약 영역을 침범하는지 검사하고 합성 후 최종 제목의 실제 glyph, 폰트와 줄바꿈을 확인한다. 단순 text box 좌표만으로 통과시키지 않는다. 기존 렌더의 glyph/paint 측정을 재사용하고 별도의 범용 SVG 검사 엔진을 만들지 않는다. 초기 필수 범위는 제목 넘침, 본문 침범, 중복/위조 헤더이며, 기존 측정으로 판단할 수 없는 효과는 미확인 사유를 보고한다. stroke, transform, 실제 보이는 paint 영역을 고려한다. 전체 canvas 배경과 의도적 공통 배경은 일반 본문 침범과 구분한다. 클리핑으로 내용이 가려져 검사를 통과하지 못하게 한다.

| 검사 | 통과 조건 |
| --- | --- |
| 헤더 동일성 | 문서 내 같은 header 설정 digest, 제목 첫 줄 위치, 정렬선, 서체/크기/색상과 본문 시작선 |
| 제목 내용 | 확정 제목과 최종 SVG/PPTX 제목 동일, 최대 2줄, 문구 정책 및 원문 근거 유지 |
| 공간 | glyph 넘침·헤더/로고 겹침·본문 침범 0, 실제 font fallback 확인 |
| 역할 | 적용 대상마다 서버 헤더 1개, 의도하지 않은 별도 페이지 제목 없음 |
| 본문 | 필수 사실·표·차트·원본 자산과 기존 native 선언/관계 유지 |
| 내보내기 | 제목이 편집형 텍스트로 출력되고 SVG와 OOXML의 물리 좌표/서체가 일치 |

서버가 합성한 제목과 헤더는 native coverage 및 export 매핑에 등록한다. 실제 줄바꿈과 줄별 위치를 전달하고 PowerPoint 자동 맞춤/자동 축소에 맡기지 않는다. 폰트 identity를 확인하며 대체 폰트는 동일성 통과로 합치지 않는다. 직렬화 반올림의 초기 허용 오차는 SVG 좌표 0.5px, OOXML 물리 좌표 0.5pt이며 단위 변환 후 각각 비교한다. 이 오차는 문구·서체·줄 수 차이를 허용하지 않고 실제 Office 확인에서 시각 차이가 있으면 좁힌다.

새 실패 사유는 제목 넘침, 본문 침범, 헤더 위조/중복과 헤더 digest 불일치를 구분한다. 정확한 코드 이름은 구현 단계에서 기존 오류 분류에 맞춰 확정한다. 수정은 기존 후보 수정 예산으로 해당 제목 또는 본문 페이지를 처리하며 문서 전체 재생성이나 자동 제공자 재호출을 기본 해법으로 넣지 않는다.

생성 입력 해시에는 헤더 설정뿐 아니라 해당 페이지의 확정 제목과 줄바꿈 digest도 포함한다. `collect.py`와 `svg_partial_recovery.py`는 같은 정규화/입력 해시 함수를 공유하며 비슷한 구현을 두 곳에 복사하지 않는다. 전체 deck preflight, 작성 프롬프트, 페이지 체크포인트, 합성 증거와 export 입력까지 같은 결합을 확인한다. 복구에서 제목을 다시 작성하거나 현재 기본값을 주입하지 않는다.

공통 헤더가 없는 이전 frozen 작업은 기존 경로로 복구한다. 새 규칙을 옛 authoring profile/동일 버전의 다른 의미로 숨기지 않으며, 새 요청은 명시적인 헤더 정책 및 호환 가능한 새 작성 규칙 버전을 고정한다. 제공자 UNKNOWN, 부분 체크포인트와 게시 revision의 기존 보수적인 경계는 유지한다.

헤더 digest가 바뀐 문서는 관련 PNG와 내보내기 증거를 재사용하지 않는다. 미리보기, SVG 및 editable PPTX에 같은 제목과 위치가 전달되어야 하며 이미지 한 장에 제목을 구워 넣어 편집성을 잃지 않는다.

## 입력 모드와 화면 설정

기본 새 SVG 생성은 `상단 통일`이 선택된 상태로 준비한다. 화면은 `상단 통일`과 `페이지별 자유 구성`을 제공하고, 표지 예외는 별도의 명시적 선택으로 처리한다. 세부 수치와 내부 digest는 일반 생성 화면에 노출하지 않는다. 실제 UI와 API의 기본값, 요청 브리지 및 worker 재구성 값을 동일하게 유지한다.

PPT/PDF/문서에서 내용만 가져와 새로 구성하는 모드에는 공통 헤더를 적용할 수 있다. 편집 가능한 원본 제목이 있는 경우 제목의 근거로 사용한다.

원본 페이지 그대로 보존하는 모드와 전체 화면 캡처에는 원래 상단이 포함될 수 있다. 새 헤더를 덮거나 이미지를 자르는 것으로 통일을 가장하지 않는다. 원본 보존과 상단 통일을 동시에 요청하면 제공자 호출 전에 충돌을 판정하고 모드 선택을 요구한다. 사용자 선택 없이 보존/재디자인 중 하나로 자동 전환하지 않는다. 사용자가 재디자인/내용 재배치 모드를 선택한 경우에만 일반 공통 헤더로 생성하고, 원본 보존 작업에서는 적용 불가/보존 우선 상태를 명확히 표시한다. 페이지 종류를 근거로 자동 예외를 만들지는 않는다.

새 공통 헤더 모드는 SVG 경로부터 구현한다. HTML/Authored와 기존 템플릿 경로는 각자의 기존 헤더/템플릿 계약을 유지하며 모두 구현됐다고 표시하지 않는다. 기존 PPT의 상단 일괄 수정은 후속 기능이고 이 설계의 신규 생성 완료 조건에 넣지 않는다.

## 품질과 속도 판단 및 완료 조건

공통 헤더 선택을 페이지마다 LLM에 맡기지 않는다. 제목을 기존 개요 호출에서 함께 준비하고 전체 글자 측정은 한 번 수행한다. 독립적인 헤더 스타일 LLM 호출은 기본 경로에 추가하지 않는다. 폰트 identity별 측정 캐시를 재사용하고 기존 렌더 측정에 헤더 검사를 합쳐 동일 페이지를 검증만을 위해 반복 렌더하지 않는다.

새로 추가되는 제목 준비 호출, 수정 호출, 렌더 횟수와 최종 PPTX 완료 시간을 실제 증거에서 분리한다. 구현 전 품질/속도 점수나 성능 개선 수치를 확정하지 않는다.

기본 정상 개요의 추가 헤더 준비 호출은 0회, 개요를 건너뛴 입력의 누락 제목 일괄 준비는 최대 1회다. 긴 제목 조정은 가능한 한 이 준비 호출 안에서 마치고 헤더 디자인만을 위한 추가 호출을 만들지 않는다. 본문 수정은 기존 페이지 후보 수정 횟수와 총 예산 안에서 실행하며 별도 무제한 헤더 재시도 예산을 추가하지 않는다.

구현 후 가장 좁은 단일 검사에서 제목 1/2줄의 같은 본문 시작선, 일반/표지 적용, 긴 제목과 본문 침범, 헤더 digest의 신규/legacy 복구 해시를 해당 변경 범위에 맞게 확인한다. 현재 설계 단계에서는 코드 테스트나 생성 실행을 하지 않는다.

실제 완료 검증은 같은 자료로 짧은 제목·긴 제목, 표·차트·구성도·화면 설명을 포함한 여러 페이지를 정상 웹 경로에서 생성하는 것이다. 헤더 위치/서체/본문 시작선의 동일성과 본문 구성 다양성을 별도로 확인한다. 최종 PPTX에서 제목·표·차트가 편집 가능하고 PowerPoint 열기·수정·저장·다시 열기가 가능해야 한다. 정적인 검사나 생성 성공만으로 최종 시각 검토/릴리스 승인을 통과했다고 표시하지 않는다.

## 구현 결과와 검증 범위

정상 개요는 기존 호출 안에서 제목을 준비하여 추가 헤더 호출 0회를 유지한다. 제목 없는 외부 `slides_markdown`은 명시적이고 의미 있는 제목을 먼저 보존하고, 누락 제목만 문서 단위 최대 1회로 준비한다. 이번 실제 실행의 최초 제목 일괄 준비는 1회였다. 입력 용량·승인 예산·원문 digest·페이지 index 및 제목 provenance를 검증하며, durable started/terminal 기록과 검증된 결과 재사용을 연결했다. 미확정·UNKNOWN 결과는 자동 재호출하지 않는다. `common_header_mode`, `common_header_cover_exception`, `svg-common-header/v1` 및 `svg-common-header-page/v1`의 확정 입력을 유지했다.

실제 경로에서 확인된 공통 경계도 최소 범위로 수정했다. Chromium 실제 크기 glyph와 Pillow 기준 측정의 차이는 제목 owned ink 검사에만 제한해 반영했다. 본문 안에 놓인 변환 없는 rect, circle, ellipse의 선 반폭이 좌우 여백으로 확장되는 경우는 배치와 paint를 구분하되, 본문 위·아래와 canvas 및 브랜드 예약 침범은 거부한다. native 선언의 body digest에서는 정확한 단일 최상위 서버 헤더 그룹만 제외한다. 게시 번호 갱신은 저장된 확정 page binding을 검증해 재사용하고, export 부모 검증은 정상 준비와 같은 canonical base/full header 관계만 허용한다. 원문·SVG 배치·기존 frozen 입력·native 선언·provider history 및 기존 UNKNOWN ledger를 변경하지 않았다.

최종 PPTX 검토의 기존 private carrier 전달, 검증된 결과의 CAS 승격, 현재 검증기 코드 pin에 맞춘 기존 PPTX 캐시 재사용도 최소 수정으로 연결했다. 새 검토는 현재 artifact와 5페이지 증거에 결합하며, 과거 실패 receipt나 다른 파일의 검토를 통과 근거로 가져오지 않는다.

실제 생성 작업은 `published`, 생성 operation은 `succeeded`, 완료 페이지는 5/5, flagged 페이지는 0이다. 최종 source QA의 gate, 디자인 개선 조건 및 페이지 coverage가 통과했다. 생성 job의 누적 제공자 receipt 14건과 별도의 정식 최종 PPTX 검토 제공자 호출 2건은 구분해 기록한다. 초기 2페이지 구조 검증과 이전 4페이지 평가·중단 기록은 과거 증거로 남겼다.
