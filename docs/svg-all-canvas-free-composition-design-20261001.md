# SVG 전체 캔버스·템플릿 지원 설계

작성일: 2026-10-01. 기준: 현재 작업 트리와 연결된 생성·스타일·캔버스 코드.
상태: 기능 구현과 선택한 실제 생성·내보내기 검증 완료. 전체 품질·성능 목표의 통계적 인증은 별도이며 달성으로 표시하지 않는다.

## 1. 사용자 결정과 설계 제안

사용자가 확정한 범위:

- SVG에서 디자인 스타일·템플릿에 관계없이 다양한 캔버스의 PPT를 생성한다.
- Authored 지원 확장은 제외한다. 기존 Authored 요청·문서의 동작은 보존한다.
- 템플릿은 필요하면 재제작할 수 있다.
- 구도는 모델이 설계한다. 고정 패턴을 선택해 컴파일하는 Deck IR 방식으로 돌아가지 않는다.
- 단조로운 구도와 비슷한 레이아웃의 반복을 품질 문제로 평가한다.
- 프로그램은 캔버스·내용 보존·측정·내보내기를 책임진다.
- 준비 단계 중복과 불필요한 재시도를 줄여 속도를 개선한다.

구현을 구체화하기 위한 제안:

- 기존 7개 프리셋에 4:3을 추가하고, 범위가 명시된 사용자 지정 크기를 제공한다.
- SVG에서는 캔버스 사용 가능 여부와 통계적 품질 인증을 분리한다.
- 디자인 팩은 새 디자인 참조 필드로 사용한다. 기존 등록 템플릿 실행 계약을 재해석하지 않는다.
- 다양성 관측은 참고 정보로 사용한다. 구도 이름의 개수로 디자인 품질을 인증하지 않는다.
- 출시 목표는 품질 비퇴행과 전체 생성 시간 중앙값 20% 개선이다. 측정 전에는 달성으로 보고하지 않는다.

## 2. 기존 구현에서 바꿀 경계

| 현재 경계 | 확인한 상태 | SVG 목표 |
| --- | --- | --- |
| 캔버스 | `constants/canvas_registry.json`에 7개, 9:13은 숨김 | 모두 선택 가능, 4:3과 사용자 지정 추가 |
| 허용 여부 | `services/authored_canvas.py`의 스타일별 단계와 공통 조합 제한 | SVG 전용 능력 판정, Authored 결과 보존 |
| 공개 요청 | 내부 DTO는 9:13을 포함하지만 public-v2에는 누락 | UI·직접 API·public-v2의 같은 지원 범위 |
| 스타일 | 미검토 형식 지침은 `svg_style_mapping_required` | 디자인 지침을 정규화하고 미확실성 표시 |
| 마스터 | 제목·본문 슬롯 필요, 기하 투영과 열 수 제한 | 디자인 특징과 로고·고정 요소를 참조로 추출 |
| 디자인 팩 | SVG에 source-native patch target이 없어 거절 | 신뢰된 팩의 디자인 참조를 별도 계약으로 해석 |
| 원본 재구성 | 선택 A4 또는 제한된 원본 크기, 일부 스타일만 지원 | 선택한 SVG 출력 캔버스, 원본 정보·페이지 대응 보존 |
| 이미지 원본 | raster target이 A4 고정 | 분석 원본과 선택 출력 기하를 구분 |
| UI | SVG A4 강제, 원본 모드에서 선택기 제한, 스타일 재선택 | 사용자 선택을 생성·재개·내보내기까지 유지 |
| 품질 | 페이지 측정·게시 digest·표/차트 읽기 검증 존재 | 재사용, 새로운 구도 엔진이나 별도 게시 경로 금지 |

`CLAUDE.md`의 기본 전략 설명에는 오래된 항목이 있으므로 실제
`services/generation_core/admission/strategy.py`의 중앙 전략 판정을 따른다.

## 3. Deck IR에서 달라지는 생성 책임

처리 순서:

1. 입력과 원본을 읽고 필수 사실·수치·표·이미지 참조를 준비한다.
2. 디자인 특징과 출력 캔버스를 한 번 고정한다.
3. 기존 아웃라인·계획 단계에서 메시지와 페이지 간 시각적 의도를 전달한다.
4. 모델이 페이지별 구도를 정하고 현재 계약의 SVG를 작성한다.
5. 실제 글꼴과 브라우저에서 렌더·측정한다.
6. 기존 제한된 수정 기회로 문제 페이지를 보정한다.
7. 측정한 SVG를 게시하고 실제 PPTX·PDF 결과를 확인한다.

프로그램이 배치 문법, 카드 수, 레이아웃 ID, 고정 슬롯 목록으로 작성 가능 범위를
정하지 않는다. 모델이 반환한 자유 구도를 검토한다. 표·차트의 의미 데이터,
로고 및 페이지 번호 같은 시스템 요소에는 결정론적 생성 경로를 계속 사용한다.

자료 구조화는 내용 보존용이다. 표의 관계·필수 수치·원본 블록을 구조화하는 것이
페이지 전체를 컴파일할 시각 IR을 도입하는 근거가 되지 않는다.

## 4. 캔버스 계약

기존 `document-canvas/v1`의 물리 EMU, 논리 크기, 안전 영역, digest를 재사용한다.
PPTX는 물리 크기, SVG·브라우저는 논리 좌표를 사용하며 래스터 이미지 해상도는
출력 품질 옵션이다. 같은 비율의 이미지 해상도 변경만으로 구도를 다시 생성하지 않는다.

### 4.1 프리셋과 사용자 지정

- 프리셋: 16:9, 4:3, 1:1, 21:9, 9:16, 9:13, A4 가로, A4 세로.
- 기존 프리셋의 물리·논리 크기와 저장 형태는 유지한다.
- 4:3은 SVG 추가 비율이다. Authored에 이를 자동으로 개방하지 않는다.
- 새 요청 `svg_canvas`는 `width_mm`, `height_mm`을 받는다. camel alias도 지원한다.
- 사용자 지정의 초기 범위는 각 변 50–1000 mm, 소수 둘째 자리까지, 비율 1:4–4:1이다.
- 이 필드는 명시한 `aspect_ratio`, `page_size`, `orientation`과 함께 제출할 수 없다.
- public-v2에서는 같은 의미의 `svgCanvas`를 사용한다.
- EMU는 mm × 36000으로 정확히 계산한다.
- 논리 장변 약 1280을 기준으로 폭을 반올림하고 물리 비율에서 높이를 반올림한다.
  portrait에서도 v1의 반 픽셀 오차 계약을 지키며, 장변은 반올림에 따라 약간 달라질 수 있다.
- 새 사용자 지정 안전 여백은 논리 64 px이다. 안전 영역이 유효하지 않으면 거절한다.
- 사용자 지정은 아무 크기의 무한 지원이라는 뜻이 아니다. API·UI에 같은 제한을 표시한다.

### 4.2 전달과 복원

입장 시 확정한 출력 canvas digest를 작업과 스타일 snapshot에 고정한다.
원본 기하와 출력 기하를 따로 보존한다. 재시작·takeover·재생성·수정·내보내기는
저장된 기하를 읽으며 기본 16:9/A4로 돌아가지 않는다.
과거 v1/v2 source binding과 스타일 snapshot은 당시 계약으로 복원한다.

SVG 입력에서 생략된 기존 selector의 의미와 원본 크기 유지 선택은 보존한다.
새 선택은 명시된 SVG 요청으로 제출한다. 지원 실패를 Authored 실행으로 숨기지 않는다.

## 5. 모든 템플릿을 위한 디자인 참조

### 5.1 정규화 snapshot

새 SVG snapshot의 `composition_mode`는 `free-svg`, `reference_semantics`는
`design-identity`이다. 다음 정보와 원본 digest를 보존한다.

- 색·글꼴·제목 계층·로고·배경 표현.
- 테두리, 강조, 이미지 처리, 표·차트의 표현과 디자인 특징.
- 검토한 참고 이미지와 적용 범위, 추출하지 못한 특징에 관한 diagnostics.
- canvas, 디자인 원본, assets/font manifest, projection 버전과 digest.

원본 좌표, 고정 제목·본문 슬롯, `max_columns=1`, 등록 템플릿의 patch handles는
새 일반 SVG 작성 지침으로 전달하지 않는다. 참고 이미지는 스타일 참고이며,
원본 위치나 도형 관계를 그대로 복사하라는 명령이 아니다.
단순 색상 변경에 머물지 않도록 핵심 디자인 특징을 별도로 보존한다.

### 5.2 입력별 처리

| 입력 | 디자인 정보 확보 | 호환성 |
| --- | --- | --- |
| 기본 등록 스타일 | 기존 YAML·fonts·assets·참고 이미지 | SVG용 정규화, Authored 원본 보존 |
| 회사 마스터 | 검증된 owner-scoped master pin | SVG 전용 참조 투영, 기존 master 실행 계약 보존 |
| 디자인 팩 | 신뢰된 package pin·manifest·원본 자료 | 새 `svg_design_reference_pin` 사용 |
| 업로드 PPTX/PDF/이미지 | 기존 reference snapshot/원본 분석 | 모델은 승인된 assets만 사용, 새 임의 파일 경로 금지 |

`svg_design_reference_pin`은 기존 `DesignPackPinInput`과 같은 pin 형태이며 명시적
SVG 생성의 디자인 참조다. 기존 `design_pack_pin`과 `registered-template`에는
source-native 실행 의미가 있으므로 자동 치환하지 않는다. UI에서 SVG를 선택한
새 생성은 디자인 참조로 제출하고 그 의미를 표시한다.

형식 지침이 HTML 전용이거나 `exact_reconstruction`으로 표시된 스타일도 SVG 디자인
참조로 사용할 수 있어야 한다. 다른 비율에서 원본 배치까지 동일하다고 주장하지 않는다.
읽을 수 없는 파일, 없는 pin, digest 불일치, 권한 없는 자산은 정상적인 실패로 남는다.

### 5.3 시스템 고정 요소

로고·헤더·푸터·페이지 번호는 선택 캔버스의 모서리·안전 영역에 재고정한다.
모델에 예약 영역과 사용 가능한 자산을 전달하고 같은 요소를 중복 작성하지 않게 한다.
앵커와 간격도 안전 영역에 들어가지 못하면 충돌을 보고한다. 구도 제한으로 숨기지 않는다.
실제 저장 SVG에 포함해 현재 exporter를 통과하도록 한다.

## 6. 원본 재구성과 일반 생성의 차이

원본 재구성은 원문·수치·표 셀·이미지 및 페이지 순서를 보존한다.
원본 한 페이지와 결과 한 페이지의 현재 대응을 유지한다. 자동 요약·분할을 추가하지 않는다.
원본 canvas는 provenance, 선택 canvas는 출력 계약이다.

새 `free-svg` source snapshot은 기존 고정 템플릿 solver를 우회하고 모델의 자유 배치
계획을 사용한다. 내용 모델에는 원본 블록 ID·출처·이미지·표를 유지한다.
기존 source layout의 데이터 검증/조립기는 재사용할 수 있지만 고정 슬롯 선택은 강제하지 않는다.
이미지 원본도 분석 좌표와 출력 좌표를 분리하고 표/차트 sidecar를 유지한다.

일반 신규 생성은 기존 고정 장수와 verbosity 계약을 유지한다. 데이터·캔버스에 맞는
내용량을 준비하되 필수 내용 삭제, 작은 글씨 축소, 장수 변경으로 성공을 꾸미지 않는다.
원문 보존 요청의 글꼴 하한을 일반 SVG에 전역 적용하지 않는다.

## 7. 디자인 다양성과 품질

### 7.1 검토 항목

- 사실·수치·단위·관계·원본 이미지 누락.
- 실제 글꼴 기준 텍스트 잘림·겹침·너무 작은 글씨.
- 표·차트와 읽기 순서, 이미지 왜곡.
- 메시지의 초점·정보 위계·여백·스타일 재현.
- 페이지 간 반복되는 구도와 구성이 내용에 필요한지.
- 저장 SVG와 PPTX/PDF의 기하·표·차트·글꼴 표현 일치.

### 7.2 반복 관측과 모델 입력

배경·로고·페이지 번호를 제외한 텍스트·이미지·도형의 위치·크기를 canvas로 정규화해
반복 의심 쌍과 관측 근거를 구한다. 서로 다른 이름의 같은 카드 배치도 관측 대상이다.
의도적인 비교·시리즈 페이지는 반복만으로 실패시키지 않는다.
관측 버전을 기록하고 기존 deck advisory에 부가한다. 이는 미적 품질의 정답 판정이 아니다.

기존 계획/아웃라인 안에서 메시지마다 필요한 시각적 의도를 전달하고, 모든 페이지를
같은 카드/열 구조로 구성하지 않도록 안내한다. 이를 위해 새 직렬 LLM 단계를 추가하지 않는다.
형태별 프리셋 목록이나 달라야 하는 패턴 수를 모델에 강제하지 않는다.

### 7.3 수정·게시

기존 페이지별 모델 수정 예산, provider ledger, durable checkpoint를 유지한다.
구도 문제의 보정은 해당 페이지에 한정한다. 자동 다양성 재생성 루프를 추가하지 않는다.
내용과 앵커를 보존할 수 있는 국소 수정만 허용하고, 변경한 SVG는 다시 측정한다.
마지막 정상 후보를 보존하며 모델 실패를 이유로 정상 페이지를 모두 다시 만들지 않는다.

`services/svg_page_publication.py`를 통해 canonical SVG와 quality source digest를 일치시킨다.
측정되지 않은 페이지나 기존 fallback 페이지를 고품질 성공으로 세지 않는다.

## 8. 속도 계획

기존 2026-09-29 실험의 중앙값 285초 중 준비 단계 166초(약 58%)는 과거 증거다.
브리프 82.7초, 계획 49.0초, 아웃라인 33.0초였으며 현재 모델에서 재측정한 값은 아니다.
관련 보고서는 `canvas-bench-pooled-candidate-20260929.md`,
`svg-outline-speed-ab-plan-20260930.md`이다.

우선순위:

1. 기존 단계별 timing receipt로 준비·작성·측정·수정·내보내기를 구분한다.
2. 디자인 참조 추출은 입력 digest 기반으로 캐시하고 worker 재개 시 재추출하지 않는다.
3. 역할이 중복되는 브리프·계획 출력을 줄인다. 기존 실험 arm을 재사용한다.
4. 낮은 추론 강도/단계 생략은 품질 비교 후 채택한다. 전역 모델 설정을 일괄 낮추지 않는다.
5. 검증은 실제 SVG/font/assets/renderer digest에 묶어 재사용한다.
6. 독립 페이지의 기존 동시성을 보존하고 과부하를 만드는 무조건 병렬 확대를 하지 않는다.

지금의 구현에 새 직렬 계획 단계·페이지별 스타일 분석·전체 덱 자동 재생성을 넣지 않는다.
20% 개선은 채택 목표이며, 품질 비퇴행을 증명하지 못하면 성능 설정을 보류한다.

## 11. 위험·롤백·완료 상태

자유 구도에는 결과 편차와 긴 꼬리 지연이 남는다. 모든 디자인의 원본 위치까지

새 profile/능력 버전은 저장된 snapshot과 함께 고정한다. 회귀 시 새 작성 정책만
되돌리며 기존 SVG·canvas·source pin은 재해석하거나 덮어쓰지 않는다.
정식 verified 표시와 별도 운영 통계 DB는 기능 개방의 선행 조건으로 만들지 않는다.

구현과 검증이 끝나면 이 문서의 상태와 실제 수행 범위·실패·미확인 사항을 갱신한다.
설계 점수와 목표를 실측 성공으로 바꾸어 기록하지 않는다.

## 12. 구현 계약과 현재 확인한 범위

- SVG는 기존 7개 프리셋과 4:3을 지원한다. 사용자 지정 입력은 각 변 50~1000mm,
  소수점 두 자리, 비율 1:4~4:1이다. 물리 크기는 mm당 36000 EMU로 보존한다.
- 내부 `svg_canvas`와 public `svgCanvas`를 사용하며 다른 캔버스 선택자와 함께 입력할 수 없다.
- 디자인 팩 참조는 `svg_design_reference_pin`, 업로드 참조는
  `svg_design_reference_snapshot_id`를 사용한다. public 필드는 각각
  `svgDesignReferencePin`, `svgDesignReferenceSnapshotId`다.
- 회사 마스터·디자인 팩·업로드 참조는 한 번에 하나를 명시한다. 참고용 업로드는
  내용 첨부와 분리하며 PPTX·PDF·PNG·JPEG·WebP를 지원한다.
- 기존 owner 범위의 ReferenceSnapshot과 자산 gateway를 재사용한다. 새 DB 스키마 없이
  소유권·만료·원본 digest를 확인하고 작업 재개 시 고정된 디자인 snapshot과 비교한다.
- PPTX에 미리보기 이미지가 없으면 추출한 색상·서체를 사용한다. 화면 모습을 참고하려면
  PDF 또는 이미지를 선택할 수 있다. 추출하지 않은 시각적 특징은 보장하지 않는다.
- 일반 SVG는 PPTX/PDF를 지원한다. 내용 보존형 source-PPTX reflow의 기존 내보내기
  계약은 PPTX 전용이다. 이 모드의 PDF를 지원했다고 표시하지 않는다.
- 승인된 래스터 원본의 재디자인은 모델이 영역의 기하를 구성하고 서버가 원래 텍스트·표·
  crop을 조립한다. 원본 모습 보존/재구성 모드에서 새 디자인 참고나 대체 스타일을
  지정하면 재디자인 선택을 안내한다. 디자인이 적용되지 않은 결과를 성공으로 처리하지 않는다.
- 실제 이미지 전용 원본의 160×240mm 재디자인에서 편집 가능한 표 1개, 원본 crop 8개,
  승인된 내용 보존 목록과 선택 스타일을 확인했다. 불확실한 OCR 텍스트·원본 차트는 이미지로
  보존하므로 모든 텍스트가 편집 가능한 결과는 아니다. 원본의 흐림·흰 배경도 남을 수 있다.
- 등록 스타일 44개 × (8개 프리셋 + 사용자 지정 1개)의 생성 admission/profile 검증은
  396/396 통과했다. 이는 실제 모델 생성이나 시각적 품질의 전수 검증이 아니다.
- 생성 진입·물리 캔버스·래스터 계약·프로필·원본 보존·내보내기의 좁은 검증을 담당별로
  수행했다. 선택자 생성, 사용자 지정 작업 복원, 참고 digest 변경 거부도 확인했다.
- 실제 브라우저에서 8개 프리셋 선택·스타일 유지, 사용자 지정 크기 검증,
  PNG 업로드·참고 등록과 대기 차단, 생성 준비→개요 이동의 캔버스·참고·스타일 보존을
  확인했다. 브라우저 오류 0건이며 이 확인에서는 모델 생성 요청을 차단했다.
- 순수 표·차트 입력은 별도 모델 기반 자산 계획을 생략하고 기존 라이브러리 벡터만
  사용한다. 저장된 checkpoint를 먼저 재사용하며, 기본 스타일의 명시적 SVG 자유 생성,
  입력과 개요의 일치, 모든 내용 줄의 데이터 문법 일치를 함께 확인한다. 일반 문장·사진·
  관계도·원본 자산·디자인 참고가 있으면 기존 자산 계획 경로를 사용한다.
- 표·차트의 명시적 데이터 요청은 SVG 그림 외에 편집 가능한 native 데이터도 확인한다.
  누락은 기존 제한된 페이지 수정 경로로 보정한다. 페이지 재작성의 preview→CAS publish에서도
  SVG와 native 선언의 결합을 확인하고 새 revision의 내보내기를 사용한다.
- 원본 PPTX 표는 source 셀·행·열·병합·줄바꿈과 실제 SVG의 격자·서체에 결합해 native 표로
  내보낸다. 원본 보존 읽기 검증은 도형 텍스트뿐 아니라 native 표 구조와 셀 값도 확인한다.
  이미 저장된 자유 SVG 결과의 보완은 소유권·원본 manifest·작성 checkpoint·배치 digest를
  검증하고, 표 그룹을 제외한 원래 그리기 순서와 내용이 일치하는 내보내기 파생본으로 한다.
  저장된 슬라이드를 바꾸거나 기존 측정/VQA digest를 새 파생본에 재표시하지 않는다.
- 페이지 재작성 후 기하·native 데이터의 공통 품질 판정과 의미 검토 상태를 구별한다.
  이전 VQA는 변경된 페이지에 대해 stale로 남으며, `semantic_review=required`를 지우지 않는다.
  현재 제품에는 SVG만 다시 의미 검토하고 이를 영구 저장하는 독립 API가 없다.
  같은 게시 candidate의 메타데이터 복구도 소유자·SVG·이미지·native 결합·현재 revision의
  일치와 CAS를 확인하며, 변경된 페이지에 과거 preview를 덮어쓰는 재실행은 허용하지 않는다.
- 격리 서버에서 16개 실제 사례의 최종 산출물 읽기를 통과했다. 32개 SVG·PNG,
  PPTX 16개·PDF 13개를 확인했다. 원본 PPTX 두 사례는 기존 PPTX 전용 계약을 유지하고,
  래스터 사례 한 건은 PPTX만 요청했으므로 해당 사례의 PDF 실행을 주장하지 않는다.
  확인 범위는 8개 프리셋·사용자 지정 2종·업로드 이미지·디자인 팩·원본 PPTX 2종·
  승인된 래스터 재디자인·순수 데이터 생성이다. 396개 조합을 모델로 전수 생성한 것은 아니다.
- 변경된 세로형 페이지는 원문·다른 페이지를 유지한 채 분기 차트의 native 데이터를 보완하고,
  공식 현재 revision의 명령으로 PNG receipt를 복구했다. 최종 데이터·크기·이미지 digest는
  통과했지만 이전 의미 검토 advisory는 해당 페이지에서 stale로 남는다.
- 새 자유 SVG 원본 snapshot은 `text_wrap_policy=latin-token/v1`을 사용해 숫자·영문 단위가
  줄 사이에서 끊기지 않도록 한다. 폭과 최소 서체 조건을 만족할 수 없는 단일 토큰은 오류로
  알려 임의 분할을 피한다. 새 정책은 좁은 검증으로 확인했다. 과거 snapshot은 기존 분할
  정책으로 재현하며, 회사 마스터 실검증의 원래 미리보기에는 `120`이 두 줄로 끊기는 한계가
  남는다. 이 결과의 원래 화면을 새 정책으로 재생성했다고 주장하지 않는다.
- 최종 증거는 `artifacts/svg-all-canvas-20261001/final-acceptance.json`에 모았다.
  실제 브라우저 증거는 같은 폴더의 `ui`, 순수 데이터 비교는
  `artifacts/svg-native-literal-control-20261001`, 래스터 승인·생성은
  `artifacts/svg-raster-custom-20261001`에 보존했다. 품질 점수나 전체 생성 시간 개선율은
  인증하지 않았다.

## 13. 실제 속도 관측

동일 입력을 이전 코드와 새 코드에서 각각 한 번 실행했다. 실제 모델은 모두
`gpt-6.1-sol`, reasoning은 `medium`이다. 표·차트의 원본 데이터와 내보내기 확인은
같은 조건으로 유지했다.

| 입력 | 이전 코드 | 새 코드 | 관측 |
| --- | ---: | ---: | --- |
| 일반 문장 + 표·차트, 2장 | 153.500초 | 162.953초 | 새 코드 6.16% 느림 |
| 순수 표·차트, 2장 | 127.937초 | 122.484초 | 새 코드 4.26% 빠름 |

순수 데이터 입력의 자산 계획 호출은 실제로 생략됐다. 다만 새 코드의 첫 차트에서
native 선언 누락을 감지하고 페이지 한 번 수정이 발생했다. 결과적으로 이 비교의
실제 provider 호출은 양쪽 모두 4회다. 준비 구간은 0.937초였지만 전체 지연은
모델 작성·수정 시간에 크게 영향을 받는다. 품질 검증을 줄여 속도를 만들지 않았다.

순수 데이터 비교는 다른 생성 작업 없이 순차 실행했다. 일반 입력 비교는 다른
후속 검증과 실행 구간이 겹쳤다. 모델·렌더러 캐시 상태는 통제하거나 인증하지 않았다.
각 입력 한 쌍의 관측이므로 전체 생성 시간 중앙값 20% 개선이나 통계적 비퇴행을
인증하지 않는다. 모델 지연 변동을 숨기거나 좋은 결과만 재실행해 선택하지 않았다.

원본 증거는 `artifacts/svg-all-canvas-20261001/baseline`과
`artifacts/svg-native-literal-control-20261001`에 보존한다.

## 14. 현재 실행 환경 반영과 기록

현재 공유 서버의 API·생성 작업자·내보내기 작업자에 반영했다. 진행 중인 작업·provider
lease가 없음을 확인하고, 미실행 대기 작업 두 건은 유지했다. 기존 Next·프록시·PostgreSQL과
포트는 유지했고, 실제 SVG 능력 응답에서 프리셋 8개와 사용자 지정 범위를 확인했다.
격리 검증 서버의 앱·작업자는 종료했으며 DB·워크트리·검증 자료를 보존했다.
실행 기록은 `artifacts/svg-all-canvas-20261001/final-runtime-delivery.json`에 있다.

이 문서는 최종 검증 뒤 결과를 갱신했다. source snapshot의 런타임 코드 기록과
검증 후 작성한 문서 결과를 같은 시점의 파일 상태로 취급하지 않는다.
`compiled-spec-memory` 스킬은 현재 환경에서 발견되지 않아 자동 Spec 레코드는 생성하지
못했다. 사용자 결정과 구현 계약·실제 확인 범위·한계는 이 문서에 기록했다.

## 15. 디자인 품질 개선 구현

2026-10-01 후속 구현은 기존 자유 SVG 구조를 유지한다. 데이터 정확성과 시각적
의도를 별도로 전달하며, 고정 레이아웃·카드 수·슬롯 선택이나 페이지별 추가 모델
호출·전체 덱 자동 재생성을 도입하지 않았다.

- `svg-native-requirements/v2`: 라벨 없는 Markdown 표와 여러 표를 독립 요구사항으로
  추출한다. 차트의 계열·카테고리·값·단위를 작성 프롬프트와 검증에서 공유한다.
  중복 표·차트에는 개체별 대응을 요구하고, 계열마다 다른 단위는 계열명에 결합한
  표기로 검증한다. 한 계열에 여러 단위가 섞여 현재 네이티브 형식으로 정확히
  표현할 수 없으면 명시적으로 미지원 처리하며 수치를 임의 변환하지 않는다.
- 업로드 참고는 실제 PPTX→PDF 렌더링과 대표 PDF 페이지를 우선 사용한다.
  활성·외부·임베디드 콘텐츠나 렌더러 부재로 렌더링할 수 없으면 사용한 대체 경로를
  provenance에 명시한다. 배경·본문·강조 색상과 서체 위계를 추출한다.
- 추출 결과는 원본 해시·형식·추출 버전·렌더러 능력에 따라 프로세스 내 최대
  8개를 재사용한다. durable 재개는 저장된 `design_pack_template`을 그대로 재사용한다.
  어느 경로에서도 소유자·만료·스캔·현재 원본 해시·최종 바인딩 검사를 생략하지 않는다.
- `svg-visual-intent/v1`: 페이지 메시지·정보 밀도·읽는 흐름·이웃 페이지 의도를
  기존 내용에서 계산해 준비 체크포인트에 고정한다. 원본·래스터에는 승인된 내용만
  사용한다. 기존 체크포인트는 의도를 새로 주입하지 않으며, 준비 정보만 저장된
  직후 중단돼도 canonical asset 경로를 잃지 않는다.
- 새 `svg-style/v4`와 `svg-source-identity/v2`는 의미별 색상과 타이포그래피 위계를
  적용한다. 래스터 표의 바탕·헤더·구분선·본문 색상을 통일하고 불확실한 OCR 이미지의
  역할·확실도·최소 크기를 모델에 전달한다. 승인된 텍스트·셀·크롭을 삭제하거나
  다시 인식한 값으로 바꾸지 않는다. 원본 측정 폰트는 기존 Noto Sans KR 계약을 유지한다.
- SVG의 `quality.review`는 `mode=analyze_only`로 선택 페이지의 현재 PNG를 한 번
  검토한다. `/presentation/{id}/svg-quality-review`도 동일한 durable 작업을 사용한다.
  소유자·리비전·작업 fence·취소·측정 완료·SVG/PNG 해시를 검토 전후 확인한다.
  SVG와 리비전을 바꾸지 않고 검토 증거만 저장한다. 모델 결과가 없으면 성공으로
  기록하지 않는다. 기존 SVG 전용 증거에 현재 PNG 해시를 새로 붙이지 않는다.
- 화면에서 슬라이드 데이터·배치 측정·현재 화면 검토·디자인 관측을 구분한다.
  VQA는 advisory이며 최신 검토가 존재한다는 사실을 미적 품질이나 의미 정확성의
  인증으로 취급하지 않는다. 실제 수정 호출은 timing의 `repair`로 별도 기록한다.

검증: 변경 경로의 집중 테스트 136개를 확인했다. 최초 116개 통과·20개 실패 후
의도 helper import 연결과 테스트 요청의 캔버스 필드를 수정하고 실패 20개만 다시
실행해 통과했다. 기존 Authored 수정 경로·SVG 데이터·부분 검토·오래된 PNG·CAS·
작업 재개·래스터 표 스타일·캐시의 소유자/해시 재검증·수정 시간 기록을 포함한다.
공유 API와 생성·내보내기 작업자에 반영했고 새 검토 API 스키마를 확인했다.

이 후속 변경으로 생성한 긴 덱의 시각 비교나 동일 조건 속도 측정은 아직 실행하지
않았다. 앞 절의 16개 사례와 속도 수치는 후속 변경 전 결과이며 개선 폭의 증거가 아니다.
