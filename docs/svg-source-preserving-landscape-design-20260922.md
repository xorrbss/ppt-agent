# SVG 원본 콘텐츠 보존·선택 템플릿 적용 설계

- 작성일: 2026-09-22
- 개정: 사용자 확정 방향에 따라 원본 크기 유지, 선택 템플릿 적용, 서버 우선 배치로 수정.
- 상태: 개정 설계를 제품 코드에 반영하고 계층별 검증을 진행했다. 30페이지 전체 제품 인수는 아직 완료하지 않았다. 기존 1차 구현·검증 이력은 10절, 실제 원본 실패 분석은 11절, 개정 구현과 검증 범위는 12절에 구분한다.
- 목표: 원본 PPTX의 내용·페이지 대응·물리 크기를 보존하면서 선택한 템플릿 디자인을 적용한 별도 SVG 문서를 만들고, 같은 확정 결과를 PPTX로 내보낸다.
- 관련 설계: `svg-generation-mode-design-20260916.md`, `svg-image-asset-pipeline-design-20260916.md`, `composer-source-preservation-and-7px-fit-design-20260913.md`.

## 1. 범위와 사용자 계약

범위는 PPTX 입력, `source_content_restyle`와 `strategy=svg`의 조합, 원본 크기의 새 문서, 기존 SVG PPTX export다. 이번 원본은 약 297×210mm의 A4 가로이며 16:9가 아니다. 정확한 크기는 PPTX slideSize EMU를 권위로 삼고, A4 표시는 그 크기에 대한 분류다. 기존 원본과 생성된 문서를 덮어쓰지 않는다. 업로드·계정·원본 snapshot·manifest·작업 큐는 기존 체계를 재사용한다.

기본 동작은 **원본 내용·크기 유지 + 선택한 템플릿 디자인 적용**이다. 원문·표 값·이미지의 등장 횟수·페이지 수·페이지 순서를 유지하고 색상·글꼴·배경·제목 체계·표·도형 스타일·레이아웃은 선택한 템플릿에서 가져온다. 임의 요약, 표지·목차 추가, 페이지 병합·분할, 다른 페이지로 콘텐츠 이동은 금지한다. 원본 좌표·서식은 내용 관계와 측정의 참고 정보이며 기본 출력 디자인의 권위가 아니다.

템플릿이 16:9여도 원본을 16:9로 변경하지 않는다. 해당 디자인의 정렬·여백·계층 규칙을 원본 캔버스에 맞춰 적용한다. 크기 변경은 명시적 사용자 선택이 있을 때만 허용하고 별도 입력 identity로 처리한다. 원본 디자인 복제나 일반 스타일로의 자동 대체는 금지한다.

선택된 실제 템플릿 ID·버전·자산을 적용 계약으로 해석할 수 있는지 접수 전에 검사한다. 임의 기본 스타일 ID로 대체하지 않는다. 회사 표준 master, 등록 템플릿, exact reconstruction, 다른 생성 엔진은 명칭만으로 일괄 허용하지 않는다. 선택 템플릿을 SVG 경로에서 표현할 수 없으면 이유를 안내하고 생성 전에 중단한다. 이번 인수 대상은 A4 가로 원본이며 세로·다른 크기·PDF 지원은 각각 capability로 판단한다.

## 2. 현재 구현과 필요한 변경

| 연결부 | 확인한 현재 동작 | 변경 방향 |
|---|---|---|
| `UploadPage.tsx`, `useUploadPageState.ts` | 1차 구현은 원본 SVG를 가로 16:9로 고정 | 원본 크기 표시·선택 템플릿 전달; canvas와 template capability 동시 확인 |
| `services/svg_generation_admission.py` | 1차 구현은 원본 SVG의 16:9만 허용 | 원본 canvas와 선택 템플릿 적용 가능 여부를 검증; 다른 차단 유지 |
| `services/source_content/pipeline.py` | 원본 manifest 검증과 페이지 구성 | 엔진 중립적인 원본 페이지 입력을 재사용; Authored 전용 라우팅에 SVG를 억지로 통과시키지 않음 |
| `services/svg_presentation_service.py`, `utils/llm_calls/author_source_svg_layout.py` | 원본 페이지마다 모델 계획 요청; 문자 위치 검사 후 로컬 보정 | 템플릿 규칙 기반 서버 배치를 먼저 실행; 필요한 페이지만 모델 요청; 문자 위치는 서버 전담 |
| `services/svg_contract.py` | 정적 SVG 요소·속성·이미지 slot 검증 | 기존 허용 목록 유지; 별도 source binding으로 보존 검사 |
| `services/svg_generation_assets.py` | 원본 이미지 slot과 자산 저장 | 원본 페이지·등장 ID에 기반한 필수 slot 배정; 의미 유사도에만 의존하지 않음 |
| `services/svg_export_operation.py`, `workers/public_svg_export_worker.py` | 격리 worker에서 SVG를 PPTX로 변환; 페이지 수·캔버스 readback | 보존 검증 receipt를 입력 revision과 연결; 원문·표·이미지 readback 보강 |

현재 exporter가 native shape 변환을 요청한다는 사실만으로 모든 원본 요소의 개별 편집 가능성을 보장하지 않는다. 기존 SVG export의 글꼴 embedding 미지원 제한도 그대로 유지한다.

## 3. 데이터와 권위

아래 명칭은 제안하는 논리 계약이다. 기존 동등 계약이 있으면 확장하며 병렬 저장소·별도 큐를 만들지 않는다.

### SourcePageModel

- 원본 snapshot ID, manifest digest/버전, source page ID/index, 원본 canvas.
- 텍스트 block ID, 문단·run 순서, 원문, run style, 언어, 제목/본문 등 원본에서 확인 가능한 역할.
- 표 ID, 행·열·병합 셀, 셀별 원문/숫자, 읽기 순서.
- 이미지 occurrence ID, 원본 asset digest, crop/회전/비율, 원본 페이지 귀속.
- 원본 좌표, 그룹과 상대 관계, 지원되지 않는 객체와 추출 손실.

모델 응답은 원문·표 값·이미지 자산의 권위가 아니다. 추출 단계에서 인식하지 못한 객체를 생성 단계에서 추정해 보완하지 않는다. 내용 손실이 예상되는 입력은 접수 전에 설명하고 원본 보존 모드의 완료로 처리하지 않는다.

### TemplateDesignSnapshot / TemplateLayoutSet

- 기존 템플릿 registry와 snapshot을 확장한다. 선택 템플릿 ID·버전·digest, 출처 자산, 색상·글꼴·배경·제목 계층·표·도형 스타일을 고정한다.
- 표지·본문·표 중심 등 실제 템플릿이 제공하는 layout 유형, slot 역할, 정렬·여백·최소 간격·크기 범위와 허용 변형을 정의한다. 존재하지 않는 layout을 임의 기본 디자인으로 만들어 통과시키지 않는다.
- 원본 페이지 역할·내용량·표 구조·이미지 비율에 따라 layout 후보를 서버가 제한된 순서로 선택한다. 원본 페이지에 없는 표지·목차를 추가하지 않는다.
- 템플릿 분석은 문서당 한 번 수행하며 동일 버전 결과는 캐시한다. 템플릿 자산 변경 시 무효화한다. 규칙화할 수 없는 요소는 적용 가능 여부 검사에서 안내한다.
- 선택 템플릿 글꼴의 가용성·한글 coverage·사용 가능 조건을 먼저 확인한다. Pretendard 고정이나 조용한 대체를 하지 않는다. 대체가 필요한 경우 사용자 선택과 대체 font digest를 고정한다. 임의 URL/font CSS의 renderer 허용 범위를 넓히지 않고 기존 검증 자산 경로를 사용한다.
- 색상·font role·배경·장식·제목·표 스타일과 layout slot 적용 결과를 페이지별 증거로 남긴다. 템플릿 ID를 기록한 사실만으로 디자인 적용을 통과시키지 않는다.

### 템플릿 지원 단위와 규칙 정의

첫 구현 대상은 사용자가 실제 선택한 템플릿으로 제한한다. 그 템플릿의 A4 적용을 검증한 뒤 다른 템플릿의 지원 범위를 확장한다. 선택 템플릿을 지원하지 않는 상태에서 일반 기본 스타일을 대신 적용해 기능을 활성화하지 않는다.

| 규칙 구분 | 반드시 정의할 내용 |
|---|---|
| 디자인 요소 | 실제 색상 토큰, font family/weight/size 역할, 배경·구분선·장식 자산, 제목 계층, 표·도형 스타일 |
| 영역 구성 | 제목·본문·표·이미지 slot, 허용 내용 유형, 필수/선택 여부, 읽기 순서와 계층 |
| 배치 제약 | A4에서의 기준 영역, 정렬선, 여백·최소 간격, 크기 범위, 허용 레이어와 겹침 |
| 허용 변형 | 열 수·slot 크기·그룹 배치 변경 범위, 축소 가능한 장식, 유지해야 하는 디자인 특징 |
| 검증 근거 | 원본 템플릿 참조 렌더, 기대 규칙, 자동 검사 항목, 시각 검토 항목과 적용 예외 |

색상·글꼴만 추출한 snapshot은 템플릿 지원 완료로 인정하지 않는다. 템플릿 규칙을 A4에 적용할 수 없거나 필수 디자인 요소를 표현할 수 없으면 capability에서 미지원 이유를 반환한다. 모델 배치를 허용할 유연 영역과 그 제약도 template snapshot에 명시한다.

### SvgLayoutPlan v2

- 입력 source page digest, 원본/출력 canvas, template snapshot digest, layout ID, plan schema version.
- block/occurrence ID별 좌표·크기·회전·서식·정렬·명시적 읽기 순서.
- 모델 입력/출력 계약에서 `line_ends`, `cell_line_ends`를 제거한다. 원문·문자 위치는 모델이 작성하지 않는다. 줄바꿈 경계와 문자 범위는 서버가 원문·실제 글꼴 측정으로 계산하여 내부 resolved plan에만 기록한다.
- 표는 원본 행·열·병합 구조를 참조하며 디자인만 변경한다.
- 필수 원본 ID는 정확히 지정된 횟수만 배치한다. 알 수 없는 ID, 범위 중복·누락, 다른 페이지 ID는 거절한다.
- 장식은 별도 namespace와 허용된 SVG 요소로 제한한다. 장식 텍스트로 원문 밖 주장·수치·표지를 추가하지 않는다.

모델은 서버의 템플릿 layout 후보로 해결되지 않는 페이지에만 호출한다. 해당 페이지의 원문 문맥·그룹·측정값과 선택 템플릿 규칙, 실패한 영역 및 제약을 제공한다. ID와 글자 수만으로 배치를 결정하지 않는다. 원문 전체 재출력, 문서 전체 문맥의 반복 전송, 불필요한 이미지 base64 전달을 피한다. 모델 반환값도 템플릿 허용 범위를 벗어나면 게시하지 않는다.

### SourceBinding / PreservationReceipt

- 원본 ID·문자 범위·이미지 occurrence와 최종 SVG element ID의 대응표.
- source digest, resolved plan digest, 확정 SVG digest, 원본/출력 canvas, template snapshot/layout/규칙 버전, 실제 font digest/renderer 버전, 자산 manifest revision.
- 템플릿 적용 검사 결과는 내용 보존·geometry 검사와 별도로 기록한다. 공용 품질 receipt로 근거를 연결하며 증거가 없으면 release readiness를 통과 처리하지 않는다.
- 페이지 수·순서, 텍스트/표/이미지 보존 결과, DOM 실제 표시와 잘림 결과, 한계·오류 코드.
- SVG 허용 속성을 우회하는 `data-*`나 script를 추가하지 않고 sidecar를 사용한다. 변환 과정에서 ID가 바뀌면 변환 매핑을 보관한다.

## 4. 생성 절차

1. **접수 전 검사:** 계정·소유권, source mode/strategy/canvas 조합, 파일 크기·페이지 제한, 지원 객체를 확인한다. 원본 bytes는 변경하지 않는다.
2. **원본·템플릿 분석:** 기존 immutable manifest에서 원본 크기와 페이지 모델을 읽는다. 선택 템플릿을 한 번 해석하고 자산·글꼴·layout 지원 여부를 확인한 뒤 실제 사용 글꼴로 문단·표를 측정한다.
3. **입력 고정:** 원본 manifest/물리 크기, 선택 template snapshot, 출력 canvas, 글꼴 정책, 자산 slot, 규칙·solver·plan 버전을 job에 고정한다. 같은 작업의 재개에는 동일 입력을 사용한다.
4. **서버 우선 배치:** 원본 역할·그룹·내용량을 템플릿 layout slot에 배치하고 줄바꿈·크기·간격을 계산한다. 제한된 후보와 보정으로 해결되지 않는 페이지만 모델에 LayoutPlan을 요청한다. 정상 영역은 유지하고 문제 영역 중심으로 조정한다.
5. **결정적 SVG 조립:** 프로그램이 고정 원문·표·원본 이미지를 삽입한다. XML escape와 안전한 원본 slot 해석을 적용한다. 이미지 원본 비율과 crop 의도를 보존한다.
6. **보존·디자인·표시 검사:** 원문 범위·표·이미지·템플릿 규칙을 먼저 검사하고 확정 후보를 실제 렌더링한다. 통과한 페이지는 checkpoint와 미리보기로 제공한다.
7. **제한된 보정:** 서버에서 변경 영역의 줄바꿈·크기·위치를 보정하고 페이지 전체 제약을 재검사한다. 모델을 이미 사용한 경우 추가 모델 보정은 최대 1회로 제한한다. 최종 변경된 SVG는 반드시 다시 렌더링한다.
8. **확정·게시:** 전체 페이지가 완료 조건을 만족할 때 확정 SVG·receipt를 원자적으로 게시한다. 부분 미리보기를 완료 문서로 표시하지 않는다.
9. **내보내기:** 게시된 revision의 동일 확정 SVG와 자산으로 격리 worker가 PPTX를 생성한다. 내보내기에서 재저작·추가 레이아웃 보정을 하지 않는다.

취소·재개·operation lease와 fencing·idempotency는 기존 durable job 계약을 따른다. 완료된 페이지는 입력 digest가 일치할 때만 재사용한다. 출력 여부가 불명확한 provider 요청은 맹목적으로 중복 호출하지 않고 기존 복구 정책을 따른다.

복구 불가능한 실패가 확정되면 신규 페이지 dispatch를 중단한다. 모든 provider 응답이 끝날 때까지 실패 통지를 미루지 않는다. 실행 중 호출의 취소 가능 여부와 실제 결과를 별도로 기록하고 기존 fence로 늦은 결과의 게시를 막는다. 취소 신호를 실제 provider 처리 중단이나 비용 취소로 간주하지 않는다. 동일 호출의 결과가 불명확하면 자동 중복 구매하지 않는다.

### 서버 배치에서 모델로 전환하는 조건

모델 호출은 '복잡한 페이지'라는 주관적 분류로 결정하지 않는다. 원본 보존·템플릿 capability·글꼴·자산 검사를 먼저 통과하고 호출 예산과 남은 deadline이 있을 때, 아래 결과에 따라 전환한다.

| 서버 결과 | 처리 |
|---|---|
| 템플릿 layout 후보가 내용·디자인·geometry 조건을 충족 | 모델 호출 없이 확정 후보를 렌더·검증 |
| 호환되는 고정 layout 후보가 없지만 템플릿이 제약된 유연 배치를 지원 | `layout_candidate_unavailable` 사유로 모델 배치 요청 |
| 제한된 보정 후 실제 내용 넘침 또는 충돌이 남음 | `layout_overflow_unresolved` 또는 `layout_collision_unresolved` 사유로 문제 영역 중심 모델 요청 |
| 서버 후보 수·처리 시간 예산 소진 | `layout_search_budget_exhausted`를 기록하고, 템플릿이 모델 배치를 허용하며 별도 호출 예산이 남은 경우에만 전환 |
| 원문 ID/자산 손상, 템플릿 미지원, 글꼴 누락, 권한 오류 | 모델로 우회하지 않고 해당 단계에서 실패 |
| 전체 작업 deadline 또는 모델 호출 예산 소진 | 추가 호출 없이 페이지와 실패 이유를 알리고 종료 |

서버 후보 탐색에는 유한한 `max_layout_candidates`와 페이지별 `local_layout_budget_ms`를 필수로 고정한다. 후보 순서를 결정적으로 정하고 기존 후보당 최대 2회 보정 제한을 유지한다. 페이지 시간 상한과 남은 operation deadline 중 작은 값을 적용하며 취소 여부를 후보 사이에 확인한다. 기본 수치는 1·2페이지 선행 검증에서 측정해 명시한 후 capability를 활성화한다. 무제한 후보 탐색이나 암묵적인 모델 호출은 허용하지 않는다.

전환 기록에는 사유, 시도한 layout ID, 보정 횟수, 남은 위반 항목, 경과 시간, 사용한 모델 호출 예산을 포함한다. 부분 조정도 전체 페이지의 읽기 순서·템플릿 제약·보존 검사를 다시 통과해야 한다.

## 5. 원본 캔버스 맞춤과 검증

원문 누락·중복은 렌더링 성공과 별도로 검사한다. 프로그램이 원문을 삽입해도 잘못된 source ID, clip, 가려짐, 투명·화면 밖 텍스트로 내용이 숨을 수 있다.

| 항목 | 통과 조건 |
|---|---|
| 페이지 | 입력과 수·순서 일치; page ID 매핑 유지 |
| 캔버스 | 원본 물리 크기·비율 유지; 명시적으로 변경한 경우 그 선택과 출력 크기 일치 |
| 템플릿 | 선택 snapshot의 색상·실제 글꼴·제목 계층·배경·표/도형 스타일과 선택 layout 제약 적용; 임의 기본 스타일 대체 없음 |
| 텍스트 | 원문 범위가 누락·중복 없이 배치되고 문단/블록 내부 읽기 순서 유지 |
| 표 | 셀 값·행열·병합 구조 보존; 줄바꿈을 값 변경으로 취급하지 않음 |
| 이미지 | occurrence 기준 보존; 같은 이미지의 반복 등장도 별도 검사 |
| 표시 | 실제 글꼴로 렌더링했을 때 잘림·화면 밖 필수 내용·숨겨진 중복 없음 |
| SVG | 기존 정적 SVG 계약과 자산 소유권·digest 검사 통과 |
| PPTX | 페이지 수·물리 canvas·텍스트와 표 값·이미지 포함 여부 및 렌더링 확인 |

보정은 템플릿 허용 범위 안에서 slot 여백·간격, 그룹·열·표 배치, 원문 그대로의 줄바꿈, 글꼴 크기 순으로 조정한다. 좌표도 조정할 수 있어야 하며 템플릿의 제목 계층·정렬·필수 디자인 요소를 제거해 통과시키지 않는다. 승인된 Composer의 7 CSS px 정책을 일반 SVG 전체에 자동 전파하지 않는다. 적용 정책 ID·단위·canvas 변환을 고정하며 별도 SVG 글꼴 하한 변경은 확정하지 않는다.

모든 content box의 교차를 곧바로 오류로 간주하지 않는다. 템플릿의 허용된 배경·장식·레이어와 텍스트 박스의 빈 여백을 구분하고, 실제 필수 내용의 가려짐·글자 충돌·잘림을 검증한다. 실제 충돌은 허용 이동 범위에서 보정하고 변경 후 다른 영역의 충돌도 확인한다. 4px라는 크기만으로 충돌을 면제하지 않는다.

기존 원본 보존 정책에 허용된 표시상 정규화만 버전으로 명시해 사용한다. 임의 공백 제거·구두점 삭제로 누락을 감추지 않는다. 원본 도형 순서와 의미 읽기 순서를 무조건 동일하게 강제하지 않는다.

정해진 시도 안에 해결되지 않으면 페이지·블록·실패한 제약과 해결 행동을 표시한다. 요약·삭제·페이지 확장, 원본 디자인 복원, 일반 스타일 또는 HTML/이미지 방식으로의 조용한 대체는 하지 않는다.

### 템플릿 적용 자동 검사와 시각 검토

전체 페이지의 원문·표·이미지·A4 크기 외에 실제 사용 색상, 로드된 글꼴, 제목 계층, 정렬·여백, 필수 배경·장식, 표·도형 스타일, 선택 layout 제약을 자동 검사한다. 사용되지 않은 스타일 선언이나 template ID만으로는 적용 증거가 되지 않는다. 필요한 template 규칙을 생략했으면 이유와 적용 가능 여부를 명시한다.

규칙 통과는 디자인 품질의 충분조건이 아니다. 선택 템플릿의 참조 렌더와 실제 A4 결과를 비교해 시각적 계층·구성·가독성·디자인 특징의 유지 여부를 검토한다. 다른 내용과 다른 캔버스에 적용하는 작업이므로 픽셀 단위 동일성을 완료 조건으로 삼지 않는다. 대표 검토 대상에는 기존 실패 1·2페이지와 전체 문서의 가장 조밀한 텍스트, 복잡한 표, 이미지 중심 및 사용한 각 layout 유형을 포함한다. 동일 페이지가 여러 유형을 대표할 수 있다.

자동 검사와 시각 검토 결과는 분리해 기록한다. 필수 검토가 미실시이면 완료로 간주하지 않고, 미흡한 페이지의 규칙·배치 또는 템플릿 정의를 수정한 뒤 영향받는 항목만 다시 확인한다.

## 6. 성능 설계

- 분석 캐시는 소유권/tenant, 파일 digest, parser·manifest 버전을 키로 한다. 타 사용자 자료를 전역 파일 해시만으로 재사용하지 않는다.
- 템플릿 캐시는 registry 권한과 ID·버전·자산 digest·규칙 추출 버전을 묶는다. A4용 변형은 출력 canvas와 layout solver 버전을 추가한다. private 템플릿을 타 사용자에게 재사용하지 않는다.
- 측정 캐시는 실제 font file digest, fallback 결과, 크기·서식·언어·문단 폭·renderer 버전을 포함한다. 글꼴이 바뀌면 무효화한다.
- 페이지별 병렬 처리는 기존 provider rate limit과 worker 예산 안에서 제한한다. 초기 제안은 모델 동시 2페이지, 렌더 동시 1페이지이며 실제 수치는 측정 후 조정한다.
- 서버 layout 후보를 정해진 작은 수로 평가하고 결정적 보정은 후보당 최대 2회로 제한한다. 정확한 후보 수·CPU 예산은 구현 시 명시하고 측정한다. 해결된 페이지는 모델 호출 0회다. 미해결 페이지만 모델 계획 1회, 필요 시 모델 보정 최대 1회를 허용한다. provider 전송 재시도와 콘텐츠 보정을 구분하고 기존 전체 operation deadline 및 남은 페이지 예산이 우선한다.
- 텍스트 누락 등 결정적으로 실패할 조건은 렌더 전에 검사한다. 변경된 페이지만 다시 렌더하고 미리보기·확정 검사가 같은 렌더를 재사용할 수 있게 receipt를 연결한다.
- 모든 페이지 PNG·이미지 bytes를 동시에 메모리에 보유하지 않는다. 자산 참조와 제한된 페이지 batch를 사용하고 기존 취소·정리 lifecycle을 따른다.
- 원문·템플릿·canvas·font·자산·solver·renderer 입력 digest가 같은 검증 완료 페이지만 재사용한다. 원문 또는 템플릿이 바뀌면 영향받는 측정·배치·렌더 캐시를 무효화한다. v1 문자 위치 계약의 실패 checkpoint를 v2 계획으로 그대로 재개하지 않는다.
- HTML 방식보다 빠르다는 보장은 하지 않는다. 모델 응답량 감소가 추가 측정·검사 비용을 상쇄하는지 실제 입력으로 확인한다.

성능 기록은 템플릿 분석 시간, 서버만으로 완료한 페이지 수, 모델을 사용한 페이지 수와 이유, 첫 검증 완료 페이지 시간, 전체 게시 시간, export 시간, 페이지별 모델 실제 호출/재시도, 렌더 횟수, token usage가 제공된 경우의 사용량, peak memory, cache hit, queue wait를 분리한다. 관측할 수 없는 provider 내부 호출 수는 추정값으로 채우지 않는다.

초기 비교는 동일 원본·스타일·canvas·모델·동시성으로 수행하고 cold/warm cache를 구분한다. 작은 자료와 이번 실제 원본을 대상으로 측정하며, 대형 자료 측정은 별도 승인된 범위에서 수행한다. 정량 latency 목표는 baseline 없이 임의 확정하지 않는다. 보존 검사 통과를 속도 때문에 완화하지 않는다.

## 7. 화면과 오류 처리

- 선택: `원본 콘텐츠 유지` + `SVG` + 선택 템플릿. 분석 후 `원본 크기 · A4 가로`와 선택 템플릿명을 표시한다. 분석 전에는 원본 크기를 확인 중으로 표시한다. 설명은 ‘원문·표·이미지와 원본 크기를 유지하고 선택한 템플릿 디자인을 적용합니다’로 한다.
- 진행: 원본·템플릿 분석 → 템플릿 배치 → 필요 페이지 모델 보정 → SVG 검사 → 완료. 검증 완료 수와 현재 작업 페이지·단계·경과 시간을 분리한다. heartbeat와 모델 응답 수신 상태를 구분하며, 경과 시간만으로 진행률을 만들어내지 않는다.
- 생성 중: 기존 전체 채팅 흐름에서 검증된 페이지 미리보기를 제공한다. 완료되지 않은 문서는 export를 활성화하지 않는다.
- 완료 후: 왼쪽 PPT, 오른쪽 채팅을 유지한다. 모바일은 기존 PPT/채팅 탭을 사용한다.
- 오류: 원본 분석/템플릿 적용 불가/모델 응답/배치 계획/내용 보존/geometry·글꼴/브라우저 측정/export를 구분한다. 렌더 전 검사 실패를 렌더 실패로 포장하지 않는다. 서버 실패가 확정되면 대기 표시를 종료한다. 사용자에게 페이지와 해결 행동을 제공하고 내부 JSON은 상세 진단으로 분리한다.
- 재시도: 같은 입력으로 실패 단계·페이지만 재개한다. A4 전환·템플릿 변경·계약 v2 전환은 새 job 입력 identity로 처리하고 원본 분석 등 독립 캐시만 재사용한다. 실패한 16:9 job의 설정을 제자리에서 바꾸지 않는다.
- ‘편집 가능’ 표시는 내보낸 텍스트·표·도형별 검증 범위를 명시한다. SVG 기반이라는 이유로 모든 원본 개체의 native editability를 보장하지 않는다.

## 8. 구현 순서와 완료 기준

1. 원본 canvas와 선택 템플릿 identity를 UI·admission·checkpoint·export까지 연결하고 A4를 지원한다. 템플릿 layout/자산/글꼴 capability를 먼저 정의한다.
2. 문서당 한 번의 템플릿 분석·캐시와 서버 우선 layout 선택을 구현한다. LayoutPlan v2에서 모델 문자 위치 필드를 제거하고 서버 계산으로 대체한다.
3. 템플릿 제약을 유지하는 위치·크기 보정과 필요한 페이지에만 모델을 사용하는 경로를 구현한다. 실패 통지·호출 정리·부분 checkpoint 복구를 연결한다.
4. 내용 보존·템플릿 적용·geometry의 증거를 확정 SVG 및 공용 품질 receipt에 연결하고 PPTX readback을 유지한다.
5. 개발 capability 아래에서 사용자 원본 30페이지의 A4 생성·템플릿 적용·export·성능을 검증한 뒤 지원 조합을 활성화한다. 일반 SVG/Authored 경로는 유지한다.

검증은 다음 두 단계로 진행한다.

1. **기존 실패 1·2페이지 선행 검증:** 같은 원본의 페이지 ID·내용·A4 크기와 사용자가 선택한 템플릿을 고정한다. 문자 위치 오류 제거, 실제 겹침 보정, 템플릿 디자인 적용, 렌더·PPTX readback, 템플릿 분석/서버 배치/모델 대기/렌더/export 시간을 확인한다. 서버로 해결된 페이지는 모델 호출 0회임을 확인하고 호출한 페이지는 위 전환 사유를 기록한다. 이 단계에서 서버 탐색 상한을 정하고 실제 값을 실행 증거에 남긴다.
2. **전체 30페이지 인수:** 선행 검증을 통과한 동일 생성·내보내기 경로로 확장한다. 모든 페이지의 내용·캔버스·템플릿 규칙을 자동 검사하고 대표 고밀도 페이지와 layout 유형을 실제 렌더로 검토한다. 전체 게시·다운로드 및 cold/warm cache 성능을 기록한다.

1·2페이지는 개발 검증용 부분 결과이며 사용자 30페이지 문서의 완료본으로 게시하지 않는다. 전체 실행에서는 30페이지 수·순서 계약을 그대로 유지한다. 2페이지 통과를 30페이지 성공이나 속도 보장으로 확대 해석하지 않는다.

각 변경 레이어에 가장 좁은 테스트를 선택한다. 기존 실패 응답의 문자 위치 오류와 4px 겹침, A4 물리 크기, 템플릿 규칙 적용/위반, 서버만으로 해결한 페이지의 모델 호출 0회, 실패 후 신규 dispatch 중단, 늦은 응답 게시 거부를 검증한다. 기존 ID 누락/중복·타 페이지 참조, 다중 등장 이미지, 표 병합, 한글/영문, 고밀도 페이지, 잘못된 자산, cache/checkpoint 입력 불일치 검사를 보존한다.

제품 인수는 이번 사용자 원본 30페이지를 보존한 별도 A4 문서로 수행한다. 서버 자동 배치와 실제 필요한 모델 경로, 전체 페이지의 내용·캔버스·템플릿 규칙 검사, 다운로드 가능한 PPTX, 원본과의 내용·페이지 대조, 선택 템플릿과 대표 어려운 페이지의 디자인/렌더 비교, 성능 기록이 필요하다. 내용만 보존하고 선택 템플릿 디자인이 적용되지 않으면 실패다. 공용 품질 receipt의 미연결 증거도 해결해야 완료로 판단한다. 1페이지 smoke나 mock만으로 전체 인수를 완료하지 않는다. 알려진 미지원 객체·편집성 한계는 결과에 명시한다.

## 9. 남아 있는 설계 조정 항목

- 해당 SVG 경로에 적용할 글꼴 정책 ID와 원본 크기/최소 크기 해석.
- 최초 지원할 선택 템플릿의 layout/허용 변형 목록과 검증 근거를 채우고, 1·2페이지 측정으로 서버 후보 수·시간 상한의 실제 값을 확정한다. 이 항목은 해당 capability 활성화의 선행 조건이다.
- 실제 원본의 지원 객체 목록과 표·차트의 native PPTX 편집성 범위.
- baseline 측정 이후 동시성·메모리·deadline 및 성능 목표 수치.

이 항목들은 원본 내용 불변, 페이지 대응, 모델의 배치 전용 역할, 확정 SVG의 export 재사용이라는 핵심 계약을 변경하지 않는다.

## 10. 개정 이전 1차 구현 및 검증 이력

아래는 16:9·페이지별 모델 호출·Pretendard 고정 방식의 과거 구현 이력이다. 이번 개정의 구현 완료 근거가 아니며 상충하는 동작은 1~9절에 따라 수정해야 한다.

- UI와 서버 admission에 PPTX 원본 콘텐츠 유지 + SVG + 가로 16:9를 연결했다. 같은 snapshot도 실행 시 새 extractor 버전으로 재분석한다.
- 원문을 모델이 재작성하지 않도록 배치 계획과 결정적 SVG 조립을 분리했다. 표 병합, 이미지 등장 횟수, 페이지 대응과 receipt를 검사한다.
- 숫자로 확정된 사용자 정의 도형 경로와 직선 연결선을 지원한다. 곡선 평탄화 오차 상한은 대상 크기에서 0.25 CSS px다. 실제 사용자 원본 30페이지는 새 추출 결과의 사전 검사를 통과했다. 이는 전체 생성 통과가 아니다.
- Pretendard Regular/Bold 실제 파일 digest를 측정·checkpoint·렌더 입력에 고정한다. 일반 HTML admission 이후 worker가 검증한 고정 글꼴만 주입하며, 임의 font URL/CSS 허용 범위는 늘리지 않는다.
- 모델 페이지 동시성 2, 렌더 동시성 1, 배치 시도 최대 2회를 적용했다. PNG는 게시 시 한 장씩 읽는다. 처리 시간 개선이나 peak memory는 아직 측정하지 않았다.
- 검증된 SVG에는 게시 단계에서 페이지 번호를 추가하지 않는다. 원본 보존 문서의 페이지 삭제·재정렬 또는 receipt 훼손을 거부한다.
- source 전용 export bundle과 PPTX 텍스트·표 셀 값·이미지 readback을 추가했다. 표 셀은 텍스트/도형이며 native table 편집성은 보장하지 않는다.
- 원본 추출 이미지를 일반 이미지 디렉터리로 해석하던 실제 export 연결 오류를 수정했다. 원본 보존 receipt, 소유자, SVG 자산 manifest, 이미지 occurrence와 실제 해시를 확인한 뒤 봉인된 DB 이미지 bytes를 읽는다. 일반 파일 경로 허용 범위를 늘리지 않는다.
- 좁은 자동 검증: source layout 21, generation/render 4, publication 7, export receipt/readback 1, UI 7건 통과. 상태 메시지 수정은 구문 검사로 확인했다.
- 이미지 export 연결 수정은 실제 생성 문서의 읽기 전용 검증으로 확인했다. 정상 봉인 이미지 읽기 1건과 잘못된 자산 해시·manifest 해시·occurrence·페이지·다른 소유자 거부 5건이 통과했다.
- 실제 export에서 발견한 v3 bundle 전달부 누락을 수정했다. v2와 동일한 소유권·자산·operation 검사를 거쳐 v3 자산을 전달하며, v2/v3 transport 좁은 테스트 2건이 통과했다.
- 실제 합성 PPTX 1페이지의 업로드→분석→모델 배치→SVG 조립→Chromium 검증→게시가 통과했다. 원문·표 셀·이미지 7개 binding과 rendering receipt를 저장된 결과에서 확인했다.
- 같은 생성 결과의 PPTX export 작업이 성공했고, 33,564 bytes의 1페이지 파일을 실제 다운로드해 열었다. worker의 source-preservation readback은 원문·표 셀 값·이미지 보존 검사를 통과했다. 검증 문서 ID는 `8477819e-b8e7-4045-9e49-f50ae0397ffa`, 최종 export operation은 `3ae9e249-9807-4ad3-b7ac-b3811f0d1a8b`다.
- 기존 공용 quality receipt의 releaseReadiness는 여전히 blocked다. 공용 authoring/geometry 증거 변환·시각 품질 검토와 사용자 원본 전체 제품 인수를 완료한 것으로 표시하지 않는다. 전용 SVG source/render receipt와 export readback 통과만 확인했다.
- 차트, 일부 이미지 효과·자르기·회전, 그림 글머리표, 이미지뿐인 페이지, 해석할 수 없는 도형 수식은 1차 구현에서 지원하지 않는다. 이 1페이지 검증 당시에는 사용자 30페이지 전체 실행이 미실시였으며, 이후 실행의 실패 결과는 11절에 기록한다. 전체 제품 인수는 완료되지 않았다.

## 11. 개정의 근거가 된 실제 원본 실행

30페이지 원본의 생성 실행은 2026-09-22 21:07:02~21:21:26 KST에 약 14분 24초 동안 진행됐고 0/30페이지 완료로 실패했다. 원본 slideSize는 10691813×7559675 EMU로 A4 가로에 해당하나 요청은 16:9였다.

- 1페이지 첫 응답은 8글자 원문의 끝 위치를 9로 지정했다. 재시도에는 텍스트 박스 2개가 세로 4px 겹쳤다.
- 2페이지 첫 응답은 문자 범위 오류 7건, 재시도는 3건이었다. 배치 항목은 163개였고 기록된 호출 경과 시간은 약 439초·392초였다. provider 내부 처리 시간으로 단정하지 않는다.
- 원인: 모델이 문자 위치를 계산하고 서버가 이를 자체 보정 전에 거부했다. 로컬 보정은 좌표를 조정하지 않았으며 페이지 task 전체를 기다린 뒤 실패를 반환했다. 렌더 전 검사 오류도 일반 렌더 실패로 분류됐다.
- 이 기록은 개정 전 구현의 실패 근거다. A4 비율 차이가 문자 위치 오류의 직접 원인이라고 단정하지 않으며 새 설계의 속도·성공을 입증하지 않는다.

## 12. 개정 구현과 검증 범위

- 원본 manifest의 slideSize에서 캔버스를 결정하고, 원본의 정확한 EMU와 canvas digest를 작업·재개·게시·내보내기에 전달한다. 화면에서 원본 유지 작업에 16:9를 강제하지 않는다. 초기 지원은 A4 가로다.
- 선택된 `default` 또는 `osb-smart-banking`의 등록 정의·exemplar·Noto Sans KR 실제 파일 digest를 템플릿 snapshot에 묶는다. 선택 실패를 다른 기본 템플릿으로 숨기지 않는다. 일반 SVG의 기존 글꼴 정책은 유지한다.
- 공개 모델 계획 `svg-source-layout/v2`는 문자 끝 위치를 받지 않는다. 서버가 원문에서 줄바꿈을 계산하고 실제 글꼴 ascent/descent로 baseline과 줄 간격을 정한다. A4 변환 후 소수점 오차로 하한에 미달하지 않도록 적합 글꼴 크기는 위로 양자화한다.
- 서버 배치는 페이지별 후보 최대 3개, 후보당 보정 최대 2회, 탐색 1,500ms 예산을 사용한다. 원본 검증·글꼴 준비 시간은 별도로 기록한다. 동일 작업에서 검증한 manifest tuple을 다시 사용하지만 사용자 간 가변 전역 manifest 캐시는 만들지 않는다.
- 서버에서 해결된 페이지의 모델 호출은 0회다. 허용된 배치 부족·미해결 넘침·충돌·탐색 예산 소진에만 모델 계획 1회와 보정 최대 1회를 허용한다. 템플릿·글꼴·원본 계약 오류는 모델로 우회하지 않는다.
- 최종 페이지 실패 시 형제 task 대기를 취소하고 늦게 도착한 결과를 게시하지 않는다. 전송된 provider 호출이 실제로 중단됐다고 간주하지 않으며 기존 inflight checkpoint를 유지한다.
- 내보내기는 템플릿 digest·배치 ID·실제 렌더 증거와 저장된 SVG digest를 연결해 검사한다. source v2 증거를 v1으로 낮춰 템플릿 검사를 건너뛰는 경로도 거부한다. 공용 품질 receipt는 자동 검증과 시각 검토·전체 인수를 구분한다.
- 접수 실패 기록은 아직 만들어지지 않은 source canvas/style pin을 요구하지 않는다. 원래 소유자·manifest 오류를 다른 오류로 덮지 않고 내부 재접수 표식을 유지하며, 정상 생성 경로는 모든 pin을 계속 요구한다.
- 검증 완료: 캔버스 계층 44건, 업로드 화면 상태 3건, 접수 실패 기록 1건, 원본 배치 28건, 생성 흐름 7건, 템플릿·글꼴 규칙 5건, 내보내기 품질 증거 5건.
- 실제 원본 1페이지의 최종 40개 binding 결과는 모델 호출 없이 생성됐고 Chromium 측정·기하 검사 모두 통과했다. 최초 시각 검토에서 발견한 과도한 도형·이미지 크기와 작은 본문을 보정했다. 전체 템플릿 시각 인수를 완료한 것으로 표시하지 않는다.
- 실제 원본 2페이지는 후보 3개·보정 6회 후 `layout_overflow_unresolved`로 모델 전환이 필요했다. 마지막 직접 검사에서 원본 검증·글꼴 준비 약 656ms, 서버 탐색 약 344ms였으며 모델은 호출하지 않았다. 이는 전체 생성 latency가 아니다. 이 페이지의 실제 모델 생성·렌더·export 통과는 미확인이다.
- 실제 1페이지의 격리된 PPTX 변환에서 정확한 EMU와 정수 픽셀 사이 반올림 차이를 거부하던 오류를 수정했다. 비레거시 변환에만 논리 높이 0.5px 이내 오차를 허용하고 물리 크기는 원본 그대로 기록한다. 재현 가능한 compatibility patch·vendor hash·변환기 버전을 함께 갱신했으며 관련 좁은 회귀 검사 1건이 통과했다.
- 동일한 최종 1페이지 SVG의 격리 PPTX 변환·readback이 통과했다. 출력 149,949 bytes, native text run 23개이며 원문·이미지 readback을 확인했다. 이는 오프라인 부분 변환 검증이며 전체 제품 업로드→생성→게시→다운로드 인수를 대신하지 않는다.
- PPTX 변환기는 Noto Sans KR 글꼴 이름과 물리 크기로 변환한 글꼴 크기를 기록한다. 현재 경로는 글꼴 파일을 PPTX에 임베딩하지 않으므로 설치 글꼴이 다른 뷰어의 동일한 표시 결과까지 검증한 것은 아니다.
- 기존 실패 작업의 재개, 실제 원본 30페이지 전체 생성·내보내기, 전체 성능 비교가 통과한 것으로 취급하지 않는다. 부분 검증 결과를 완성된 30페이지 문서로 게시하지 않는다.
