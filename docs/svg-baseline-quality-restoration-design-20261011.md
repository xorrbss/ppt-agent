# 기준 PPT보다 좋은 웹 생성 결과를 위한 디자인 품질 복구 설계

작성일: 2026-10-11. 상태: **설계 작성 완료, 구현·서버 적용·실제 개선 결과 미완료**.

사용자가 지정한 기준 PPT의 현재 결과를 최소 품질 기준으로 삼는다. 품질이 첫 번째 목표이고, 필수 품질을 충족한 최종 PPTX까지의 시간이 두 번째 목표다. 이번 작업의 범위는 설계 문서이며 코드 변경, 서버 재시작, 제공자 호출, 기존 실패 작업 재시도, DB 변경, 게시·배포를 포함하지 않는다.

이 문서는 [2026-10-08 자유 설계·품질 복구 설계](svg-quality-first-free-design-recovery-20261008.md)를 보완한다. 이미 있는 작성·참고자료 선택·검토·수정 기능을 다시 만들지 않는다. 기존 설계와 구현 현황에 적힌 기능의 존재를 실제 디자인 개선으로 인정하지 않는다.

## 3. 성공 기준

### 반드시 유지할 조건

- 원본의 필수 문구·사실·수치·단위·표·차트·이미지 그룹과 설명의 바인딩을 유지한다. 누락·왜곡·글자 축소로 여백을 확보하지 않는다.
- 사용자가 선택한 출력 캔버스와 원본 보존 계약을 유지한다. A4 작업을 기준의 16:9로 자동 변경하지 않는다.
- 요청한 표지·목차·페이지 수·순서·스타일·이미지 처리 조건을 우선한다. 모든 페이지를 본문으로 전달한 원인이 사용자 조건인지 입력 손실인지 먼저 구분한다.
- 기준 결과 수준의 가독성과 편집형 PPTX 구조를 유지한다. 지원 SVG·native 데이터·폰트·내보내기 계약을 우회하지 않는다.

### 디자인 개선의 판단

같은 자료와 같은 캔버스의 기준/후보를 함께 보고 다음을 `개선 / 동등 / 악화 / 미판정`으로 기록한다. 모델의 자의적인 총점 하나로 채택하지 않는다. 전후 화면은 A/B로 제시하고 평가자에게 버전명·생성 순서를 노출하지 않는다. 좌우 배치는 기록하되 결과 선택의 근거로 사용하지 않는다.

| 평가 축 | 실제 확인할 내용 |
| --- | --- |
| 메시지·위계 | 중요한 주장이나 근거를 바로 찾을 수 있는가. 제목·주장·설명·주석이 구분되는가. |
| 정보 구조·시각화 | 비교·순서·관계·수치를 원본에 맞는 표현으로 읽기 쉽게 전달하는가. 설명을 박스에 담기만 한 결과에서 개선됐는가. |
| 이미지·도표 활용 | 필요한 세부가 보이는 크기인가. 캡처·도표와 설명의 관계가 명확한가. 원본이 허용한 범위에서만 크롭·확대하는가. |
| 밀도·균형 | 읽을 수 있는 크기, 한국어 줄바꿈, 적절한 여백과 시각적 중심이 확보됐는가. |
| 덱의 흐름·반복 | 내용상의 비교를 돕는 반복과 무의미한 동일 구도를 구분하는가. 스타일 일관성과 페이지 변화가 함께 유지되는가. |

기존 검토의 통과는 최소 화면·디자인 조건이다. 이 기준보다 좋아졌다는 증거는 별도로 필요하다. 기준과 동등한 결과만 얻었다면 품질 유지로 보고하고 개선 완료라고 하지 않는다. 내용·가독성·편집성의 중대한 악화가 있으면 미채택한다. 핵심 평가가 미판정이면 개선을 확정하지 않는다.

각 비교에는 페이지·평가 축·문제가 있는 실제 영역·원본 근거·변경 내용·개선 이유를 남긴다. 기존 리뷰 호출 안에서 전후 이미지를 함께 평가하고, 원 저자의 자기 설명만으로 판단하지 않는다. 결론이 모호하거나 배치 편향이 의심되는 경우에만 승인된 비교 호출 한도 안에서 순서를 바꿔 확인한다. 모든 페이지를 기본 두 번 평가하지 않는다. 불일치가 남으면 미판정으로 보고한다.

후속 신규 자료는 내용이 다른 기준 페이지와 수치나 배치의 일치를 요구하지 않는다. 기준에서 확인한 위계·의미 있는 시각화·가독성 수준을 적용한다. 다른 스타일에 OSB 팔레트나 동일 모티프를 강제하지 않는다.

## 4. 퇴행 조사와 변경 경계

첫 단계는 기준과 현재 작업의 실제 작성 입력을 비교하는 것이다. 현재 저장소 HEAD는 `7612d3c5b62d6455ca415c40405ac0e946cd625c`이며 미커밋 변경과 실행 중 서버의 로드 상태가 같다고 가정하지 않는다. 원래 잘 작동한 경로를 확인하기 전에는 롤백이나 전면 교체를 결정하지 않는다.

| 조사 대상 | 확인 질문 | 확인 후 변경 범위 |
| --- | --- | --- |
| 원본과 페이지 역할 | 표지 조건·원본 순서·의미가 작성 입력까지 전달됐는가 | 누락된 입력 연결과 의미 전달만 수정. 자동 표지 추가·재분류 금지 |
| 디자인 지침 | 스타일의 위계·강조·이미지 처리 원칙이 실제 프롬프트에 있는가 | 의도와 시각적 특성을 전달. 위치·열 수·박스 수를 강제하지 않음 |
| 참고자료 선택 | native 데이터나 수치 표현이 다른 의미를 덮어 data 선택을 지배하는가 | 원본 의미에 맞는 복수 참고와 선택 이유 보완 |
| 시각 의도 | 제목·문자 수·키워드 휴리스틱이 실제 핵심 메시지와 밀도를 충분히 표현하는가 | 실제 원문과 바인딩에 근거한 강조·관계 보완 |
| 검토·후보 선택 | 평범하지만 passed인 결과가 개선 대상에서 빠지는가 | 디자인 미달 발견과 비교 근거를 기존 평가·선택에 연결 |
| 캔버스·내보내기 | 공간·서체·변환 때문에 차이가 생기는가 | 동일 캔버스에서 분리 검증. 원본·출력 비율 자동 변경 금지 |

현재 `visual_intent.py`는 첫 제목/줄, 문자 수와 정규식으로 위계·밀도·흐름을 추정한다. `reference_selection.py`에는 이미 복수 참고 역할 선택이 있다. `quality.py`에는 실제 후보 비교와 위계·구조·브랜드·밀도·반복 평가가 있다. 특히 기존 비교는 실패 축이 없으면 `no_targeted_defect`로 이전 후보를 유지한다. 이것은 무근거 교체를 막는 동작이지만, 통과한 평범한 결과를 더 좋게 만드는 전체 목표를 대신하지 못한다.

추정 원인은 사실과 분리해 기록한다. 예를 들어 숫자·메타데이터 때문에 참고자료가 편중됐다는 주장은 실제 선택 basis와 원문을 대조한 뒤 확정한다. 문서의 분포만 보고 규칙을 삭제하지 않는다.

## 5. 기존 작성 경로의 입력 개선

### 덱 방향과 페이지 메시지

기존 개요·content brief·사용자 지시·선택 스타일을 활용해 공통 디자인 방향을 기존 작성 입력에 전달한다. 전달 내용은 발표 목적, 청중, 원본에서 강조할 주장·근거, 정보량, 읽는 흐름과 스타일 원칙이다. 기존 단계에서 이미 알 수 있는 내용을 얻기 위해 별도 LLM 계획 호출을 기본 추가하지 않는다.

페이지별 입력에는 현재 원문, 실제 이미지 그룹, native 데이터, 강조할 원문 근거, 필요한 관계·순서, 인접 페이지의 역할을 전달한다. 이는 작성 조언이며 좌표·배치 계열·도형 목록을 만드는 중간 표현이 아니다. 기존 `visual_intent`를 활용하고 Deck-IR·별도 blueprint·레이아웃 배정표를 만들지 않는다.

주제명만 있는 제목 아래 긴 설명을 나열하는 대신, 원본에 핵심 주장이 있으면 그 주장이 잘 보이도록 한다. 원 제목과 문구가 필수 보존 대상이면 그대로 유지한다. 원문에 없는 요약 주장이나 관계를 새로 만들어 넣지 않는다.

### 첫 작성에 실제로 전달할 내용

| 작성 입력 | 만들거나 확인할 근거 | 모델에 전달할 책임 |
| --- | --- | --- |
| 핵심 메시지 | 사용자 지시·기존 개요·페이지 원문에 있는 주장이나 결론 | 어떤 메시지를 먼저 읽게 할지 분명하게 한다. 근거가 없으면 주제와 사실을 그대로 사용한다. |
| 중심 근거 | 해당 메시지를 뒷받침하는 실제 문구·수치·이미지·관계 | 근거의 상대적 중요성을 드러낸다. 모든 단락에 동일한 시각적 무게를 주지 않는다. |
| 내용 관계 | 원본에서 확인되는 비교·순서·포함·연결·수치 구조 | 관계가 읽히도록 표현한다. 원본이 뒷받침하지 않는 화살표·단계·축은 만들지 않는다. |
| 이미지의 핵심 부분 | 원본 이미지 그룹·설명·허용된 크롭 조건 | 필요한 세부가 판독되는 비중을 확보하고 관련 설명을 함께 배치한다. |
| 참고를 사용하는 이유 | 현재 내용과 연결되는 참고의 위계·강조·관계·이미지 처리 특성 | 필요한 디자인 특성을 활용하고 예시의 문구·값·구도를 그대로 복사하지 않는다. |
| 덱 문맥 | 기존 인접 페이지와 실제 비교·연속 관계 | 의도적인 반복을 유지하고 불필요한 같은 강조·읽는 흐름을 줄인다. |

위 내용은 기존 개요·원문·참고 선택을 작성 프롬프트에 연결하는 요구다. 필드마다 새 LLM 추출 호출을 만들거나 별도 계획 데이터를 생성하지 않는다. 구현 검증은 작성 지침의 존재가 아니라 해당 페이지의 원문 근거와 실제 제공자 입력의 대응을 확인한다. 내용 관계를 키워드만으로 확정하지 않으며, 수치·표가 있다는 이유만으로 나머지 강조·이미지 맥락을 덮지 않는다.

### 참고자료와 자유 작성

- 선택 스타일의 브랜드·서체 위계·강조·이미지 처리는 유지 요구로 전달한다. 기하·카드 수·열 수·모티프 위치는 LLM이 결정한다.
- 표·숫자가 있다는 이유만으로 페이지 전체를 데이터 표현으로 제한하지 않는다. 비교·순서·관계·이미지 설명이 함께 있으면 관련 참고와 설명을 함께 제공한다.
- 참고는 디자인 증거다. 예시의 회사명·문구·수치·관계를 현재 자료로 복사하지 않는다.
- 참고 역할의 개수나 동일 박스의 수를 품질 지표로 삼지 않는다. 의미와 출력 조건에 맞게 고른 실제 예시를 제공한다.
- 원본 이미지와 디자인 예시의 입력 예산을 구분한다. 이미지 2개 제한을 두지 않으며 그룹 구성원과 설명 그룹 수를 혼동하지 않는다. 요청 용량을 넘으면 원본을 조용히 생략하지 않는다.
- 원본이 PPT가 아니어도 동일 원칙을 적용한다. 문서·PDF·캡처에서 확인된 사실·관계·이미지 묶음을 기존 원본 처리 계약으로 전달한다.

## 6. 디자인 검토와 반복 개선

기존 평가 축과 리뷰 경로를 보완한다. 숫자 총점, 박스 종류 수, 임의의 패턴 할당을 새 완료 조건으로 추가하지 않는다.

| 문제 | 검토 근거 | 다음 처리 |
| --- | --- | --- |
| 원본 누락·숫자 오류·화면 깨짐 | 실제 원본과 렌더의 구체적 불일치 | 보존·화면 오류 수정. 디자인 개선 근거와 구분 |
| 화면은 정상이나 의미 없는 설명 나열·약한 강조 | 현재 원문에서 중요 근거를 찾기 어려운 위치·크기·관계 | 해당 페이지 전체 자유 재작성 |
| 작은 캡처·평면적인 관계 표현 | 필요한 세부·연결을 판독하기 어려운 실제 영역 | 원본 계약 안에서 이미지 비중·설명·관계 표현 재설계 |
| 불필요한 구성 반복 | 핵심 영역·이미지/텍스트 비중·읽는 흐름의 반복과 내용상 반복 근거 부족 | 잘 나온 대표 페이지 유지, 부족한 페이지 선택 재작성 |
| 의도적인 비교·연속 자료 | 같은 지표·항목·절차를 비교하는 실제 원본 관계 | 공통 구도 유지 가능. 나머지 디자인 평가 계속 수행 |
| 기준보다 평범한 결과이나 기존 검사 passed | 같은 내용/캔버스의 비교에서 확인한 위계·시각화·밀도 부족 | 기존 디자인 축에 구체적인 미달 근거와 수정 목표 연결 |
| 평가 불명확·증거 부족 | source/PNG·참고·컨텍스트 연결이 확인되지 않음 | 미판정. 무근거 재작성·자동 통과·성과 확정 금지 |

구성 관찰은 반복 후보를 찾는 신호다. 동일 팔레트·폰트·로고·머리말은 브랜드 일관성이므로 반복 결함으로 보지 않는다. 박스 이름이 달라도 실제 구도와 읽는 흐름이 같으면 반복 후보로 본다. 인접 페이지와 덱 전체를 함께 보되, 모든 페이지 쌍에 제공자 호출을 만들지 않는다.

비교라는 단어 하나로 반복을 면제하지 않는다. 반대로 일정·동일 지표 시리즈에 무조건 다른 구도를 요구하지 않는다. 원본 관계와 시각 판단을 함께 남긴다.

검증된 대체 SVG는 이미 승인된 화면 깨짐 복구 범위에서만 고려한다. 디자인이 평범하다는 이유로 고정 템플릿으로 교체하지 않는다. 기준 PNG는 검증된 대체 SVG로 승격하지 않는다. 이번 단계에서 대체 레이아웃 카탈로그를 새로 구축하지 않는다.

### 정상 화면의 디자인 미달을 재작성으로 연결

화면·원본의 유효성과 디자인 개선 필요성을 별도로 판정한다. 기존 passed/failed 이력은 보존한다. 신규 정책의 현재 검토에서 구체적 디자인 미달이 확인되면, 기존 평가 축 안에서 수정 대상·근거 영역·개선 목표를 추가로 기록한다. 이는 좌표 배정이나 공개 작업 상태가 아니다.

| 현재 화면/원본 | 현재 디자인 판단 | 작성 결정 |
| --- | --- | --- |
| 유효 | 기준 충족, 구체적 부족 없음 | 유지. 변화 자체를 목적으로 재작성하지 않음 |
| 유효 | 위계·시각화·이미지 판독·밀도·불필요한 반복의 구체적 부족 확인 | 해당 축을 목표로 자유 재작성. 과거 passed를 failed로 덮어쓰지 않음 |
| 유효 | 비교 근거 부족 또는 취향 수준의 차이 | 미판정. 자동 재작성·개선 확정 없음 |
| 무효 | 보존·화면 결함 존재 | 해당 결함 우선 해결. 이후 실제 렌더에서 디자인 판정 |

새 정책의 후보 선택은 기존 실패 축뿐 아니라 현재 검토에서 근거가 있는 디자인 수정 목표도 읽는다. 새 후보는 목표의 개선, 필수 내용·화면의 유효성, 다른 축의 중대한 악화 없음이 확인될 때만 채택한다. `no_targeted_defect`를 전역 삭제하거나 기존 정책·과거 작업에 새 조건을 소급하지 않는다.

## 7. 선택적 재작성과 실제 최종 결과

1. 첫 작성의 모든 페이지를 화면·원본·디자인 관점에서 평가한다.
2. 문제 페이지에 실제 원문, 이전 SVG/PNG, 관련 참고, 구체적 결함과 개선 목표를 전달한다. 정상 페이지를 함께 다시 만들지 않는다.
3. 전체 구도 결함은 자유 재작성으로, 측정 가능한 국소 오류는 관련 영역 수정으로 처리한다. 둘을 기계적으로 연속 실행하지 않는다.
4. 바뀐 페이지를 렌더하고 기존 유효 후보와 비교한다. 새 결과라는 이유로 채택하지 않는다.
5. 필수 조건을 만족하고 목표 결함이 실제로 개선됐으며 중대한 악화가 없는 후보를 선택한다. 불확실하면 이전 후보를 보존하고 미완료 상태를 유지한다.
6. 실제 최종 선택이 이미 평가한 덱과 정확히 같으면 유효한 증거를 검증해 재사용한다. 이전·새 페이지가 섞여 다른 덱이 되면 영향받은 로컬 검토와 덱 전체의 반복·흐름을 갱신한다. 서로 다른 후보 덱의 검토를 최종 덱 검토로 재사용하지 않는다.
7. 최종 PPTX를 정상 제품 경로에서 생성하고 실제 선택 SVG와 최종 출력의 일치·편집성·가독성을 확인한다. 웹 PNG 개선만으로 PPTX 개선을 확정하지 않는다.

기존 실패 판정은 원래 증거 그대로 남긴다. 미개선 페이지를 유지하면서 과거 failed를 passed로 바꾸지 않는다. 기준 v7 결과와 신규 결과의 비교는 서로 다른 작업의 벤치마크 분석이다. 과거 영수증을 신규 작업의 producer로 재서명하거나 기존 작업 내 후보 선택 계약을 우회하는 데 사용하지 않는다.

초기·수정 후보·실제 최종 선택의 검토 목적과 물리 호출은 신규 요청의 기존 내구성 실행 계획에 사전 고정한다. 기존 호출 한도 밖의 검토를 숨겨 실행하지 않는다. 계획된 한도로 필수 검토를 완료할 수 없으면 품질 미완료로 보고한다.

## 8. 품질 다음의 속도

| 수단 | 적용 조건 | 지킬 품질 조건 |
| --- | --- | --- |
| 첫 작성 입력 보완 | 기존 작성 호출에 메시지·참고·관계를 전달 | 계획용 LLM 호출을 기본 추가하지 않음 |
| 기존 동시성 유지 | 페이지 작성·렌더의 독립 작업 | 제공자·브라우저 한도, 작업 소유권·기한 유지 |
| 변경 없는 로컬 검사 재사용 | 원본·SVG·PNG·캔버스·스타일·정책·도구·폰트·실행 조건과 권한 일치 | 기존 실패 판정 보존, producer와 신규 consumer 분리 |
| 수정 페이지 한정 재렌더 | 실제 SVG나 이미지가 바뀐 페이지 | 변경된 페이지 검사를 생략하지 않음 |
| 영향받은 검토 갱신 | 로컬 묶음·이웃·덱 문맥 변화 | 바이트가 같아도 문맥이 달라진 판단은 재검토 |
| 호출·토큰 최소화 | 공통 참조와 필요한 문맥 재사용 | 원본 내용·필수 이미지·디자인 근거를 절감 대상으로 삼지 않음 |

수정 횟수·단계는 기존 승인 계획과 비용 한도 안에서 끝낸다. 자동으로 80페이지 전체를 반복 작성하거나 검토하는 경로를 기본 재시도로 두지 않는다. 캐시 불일치나 재개 오류가 발생하면 원인과 요청한 품질 작업의 진행 상태를 구분해 즉시 보고한다.

측정 항목은 첫 작성 시간, 첫 작성 디자인 미달 페이지 수, 채택한 수정 수, 재렌더 수, 실제 제공자 호출·사용량·비용, 검토 대기, 최종 검증까지의 전체 시간이다. 실패·미완료 실행도 포함한다. 첫 미리보기 시간만으로 속도 개선을 주장하지 않는다. 동일 입력·모델·캔버스·장수·동시성·정책의 실제 비교 전에는 배수·분·품질 점수를 추정 성과로 제시하지 않는다.

### 호출 수와 시간 예산

페이지 수를 N, 고정 로컬 묶음 수를 G, 수정 후보 때문에 입력이 달라진 묶음 수를 R, 실제 최종 혼합 결과 때문에 추가로 입력이 달라진 묶음 수를 M으로 둔다. 묶음은 현재 지원 크기와 판독 조건으로 고정하며, 페이지 수나 수정 페이지 수만으로 캐시 재사용을 확정하지 않는다.

| 실행 형태 | 논리적 리뷰 호출 계획 |
| --- | --- |
| 수정 없음 | G개 로컬 + 전역 1회 |
| 수정 후보가 그대로 최종 선택됨 | G + R개 로컬 + 초기/후보 전역 각 1회 |
| 이전·새 결과가 섞여 후보 덱과 다른 최종 결과가 됨 | G + R + M개 로컬 + 초기/후보/최종 전역 각 1회 |

현재 5페이지 묶음 기준 80페이지의 첫 리뷰는 로컬16+전역1이다. 이는 논리적 계획 예시이며 실제 호출·시간 측정값이 아니다. 포맷 수정·허용된 비교 재확인 등 모든 추가 물리 호출은 이와 별도로 실행 계획에 고정하고 비용에 포함한다. 기존 목적·ordinal·슬롯 계약은 유지하며 호출 수를 예측한 것만으로 새 호출 권한이 생기지 않는다.

실제 최종 덱이 이전 검토와 동일하다는 판단에는 전체 SVG/PNG 벡터, 순서, 원본, 스타일·예시, 정책, 관련 문맥, 실제 producer와 현재 소비 권한이 모두 필요하다. 전역은 최종 선택과 이전 평가가 정확히 같을 때만 재사용한다. 원래 실패 판정은 그대로 유지한다. 정상 페이지의 source/PNG를 재사용하더라도 덱 문맥이 바뀐 전역 판단을 재사용하지 않는다.

시간 한도는 기존 전체 deadline에서 거꾸로 배분한다. 요청별로 준비·작성·렌더·검토·출력의 예측 범위, 현재 동시성, 남은 호출·시간, 최소 최종 검증·출력 예약 시간을 기존 계획/체크포인트에 기록한다. 별도 작업 상태나 새로운 스케줄러를 만들지 않는다. 근거 없는 고정 완료 분수를 약속하지 않는다.

- 첫 수정 전에 남은 시간과 슬롯이 수정 작성·재렌더·관련 리뷰·최종 출력까지 충족하는지 확인한다. 부족하면 새 수정 라운드를 시작하지 않고 품질 미완료 사유를 전달한다.
- 리뷰 대기에는 기존 허용 동시성과 호출 timeout을 적용하고, 전체 deadline이나 소유권 상실 후 추가 I/O를 시작하지 않는다. UNKNOWN을 확정 실패로 바꿔 재호출하지 않는다.
- 관측 시간은 제공자 외 준비·PNG 읽기·해시/체크포인트 계산·렌더·내보내기를 포함한다. 실제로 지배적인 병목을 확인한 뒤 해당 부분만 최적화한다.
- 첫 실제 비교에서 단계별 시간·호출을 수집해 다음 요청의 예상 범위를 보정한다. 자료·캔버스·장수가 다른 실행을 같은 속도 기준으로 섞지 않는다.
- 예산·슬롯·시간 부족을 검토 생략, 품질 기준 하향, 숨은 재시도 또는 전체 덱 재생성으로 해결하지 않는다.

설계안은 기존 정책 식별자의 새 개정 `svg-quality-first@2`를 신규 요청에 고정하는 방식을 권장한다. 현재 코드가 이를 지원한다는 뜻은 아니다. 실제 필드·직렬화·호환성 변경은 구현 준비에서 확정한다. v1과 기존 v7/v8 고정 요청·재개는 원래 지침·선택·한도를 유지한다. 새 작성 프로파일 v9는 전제하지 않는다. 같은 v8이라는 이유로 과거 작업에 새 프롬프트·판정 기준을 적용하지 않는다.

`vision_qa=false`는 기본 사용자 확인 설정으로 유지한다. 자동 디자인 검사 적용을 이를 true로 바꾸는 방식으로 해결하지 않는다. 현재 `seal_new_quality_recovery_plan` 내부에 vision_qa 조건은 없지만, 이것만으로 웹의 모든 진입점과 실행 서버가 해당 정책을 사용한다고 확정하지 않는다. 신규 웹 요청의 실제 고정 정책과 작성 영수증을 확인한다.

기존 원본·요청·부모 작업·admission·기한·비용·UNKNOWN·리스를 변경하지 않는다. 기존 dirty 변경은 보존한다. 이번 디자인 작업으로 재개·예산·SDK·브라우저·DB 계층을 다시 구축하지 않는다. 직접 연결된 결함이 발견되면 품질 변경과 분리해 최소 수정·별도 검증한다.

D3~D5는 실제 제공자·제품 실행 계획이며 이번 설계 작성의 검증 명령이 아니다. 사용자 승인 없는 새 유료 작업·비용 증가·배포를 시작하지 않는다. 비교 실행의 제공자 호출은 시작 전에 기존 한도와 비용을 고정하며 숨은 재시도나 전체 반복 실행을 하지 않는다.

기준11쪽은 개념 화면으로 실제 화면 캡처 중심의 사례를 대체하지 못한다. D5에서는 이미 접근이 허용된 원본의 실제 캡처·설명 그룹이 있는 소규모 사례를 먼저 포함하고, 결과 확인 뒤 긴 덱으로 확대한다. 화면 개수나 페이지 개수를 늘리는 것 자체를 품질 검증으로 인정하지 않는다.

모델·스타일·원본·페이지 수·출력 비율·의도한 보정 단계가 다르면 결과 차이를 특정 코드 변경의 효과로 확정하지 않는다. 기준의 원 실행 재현이 불가능하면 그 한계를 밝히고, 같은 조건의 현행/개선 비교를 추가해 판단한다. D4 통과는 12페이지 사례의 증거이며 80페이지 전체·모든 캔버스·모든 자료 종류의 품질 보장을 뜻하지 않는다.

초기 웹 디자인과 최종 편집형 PPTX를 모두 목표로 삼는다. 실제 완료 보고에는 신규 작업 ID, 고정 정책·입력·캔버스, source/PNG/PPTX 연결, 전체 페이지 디자인 판정, 남은 결함, 실제 비용·완료 시간, 서버 적용 상태를 포함한다. 코드·무료 fixture·Office 열기·구조 검사만 통과한 결과는 그 범위만 보고한다.

## 12. 이번 작업에서 실제 확인한 범위

- 기준 PPT의 웹 메타데이터와 기존 12페이지 PNG를 확인했고, 웹 이미지 참조·영수증·저장 파일 해시가 모두 일치했다. 새 제공자 호출이나 렌더 실행은 없었다.
- 직접 연결된 기존 설계·구현 현황과 작성 프로파일·시각 의도·참고 선택·후보 비교 코드를 확인했다. 과거 문서의 활성화 설명을 현재 웹 동작으로 확정하지 않았다.
- 이번 변경은 이 설계 문서 한 파일이다. 구현 코드·설정·서버·DB·기존 자료와 실패 작업을 변경하지 않았다.
- 문서 내용과 근거·경계·완료 조건을 검토했다. 문서 변경에 테스트·타입 검사·린트·빌드를 실행하지 않았다.
- `compiled-spec-memory` 스킬은 현재 도구와 저장소·계정의 관련 스킬 경로에서 찾지 못했다. 따라서 자동 기록을 수행하지 않았으며 이 문서 작성이나 일반 메모로 대체한 성공 표시도 하지 않는다.
