# 원문 보존형 구조 보정 설계

작성일: 2026-09-10

상태: 설계 v2 및 후속 구현. 사용자 선택은 구조 패치 우선, 누적 보정 보조, 엄격한 최종 저장이다. 속도·품질·구조 검토를 반영해 변경 범위 선정, 검증 책임, 비용 상한, 스타일 보호를 구체화했다. 구현 사항은 11절에 구분하며, 실제 원본 네 장과 전체 35장의 제품 완료 증거는 아직 없다.

## 1. 목표와 범위

이미 작성·렌더된 슬라이드의 구조 결함을 기존 QID와 원문을 유지하면서 보정한다. 부모 그리드, 자식 카드 크기, 간격을 하나의 패치로 변경하는 것이 주 경로다. 완결되지 않았지만 측정상 개선된 결과만 같은 보정 시도의 다음 cycle 입력으로 사용한다.

완료 조건은 composition gate와 source readback을 모두 통과한 정확한 HTML·PNG·브라우저 증거의 저장이다. HTML 변경이나 렌더 성공은 완료 조건이 아니다.

- 원문 텍스트·블록 ID·블록 내부 순서 및 기존 원문 보존 계약을 유지한다.
- 기존 QID를 보존하고 요소 추가·삭제, 원문 축약, 이미지 교체, full_reauthor는 허용하지 않는다.
- 9.5pt local-fit 하한 및 더 엄격한 기존 역할별 제약을 유지한다.
- 작성 배치/클러스터/렌더 동시성 5/2/2와 PostgreSQL 관리 스택을 유지한다.
- 기존 attempt fencing, repair claim, 호출 예약 정책을 유지한다. 재시작으로 보정 예산을 초기화하지 않는다.
- 최초 설계 단계는 문서만 작성했다. 이후 사용자가 멀티 에이전트 구현과 테스트를 승인했다. 현재 개발 검증은 외부 모델 호출 및 제품 전체 재실행과 구분한다.

## 2. 현재 코드에서 확인된 연결 문제

| 위치 | 현재 동작 | 설계상 변경 |
| --- | --- | --- |
| `utils/llm_calls/author_slide_patch.py` | 구조 스타일 허용을 `retry_invalid_model_patch`에 연결 | 보정 능력과 제안 재시도 정책을 분리 |
| 같은 파일의 프롬프트 | static 요소 이동은 full_reauthor를 안내하면서 구조 reflow도 요구 | 기존 부모 QID의 reflow를 우선 안내하고 불가능하면 명시적 실패 반환 |
| `utils/authored_patch_engine.py` | 패치 전체를 원자적으로 적용하는 기능이 이미 있음 | 기존 엔진 재사용. 새 구조 수정 엔진을 만들지 않음 |
| 같은 파일의 스타일 목록 | `grid-template-columns`는 있으나 `grid-template-rows`는 없음 | 첫 구현은 지원 속성으로 계획. rows 지원 확대는 필요 증거가 있을 때 별도 검증 |
| `utils/llm_calls/author_vision_qa.py` | 엄격한 candidate validator가 부분 개선도 예외로 거절 | 구조 평가 결과를 reject/provisional/admitted로 반환 |
| 같은 파일의 `fixed` | HTML이 변경되면 포함 | 내부는 슬라이드별 결과 객체로 전환하고 기존 반환은 경계에서만 변환 |
| `services/authored_presentation_generation.py` | 잔여 결함 예외의 `fixed`를 체크포인트에 저장 | 최종 입장 검증을 통과한 결과만 저장 |
| `services/source_content/browser_readback.py` | 실패 결과를 예외로 반환하고 누락·가림 ID가 합쳐짐 | 내부 진단 결과를 보존하고 기존 엄격 verifier는 그대로 유지 |

## 3. 전체 흐름

```text
원본 체크포인트 + manifest/outline + 절대 인덱스
  → 동일 HTML의 브라우저 측정, 기준 증거 고정
  → 결함 분류 및 수정 범위/보호 범위 확정
  → 적용 가능한 기존 결정적 보정 1회, 없으면 바로 모델 구조 패치
  → 전체 계획 원자 적용 → 정확한 HTML 렌더 → 단일 후보 평가기
      reject      → 직전 허용 상태 유지; 새로운 수정 근거와 예산이 있을 때 재제안
      provisional → 메모리 안의 다음 cycle 입력으로만 사용
      admitted    → 증거 연결 및 fencing 확인 → 원자 체크포인트 저장
  → 예산 종료 시 admitted 결과만 보존, 미해결 슬라이드는 명시적으로 실패
```

임시 후보는 완료 체크포인트와 게시 대상 배열에 병합하지 않는다. 프로세스 종료 시 임시 후보가 유실되는 것은 허용하며, 원본 또는 이미 통과한 체크포인트가 복구 기준이다. 디버깅 산출물에 후보를 남겨도 production hydration 대상으로 취급하지 않는다.

## 4. 구조 패치 계획

### 결함 분류와 빠른 처리

처음부터 모델을 호출하지 않는다. 현재 파이프라인에 이미 있는 결정적 보정 중 결함 유형·역할·원문 보존 조건이 일치하는 보정만 사용한다. 기존 단계가 동일 기준 HTML에 적용해 평가한 결과가 있으면 그대로 재사용하며 같은 보정을 반복하지 않는다.

| 분류 | 처리 | 다음 단계 |
| --- | --- | --- |
| 기존 보정이 처리하는 높이/간격/containment 결함 | 관련 변경을 묶은 결정적 후보 1개 | 통과 시 종료, 부분 개선이면 그 후보에서 모델 보정 |
| 여러 카드가 연동되는 grid/flex 배치 결함 | 범위를 선정하고 모델 구조 패치 | 첫 후보 통과 시 종료 |
| 필요한 QID/측정/허용 속성이 없음 | 결함과 부족한 능력을 명시 | 모델 호출 없이 실패 |
| 이미 최종 gate 통과 | 기준 증거 재사용 | 보정 없이 종료 |

11px 같은 작은 이탈값 자체가 결정적 보정 가능성을 증명하지는 않는다. clipping 원인과 기존 reducer의 적용 조건을 확인한다. 새 범용 레이아웃 탐색기를 도입하지 않는다.

### 구조 변경 범위 선정

1. 결함별 원문 소유 QID와 이탈/가림을 발생시키는 QID를 찾는다. clipping은 실제 clipping ancestor, overlap은 가리는 요소와 가려진 요소를 모두 포함한다.
2. 가장 가까운 grid/flex/positioning 컨테이너부터, 해당 요소들의 배치를 실제로 제어하는 부모를 찾는다. 단순 DOM 공통 조상이라는 이유만으로 선택하지 않는다.
3. 부모의 열 수·gap·가용 크기 변경에 영향을 받는 모든 직접 배치 자식을 한 그룹으로 포함한다. 그 자식 내부 원문은 검사 범위에 포함하되 텍스트는 수정하지 않는다.
4. 여러 결함의 수정 그룹이 겹치면 하나로 합친다. 상위 공간 제약이 원인이면 다음 배치 조상으로 확장하되, 제목·본문·푸터 등 기존 역할 경계를 보호한다.
5. 슬라이드 루트는 측정 기준으로 읽을 수 있지만 포괄적인 편집 대상으로 삼지 않는다. 역할 경계를 넘어야 하거나 기존 action 한도/입력 한도 안에 연동 그룹을 담을 수 없으면 `repair_scope_unavailable`로 끝낸다. 그룹을 잘라 독립 패치인 것처럼 실행하지 않는다.

범위 결과는 `layout_owner_qid`, `editable_qids`, `affected_source_block_ids`, `protected_qids`, `reasons`를 포함한다. 허용 QID 중에서도 원인에 필요한 속성만 변경하며, 부모 변경이 보호 영역에 미치는 영향은 후보 렌더 후 검사한다.

모델 입력에는 결함이 있는 leaf QID뿐 아니라 관련 부모와 형제의 QID, 계산된 display/position, 가용 내부 크기, 자식 bbox, 고정 높이·최소 높이, gap·padding을 포함한다. 기존 compact DOM에 부족한 정보만 해당 컨테이너 범위에서 보완한다.

한 계획은 부모 레이아웃과 영향을 받는 자식 크기를 함께 포함한다. 각 action 사이를 렌더하거나 후보로 평가하지 않는다. 엔진이 전체 계획을 적용한 최종 HTML만 평가한다.

카드 n개, 열 수 c, 행 수 r=ceil(n/c)에 대해 다음은 후보 생성의 필요조건이다.

- 열 폭: `(가용 폭 - (c-1) × 가로 gap) / c`
- 행 높이 합계 + `(r-1) × 세로 gap` ≤ 가용 높이
- 카드별 실제 텍스트 높이 + 내부 padding ≤ 카드 내부 가용 높이

줄바꿈 때문에 열 수를 늘리면 필요한 높이가 증가할 수 있다. 산술 조건만으로 통과 판정을 내리지 않고 브라우저 측정을 최종 근거로 사용한다. 최소 글자 크기를 낮추거나 overflow:hidden으로 원문을 숨겨 맞추는 계획은 거절한다.

새 탐색 루프나 다수 후보 렌더를 기본으로 추가하지 않는다. 최대 두 번의 모델 제안 기회 안에서 첫 계획에 관련 구조 변경을 묶고 두 번째에서 남은 결함을 보정한다. 계획을 찾지 못하면 `repair_search_exhausted`로 끝낸다. 제한 탐색 실패를 배치가 수학적으로 불가능하다는 증거로 표현하지 않는다.

### 호출·렌더 예산과 종료

아래 상한은 v2의 목표 계약이며 기존 실행에서 측정된 수치가 아니다. 기존 durable 예약이 더 적게 허용하면 더 작은 한도를 따른다.

| 항목 | 슬라이드당 상한/규칙 |
| --- | --- |
| 기준 capture | 유효한 증거 재사용 시 0회, 없으면 1회 |
| 결정적 후보 capture | 최대 1회. 기존 단계와 합산하며 동일 후보 재실행 없음 |
| 실제 provider 전송 | 최대 2회. patch 제안, schema 재시도, provider 재시도를 모두 합산 |
| 모델 후보 capture | 최대 2회. 파싱·무결성 사전 검사에 실패하면 렌더하지 않음 |
| 추가 모델 critique | 이 구조 gate repair 경로에서는 0회. 현재 결정적 결함과 측정 결과로 재제안 |
| 최종 저장용 추가 capture | 동일 증거가 유효하면 0회 |

따라서 정상 증거 조건에서 새 후보 capture는 최대 3회이며, 기준 capture가 필요하면 총 4회다. 두 번의 provider 전송 중 하나를 schema/transport 재시도에 쓰면 두 번째 구조 후보 기회도 소진된다. 숨은 내부 재시도가 상한 밖으로 나가지 않도록 예약 경계에서 차단한다.

첫 admitted에서 즉시 종료한다. 같은 HTML digest를 다시 제안하거나 개선 없이 같은 실패를 반복하면 조기 종료한다. reject 후에는 구체적인 수정 근거가 생기고 예산이 남아 있을 때만 재제안한다. 렌더 실패에 대한 별도 무제한 재시도는 추가하지 않는다.

후보별 provider 전송 수, capture 수, 처리 시간, 재사용 여부, 종료 이유를 기존 receipt/detail에 남긴다. 대기·모델·렌더·평가 시간을 구분하여 실제 병목을 판단한다. 동시성 5/2/2는 유지하며 이 경로에서 별도 무제한 gather나 중첩 worker pool을 추가하지 않는다.

## 5. 후보 평가 계약

### 항상 만족해야 하는 조건

원문 누락·변경·중복, 기존 원문 순서 계약 위반, QID 손실, 이미지/자산 계약 위반, 금지 action, 글자 하한 위반, 불완전한 브라우저 증거는 즉시 reject한다. 이 조건은 개선 점수로 상쇄할 수 없다.

기존 browser verifier의 실패 ID 개수만 비교해서는 안 된다. 진단 계층에서 원문 무결성 실패와 가시성 실패를 분리한다. 기존 `verify_browser_source_readback`은 이 결과에 엄격한 통과 조건을 적용하는 wrapper로 유지하여 다른 호출자의 의미를 바꾸지 않는다.

### 스타일과 보호 영역

- 기존 스타일/역할 계약에 있는 제목·본문 크기 위계, 최소 여백, 정렬, 이미지 비율 제약을 모델 입력과 평가에 동일하게 전달한다.
- 같은 반복 카드 그룹은 기존에 공통 규칙을 사용한 경우 열 정렬·gap·padding 규칙을 유지한다. 원래 다른 디자인의 카드를 임의로 같은 크기로 강제하지 않는다.
- 구조 보정은 기존 폰트 계열·색상·장식 스타일을 유지한다. 글자 크기를 바꾸는 기존 reducer는 하한과 역할 위계를 함께 지켜야 한다.
- 수정 범위 밖 QID에는 직접 action을 금지한다. 간접 reflow로 보호 영역의 위치·크기·가시성이 변하면 기존 허용오차 및 역할 계약으로 검사한다.
- 이미 깨져 있는 스타일 조건은 개선할 수 있지만 새로운 스타일 위반을 만들 수 없다. 기존 계약에 없는 미적 수치를 임의로 만들어 최종 gate에 추가하지 않는다.

이 항목은 정렬·위계의 측정 가능한 악화를 막는 보호 조건이다. 자동 게이트 통과를 전체 미적 품질의 증명으로 주장하지 않으며, 이번 범위에 별도 미적 평가 모델이나 시각 비교 실행을 추가하지 않는다.

### admitted

단일 후보 평가기가 같은 최종 HTML에 대한 모든 슬라이드별 composition 조건과 strict source readback 통과를 판정한다. 로컬 DOM report만 통과한 경우는 해당하지 않는다. capacity/역할/원문/자산 및 위 스타일 보호 조건도 적용한다. 덱 전체 관계 검사는 후보마다 전체 35장을 다시 검사하지 않고 기존 최종 게시 gate에서 별도로 유지한다. 슬라이드 admitted는 덱 게시 승인과 다르다.

### provisional

항상 만족해야 하는 조건은 통과했으나 최종 결함이 남아 있는 후보다. 다음 조건을 모두 충족할 때만 다음 cycle로 전달한다.

1. 새로 실패하는 원문 블록이 없다.
2. 기존 실패 블록별 최대 viewport/card 이탈 거리, clipping 면적 비율, occlusion 비율이 각각 악화되지 않는다.
3. 위 지표 중 하나가 측정 오차 범위를 넘어 개선되거나 실패 블록이 줄어든다.
4. 원문 외 요소에 대해서도 기존 category/QID별 DOM 비악화 검사를 유지한다.

비교 기준은 직전 provisional 또는 최초 기준 후보이며, QID/원문/스타일 보호 기준은 최초 체크포인트에서 고정한다. cycle마다 허용오차를 누적해 기준이 조금씩 악화되지 않도록 최초 기준에 대한 비악화도 함께 확인한다.

거리와 면적을 하나의 가중 합계로 합치지 않는다. 한 블록의 회복으로 다른 블록의 악화를 상쇄하지 않는다. 비교 키는 원문 block ID와 안정적인 QID이며 local 배열 위치가 아니다.

수치 비교 오차는 기존 렌더 판정의 허용오차를 재사용하고, 별도 완화 상수를 임의로 만들지 않는다. 필요한 면적 측정이 현재 telemetry에 없으면 관련 브라우저 측정을 보완하며, 그 전에는 해당 후보를 추측으로 허용하지 않는다.

구조를 한 번에 바꿨는데도 이 조건을 통과하지 못하면 후보를 거절한다. 임시 후보 통과를 위해 전역 `has_dom_quality_regression`을 완화하지 않는다. 두 번째 cycle에는 실패 이유와 현재 허용 HTML의 증거를 전달한다.

이 비악화 조건은 일부 배치의 중간 단계를 의도적으로 허용하지 않는다. 그런 연동 변경은 4절의 그룹 전체를 첫 구조 패치에 포함하여 완결해야 한다. 단조 개선 경로가 발견되지 않으면 실패로 남기며, 실패 수나 가중 합계로 조건을 우회하지 않는다.

## 6. 최소 인터페이스 변경안

- `propose_authored_slide_patch`: 명시적인 `allow_source_reflow_safe_styles`를 추가하고 메시지/스키마/validate/apply에 같은 값을 전달한다. `retry_invalid_model_patch`는 재시도만 제어한다.
- 소규모 서비스 평가 모듈: `RepairAssessment`로 `decision`, `reasons`, `source_integrity`, `visibility_by_block`, `composition_report`, `style_report`, 증거 참조를 반환한다. 원문/manifest 지식은 서비스가 소유하고 LLM 유틸리티에 중복 구현하지 않는다.
- `revise_authored_deck`: baseline과 candidate 증거를 받는 선택적 evaluator를 추가한다. source-reflow gate repair에서는 evaluator만 호출한다. 기존 strict `candidate_validator`와 동시에 제공되면 설정 오류로 거절하여 두 경로를 중복 실행하지 않는다. 다른 호출자의 기존 strict 의미는 유지한다.
- 내부 결과는 아래 `SlideRepairResult`로 통일한다. 기존 tuple/`fixed`가 필요한 호출자만 경계 adapter를 사용한다. durable 저장은 adapter 배열을 사용하지 않는다.
- `AuthoredVqaResidualDomIssuesError`: 같은 결과 객체 목록을 전달한다. 정상 반환과 예외 반환의 최종 통과 결과 수집 함수를 공통으로 사용한다.
- 체크포인트 소유자는 평가 규칙을 재구현하거나 같은 증거를 다시 렌더하지 않는다. 평가 증거의 digest/검사 버전/문맥/필수 report와 fencing을 확인하고 저장한다. 증거가 없거나 유효하지 않으면 저장을 거절하여 평가 경로로 돌려보낸다. PNG/metrics를 `{}`로 대체하지 않는다.

| 구성 요소 | 단일 책임 |
| --- | --- |
| 범위 선정/계획 | editable/protected 범위와 연동 변경 제안 |
| 패치 엔진 | 스키마·허용 action 검증 및 원자 적용 |
| 후보 평가기 | 무결성·스타일·개선 여부·슬라이드 최종 gate 판정 |
| 보정 루프 | 예산 소비, 다음 입력 선택, 조기 종료 |
| 저장기 | 승인 증거의 결합과 fencing 확인, 원자 저장 |

`SlideRepairResult`의 제안 구조:

```text
absolute_slide_index
baseline_html_digest
changed
final_status: admitted | unresolved
selected_candidate: HTML + PNG + metrics + bound evidence
assessment: decision + reports + reasons
cycle_history: 후보 digest + 판정 + 비용 + 실패 이유
```

`selected_candidate`는 현재 허용된 기준/provisional/admitted 중 하나이며 `unresolved` 결과에서는 진단과 같은 호출 내부 전달에만 사용한다. rejected 후보는 history로만 남기고 선택 상태를 덮어쓰지 않는다. 저장기는 `final_status=admitted`와 해당 assessment/evidence가 모두 일치하는 객체만 받는다. 별도의 changed/admitted 병렬 인덱스 배열은 내부 상태로 만들지 않는다.

구조 평가 기능을 기존 source 검증과 composition gate에 연결하고, 같은 규칙의 복제 구현은 피한다. 필요한 세부 함수 추출 범위는 구현 시 해당 호출 경로로 제한한다.

## 7. 증거와 인덱스, 저장

후보 식별자는 절대 slide index, 기준 HTML digest, 후보 HTML digest, cycle로 구성한다. 증거에는 PNG/metrics digest, source manifest/outline·자산 문맥 digest, 스타일/역할 문맥, gate 버전, capture의 viewport/폰트·자산 준비 상태를 결합한다. source manifest/outline의 원래 결합과 원문 자산 digest도 재현 입력에서 고정한다.

35장 중 22/28/30/34장의 절대 0-based 인덱스는 21/27/29/33이다. 부분집합 local index를 전체 덱 인덱스로 추정하지 않는다. 반환 길이, 매핑 유일성, 범위, HTML/PNG/metrics의 연결을 검증한다.

정규화가 HTML을 바꾸면 렌더보다 먼저 수행한다. 렌더 후 bytes를 바꾸지 않는다. 같은 bytes와 검사 문맥에 묶인 후보 capture를 검증과 저장에 재사용한다. 캐시 증거가 digest와 연결되지 않으면 새 capture가 필요하며 기존 stage 예산 안에서 수행한다. 이것을 별도 저장 재시도 루프로 만들지 않는다.

성공/잔여 결함 예외 양쪽 저장 경로는 평가기가 발급한 동일한 admission 증거를 사용한다. 통과한 일부 슬라이드는 기존 attempt/fencing 아래 HTML·PNG·metrics를 함께 교체할 수 있다. 미통과 슬라이드는 기존 체크포인트를 유지한다. 게이트 실패를 성공 receipt로 바꾸거나 게시를 진행하지 않는다.

## 9. 구현 순서와 검증 계획

1. 네 장의 증거에서 수정 그룹/QID/측정 충족 여부 확인. 기존 결정적 보정의 적용 가능성 분류.
2. 스타일 능력/재시도 분리, 실제 속성과 수정 그룹에 맞는 프롬프트 정렬, 호출 상한 연결.
3. 원문 진단 결과 추출과 단일 후보 평가기/스타일 보호 연결.
4. 슬라이드별 결과 객체 도입, 정상/예외 저장 경로 통합, 기존 반환 adapter 연결.
5. 기존 체크포인트를 읽어 네 장만 보정하는 제한 실행 경로 준비.

구현 완료 후 기본 검증은 기존 테스트 중 후보 평가와 저장 admission을 직접 다루는 가장 좁은 대상 하나를 선택한다. 검증만을 위한 새 테스트 파일이나 전체 테스트/빌드를 자동 추가하지 않는다. 반드시 확인할 경계는 부분 개선의 다음 cycle 전달, 원문 손실의 거절, 임시 후보 저장 차단, 부분집합 인덱스 보존이다. 선택한 검사로 덮이지 않은 중요한 경계는 미확인으로 명시한다. 네 장 제한 실행에서는 다음 증거도 함께 확인한다.

- 모델 호출이 필요 없었던 경로, 실제 provider 전송/capture 수, 조기 종료 이유.
- 원자 변경 그룹의 완결성, 범위 밖 변경 부재, 원문/스타일 보호 결과.
- evaluator 단일 실행 경로와 정상/예외 저장기의 동일한 증거 요구.
- 미해결 후보는 실패로 남고 admitted 후보의 정확한 bytes만 저장되는지 여부.

제품 검증 단계는 구현 검증과 구분한다. 네 장 제한 실행은 기존 원문/요청/체크포인트 bytes를 사용하고 출력 증거를 분리한다. 운영 repair claim을 수동 초기화하지 않는다. 기존 claim이 소진되었다면 제한 재현의 호출 권한을 별도로 마련하고, 그 결과를 원래 operation의 성공이나 retry 0 증거로 주장하지 않는다.

네 장이 모두 composition/source readback을 통과한 후에만 전체 35장 실행 1회를 진행한다. 새 자산 ID·snapshot을 사용하더라도 원본 bytes/digest와 요청 옵션을 동일하게 유지한다. 실행은 사용자가 승인한 구현/검증 범위에서 진행하며 이번 설계 단계에서는 시작하지 않는다.

전체 완료 증거는 동일한 새 실행에 연결된 attempt 1, operation retry 0, 35/35, 원문 289/289, quality residual 0, published, 실제 PPTX artifact 및 PostgreSQL/동시성 5/2/2이다. 로컬 네 장 통과나 PPTX 파일 존재만으로 전체 완료를 주장하지 않는다.

## 10. 구현 착수 시 확인할 증거

- 실제 네 장의 compact DOM에 수정 가능한 공통 부모 QID와 필요한 치수가 모두 있는가.
- 기존 telemetry만으로 블록별 clipping 면적과 card/viewport 이탈을 분리할 수 있는가.
- 실제 provider 전송 상한을 기존 repair claim과 schema/transport 재시도 경계에 연결할 수 있는가. 기존 durable 예산은 늘리지 않는다.
- 최종 gate에서 슬라이드별 순수 검사와 덱 전체 관계 검사를 분리하여 재사용할 수 있는가.
- 기존 스타일/역할 계약이 어떤 보호 항목을 제공하고 어떤 항목은 측정되지 않는가.

이 항목은 구현 전 해당 코드/증거로 확인할 사항이다. 부족한 정보나 소진된 예산을 통과로 취급하지 않는다.

## 11. 후속 구현과 검증 경계

- `author_slide_patch.py`: 구조 스타일 능력/재시도 분리, 수정 범위 선정, 실제 전송 1회 예산을 가진 구조 제안 경로. 일반 제안의 예산은 유지한다.
- `authored_structural_repair.py`: 원문 무결성·블록별 가시성·스타일 평가, 임시/최종 후보 구분, HTML·PNG·metrics·평가 증거 결합.
- `author_vision_qa.py`: 추가 critique 없이 최대 두 구조 제안, 임시 후보 누적 및 중복 후보 중단, 기존 반환 형식은 경계에서 변환.
- `authored_presentation_generation.py`: 결정적 후보의 측정·평가 후 모델 경로 연결, 성공/실패 양쪽에서 승인 결과만 Scene과 render 체크포인트에 저장.
- `authored_presentation_pipeline.py`: 새로 복원한 원본 digest와 Scene·render tuple 및 승인 영수증이 일치하는 보정을 재개 시 재사용. 단순히 HTML이 같다는 이유로 승인하지 않는다.
- `slide_capture.py`/`browser_readback.py`: source clipping 경계 측정, 기존 strict API를 유지한 진단 결과 분리, 이미지의 조상 clipping도 strict 검사에 반영.

현재 source-reflow pipeline은 local fit을 비활성화한다. 이 보정 경로에서는 원문 검증·capacity 검사와 명시적인 9.5pt 하한을 적용하며 전역 글자 정책을 바꾸지 않는다. local fit 영수증이 존재하는 호출 경로를 위해서는 기존 fit/재구성 절차를 후보 평가 전에 실행한다. 그 경우 추가 capture 비용이 발생할 수 있으므로 source-reflow 기본 경로의 capture 상한을 모든 호출 경로의 실측값으로 주장하지 않는다.

저장 영수증은 원래 측정값의 해시와 별도로 `authored_structural_repair` 필드에 첨부한다. 기존 artifact bundle은 영수증을 포함한 전체 측정 객체를 다시 결합한다. 재개 시에는 이 필드를 분리하여 원래 측정 해시와 HTML·PNG·원본 digest·슬라이드 인덱스를 검증하므로 자기 자신을 해시하는 순환이 없다.

기존 테스트 파일에서 후보 누적·보호 영역·전송 예산·원문 및 이미지 검증·승인 증거·재개 연결을 검증한다. 이 테스트들은 실제 원본 네 장이나 외부 provider/게시/PPTX 생성의 성공 증거가 아니다. 서비스 시작, 전체 테스트/빌드, 전체 35장 실행은 이 개발 검증에 포함하지 않는다.

최종 좁은 pytest 실행 결과: **65 passed in 6.97s**. 패치 제안/원문 브라우저 검증 파일과 보정 루프·저장·재개·결정적 후보 연결의 지정 테스트를 한 호출로 실행했다. 앞선 수집 단계 들여쓰기 오류와 테스트 두 건의 실행/기대값 문제를 수정한 뒤, 변경 및 실패 관련 범위만 다시 확인한 결과다.

남은 제품 검증은 동일 원문 네 장의 실제 checkpoint 재현 및 이후 전체 35장 실행이다. 현재 `repaired` 통계의 공통 집계는 flagged 중 실제 HTML이 바뀌지 않은 슬라이드를 포함할 수 있다. 후보 저장 자격은 별도 admission/changed 검증을 사용하며, 이 통계를 원문 보정 성공 증거로 사용하지 않는다.
