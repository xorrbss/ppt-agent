# Composer 원본 보존 및 고밀도 7px 맞춤 설계

작성일: 2026-09-13
상태: 검토 보완 반영 후 구현 진행. 7px 허용과 보완 설계 적용은 사용자 확정 조건이다. 실제 생성·내보내기 검증 전에는 성공으로 판정하지 않는다.
대상: 원본 PPTX로 새 PPT를 만드는 source_content_restyle의 Composer 경로.

## 1. 목표와 확정 조건

- 기존 Composer에서 원문, 이미지, 표, 페이지 수와 순서를 보존한다.
- 콘텐츠가 넘칠 때 글꼴을 최종 슬라이드의 CSS 크기 기준 7px까지 줄일 수 있다. 처음부터 모든 텍스트를 7px로 만들지 않는다.
- 7px는 폰트 크기이며 7pt가 아니다. 96dpi CSS 단위에서 5.25pt에 해당한다. PPTX 출력 좌표계의 크기는 실제 캔버스 변환과 함께 일치시킨다.
- 줄이거나 요약해서 내용을 빼지 않는다. 최종 캡처 전에 배치·크기를 확정하고, 동일 HTML로 측정·저장·내보내기를 연결한다.
- 이 설계는 제품 코드 구현이나 생성 성공 판정이 아니다.

## 2. 확인된 문제와 증거의 한계

직전 실제 원본에 대한 읽기 전용 진단 결과:

| 항목 | 확인 결과 |
| --- | --- |
| 원본 | 12페이지, 텍스트 145블록, 표 7개/논리 셀 405개, 이미지 55회 |
| 누락 좌표 | 2~12페이지 각 2개, 총 22개. 같은 슬라이드 레이아웃에 좌표 존재 |
| 좌표만 메모리에서 보완 | 12페이지 HTML 생성 및 텍스트 readback 통과 |
| 실제 Chromium 배치 | 8페이지 통과, 2페이지는 원본 좌표 대체 후에도 clipping/off_canvas로 실패 |
| 2페이지 구성 | 원래 두 텍스트 상자가 하나의 process로 묶임. 각 그룹에 투영된 텍스트 조각 92개씩 들어감 |
| 병합 셀 | 2페이지 7개, 5페이지 12개 병합 영역. 추출되지만 Composer 표 계획에서 소실 |
| 폰트 저장/내보내기 | publish_semantic.py와 browser-source.ts에 최소 9pt 보정 존재 |

HTML에 값이 들어 있다는 사실은 브라우저에서 모두 보인다는 증거가 아니다. 좌표 보완만으로 최종 생성·PPTX 출력을 통과한다고 판단하지 않는다. 원본 자료의 내용이나 개인 정보는 설계 문서와 Spec Memory에 기록하지 않는다.

## 3. 기존 구현 재사용과 변경 경계

새 생성 엔진을 만들지 않는다. 기존 admission, immutable manifest, Composer classifier, fit ladder, Chromium 측정, source binding, semantic publication, PPTX export를 확장한다.

| 기존 위치 | 재사용 / 변경 |
| --- | --- |
| source_content/pptx.py, pptx_typography.py | 관계 탐색과 placeholder 매칭 재사용; 좌표 상속과 분석 버전 갱신 |
| source_content/pptx_text_body.py | 원본 문단·runStyles 재사용; 원문 범위, 문단 간격·상자 여백 등 필요한 배치 정보 추가 |
| composer/plan.py, classify_bindings.py, classify.py | 기존 분류 계획 유지; 그룹화 전 원본 배치 정보 추가 |
| composer/render_geometry.py, render_text.py | rung 5에서 원본 상자 단위와 실제 문단 경계 사용 |
| composer/render_table.py | 논리 셀 그리드와 병합 anchor/covered cell을 유지하는 렌더링 |
| composer/fit.py, fit_ladder.py, render_css.py, estimate_components.py | 공통 맞춤 정책으로 7px까지 한정 축소; 예측/렌더/측정 일치 |
| composer/publish_semantic.py, Next.js authored-hybrid/browser-source.ts | 허용된 크기를 9pt로 올려쓰지 않고 동일한 크기로 표현 |
| composer/receipt.py, pipeline.py, 작업 오류 분류 | 슬라이드·단계·실패 원인 기록, 결정적 데이터 오류의 반복 재시도 방지 |

backend 경로 기준은 servers/fastapi/services/, frontend는 servers/nextjs/lib/이다.
미지원 유형을 지원한다고 선언하거나 차트 범위를 확대하지 않는다.

## 4. 원본 좌표와 문단을 먼저 복원

### 4.1 좌표 상속

1. 슬라이드에서 명시한 위치·크기를 우선 사용한다.
2. 생략한 정보는 해당 placeholder의 layout에서 찾고, 이어 master에서 해석한다.
3. 기존 PptxTypographyResolver의 관계 파싱 캐시와 placeholder 매칭을 재사용한다. layout의 idx 매칭과 master의 대응 타입 매칭을 구분한다.
4. 일부 위치/크기만 있는 변환, 회전·flip, 그룹 내부 좌표계를 처리하고 그룹 변환은 한 번만 적용한다.
5. resolved geometry의 출처와 sourceBlockId를 연결한다. 임의 기본 사각형으로 누락을 숨기지 않는다.
6. 현재 자료에서 누락된 22개 모두 해석되는지 확인한다. 상속 체인에도 없으면 영향을 받는 페이지와 객체를 명시한다.

### 4.2 원본 배치 계획

ComposerSlidePlan에 원본 배치용 필드를 추가한다(가칭 source_placements). 각 항목은 원본 block ID, 객체 순서, 사각형, 실제 문단/run 범위, 표/이미지 식별 정보를 갖는다. 원본 데이터는 immutable manifest가 권위이며 이 필드는 결정적 투영이다.

- template용 process/comparison 그룹은 원본 상자의 좌표·문단 경계를 대체하지 않는다.
- rung 5에서는 source_placements만 배치한다. 기존 grouped components와 함께 그려 중복시키지 않는다.
- 원본의 두 단짜리 연혁은 두 텍스트 상자로 되돌린다. 큰 union rectangle 안에 프로세스 카드를 다시 그리지 않는다.
- 실제 PPTX a:p는 문단, a:r/a:fld는 문단 안의 텍스트·서식, a:br는 줄바꿈으로 처리한다.
- source_runs의 비교용 조각을 새 문단으로 취급하지 않는다. 원본 문자 범위와 기존 SourceRunRef의 binding/range 계약을 연결해 run 소실·중복·순서 변경을 막는다.
- 내용이 같은 문장이 반복될 수 있으므로 문자열 검색으로만 run 위치를 복원하지 않는다.
- 상자 내부 여백, 정렬, 들여쓰기, 행간·문단 전후 간격을 필요한 범위에서 추출한다. 기본 CSS 문단 margin으로 원본보다 높이가 늘어나지 않게 한다.
- 기존 QID 및 readback 기구를 사용하고, 원본 이미지의 occurrence와 crop/비율·배치 정보도 보존한다.
- 글머리표·자동 번호는 원문 문자열과 분리된 표시 정보로 보존한다. 그림 글머리표는 문단의 봉인된 이미지 리소스로 유지하며 본문 이미지 55회와 별도로 집계한다. Wingdings 등의 기호를 일반 글꼴의 같은 문자로 바꿔 표시하지 않는다.

분류기의 넓은 재설계는 선행 조건이 아니다. 우선 원본 대체 단계가 분류 결과 때문에 원본 상자를 잃지 않도록 고친다.

## 5. 병합 표를 끝까지 보존

추출된 rows, gridSpan, rowSpan, hMerge, vMerge, mergedCells를 표 계획까지 유지한다. 원본 열 너비와 행 높이도 추출해 균등 열 분배로 인한 불필요한 줄바꿈을 방지한다.

- 논리 그리드의 405셀과 화면의 td/th 개수를 구분한다. 병합 영역은 anchor 셀 하나를 그리고 덮인 셀은 중복 렌더링하지 않는다.
- covered cell에 내용이 있으면 버리지 않는다. 원본 표시 규칙과 콘텐츠 보존 계약에 맞춰 처리하고 모순 데이터는 명시적 오류로 보고한다.
- DOM은 rowspan/colspan과 열 너비를 사용한다. 표의 원본 병합 범위와 셀별 값·문단 순서를 검증한다.
- 기존 authored-hybrid/native-table.ts의 mergedCells 및 grid 검증 계약을 재사용한다.
- HTML만 병합하고 semantic/native export에 전달하지 않는 부분 구현은 완료로 보지 않는다. 원본 문단·run·논리 표 그리드를 최종 DOM에 보존하고 같은 데이터를 semantic/native export로 투영한다. 기존 단일 문단·run 텍스트 수집기로 복원 구조를 다시 평탄화하지 않는다. 새 표 계약은 버전으로 구분하며 기존 계약을 소급 완화하지 않는다.
- source block / row / column 기반의 안정된 식별을 유지한다. 병합 때문에 DOM 수가 줄어드는 것을 콘텐츠 손실로 잘못 판정하지 않는다.
- 현재 텍스트 readback만으로 표 셀 보존을 증명하지 않는다. 표 값·병합 범위·이미지 occurrence에 대한 확인을 별도로 연결한다.

## 6. 7px 맞춤 정책

### 6.1 적용 범위와 공통 계산

새 Composer source-content 작업에 서버 소유 맞춤 정책을 저장한다(가칭 composer-source-fit/v2). font_floor_px=7.0, 적용 시점은 overflow 발생 후이다. 수치 기준은 최종 캡처 캔버스의 computed font-size이다.

기존 공개 입력에 임의 엔진 선택 스위치를 추가할 필요는 없다. 작업 payload에 정책 revision과 유효 하한을 저장하고 워커·재시도·게시·내보내기가 같은 정책을 읽는다. 기존 작업의 정책은 소급 변경하지 않는다.

모든 크기 계산은 동일한 함수와 단위를 쓴다. 원본 pt → CSS px → source canvas scale → 허용된 개별 축소 → 최종 7px clamp 순서로 계산한다. table cell과 inline run에도 적용한다. 글꼴이 없는 객체에는 적용하지 않는다. 제목도 해당 상자가 넘칠 때만 축소 대상이다.

CSS transform, zoom 또는 최종 페이지 축소로 7px 아래로 내려가는 우회를 허용하지 않는다. 픽셀 기반 7px 하한을 전역 Authored 9pt/9.5pt 정책에 무조건 덮어쓰지 않는다.

### 6.2 배치와 축소 순서

1. 기존 template rungs로 구성하되 크기를 유지할 수 있는 배치를 우선한다.
2. 맞지 않으면 원본 상자·문단·병합 표를 복원한 rung 5로 이동한다.
3. 원본 간격을 복원하고 불필요한 장식 여백을 줄인 뒤 실제 Chromium으로 판정한다.
4. 측정에서 넘치는 상자/표를 특정해 해당 부분의 글자 크기를 단계적으로 줄인다. 페이지 전체의 글자를 즉시 줄이지 않는다.
5. 원본 크기 후보 이후 필요한 영역의 7px 후보를 우선 확보하고, 통과하면 남은 렌더 예산에서 더 큰 크기를 탐색한다. 후보는 상자/표별 배율로 생성하되 각 run의 최종 크기를 7px 이상으로 clamp한다. 실제 검사한 후보 중 가장 큰 통과 크기를 선택한다. 배율만 낮아지고 clamp 때문에 실제 출력이 같으면 다시 렌더링하지 않는다.
6. 7px 후보까지 확인하고도 내용이 잘리면 성공으로 처리하지 않는다. 문제 페이지·블록·최소 적용 크기를 남긴다.

현재의 고정 10% 축소만으로 하한까지 도달한다고 가정하지 않는다. 기존 렌더 예산 안에서 원본 배치 진입과 최소 크기 후보에 필요한 측정을 우선 확보한다. 부족하면 중간 template 후보 탐색을 줄이고, 통과하지 않은 결과를 예산 소진만으로 승인하지 않는다. 최대 후보 수와 탐색 순서는 FitReceipt에 기록한다.

### 6.3 저장·내보내기 일치

- publish_semantic._declared_size_pt와 browser-source.ts의 최소 9pt 보정을 함께 처리한다.
- 측정기는 실제 computed size를 기록하고, 제품의 허용 하한은 정책 검증에서 판단하는 것이 원칙이다. 과거 semantic bundle의 9pt 정규화 계약은 버전으로 구분해 기존 export와 충돌하지 않게 한다.
- 7px를 단순히 9pt로 올려 저장하지 않는다. canonical canvas의 7px는 5.25pt이며, native PPTX에는 캔버스 변환이 반영된 크기가 전달되어야 한다.
- 관련 semantic/native table 스키마에 6pt 등의 하한이 있는 경로는 사용 여부를 추적한 뒤 해당 계약을 버전 단위로 조정한다. 저장값만 바꾸고 관측값이 예전 보정을 유지하는 상태를 피한다.
- 낮은 글꼴 크기는 허용된 품질 정책으로 표시한다. clipping, off_canvas, 누락 검사는 그대로 유지한다.
- 최종 HTML 확정 이후에는 보정하지 않는다. 다른 후보를 선택하면 그 후보를 다시 캡처·검증해 HTML/PNG/측정값/semantic digest를 일치시킨다.

## 7. 분석 버전·실패 작업·오류 전달

- 좌표·문단·표 payload 변경 시 MANIFEST_ID_EXTRACTOR_REVISION을 갱신한다.
- 새 manifest는 sourceLayoutVersion을 명시하고, 새 맞춤 정책은 이 capability가 없는 옛 pin에 재분석 필요 오류를 반환한다. 과거 manifest의 생략 필드를 새 null 값으로 채워 digest를 바꾸지 않는다.
- 재분석은 새 manifest ID/digest를 만든다. 기존 sealed manifest를 덮어쓰거나 digest 검증을 생략하지 않는다.
- 이미 실패한 작업은 옛 manifest와 옛 정책을 참조한다. 단순 재시작으로 새 분석 결과를 사용한다고 안내하지 않는다.
- 기존 원본 첨부를 재사용해 재분석 후 새 작업을 만드는 제품 경로를 사용한다. 기존 첨부 수명/접근 권한을 유지하고, 오래된 pin을 발견하면 재분석이 필요하다는 명확한 메시지를 준다.
- ComposerRenderError를 일관된 ComposerPipelineError 계열/실패 매핑으로 연결한다. 잘못된 geometry/plan은 재시도하지 않고, 브라우저 일시 오류 등만 기존 재시도 정책을 따른다.
- 실패 기록에는 slideIndex, sourceBlockId, stage/rung, code, 유효 정책과 적용 크기를 담는다. 원문/개인 정보는 넣지 않는다.
- 실패가 있어도 진단 receipt를 남긴다. 독립된 오류 상속 때문에 receipt가 누락되거나 동일 입력을 세 번 실행하는 현상을 막는다.

## 8. 구현 순서와 완료 기준

검토에서 확인한 연결 누락은 다음 계약으로 보완한다.

- 원본 block ID → 원본 배치 항목 → DOM QID → 측정 오류 → 축소 대상의 연결을 유지한다. 기존 grouped component 기반 오류 식별만 재사용해 다른 상자를 줄이지 않는다.
