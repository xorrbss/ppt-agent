# Authored 편집형 익스포트 복구 설계

상태: 설계 초안. 사용자 요청에 따른 설계 문서이며 제품 코드·런타임 설정 변경은 포함하지 않는다.
개정: 검토의 여섯 가지 지적을 반영했다. 아래 신규 계약은 구현·검증 전 제안이다.
범위: 기존 Authored public export 경로의 모드 전달, 실행 파일 수명, 편집 조작성, 비용 관측.

## 1. 목표와 판단 기준

사용자가 편집형 PPTX를 요청하면 본문 텍스트와 지원되는 도형을 실제 PowerPoint 개체로 전달한다. 사진과 장식의 이미지 사용은 허용한다. 이미지가 존재한다는 이유만으로 실패시키거나, 숨겨진 의미 소유권 개체가 있다는 이유만으로 편집 가능하다고 판정하지 않는다.

우선 고칠 문제는 전체 이미지형으로의 자동 대체, 실행 중 파일 만료, 투명한 전체 화면 그림의 선택 방해다. 성능은 이 결함을 제거한 뒤 단계별 비용으로 판단한다. 생성 프롬프트·모델 변경, 생성 시 사전 변환, 새로운 저장소·작업 체계, 동시성 확대는 첫 단계 범위 밖이다.

## 2. 근거와 미확인 범위

이번 세션에서 확인한 100페이지 작업 기록:

| 항목 | 관측 |
| --- | --- |
| 편집형 요청의 전체 이미지 대체 | 요청 editable-hybrid, 전달 fidelity-raster, 사유 hybrid_job_wire_limit |
| 조립기 입력 한도 | 기존 1 MiB, 앞선 복구에서 8 MiB로 변경 |
| 복구 작업 총 경과 | 약 28분 57초, retryCount=1 |
| 최종 성공 시도 | operationWallMillis=644780, exportWorkerMillis=602226 |
| 최종 파일 | 100페이지 중 95페이지 텍스트 존재; 14·88·98·99·100페이지 이미지 전용 |
| 래스터 대체 요소 | 467개 |

첫 시도는 약 18분 후 실패했으며 워커 로그에 public_worker_artifact_expired가 존재한다. 다만 실패 이벤트와 해당 로그의 정확한 연결, 만료된 파일의 입출력 구분, TTL 값과 복사 시각 보존 여부는 구현 시작 시 좁게 재확인한다. 로그의 단일 오류만으로 모든 소요 시간을 설명하지 않는다.

operationWallMillis는 여기서 최종 성공 시도 값이다. 전체 사용자 대기 시간과 혼동하지 않는다. render_execution_count=0은 승인 PNG 재사용 경로의 계수이며 하이브리드 조립기 내부 Chrome 작업이 없었다는 의미가 아니다. artifact_cache_hit_count=0 역시 페이지 변환 캐시나 최종 결과 재사용 부재를 증명하지 않는다.

과거 생성 품질 대비 저하의 인과, 단계별 Chrome 소요 시간, 수십 초 재익스포트 가능 여부는 미검증이다. 이번 설계의 성능 약속으로 사용하지 않는다.

## 3. 기존 경계 재사용

- `services/public_export_operation.py`: canonical export identity, 진행 작업 합류, 완료 결과 재사용, 리비전·fence를 유지한다.
- `workers/public_export_worker.py`, `workers/public_export_hybrid.py`: Chrome과 OOXML 조립을 격리 워커 안에 둔다. API/Core에서 실행하지 않는다.
- `services/trusted_executor/wire_transport.py`, `workers/public_worker_store.py`: 승인된 artifact reference, 경로·소유자·digest·size 검증과 작업 전용 입출력 디렉터리를 사용한다.
- `scripts/public-hybrid-export-worker.mjs`, `lib/authored-hybrid/slide-layer.ts`: 기존 페이지별 변환과 예산 스케줄러를 사용한다.
- `lib/authored-hybrid/pptx-assembler.ts`: 기존 z-band 정렬, 슬라이드 배경 XML, 관계 정리 로직을 확장한다. 이 파일의 현재 미커밋 변경을 먼저 확인하고 보존한다.
- 기존 durable operation result와 quality receipt를 확장한다. 병렬 상태 테이블이나 별도 익스포트 API는 만들지 않는다.

위 경로는 각각 `servers/fastapi/` 또는 `servers/nextjs/` 아래에 있다. 기존 durability 문서는 candidate 계약이므로 그 문서만을 근거로 DB 마이그레이션이나 저장소 교체를 수행하지 않는다.

## 4. 요청 모드와 전달 결과

### 4.1 계약

| 요청 / 결과 | 동작 |
| --- | --- |
| fidelity-raster / 이미지형 | 기존 명시적 이미지형 익스포트 유지 |
| editable-hybrid / 필수 편집 대상 보존 확인 | 성공. 래스터 요소·편집 범위는 결과에 기록 |
| editable-hybrid / 일부 필수 편집 대상이 이미지 또는 선택 불가 | 부분 편집 결과로 완료. 해당 페이지·대상·사유를 다운로드 옆에 표시 |
| editable-hybrid / 모든 필수 편집 대상이 이미지 | 편집형 실패. 이미지형 파일을 편집형 성공 결과로 게시하지 않음 |

부분 편집 결과와 전체 이미지 대체를 구별한다. 현재 사용자의 이미지 페이지 보고 요구를 유지하며, 부분 편집 결과를 자동으로 폐기하지 않는다. 사용자가 이미지형을 별도로 선택하면 기존 이미지형 경로를 호출할 수 있다.

판정 모수는 7절의 원본 필수 편집 대상이다. 페이지 번호만 네이티브인 문서를 편집형으로 인정하지 않는다. 원래 사진만 있는 페이지는 이미지 전용으로 보고하되 편집성 실패로 계산하지 않는다. 문서 전체에 편집 대상이 없으면 해당 없음으로 표시한다. 증거 부족은 확인 필요로 표시하고 검증된 편집형 성공으로 표시하지 않는다. 작업 완료와 품질 판정은 분리하며 새 작업 상태 enum 대신 기존 result/quality receipt의 호환 가능한 확장을 우선한다.

### 4.2 적용 지점

워커가 실제 전달 모드·대체 사유를 반환하는 기존 증거를 보존하고 `PublicExportHybridFallback` 처리에서 자동 `run_canonical(hybrid=False)` 후 성공 게시하는 동작을 제거한다. 실패한 편집형 identity는 완료로 봉인하지 않는다. 이미 존재하는 이미지형 성공 identity와 파일은 변경하지 않는다.

작업 결과와 웹 다운로드 표시가 같은 전달 증거를 읽어야 한다. 폴백 사유는 내부 실패 영수증에 보존하고 화면에는 간결한 설명과 재시도 가능 여부를 제공한다. 결정적 입력 크기 오류는 같은 입력으로 자동 반복하지 않는다.

### 4.3 입력 경계

8 MiB 확장은 기존 복구로 유지하되 최선의 영구 해법으로 간주하지 않는다. Python 직렬화 크기와 Node 수신 제한을 같은 단위의 UTF-8 바이트로 검사하고 한도 초과를 실행 전에 명확히 반환한다. 한글 JSON의 ensure_ascii 인코딩 팽창도 검사 대상이다. 외부 번들과 내부 조립 요청의 크기는 서로 다른 값이므로 같은 상수만으로 안전하다고 판단하지 않는다.

8 MiB를 넘는 합법적 입력이 재현될 때만, 기존 검증된 scratch 내 그래프 파일 참조 방식으로 옮기는 후속 설계를 검토한다. 임의 호스트 파일 경로 접근은 허용하지 않는다.

### 4.4 오류·재시도·캐시 결정표

| 조건 | 전달 및 재시도 | 캐시·게시 처리 |
| --- | --- | --- |
| 직렬화 바이트 한도 초과 | 같은 입력 자동 재시도 금지 | 편집형 실패 유지; 이미지형 전환 금지 |
| semantic binding, digest, size, owner 무결성 실패 | 같은 입력 자동 재시도 금지 | 결과 게시·캐시 채택 금지 |
| 일시적 워커 실행 오류 | 기존 횟수·deadline 예산 안에서만 재시도 | 성공한 현재 attempt만 게시 |
| dispatch 전 유휴 캐시 만료 | 권위 있는 원본에서 한 번 재확보; 원본 없으면 실패 | 검증한 새 reference로 바인딩 |
| admission 후 활성 파일 만료·퇴거 | 수명 계약 결함으로 기록; 같은 경로 반복 재시도 금지 | 해당 attempt 게시 금지; 원본 재확보 가능할 때만 기존 예산 내 복구 |
| stale revision, fence 불일치, 취소 | 오래된 실행 재시도·게시 금지 | 현재 작업 authority만 결과 채택 |
| 전체 필수 편집 대상 래스터화 | 편집형 실패; 자동 재시도 금지 | 파일 생성 성공을 편집형 완료 캐시로 봉인하지 않음 |
| 부분 편집 결과 | 완료 상태와 부분 편집 판정 함께 전달 | 같은 identity는 경고 포함 재사용; 명시적 재시도 또는 입력·정책 변경 때만 재실행 |
| 과거 캐시의 편집성 증거 부족 | 기존 파일 재검증이 가능하면 재검증, 아니면 cache miss | 원본 보존; 새 기준 통과로 간주하지 않음 |

워커부터 `workspace_quality_export_operation_handlers.py`의 상위 재시도 분류와 웹 표시까지 같은 결정을 유지한다. 실패 identity를 성공으로 덮어쓰지 않는다. 명시적 재시도는 기존 authority를 사용하고 singleflight를 우회하지 않는다. 정책·조립 계약 변경은 canonical identity에 반영한다. 완료 캐시에도 현재 revision·owner·파일 무결성·품질 증거를 검사한다.

## 5. 실행 중 파일 수명

`LocalContentAddressedStore.verified_path`는 현재 파일 mtime과 TTL로 읽기를 거부한다. 실행 중인 작업의 유효성과 유휴 캐시의 보존 기간을 별도로 다룬다.

1. dispatch 시 기존 승인된 reference 목록으로 입력 파일을 작업 전용 경로에 stage한다.
2. 이미 admission을 통과한 입력은 해당 실행의 deadline·취소·fence 경계까지 읽을 수 있게 한다. 원본 파일 mtime만으로 유효한 작업의 읽기를 거부하지 않는다.
3. 유휴 캐시 TTL은 작업 완료·회수 이후의 정리 정책으로 유지한다. 공유 캐시의 파일을 재사용한다면 활성 참조를 기존 supervisor 수명에 결합하고 활성 파일은 eviction에서 제외한다.
4. 출력은 활성 실행 중 생성·소비·게시 구간에서 보호한다. 결과 digest·size 검증과 게시 fence는 유지한다.
5. 크래시·시간 초과·취소 시 supervisor가 자식 프로세스를 회수하고 작업 경로를 정리한다. 무기한 pin이나 전역 TTL 해제는 금지한다.

새 DB lease를 먼저 추가하지 않는다. 기존 작업별 staging 소유권만으로 충분한지 확인하고, 공유 경로일 때만 최소 pin 수명 관리를 보완한다. 데이터 보존 만료와 cache TTL은 서로 대체하지 않는다.

보호는 TTL뿐 아니라 바이트 용량 기반 LRU 퇴거에도 적용한다. 현재 `_evict(protected=path)`의 단일 경로 보호로는 다중 입력·출력을 보장할 수 없다. 작업 staging이 캐시 퇴거와 분리돼 있으면 그 소유권을 사용한다. 공유 저장소라면 supervisor가 관리하는 활성 경로 집합과 참조 수를 TTL/LRU 양쪽에서 확인한다. 경로·소유자 검증은 유지한다.

admission에서 입력 총량과 유한한 출력 예약량을 확보한다. 출력 예약은 wire 크기가 아닌 디스크 작업량 기준이다. 초기 수치는 기존 작업 예산과 관측 파일 크기를 확인해 B 단계 구현 전에 명시한다. 용량이 부족하면 기존 대기 예산 안에서 기다리거나 용량 부족으로 실패한다. 일부 파일만 pin한 채 나머지 용량을 무기한 기다리지 않는다. 출력 예약 초과 시 추가 예약에 성공한 뒤 기록하거나 명시적으로 중단한다. 활성 파일 삭제나 무제한 pin으로 해결하지 않는다.

출력은 게시 검증과 최종 저장소 인계까지 보호한다. 취소·크래시·deadline 회수 시 참조와 예약량을 한 번만 반환한다. 공유 파일은 마지막 활성 참조 해제 후 유휴 정책에 들어간다. 구현 전 만료 파일 종류와 실제 정리 주체를 확인해 필요한 경로만 수정한다.

## 6. PowerPoint 선택 조작성

### 6.1 배경

기존 `backplateBackgroundXml` 경로를 확장한다. 현재 RGB PNG 조건만으로 전체 사례를 포괄할 수 없으므로, 색상 타입보다 paint 의미와 실제 alpha를 검사한다.

슬라이드 최하단이며 본문·사용자 편집 대상이 아닌 배경만 `p:bg`로 옮긴다. 기존 네이티브 배경과의 중복 및 합성 순서를 확인한다. 텍스트가 구워진 이미지나 중간 z-band를 이름만 보고 배경으로 옮기지 않는다. 모든 이미지를 맨 뒤로 보내지 않는다.

배경 승격은 합성 의미가 확인된 최하단 밴드에만 적용한다. 해당 밴드를 승격했다고 다른 중간·상단 밴드까지 출력에서 제외하지 않는다.

### 6.2 중간 래스터 레이어

- 디코딩된 PNG에서 alpha>0인 픽셀의 경계를 계산한다. 완전히 투명한 밴드는 시각 리소스에서 제외한다.
- PNG를 무손실 crop하고 원래 좌표를 유지한다. xEmu=xPx/captureWidthPx*slideWidthEmu, y와 크기도 같은 비율을 사용한다. 캡처 배율을 고정값으로 가정하지 않는다.
- 원래 zBand 및 같은 밴드 내부 순서를 유지한다. 그림자와 안티앨리어싱 픽셀을 임계값으로 임의 삭제하지 않는다.
- 원본 캡처 digest와 crop 산출물 digest·rect를 구분해 기존 검증 증거에 반영한다. crop 결과를 원본 PNG digest와 비교해 오류를 무시하는 방식은 사용하지 않는다.
- 단일 사각 crop 내부의 큰 투명 공간도 클릭을 가로챌 수 있다. 네이티브 텍스트 위를 가로지르면 기존 paint 소유 단위를 활용해 공간적으로 분리할 수 있는 조각으로 나눈다. 조각 수·바이트 상한을 둔다.
- 상한 때문에 분리가 불가능한 경우 조작성 미달 페이지와 사유를 보고한다. crop을 수행했다는 이유만으로 조작성 통과를 선언하지 않는다.

반투명 장식이 실제로 본문 위에 그려지는 경우에는 시각 일치와 직접 선택이 충돌할 수 있다. 그런 페이지는 별도 결함으로 남기고 해당 요소의 네이티브화나 의미에 맞는 재구성이 필요하다. 무조건 뒤로 보내거나 잠금 지원을 가정하지 않는다.

### 6.3 밴드·조각 데이터 계약

현재 `rasterBands`는 밴드마다 전체 캔버스 PNG 하나를 받고, 조립기는 고유한 오름차순 zBand와 전체 캔버스 크기를 요구한다. crop PNG를 기존 필드에 그대로 넣거나 동일 zBand 항목을 여러 개 만들지 않는다.

새 구조는 고유 zBand를 가진 밴드 아래 조각 목록을 둔다. 밴드는 원본 capture 크기·digest와 semanticOwnerQids를 소유한다. 조각은 밴드 내 고유 id, 안정적인 순서, 원본 캡처 좌표의 정수 rect, PNG reference 또는 기존 내부 Buffer, digest·size를 가진다. PNG 크기는 rect와 일치하고 rect는 캔버스 내부여야 한다. semantic ownership은 밴드 수준에서 한 번만 처리하며 조각마다 복제하지 않는다.

첫 구현은 완성된 밴드 PNG를 겹치지 않는 사각 영역으로 나눈다. alpha>0인 모든 픽셀은 정확히 한 조각에만 속하고 원래 위치에 합성한 결과가 원본과 같아야 한다. 소유 단위는 분할 경계를 찾는 데만 사용한다. 반투명 픽셀을 두 번 합성하지 않으며, 이 제약으로 선택 방해를 제거할 수 없으면 미달로 보고한다. 완전 투명 밴드는 시각 조각 0개로 처리하되 의미 소유권 검증은 유지한다.

조각 수·총 PNG 바이트 제한은 작업 예산에서 페이지별로 배분한다. 초기 상한 수치 확정은 C 단계 구현 진입 조건이다. 초과 시 기존 밴드를 유지하고 선택 방해 경고를 반환하며 조각을 누락하지 않는다. 기존 전체 PNG는 어댑터에서 전체 rect 조각 하나로 정규화한다. 새 구조는 버전으로 구분하고 조립기 크기 검사·관계 정리·digest 검증을 함께 변경한 뒤 exporter identity를 갱신한다. 구버전 수신기에 새 구조를 보내지 않는다.

## 7. 편집성 및 품질 증거

페이지별로 visible native text/shape, image-only, raster fragment, selection obstruction, visual comparison 결과를 분리한다. XML 네임스페이스로 읽고 문자열 `<a:t>` 검색만으로 판정하지 않는다. hidden semantic owner, 빈 텍스트, 화면 밖 증거 개체는 편집 가능한 본문으로 세지 않는다.

변환 전 원본 semantic graph에서 제목, 본문, 표 셀, 그룹 내 텍스트, 페이지 번호·장식, 지원 편집 도형을 구분해 필수 편집 대상 목록을 만든다. 콘텐츠 대상 id와 정규화 텍스트를 출력 개체에 대응시킨다. 페이지 번호·장식은 본문 보존의 분모와 분자에서 제외한다. 역할이 없는 입력은 근거 있는 추출 결과를 사용하고 구분할 수 없는 대상은 unknown으로 남긴다.

대상별 결과는 네이티브 대응 확인, 래스터화, 누락, 가림·선택 방해, 미확인으로 기록한다. native 대응은 텍스트 보존과 화면 내 렌더링을 확인해야 한다. 위쪽 이미지에 완전히 가려진 텍스트는 편집 가능 대상으로 세지 않는다. 부분 가림·선택 방해도 별도 결함이며 증거가 부족하면 미확인으로 남긴다.

페이지별로 본문 대상 보존 수/전체 수와 제목·표 결과를 따로 보고한다. 모든 필수 대상이 보존돼야 완전 편집 판정을 부여하며 임의의 텍스트 개수·비율 임계값으로 통과시키지 않는다. 변환 전후 누락도 확인한다. 구조상 실패와 증거 부족을 구별하고 실제 PowerPoint 조작성 확인 여부는 별도 필드로 유지한다.

텍스트 XML 존재는 실제 편집 검증의 대체물이 아니다. 대표 본문을 PowerPoint에서 선택·변경하고 별도 복사본에 저장한 뒤 재열어 변경 텍스트와 주변 레이아웃을 확인한다. 사용자 원본 파일은 변경하지 않는다.

이미지 전용 페이지는 1-based 번호로 보고한다. 페이지 전체 래스터 존재 수와 이미지 전용 페이지 수를 별개로 표시한다. 생성 품질 passed, export 구조 검증, 편집 조작성, 시각 일치, 작업 완료는 독립 판정으로 유지한다.

## 8. 성능 관측과 후속 조건

기존 영수증에 attempt별 elapsed와 전체 operation elapsed를 구분한다. 최종 성공 시도 시간만으로 사용자 대기 시간을 설명하지 않는다.

페이지별 측정: 글꼴 수집, DOM 추출, 네이티브 레이아웃 준비, 배경 캡처, paint-band 캡처 횟수·시간·바이트. 문서별 측정: 대기, staging, 조립, 임베딩, 검증, 게시, 브라우저 launch/reuse, 최고 메모리, 재시도 원인.

병렬 작업의 시간 합은 wall time과 구별한다. 페이지 번호·단계·집계 시간만 영수증에 저장하고 HTML·본문·절대 경로는 넣지 않는다. 최소 계측 D0를 모든 동작 변경보다 먼저 적용한다. 기존 영수증은 총/attempt 기준선으로 보존하며 과거 단계별 값을 소급 추정하지 않는다. 기준선만을 위한 100페이지 추가 실행은 하지 않고 이후 승인된 실행에서 새 항목을 수집한다.

현재 Python 워커는 `process.communicate(payload)` 완료 후 stdout 마지막 줄의 최종 JSON을 해석한다. Node 중간 로그만으로 실시간 웹 진행률은 전달되지 않는다. 첫 구현은 제어기가 실제 관측한 staging·worker 실행·검증·게시 전환만 표시한다. worker 내부 N/전체는 최종 영수증에만 집계하며 실행 중 추정 진행률로 표시하지 않는다. 계측 누락은 0이 아닌 미측정으로 기록한다.

페이지별 실시간 진행은 후속 범위다. 필요성이 확인되면 기존 subprocess 경계에 버전 있는 제한된 JSONL event 통로를 설계한다. operation/attempt/fence, 단조 sequence, 단계·완료 수, 크기·빈도 제한, stdout/stderr 동시 소비, 취소·deadline 전파가 필수다. 재시도 진행은 이전 attempt와 분리하고 오래된 이벤트를 폐기한다. 진행 이벤트는 게시 권한을 갖지 않으며 최종 검증된 result만 완료를 확정한다. 이 프로토콜 구현 전에는 페이지별 실시간 진행을 제공한다고 약속하지 않는다.

판단 순서:

1. 동일 identity 재익스포트가 기존 완료 결과를 실제 재사용하는지 확인한다.
2. 한 번의 성공 실행에서 가장 큰 비용 항목을 확인한다.
3. Chrome 시작 비용이 클 때만 격리 워커 내부에서 브라우저를 재사용한다. 작업 간 세션·페이지 상태는 공유하지 않는다.
4. 변경된 덱에서 미변경 페이지 재처리가 주요 비용일 때 페이지 캐시를 추가한다. 키에는 owner/tenant, HTML·semantic·자산 digest, canvas, font, renderer/exporter, 정책 버전이 포함돼야 한다. 다른 operation의 artifact를 새 작업 참조로 게시하는 기존 authority 경계를 거친다.
5. 장시간 실패에 따른 재작업이 여전히 클 때만 기존 checkpoint authority에 페이지 변환 결과를 연결한다. 10~20페이지 고정 배치 크기나 새 상태 저장소를 선결정하지 않는다.

수십 초·특정 배수의 속도 목표는 측정 전 약속하지 않는다. 우선 기준은 유효한 입력이 실행 중 만료되지 않음, 모드 불일치 없음, 동일 identity 결과 재사용이다.

## 9. 구현 순서와 검증

| 단계 | 변경 | 가장 좁은 검증 |
| --- | --- | --- |
| D0 | 최소 단계 계측·관측 가능한 진행 표시, 기존 시간 근거 보존 | 기존 worker receipt 검사에서 attempt/총 경과·미측정·크기 제한 확인 |
| A | 본문 기준 전달 모드 계약·오류/UI 결과, 내부 입력 크기 검사 | 기존 모드 대체/worker wire 관련 테스트에서 실패 전달과 부분 편집 분기 확인 |
| B | 활성 입력·출력 수명과 용량 예약 | 기존 store/transport 검사에서 TTL/LRU 보호와 회수 확인 |
| C | 밴드 아래 조각 구조·배경·crop·선택 충돌 | 기존 assembler 검사에서 합성·좌표·소유권·digest 보존 확인 |
| E | 실제 제품 경로 확인 | 동일 100페이지 덱 한 번 익스포트, 파일/receipt digest 대조, PowerPoint 본문 편집·재열기 및 대표 레이어 시각 비교 |

각 변경 후 직접 관련된 좁은 검사 하나를 선택한다. 전체 테스트·빌드·린트를 자동 실행하지 않는다. E는 구현 완료 후의 제품 수용 검증이며 별도 장시간 성능 실험은 필요할 때 범위를 정한다.

각 단계의 기존 좁은 검사에 포함할 필수 사례:

- A: 실제 전송 직렬화 기준 8 MiB 직전·동일·초과와 한글 입력, 잘못된 reference, 페이지 번호만 네이티브인 경우, 표·그룹 본문, 가려진 텍스트, 정당한 사진 전용 페이지, 증거 없는 과거 캐시·부분 편집 캐시, 오류별 재시도와 fence 거부.
- B: 오래된 mtime, 활성 다중 입력·출력의 용량 퇴거, 예약 부족·출력 초과, 공유 참조 해제, 취소·크래시 회수, owner·digest 변조 거부.
- C: 다중 zBand의 최하단만 배경 승격, 반투명 그림자·빈 밴드 소유권, 조각 겹침·누락 거부, 세로 캔버스·다른 capture 배율, 구버전 전체 PNG 어댑터.

E의 실제 제품·PowerPoint·시각 검증은 구현 후 실행 범위를 명시해 진행한다. 이번 설계 개정에서는 실행하지 않는다. 전체 덱 구조 증거와 대표 페이지 실제 편집·시각 검증 범위를 구별해 보고한다. 단계별 시간은 동일 입력·환경 근거가 있는 항목만 비교하고 근거가 없으면 속도 개선 판정을 보류한다.

실제 결과에 필요한 기준:

- 웹에서 편집형 선택 시 전체 이미지 파일을 성공으로 자동 다운로드하지 않는다.
- 일부 페이지 대체는 파일과 화면 모두 같은 페이지 목록·사유를 표시한다.
- 본문·표 누락 및 래스터화가 페이지 번호에 가려지지 않는다. 미확인은 통과로 표시하지 않는다.
- 활성 아티팩트 TTL/LRU로 인한 재시도가 없다. 용량 예산과 크래시/취소 시 회수가 유지된다.
- 대표 본문 클릭·편집·저장·재열기 성공. 숨겨진 소유권 개체만으로 성공 판정하지 않는다.
- 배경·crop 변경 후 디자인 합성이 보존되고 투명 전체 화면 그림에 의한 클릭 가로채기가 없다. 잔여 충돌이 있으면 해당 기준은 미통과다.
- 동일 identity 재사용과 변경 identity 무효화가 유지된다.
- 결정적 오류는 반복하지 않고 일시적 오류는 기존 재시도 예산을 준수한다. 오래된 fence 결과는 게시하지 않는다.

## 10. 적용 및 되돌리기

기존 dirty checkout을 보존하고 각 단계 변경 파일만 분리한다. 렌더러/조립 결과 의미가 바뀌면 기존 exporter bundle identity와 정책 버전에 반영해 옛 파일을 새 검증 결과로 재사용하지 않는다.

코드 실행 경로에 맞는 워커 또는 서비스만 managed local stack으로 재시작한다. schema migration은 현재 설계에 필요하지 않다. 배경/crop 시각 검증 실패 시 해당 단계 변경만 되돌리고 모드 불일치 차단과 TTL 수정은 유지한다. 기존 문서·아티팩트·다른 세션 변경은 롤백 대상이 아니다.

완료 보고는 실제 전달 모드, 편집/이미지 전용 페이지 수, 선택 방해 잔여 페이지, 시도 횟수와 총/성공 시도 시간, PowerPoint 검증 결과로 구성한다. 품질 복구 완료는 이 기준을 충족한 뒤에만 선언한다.
