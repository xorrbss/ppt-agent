# Authored 원본 보존형 비LLM 보정 설계

- 작성일: 2026-09-08
- 설계 revision: **v1.2 — 슬라이드별 완료·증거 재사용·동일 결과 탐색 최적화 반영**
- 상태: v1.2 기준 설계. 관련 구현은 진행됐으나 이 문서의 모든 완료 조건이 검증됐다는 뜻은 아니다.
- 후속 설계: [v1.3 상위 영역 세로 재배분 설계](authored-local-fit-parent-reflow-design-20260908.md). 이번 요청은 해당 문서의 1~3단계 설계까지이며 구현·벤치 실행은 포함하지 않는다.
- 대상: 일반 authored 신규 생성과 사용자가 명시적으로 요청한 해당 모드 재생성
- 핵심: 자유로운 HTML/CSS 저작을 유지한다. 가벼운 여백 보정을 먼저 시도하고, 부족하면 강한 여백 압축과 소폭 글자 축소를 함께 비교한다.
- 글자 기준: **최종 PPT 기준 최소 9.5pt, 최초 저작본 대비 누적 축소 최대 10%.**

## 1. 결정과 근거의 구분

### 사용자와 합의한 제품 방향

1. Deck IR, source-native, 고정 템플릿으로 생성 엔진을 바꾸지 않는다.
2. 원본 디자인을 유지하는 국소 비LLM 보정을 생성 경로에 통합한다.
3. 글자 크기의 소폭 축소를 허용한다. “9pt 이하는 금지”를 만족하도록 앞선 제안의 9.5pt 하한을 채택한다.
4. 가벼운 여백 보정 우선, 문제 영역만 최대 10% 축소, 내용 보존을 적용한다. 과도한 여백 압축을 무조건 우선하지 않는다.
5. 성능 개선은 슬라이드별 보정·검증 통합, 확정 결과 재사용, 중복 측정과 불필요한 후보 평가 제거로 추진한다.
   디자인·내용·글자 하한·검증 범위를 완화하여 속도를 얻지 않는다.

### 이 문서의 구현 결정안

후보 단계, 후보 수, 시간 예산, 그룹 구성, 영속화 형식, 적용 경계와 검증·성능 최적화 방법은 아래의 구현 결정안이다.
구현과 좁은 검증으로 확인되기 전까지 검증된 현재 동작으로 취급하지 않는다.
9.5pt는 기본 목표 크기가 아니라 **절대 하한**이다. 큰 글자를 일괄적으로 9.5pt까지 줄이는 정책이 아니다.

### 실증으로 확인한 범위

벤치 작업트리 `.claude/worktrees/fit-bench-20260907`의 기존 실증:

| run 54 페이지 | 기존 차단 결함 | 수정본 재렌더링 결함 | 텍스트 변경 | 글자 크기 변경 |
| --- | ---: | ---: | --- | --- |
| 1·2, 대조군 | 0 | 0 | 없음 | 없음 |
| 14, 오른쪽 카드 넘침 | 2 | 0 | 없음 | 없음 |
| 19, 표·AI 정책 문구 가림 | 3 | 0 | 없음 | 없음 |

4장 모두 수정 시점과 수정 HTML 재렌더링 시점의 요소 좌표 차이는 0px였다.
이는 **세로 여백 보정의 실증**이며, 9.5pt 하한·10% 축소·PPTX 검증까지 통과했다는 의미가 아니다.
기존 실증은 높이 확장/글자 축소 실패 후 여백 보정을 사용했다. 본 설계는 사용자 합의에 따라
**여백 우선으로 순서를 바꾸므로**, 벤치 코드를 그대로 복사하는 것으로 완료되지 않는다.

근거: 벤치의 `docs/authored-local-spacing-fit-pilot-20260908.md`,
`servers/fastapi/artifacts/local-fit-run54-verified/summary.json` 및 `review.html`.

## 2. 범위와 비범위

### 1차 적용

- 일반 authored HTML의 본문, 표, 프로그램이 저작한 차트 라벨, 주석, 페이지 번호 등 모든 표시 텍스트.
- 일반 흐름의 카드, 목록, 표 형태 그리드, 세로 스택 내부 여백과 높이 문제.
- 부모의 고정 높이 때문에 실제 텍스트가 다음 형제 영역을 침범하는 문제.
- Fidelity 및 Hybrid 내보내기에서 같은 글자 크기 정책을 검증한다.

### 자동 변경하지 않는 대상

- 기존 저장 발표 자료의 일괄 수정, exact reconstruction, source-locked, 원문 재현 경로.
- 다른 생성 엔진, 사용자 편집본의 무단 재배치, 외부 이미지 원본.
- 의도적 겹침, 회전/비균등 변환/일반 절대좌표 텍스트 등 보정 안전성을 아직 입증하지 못한 구조.
  단, §3.5의 검증된 페이지 번호·고정 푸터 슬롯은 제한된 하한 정상화만 허용한다.
- 텍스트 요약·삭제·숨김, 페이지 추가, 차트 데이터나 도형 유형 변경, 전체 슬라이드 축소.

지원하지 않는 구조도 **검사에서 제외하여 통과시키지는 않는다.** 안전하게 수정할 수 없으면
`unsupported_geometry` 또는 `unverifiable_font_size`로 남긴다. 구조가 복잡하다는 이유만으로
이미 정상인 페이지를 실패시키지 않으며, 정책 준수 여부를 측정할 근거가 없는 경우와 구분한다.

## 3. 글자 크기 계약

### 3.1 기준점과 누적 한도

각 텍스트 run의 최초 저작본을 실제 폰트로 측정한 최종-PPT 환산 크기를 `original_pt`로 저장한다.
이 기준은 **보정 이전의 저작 revision**에 묶으며, 재시도·재렌더링·체크포인트 복구가 기준을 재설정하지 않는다.

```text
floor_pt = 9.5
minimum_allowed_pt = max(original_pt * 0.90, floor_pt)

original_pt >= floor_pt:
    minimum_allowed_pt <= final_pt <= original_pt

original_pt < floor_pt:
    final_pt = floor_pt 이상으로 정상화한 뒤 동일 영역을 재배치
    정상화로 새로 커진 크기를 추가 축소 여유로 간주하지 않음
```

| 최초 크기 | 허용 하한 | 의미 |
| --- | ---: | --- |
| 16pt | 14.4pt | 최대 10% 축소 |
| 12pt | 10.8pt | 최대 10% 축소 |
| 10pt | 9.5pt | 최대 5% 축소 |
| 9.5pt | 9.5pt | 축소 금지 |
| 9pt | 9.5pt 이상 | 확대 정상화 필요, 기존 크기로 통과 금지 |

`0.9 × 0.9`처럼 반복 적용하지 않는다. 형제 영역 이동, 그룹 크기 조정, export autofit까지 포함한
최종 크기로 비교한다. 새 저작 revision은 새로운 기준이지만, 단순한 보정 revision은 그렇지 않다.

### 3.2 px와 최종 PPT pt

CSS 표준의 `1in = 96px = 72pt`는 단위 관계다. 프로젝트의 현재 capability 상수도
`AUTHORED_FONT_FLOOR_PX=12.0`, `AUTHORED_FONT_FLOOR_PT=9.0`이다.
그러나 **CSS 값에 0.75만 곱해서 최종 PPT 크기라고 판단하지 않는다.**

균일 배율로 내보내는 경우:

```text
pt_per_css_px = exported_slide_width_pt / rendered_viewport_width_css_px
effective_pt = computed_font_px * effective_text_scale * pt_per_css_px
required_font_px = 9.5 / (effective_text_scale * pt_per_css_px)
```

- `effective_text_scale`에는 텍스트/조상 요소의 시각적 축소를 포함한다.
- 가로·세로 배율이 같은지 확인한다. 다른 경우 단순 환산으로 승인하지 않는다.
- 픽셀 캡처 DPR은 해상도이지 글자 크기 배율이 아니다. DPR을 중복 반영하지 않는다.
- 표준 0.75pt/px 매핑에서는 9.5pt가 약 12.6667px다. 구현의 소수 정밀도에 맞춰 **위로 반올림**한다.
- PPT 텍스트 run의 1/100pt 등 출력 정밀도를 반영하고, 반올림으로 하한을 침범하는 경우 올림한다.
- 글자 하한에는 기하 비교용 0.5px 허용 오차를 적용하지 않는다.

출력 페이지 크기·렌더 viewport·폰트/배율 manifest는 생성 시 확정하여 정책 identity에 포함한다.
내보내기에서 크기나 배율이 달라지면 이전 통과 판정을 재사용하지 않는다.

참조: [W3C CSS 절대 길이 단위](https://www.w3.org/TR/css-values-4/#absolute-lengths).

### 3.3 텍스트 그룹과 위계

그룹은 후보마다 다시 추론하지 않고 최초 측정에서 다음 순서로 한 번 고정한다.

1. 각 텍스트 노드를 가장 가까운 QID 소유자에 귀속한다. run id는
   `(author_revision, owner_qid, text_node_ordinal, start_offset, end_offset)`로 정의한다.
   원문 문자열은 기존 저장소에 두고 기준 레코드에는 내용 digest와 측정값을 연결한다.
2. 그룹 키는 `(수정 영역 qid, 가장 가까운 셀/카드 qid, 정규화된 역할, 원본 스타일 fingerprint)`다.
   fingerprint는 실제 font family, weight, style, 원본 pt, line-height 방식/값, letter-spacing,
   writing-mode를 포함한다. 후보 적용 중 바뀐 스타일로 그룹을 재구성하지 않는다.
3. 서로 다른 카드/셀은 기본적으로 별도 그룹이다. 기존 명시적 반복 그룹 정보가 있고 역할·스타일이
   같을 때만 병합한다. 클래스 이름 유사성이나 문장의 뜻으로 임의 병합하지 않는다.
4. 같은 그룹에 같은 배율을 적용한다. 하한에 걸린 주석과 큰 본문은 원본 스타일이 다르므로
   별도 그룹이다. 한 그룹의 작은 글자 때문에 관계없는 전체 슬라이드 축소가 막히지 않는다.
5. 후보의 글자 배율은 결함을 일으킨 흐름 안의 대상 그룹에 적용한다. 제목·강조 그룹은
   자체 결함이 확인된 경우에만 포함한다. 부모 컨테이너에 font-size나 scale을 일괄 적용하지 않는다.

중첩 span은 각 run의 **최초 computed 크기 × 후보 배율**을 한 번만 투영한다.
자식이 자체 크기를 가지면 해당 값을 명시하고, 상속받는 run도 최종 computed 값으로 확인한다.
DOM을 재구성하거나 span을 추가해야만 가능한 복합 소유자는 1차 버전에서 수정하지 않는다.
고정 px 행간은 글자와 함께 계산하고, 단위 없는 행간은 자연 재계산시킨다. 이중 축소나 glyph clipping은 거절한다.

위계 관계는 같은 내용 영역에서 명시적으로 구분된 `title > body > supporting` 그룹에 한해 만든다.
알 수 없는 역할을 새 LLM 호출이나 텍스트 의미 추론으로 분류하지 않는다. 원본 글자 크기가 큰 그룹 A와
작은 그룹 B의 비율을 `r0`라 할 때 `r0 > 1.01`이면 `final_A/final_B >= max(1.01, 0.90*r0)`를 요구한다.
같은 그룹의 원래 같은 크기는 출력 반올림 정밀도 안에서 같아야 한다. 굵기·색·정렬은 변경하지 않는다.
하한 확대와 위계 조건을 동시에 만족할 수 없으면 하한을 완화하지 않고 `hierarchy_unfit`로 남긴다.
위계 비율의 0.90은 초기 구현 결정안이며 미적 품질이 실증된 수치가 아니다.

### 3.4 하한 정상화와 ‘정상 페이지 무변경’

정상 페이지는 **기하 결함이 없고, 모든 검사 대상 텍스트가 9.5pt 이상인 페이지**다.
이 조건을 만족하면 HTML을 바이트 단위로 그대로 유지한다.
종전 실증에서 정상 판정된 페이지라도 12px/9pt 페이지 번호 등이 있으면 새 정책상 정상화 대상이다.
하한 확대가 다른 카드까지 무제한 재배치하도록 허용하지 않는다. 허용된 국소 영역 안에서
수용할 수 없으면 `font_floor_unfit`로 종료한다. 과거 정상 2장의 무변경 결과를 새 정책의 보장으로 재사용하지 않는다.

### 3.5 페이지 번호·고정 푸터 전용 정상화

이 경로는 일반 절대좌표 본문을 보정하는 예외가 아니라, 지정된 고정 슬롯의 9.5pt 하한을 충족시키는 경로다.

- 서버 소유 헤더/푸터 계약의 명시적 qid·역할·안전 영역이 있거나, 기존 페이지 번호 검출기가
  문서 페이지 순서와 일치하는 번호 및 하단 슬롯을 확인한 경우만 허용한다.
  클래스명 `page` 또는 `supporting` 역할 하나만으로는 충분하지 않다.
- 실제 글자 크기가 하한 미만이면 출력 정밀도로 올림한 9.5pt로 올리고 필요한 line-height만 맞춘다.
- 바닥/중앙 등 기존 anchor, 텍스트, 색·굵기와 주변 요소는 유지한다. 텍스트 상자는 승인된 슬롯
  내부에서만 확장할 수 있다. §5.1의 카드 외곽 잠금과 달리 이 경로는 **슬롯 경계**를 잠근다.
- 본문·그림과 새 충돌이 나거나 안전 슬롯이 없으면 원복하고 `fixed_chrome_unfit`로 종료한다.
- 하한에 도달한 페이지 번호를 다른 카드의 축소 후보에 포함하지 않는다. 적용/거절 이유를 기록한다.
- 페이지 번호 검출기의 최대 글자 크기 조건과 새 하한을 같은 정책에서 조정하여, 정상화 뒤에
  페이지 번호 인식이 사라지거나 footer 안전선이 바뀌지 않도록 한다.
- 신규 생성의 서버 소유 고정 컴포넌트는 확정된 출력 배율 기준으로 처음부터 9.5pt 이상을 생성한다.
  LLM의 본문 디자인을 고정 템플릿으로 바꾸거나 모든 글자를 하한 크기로 강제하지 않는다.
  기존 저작 HTML의 작은 글자를 뒤늦게 바꾼 경우는 여전히 변경본이며, 기준점을 재설정하거나
  무변경으로 분류해 검증을 생략하지 않는다. 기존 저장 자료에는 소급 적용하지 않는다.

## 4. 생성 중 처리 흐름

```text
기존 authored 저작 HTML
  → 실제 폰트·필수 에셋 준비 확인
  → 원본 run/크기/배치 기준점 확보 및 검사
  → 고정 슬롯/일반 텍스트의 하한 정상화 후보
  → 문제 영역별: 가벼운 여백 보정 → 축소·압축·조합 후보 비교
  → 전체 페이지 검사 + 원본 보존 검사
  → 변경된 경우에만 수정 HTML을 fit 없이 독립 재렌더링
  → 동일 수정본의 HTML·PNG·측정값·scene 확정
  → 게시/내보내기
```

`document.fonts.ready`를 기다리되 이것만으로 지정 폰트의 로딩 성공을 간주하지 않는다.
실제 사용 폰트 또는 승인된 대체 폰트의 준비 상태를 확인하고 그 identity를 기록한다.
검사 실패를 완료 이벤트 뒤에 숨기지 않는다. 사용자에게 처음 제공하는 완료본은 검증된 수정본이다.

### 4.1 슬라이드별 완료와 기존 스트리밍 연결

전체 저작 완료를 기다린 뒤 보정을 일괄 실행하지 않고, 각 슬라이드의 완전한 저작 HTML이 준비되면
그 슬라이드의 첫 렌더 안에서 국소 보정을 수행하고 변경본 검증까지 이어간다. 다른 슬라이드의 저작과
이 후속 처리가 겹칠 수 있도록 기존 `authored_presentation_pipeline.py`의 tail streaming 경로를 확장한다.
부분 토큰 스트림이나 불완전한 HTML을 렌더하지 않는다.

- 현재 코드는 `generation_job`, 저작 callable, streaming 설정 조건에 따라 경로를 선택한다.
  구현 전 실제 대상 작업의 선택 경로를 확인하며, 코드 존재만으로 운영 활성화를 주장하지 않는다.
- 기존 provider admission, author/render gate, worker 격리와 소유권을 유지한다.
  새 독립 큐/브라우저 pool을 중복 도입하거나 모델·저작 배치·동시성 값을 자동 변경하지 않는다.
- 저작 완료본 대기열은 기존 coordinator/checkpoint를 사용해 제한한다. 검증에도 기존 렌더 용량을
  사용하고, 다음 브라우저 슬롯을 기다리는 동안 현재 슬롯을 점유해 교착시키지 않는다.
- 정상 무변경은 최초 전체 검사 증거로, 변경본은 독립 재현 검증 증거로 슬라이드 결과를 확정한다.
  검증 실패를 슬라이드 완료로 기록하지 않으며, 재개 시 유효한 확정본을 다시 저작하지 않는다.
- 덱 전체의 순서·페이지 번호·교차 슬라이드 일관성 검사와 export readback은 유지한다.
  검증된 슬라이드 완료와 최종 덱 게시 가능 상태를 구분한다. 후속 내용 수정은 새 digest로 재검증한다.
- 검증 대기에도 작업 deadline을 적용한다. §5.3의 검증 예약은 시간 예산이지 worker 독점 예약이 아니다.

### 4.2 동일 상태의 중복 관찰 제거

벤치 `utils/slide_capture.py`의 `run()`은 폰트가 이미 준비된 경우 즉시 final 관찰을 수행한 뒤
`document.fonts.ready` 콜백에서도 final 관찰을 호출할 수 있다. 중복 **측정 경로**가 확인된 것이며,
동일 fit 수정이 두 번 적용된다거나 실제 지연이 얼마인지는 별도 검증 대상이다.

- 동일 document·폰트/에셋 identity·DOM/style/layout revision의 final 관찰은 한 번만 계산한다.
  최초/후보/최종 상태는 서로 다른 revision이며 단순한 전역 `done` 플래그로 합치지 않는다.
- provisional 증거는 최종 승인에 쓰지 않는다. 폰트 준비 완료나 실제 자산·레이아웃 변경 시
  이전 측정 캐시를 무효화하고 deadline 안에서 다시 관찰한다.
- 최종 상태의 전체 차단 검사는 한 번 계산해 해당 상태의 소비자들이 공유한다. 수정 후 상태를
  수정 전 검사로 승인하지 않으며, 독립 fit-disabled 문서의 검증까지 중복으로 취급하지 않는다.

## 5. 국소 후보 생성과 선택

### 5.1 수정 영역 선정

검사에서 확인된 텍스트와 그 텍스트를 소유하는 최소 카드/흐름 컨테이너를 기본 영역으로 한다.
영역의 원래 외곽 위치·크기는 잠그고, 외부 요소의 위치·크기도 보존한다.
1차 버전은 카드 외부로 공간을 빌리거나 다른 열을 다시 설계하지 않는다.

v1.3 제안은 기존 후보가 모두 실패한 경우에만 제한된 상위 영역 내부의 세로 공간 재배분을 추가한다.
영역 선정·카드 높이 변경·후보 수 예외는 후속 설계에 명시하며, v1.2의 현재 통과 판정에 소급 적용하지 않는다.

고정 높이 해제는 다음 조건이 모두 성립할 때만 허용한다.

1. 일반 세로 흐름의 컨테이너이며 다음 형제가 실제로 존재한다.
2. 직접 소유/하위 텍스트의 실제 ink가 다음 형제 시작 영역을 침범한다.
3. 그림이나 배경판의 디자인 높이를 임의로 바꾸는 것이 아닌, 보정 가능한 흐름 래퍼다.
4. 해제 후 국소 카드와 외부 영역의 보존 조건 및 전체 페이지 검사를 통과한다.

겹치는 수정 영역은 잠글 수 있는 최소 공통 조상 하나로 합친다. body/페이지 전체까지 올라가야 하면
영역을 무제한 확대하지 않고 `unsupported_geometry`로 남긴다. 서로 독립인 영역은 최초 DOM 순서로 처리한다.
영역 간 새 영향이 생기면 해당 후보를 거절한다. 이미 승인된 외부 영역을 다시 보정하지 않는다.
같은 글자를 여러 영역에서 누적 축소하지 않으며, 후보는 원본 기준점과 승인된 외부 상태에서 시작한다.

### 5.2 단계별 후보

| 단계 | 후보 `(글자 배율, 세로 여백 배율)` | 선택 기준 |
| --- | --- | --- |
| A: 가벼운 여백 보정 | `(1,1)`, `(1,.85)` | 통과하면 글자 크기를 유지하고 종료 |
| B: 글자만 소폭 축소 | `(.975,1)`, `(.95,1)`, `(.925,1)`, `(.90,1)` | C와 함께 비교, 단독 조기 채택 금지 |
| C: 강한 압축/조합 | `(1,.70)`, `(1,.55)`, `(1,.50)`, `(1,.40)`, `(.975,.85)`, `(.95,.70)`, `(.925,.55)`, `(.90,.40)` | B와 함께 변화 비용이 가장 작은 통과 후보 선택 |

- 배율은 후보 상한이다. 실제 run별 9.5pt/10% 계약을 만족하지 않는 배율은 제거한다.
- 그룹의 하한에 정확히 닿는 배율을 가까운 후보 대신 사용할 수 있다. 후보 수는 늘리지 않는다.
- 양수 여백만 줄이고 기존 0/음수 여백·겹침 의도를 재해석하지 않는다.
- 줄일 수 있는 padding/margin/gap은 2 CSS px 아래로 새로 내리지 않는다.
  원래 2px보다 작은 정상 값은 이 여백 연산으로 변경하지 않는다.
- A의 원래 높이 충돌 해제와 최대 15% 여백 보정이 실패한 경우에만 롤백 후 B/C를 평가한다.
- B/C는 동일 기준 상태에서 비교한다. §5.4의 동등성/비용 하한으로 생략 가능한 경우 외에는 각각 평가한다.
  `.40` 여백 후보가 통과했다는 이유만으로 작은 글자 축소 후보를 생략하지 않는다.
- 위 14개 이내의 고정 후보만 사용하며 전수 Cartesian 탐색이나 그룹별 조합 폭발을 허용하지 않는다.
  후보를 못 찾았다는 것은 허용된 후보 집합에서 미해결이라는 뜻이지, 수학적으로 해가 없다는 증명이 아니다.
- 하한 정상화 외의 폰트 확대, 글자 폭 압축, 이미지/도표 축소, 가로 열 재배분은 이 후보 집합에 없다.

B/C 선택은 §6의 하드 조건을 모두 만족한 후보에만 다음 비용을 적용한다.

```text
T = 대상 run의 최대 누적 축소율 / 0.10
S = 대상 양수 여백 속성의 최대 실제 감소율 / 0.60
D = 영역 내부 요소의 최대 세로 이동량 / 원본 영역 높이
cost = 0.60*T + 0.30*S + 0.10*D
```

각 항목은 원본 측정 대비 계산하고 정책 정밀도로 정규화한다. 하한 확대는 후보 공통 전처리이므로
축소 비용으로 세지 않되 위계/기하 검사 대상에는 포함한다. 비용 동률은 작은 최대 축소율,
적은 변경 속성 수, 고정 후보 순서로 해소한다. 예컨대 다른 조건이 같으면 여백 60% 압축보다
글자 2.5% 축소가 낮은 기본 비용을 갖는다. 이 가중치는 **초기 비교 규칙**이며 미적 품질 점수가 아니다.
실증에서 사용자가 선호한 후보를 보존하는지 확인한 후 정책 revision 단위로 조정한다.

### 5.3 예산과 롤백

**6초는 후보 탐색 상한이지 전체 추가 지연 상한이 아니다.** 준비·관찰·검증 렌더를 별도로 관리한다.
기존 renderer 요청 timeout을 `R`, 첫 렌더 시작 시 남은 작업 시간을 `J`라 하면 아래 예산을 배정한다.

```text
T_slide = min(J, 2*R)                 # 최초 준비/관찰/fit + 변경본 검증
T_verify_reserved = min(R, T_slide/2) # 후보 탐색 전에 검증 시간을 확보
T_first = T_slide - T_verify_reserved
T_fit <= min(R*0.10, 6초, T_first의 남은 시간)
```

- 폰트·에셋 대기와 첫 전체 관찰, 후보/국소 검사는 `T_first`에 포함한다. 남은 시간으로 각 호출 timeout을 줄인다.
- 정상 무변경이면 검증 예약을 해제한다. 변경본은 예약한 시간으로 fit 없는 렌더와 전체 검사를 최대 1회 수행한다.
- 예약은 기다림이나 추가 대기를 뜻하지 않는다. 이전 단계가 빨리 끝나면 즉시 다음 단계로 진행한다.
- 후보 탐색은 슬라이드당 최대 16개 문제 영역, 160회 측정, 영역당 A 2개+B 4개+C 8개로 제한한다.
- B/C 비교를 시간/횟수 제한으로 끝내지 못하면 기본 적용 경로에서 부분 비교의 첫 통과 후보를 최선으로 채택하지 않는다.
  `budget_exhausted`로 남긴다. 모든 후보가 평가·정책상 제거·안전한 가지치기 중 하나로 정리되어야
  비교 완료로 인정한다. 생략 근거가 없는 미평가 후보가 남으면 완료가 아니다.
- 후보/검사 단계 사이에 deadline을 확인하며, 단일 browser 작업이 멈추는 경우 기존 격리 worker의
  요청 timeout/cancellation으로 종료한다. 다른 작업의 브라우저나 서버를 종료하지 않는다.
- 실패 후보의 style과 임시 DOM 상태는 전부 원복한다. 마지막 검증 시간을 새 후보 탐색에 빌려주지 않는다.

PPTX packaging/readback은 기존 export 작업의 별도 deadline을 따르며 위 `T_slide`에 포함되었다고 주장하지 않는다.
`prepare_ms`, `observe_ms`, `fit_search_ms`, `verify_ms`, `export_verify_ms`와 변경 슬라이드 비율을 따로 기록한다.
페이지 번호 정상화로 대부분의 페이지가 변경되는 사례도 포함해 총 지연을 비교한다.
정책상 LLM 0회가 전체 생성 시간 감소를 뜻하지 않는다. 위 값은 초기 상한이며 실측 성능 보장이 아니다.

### 5.4 선택 결과를 보존하는 후보 가지치기

A의 가벼운 여백 우선 규칙은 유지한다. 이후 B/C 최적화의 기준은 **같은 원본·승인된 외부 상태와
같은 고정 후보 집합을 전부 비교했을 때의 승자**다. 새로운 후보나 다른 비용 정책을 몰래 추가하지 않는다.

1. 9.5pt/10% 정책과 그룹 제약으로 불가능함을 확정할 수 있는 후보를 제거한다.
2. 하한 보정·반올림 후 대상 run과 최종 CSS 선언 집합이 동일한 후보는 한 번만 측정한다.
   signature에는 영역/기준 상태를 포함하고, 동점용 고정 순서는 원래 가장 앞선 후보를 유지한다.
3. 모든 비용 항은 비음수다. 미평가 후보의 보수적인 하한을
   `LB = 0.60*T_lower + 0.30*S_lower`로 계산한다. 적용 계획으로 확정할 수 없는 항의 하한은 0으로 둔다.
   CSS 선언값이 실제 computed 값과 같다는 근거 없이 T/S를 정확값으로 간주하지 않는다.
4. 모든 하드 검사를 통과한 현재 최선 후보의 비용보다 LB가 **엄격히 큰** 후보만 생략한다.
   비용 동률 또는 정책 정밀도상 구분 불가인 경우에는 기본적으로 측정하여 §5.2의 동점 규칙을 보존한다.
   하한 계산은 보수적으로 반올림해 부동소수 오차로 더 좋은 후보를 버리지 않는다.
5. 부족 높이·넘침 방향·기존 측정에서 결정론적으로 계산한 예상 적합도는 B/C 평가 순서에만 쓴다.
   실제 채택은 측정과 하드 검사로 결정하며 예상값만으로 후보를 탈락시키지 않는다.

줄바꿈과 grid/flex 재배치는 배율에 대해 단조롭다고 가정하지 않는다. 단순 이분 탐색이나
부족 높이 비례 계산만으로 최종 크기를 결정하지 않는다. 후보 거절/중복/가지치기 사유와 LB를 기록한다.
최적화가 증명하는 것은 고정 후보 집합 안의 동일 선택이지, 모든 가능한 디자인의 최적해가 아니다.

### 5.5 측정 재사용의 범위

- 문서 내 DOM 노드 인덱스, 텍스트 소유 관계, 그룹 구성, 원본 스타일 스냅샷, 원본 CSS 규칙 매칭을
  최초에 수집해 재사용한다. live `getComputedStyle` 객체 자체를 원본 스냅샷으로 보관하지 않는다.
- 후보의 style 쓰기를 모은 뒤 필요한 읽기를 수행한다. 같은 후보 revision 안에서 동일 노드의
  bbox·text range·ink 측정을 공유하되, 후보 적용/롤백·고정 높이 해제 후 이전 좌표를 쓰지 않는다.
- 초기 관찰, 후보의 국소 기하 검사, 최종 전체 검사를 구분한다. 현재 벤치도 국소 후보 검사를 하므로
  후보마다 전체 paint 검사를 한다고 가정하지 않는다. 실제 반복 tree walk/스타일 조회부터 줄인다.
- 국소 검사에서는 잠근 외곽·관련 없는 영역·중첩 카드의 보존 조건을 생략하지 않는다.
  비용 비교에 채택하는 후보는 §6의 모든 조건을 충족해야 하며, 저비용 검사부터 순서대로 탈락시킬 수 있다.
- DOM 구조·스타일시트·폰트·에셋 변경 시 영향받는 캐시를 무효화한다. 영향 범위를 확정할 수 없으면
  해당 문서 측정을 다시 수행한다. 다른 슬라이드/사용자의 DOM 객체나 원문을 공유하지 않는다.

## 6. 통과 검사와 실패 처리

후보는 아래를 모두 만족해야 한다.

1. 소유 텍스트와 순서, 수치, 표 셀/차트 데이터, 이미지 참조, QID가 보존된다.
2. 실제 최종-PPT 환산 글자 크기가 9.5pt 이상이고 최초 대비 10% 이내 축소다.
3. 제목/본문/라벨의 위계가 보존되고 새 clipping·overflow·occlusion·off-canvas가 없다.
4. 의도적으로 허용된 기존 중첩과 실제 글자 가림을 구분한다. 검출기를 완화하지 않는다.
5. 잠근 카드 외곽과 관련 없는 모든 영역의 bbox 차이가 0.5 CSS px 이내다.
   고정 페이지 번호/푸터는 §3.5의 슬롯 경계 안에서만 자체 텍스트 상자 크기 변경을 허용한다.
6. 변경 영역 밖의 색·이미지·텍스트 스타일을 바꾸지 않는다. 필요 시 변경 영역 밖 픽셀 차이도 확인한다.
7. 최종 전체 페이지의 기존 차단 검사와 새 폰트 하한 검사를 통과한다.

결과 상태는 `unchanged`, `spacing_adjusted`, `text_scaled`, `combined`,
`floor_normalized`, `unresolved`로 기록한다. 복합 변경의 세부 연산 목록을 별도 기록한다.
미해결 사유에는 `font_floor_unfit`, `fixed_chrome_unfit`, `hierarchy_unfit`, `shrink_limit`, `unsupported_geometry`,
`unverifiable_font_size`, `budget_exhausted`, `reconstruction_mismatch`를 구분한다.

이 정책이 활성화된 일반 authored 경로의 **기하·글자 크기 미해결 문제를 자동 LLM repair/remake로
넘기지 않는다.** 승인된 후보가 없으면 기존 게시 차단 계약에 따라 실패 이유를 반환한다.
잘못된 내용을 고치는 별도 정책까지 일괄 해제하지 않지만, 기하 오류를 내용 오류로 이름만 바꿔
재생성하는 우회도 허용하지 않는다. 사용자가 직접 요청한 재생성은 별도 작업이다.

## 7. 재현성·저장·내보내기

### 7.1 HTML과 렌더 결과

기존 `apply_fit_edits`의 QID 기반 정확한 style append를 재사용한다.
HTML 전체를 파싱 후 재직렬화하거나 브라우저에서만 임시 스타일을 적용하지 않는다.

1. 후보를 통과시킨 수정 HTML의 digest를 계산한다.
2. **변경된 슬라이드에 한해서** fit을 끈 검증 렌더를 최대 1회 수행한다.
3. 수정 시점과 검증 시점의 QID·geometry·폰트 크기·가시성·차단 결과를 비교한다.
4. 아래 render identity가 같으면 캡처를 재사용할 수 있으나, 정책 통과 결과는 별도 acceptance identity까지 같아야 한다.
5. 통과한 검증 캡처를 HTML/PNG/metrics/scene/receipt에 함께 연결한다.

렌더 증거 캐시와 정책 통과 캐시를 구분한다.

```text
render_key = hash(final_html_digest, fonts_assets_digest, viewport, DPR,
                  renderer_revision, probe_revision, fit_mode, fit_policy_revision)
baseline_digest = hash(author_revision, original_html_digest,
                       ordered_run_ids_and_original_pt, group_membership,
                       original_measurement_identity, baseline_schema_revision)
acceptance_key = hash(render_key, baseline_digest, policy_revision,
                      export_scale_manifest, image_text_scope_revision)
```

`baseline_digest`는 체크포인트에 영속화하고 원본 기준이 없거나 다른 run에 연결되면 `baseline_unavailable`로 거절한다.
동일한 최종 10pt라도 11pt 원본에서는 약 9.1% 축소로 통과하고, 12pt 원본에서는 약 16.7% 축소로 거절해야 한다.
두 경우에 같은 렌더 캡처를 사용할 수는 있지만 이전의 정책 통과 판정을 공유할 수는 없다.
fit-enabled 캡처와 fit-disabled 재현성 캡처도 구분한다. 구 정책의 승인 증거를 새 정책 승인으로 승격하지 않는다.
부분 수정본을 성공본으로 저장하지 않고, 기존 bundle/checkpoint 트랜잭션 경계를 재사용한다.
재검사가 불일치하면 같은 작업 안에서 다시 자동 저작하거나 무한 보정하지 않는다.

확정 결과의 후속 소비 계약:

- 생성 단계는 기존 bundle/checkpoint에 정확한 HTML·PNG·metrics·scene·receipt와 위 identity를
  함께 연결한다. 메모리 캐시만을 유일한 증거로 삼지 않으며, 복구 시 파일 digest와 소유권도 확인한다.
- 전체 덱 gate는 같은 identity의 유효한 슬라이드 증거를 재사용하고, 덱 수준의 별도 검사는 계속 수행한다.
  증거가 없거나 무효한 슬라이드만 필요한 재검증 대상으로 삼는다. 실패를 렌더 재시도로 숨기지 않는다.
- Fidelity export는 출력이 요구하는 viewport/DPR/에셋 등 렌더 identity가 정확히 같을 때 검증된 PNG를
  재사용한다. 다른 해상도가 필요하면 새 렌더 증거를 만들고, 최종 이미지 배치·페이지 크기 검사는 유지한다.
- Hybrid export는 필요한 native 측정과 PPTX readback을 생략하지 않는다. generation receipt 하나로
  exporter의 자동 축소나 변환 결과까지 검사했다고 간주하지 않는다.
- 동일 승인 결과에 대한 동시 요청은 기존 소유권·취소 규칙 안에서 중복 작업을 합칠 수 있다.
  실패/부분 결과를 성공 캐시에 넣지 않으며 다른 사용자에게 캐시 존재나 결과를 노출하지 않는다.
- 기존 reusable Chrome 경로를 활용하되, 변경본 검증은 저장 HTML을 **별도 document에서 fit=False로**
  재현한다. 같은 수정 중 DOM을 다시 읽는 것으로 대체하지 않으며 기존 worker 격리를 우회하지 않는다.

### 7.2 Fidelity

Fidelity는 전체 슬라이드를 이미지로 담으므로 PPTX에 글자 run의 pt 속성이 존재하지 않는다.
이미지로 바뀌기 전 실제 글자 측정값과 최종 PPT의 이미지 배치 크기를 결합해 **환산 크기**를 검증한다.
최종 PPTX에 삽입된 이미지/페이지 크기가 승인 manifest와 같은지도 확인한다.
픽셀 해상도를 높이는 것을 작은 글자 문제의 해결로 인정하지 않는다.

### 7.3 Hybrid / native 텍스트

PPTX에 저장된 실제 run 크기, 상속된 글자 속성, 그룹 변환과 `normAutofit` 등 추가 축소를 확인한다.
모델이나 HTML의 선언 크기만 검사하고 serializer의 자동 축소를 놓치지 않는다.
확인할 수 없는 배율/속성은 성공으로 추정하지 않는다. 하한을 침범하는 export-time 자동 축소를 금지한다.
표·차트도 native 객체로 바뀐 후의 글자 크기를 확인한다. raster island는 Fidelity와 같은 근거를 사용한다.

### 7.4 이미지 속 글자

검증 범위를 아래처럼 명시한다. 생성 슬라이드에 포함된다는 이유로 외부 이미지까지 DOM 글자로 간주하지 않는다.

| 텍스트 출처 | 하한 검사 근거 | 현재 설계의 판정 |
| --- | --- | --- |
| 직접 저작한 HTML/native 텍스트 | 실제 run 크기·최종 출력 배율 | 9.5pt/10% 강제 |
| 저작 텍스트를 rasterize한 이미지 | rasterize 전 run/폰트 증거 + 삽입 배율 | 같은 하한 강제 |
| 외부 이미지 속 텍스트 | 원본의 신뢰할 수 있는 크기·배치 증거 | 근거가 있으면 하한 검사 |
| 글자가 있거나 존재 여부가 불명확한 외부 이미지, 크기 근거 없음 | DOM 크기/OCR 문자열만으로 pt 증명 불가 | `unverifiable_font_size`, 전체 준수 판정 거절 |
| 글자가 없음을 확인한 이미지 | 자산별 검토/출처 증거 | 글자 검사 비대상, 이미지 품질 검사 유지 |

OCR에서 글자가 안 잡혔다는 이유만으로 ‘글자 없음’ 처리하지 않는다. 자산 digest와 검토 근거를 연결한다.
스크린샷·로고·참고 도표 때문에 생성/내보내기가 차단될 수 있음을 사전 검사와 오류에 명시하고,
원인이 된 자산 및 필요한 크기 증거/텍스트 분리 등 해결 방법을 제공한다. 추가 분류 LLM은 호출하지 않는다.

**현재 기본은 전체 텍스트 하한을 요구하는 엄격 정책을 유지한다.** 검증 불가 이미지를 조용히 경고로 바꾸지 않는다.
‘직접 저작한 글자만 보장하고 외부 이미지 글자는 별도 경고’로 범위를 좁히는 선택은 아직 승인되지 않았다.
그 선택이 필요하면 별도 사용자 승인과 정책 revision, 사용자에게 표시되는 보장 범위 변경이 먼저다.
이 미승인 선택은 이미지가 없는 검증 가능한 경로의 개발을 막지는 않지만, 외부 이미지를 포함한 전면 기본 적용 전의 결정 항목이다.

## 8. 구현 연결 지점

아래는 대상 파일과 역할이며 모든 파일을 일괄 수정하라는 지시가 아니다.
메인의 기존 사용자 변경을 보존하고 각 단계에서 직접 필요한 연결만 변경한다.

| 계층 | 현재 연결/재사용 후보 | 필요한 작업 |
| --- | --- | --- |
| 크기 정책 | `services/authored_vnext/capability_registry.py`, 기존 폰트/fit 설정 | 일반 authored용 버전 정책에 pt 하한·누적 축소 한도와 환산 규칙을 집중 |
| 고정 슬롯 정상화 | 기존 헤더/푸터 계약, 페이지 번호 검출·보정 경로 | 명시적 슬롯 증거가 있는 절대좌표 글자에 한해 하한·행간 정상화 |
| 렌더 관찰 | 벤치 `utils/slide_capture.py` | 같은 상태의 final probe 중복 제거, 상태 revision별 측정 재사용 |
| 렌더 fitter | 벤치 `utils/slide_capture_fit_script.py`, `slide_capture_fit_spacing.py` | 가벼운 여백 우선 + B/C 비용 비교·안전한 가지치기·고정 그룹별 제한 축소 추가 |
| 정확한 수정 재구성 | 벤치 `utils/authored_fit_edits.py`, `slide_capture_fit.py` | 원본 크기 기준과 policy/scale identity를 연결 |
| 수정본 검증 | 벤치 `utils/authored_fit_verify.py` | 샘플링 대신 변경본 필수 검증 경로에 연결, 폰트/내용 조건 추가 |
| scene 일치 | 벤치 `services/authored_fit_envelope.py` | 수정 digest와 최종 scene/checkpoint 일치 유지 |
| 생성·repair 분기 | `services/authored_presentation_generation.py`, `authored_repair_round_order.py` | 첫 렌더의 수정본 소비, 기하 문제의 provider fallback 차단 |
| 슬라이드별 후속 처리 | `services/authored_presentation_pipeline.py`, 기존 tail coordinator/checkpoint | 실제 streaming 경로 확인, 보정·검증·확정을 기존 gate 안에서 연결 |
| 확정 증거 소비 | 기존 generation gate, checkpoint artifact/cache, export adapter | 유효한 슬라이드는 재작업하지 않고 identity별 증거 재사용, 덱/export 고유 검사는 유지 |
| 기존 축소 우회 차단 | `utils/authored_text_scale.py`, offcanvas/개별 텍스트 보정 호출부 | 활성 정책에서는 원본 기준·9.5pt/10% 제한을 우회할 수 없도록 라우팅 |
| 내보내기 | `utils/export_utils.py`, `services/presentation_export_adapters.py`, Next.js export/hybrid 경로 | 출력 페이지 배율과 실제 글자 크기 readback을 기존 receipt에 연결 |

현재 메인에는 벤치와 같은 in-render fit 기반이 모두 있다고 가정하지 않는다.
필요한 의존 관계만 확인하여 가져오며 벤치 브랜치 전체 병합, 프롬프트/모델/동시성 변경은 하지 않는다.
공유 capability의 9pt 상수를 단순 전역 치환해 source 재현 등 비대상 경로를 바꾸지 않는다.
일반 authored 정책을 명시적으로 전달하고 px/pt를 각 호출부에서 따로 계산하지 않는다.

새 public 설정이 필요하면 중앙 settings registry와 기존 설정 전달 계약을 따른다.
임시 환경 변수만 읽는 별도 플래그를 추가하지 않는다. 먼저 내부 버전 정책으로 제한 적용한다.

## 9. 계측과 증거

기존 fit report/quality receipt에 다음을 추가하거나 연결한다. 별도 대형 데이터 계층을 만들지 않는다.

- policy id/revision, baseline digest, render/acceptance key, 원저작/수정 HTML digest, 폰트·viewport·출력 scale identity
- 문제 qid/소유 영역, 결함 종류와 전후 수치
- 적용 연산, spacing factor, 그룹별 최초/최종 pt, 누적 축소율
- 최소 최종 pt, 최대 축소율, 하한 정상화 여부
- 후보/측정 횟수, 후보 비용 구성 T/S/D, 단계별 소요시간, budget 소진과 미해결 사유
- 고정 슬롯 정상화 및 외부 이미지 텍스트의 보장 범위/검증 불가 비율
- 내용·외부 geometry 보존 여부, reconstruction 비교, export readback 결과
- 기하 보정으로 발생한 추가 provider 호출 수: 0이어야 함
- 실제 선택된 streaming 경로, 슬라이드별 author 완료·render 대기/시작·fit 종료·verify 대기/종료·확정 시각
- 최종 전체 관찰 실행/중복 생략 수, 후보 평가/정책 제거/동등 후보 제거/가지치기 수와 사유
- 증거 재사용 hit/miss와 무효화 사유, 재렌더 이유, 변경본 검증 횟수와 재현 실패 수

시간 해석과 성능 판정:

- 기존 `pipeline.author_work`/`render_work` 합계는 작업량이며 사용자 대기시간이 아니다.
  덱 시작→최종 완료의 wall time, 최초 검증 슬라이드까지 시간, 마지막 저작 완료→최종 완료의
  후속 지연을 별도로 측정한다. 겹쳐 실행된 단계 시간을 더해서 단축 가능 시간으로 주장하지 않는다.
- author/provider 대기, 렌더 큐 대기, 실제 보정 실행, 검증 큐 대기와 export 시간을 구분한다.
  프로세스 내부 duration은 monotonic clock으로 계산하고, 재시작 전후에는 attempt identity를 구분한다.
- 검증 슬롯 대기는 §5.3의 남은 작업 deadline에 포함하고 `verify_queue_ms`로 별도 기록한다.
  큐 대기를 제외한 실행시간만으로 사용자에게 추가 지연 상한을 설명하지 않는다.
- 별도 승인된 성능 비교에서 동일 원본 HTML 재생은 렌더/보정 개선만 평가한다. 전체 생성 속도는
  같은 입력·모델/설정·배치/동시성·출력 조건과 명시한 cold/warm cache 조건으로 별도 비교한다.
  충분한 표본이 있을 때 p50/p95와 표본 수를 보고하며 4장 결과로 tail latency를 일반화하지 않는다.
- 성공률·미해결률·내용 보존·9.5pt/10% 준수·디자인 품질을 함께 본다. 빨리 실패하거나 검증을
  생략해서 얻은 시간 감소를 성능 개선으로 승인하지 않는다. 최초 LLM 저작 시간 단축은 이 변경의 보장이 아니다.

사용자 원문·이미지·자격 증명을 새 로그에 복제하지 않는다.
실제 출력 파일·원문 증거는 기존 소유권/보존 정책을 따른다.

## 10. 구현 단계와 좁은 검증

각 단계 완료 후 해당 변경 계층을 직접 검증하는 가장 작은 검사 하나를 선택한다.
아래는 전체 테스트/전체 덱 벤치마크를 자동 실행하라는 지시가 아니다.

### 단계 0 — 실제 경로와 병목 확인

기존 실행 증거에서 streaming 선택과 단계별 대기/실행 시간을 우선 확인한다. 증거가 없으면
§9의 최소 계측 연결을 구현 대상으로 명시하고, 측정 전에는 최대 병목이나 단축률을 단정하지 않는다.
새 성능 측정은 사용자 명시 요청 시에만 수행한다. 이 문서 수정 자체는 측정 실행 승인이 아니다.

### 단계 1 — 크기 정책

정책 환산과 최초 크기 기준을 먼저 구현한다. 기존 근접 단위 테스트에 연결하여
16→14.4, 12→10.8, 10→9.5, 9.5 축소 금지, 9pt 확대 정상화, 누적 축소와 출력 올림 경계를 확인한다.
다른 출력 페이지 크기와 조상 scale이 하한을 우회하지 못하는지 포함한다.
같은 최종 10pt에 서로 다른 11pt/12pt 기준을 넣어 렌더 재사용과 승인 거절이 분리되는지 확인한다.

### 단계 2 — 생성 중 국소 보정

세로 여백 보정과 그룹 축소를 통합하고 저장 HTML 재생을 가장 좁은 브라우저 검증으로 사용한다.
run 54의 두 문제 페이지를 유지하되, 9pt 페이지 번호 정상화가 필요한 점을 명시한다.
새 정책까지 만족하는 정상 대조군은 무변경이어야 한다.
미해결 후보 원복·예산 종료·절대좌표 텍스트 거절·중첩 span 이중 축소 방지를 해당 좁은 사례로 확인한다.
추가 핵심 사례는 고정 페이지 번호 9→9.5pt, 위계 역전 거절, 다중 영역의 결정론적 순서,
강한 여백 압축과 2.5% 글자 축소의 비용 비교, 첫 관찰 지연에도 검증 예약이 보존되는 경우다.

### 단계 2A — 슬라이드별 완료와 증거 재사용

기존 streaming 경로에 보정·독립 검증·확정을 연결한다. 기존 근접 검사 중 하나로 다른 슬라이드의
저작 중에도 준비된 슬라이드의 후속 처리가 진행되고, 미검증 결과는 완료로 저장되지 않는지 확인한다.
이어 증거 소비 연결 변경에는 identity 일치 시 재사용, 불일치 시 해당 슬라이드만 무효화하는
가장 좁은 기존 검사를 선택한다. 검증 슬롯을 기다리는 동안 렌더 슬롯을 점유하지 않아야 한다.

### 단계 2B — 결과 동등성을 유지하는 내부 최적화

중복 final 관찰 제거 → 후보 가지치기 → 구조/측정 정보 재사용 순으로 작게 적용한다.
변경 단위마다 해당 계층의 기존 좁은 검사 하나만 선택하며 검증만을 위한 새 테스트는 만들지 않는다.
관찰 변경은 폰트가 이미 준비된 경우와 뒤늦게 준비된 경우의 최종 증거를 확인한다.
탐색 변경은 같은 고정 후보의 전수 비교와 선택 결과가 같은지, 동률·하한 반올림·예산 종료를 포함해 확인한다.
캐시 변경은 후보 변경/롤백 후 오래된 좌표가 재사용되지 않는지 확인한다. 적절한 기존 검사가 없으면
가장 작은 재생/실행 확인으로 대체하고 미확인 동등성은 보고한다. 성능 수치 측정은 별도 승인 범위다.

### 단계 3 — 수정본 확정과 PPT 내보내기

동일 수정본의 HTML/PNG/metrics/scene을 묶고, 작은 내보내기 사례의 실제 PPTX readback으로
Fidelity 환산 크기 및 Hybrid 실제 텍스트 크기를 확인한다. 이 검증 전에는 “PPT 9.5pt 보장”으로 출시하지 않는다.

### 단계 4 — 기본 적용 판단

사용자가 전후 결과를 확인한 뒤 일반 authored 경로에서 기본 적용할지 결정한다.
전면 적용 전에 제한된 고정 사례에서 복구율·신규 결함·미지원/이미지 검증 불가·변경 슬라이드 비율과
추가 렌더 지연을 보고한다. 코호트와 성능 허용치는 결과를 보기 전에 정하며, 4장 실증만으로 일반화하지 않는다.
활성 정책의 미해결 오류를 기존 무제한/큰 폭 축소로 우회하지 않는다.
롤백은 새 작업의 보정 경로 선택을 되돌리는 것이며, 이미 생성된 발표 자료를 덮어쓰지 않는다.
명시된 9.5pt 하한을 지킬 수 없는 구 경로를 같은 정책의 성공 경로로 되살리지 않는다.

완료 조건:

1. 처리 가능한 기하 결함이 사라지고 추가 기하 repair LLM 호출은 0회다.
2. 최종 PPT 기준 모든 검증 대상 텍스트가 9.5pt 이상이며 누적 축소가 10% 이하다.
3. 내용·데이터·디자인 위계를 유지하고, 새 정책에 적합한 정상 페이지는 변경하지 않는다.
4. 수정 HTML 재렌더링과 최종 PPTX가 같은 승인본을 표현한다.
5. 지원 불가·공간 부족·검증 불가를 성공으로 표시하지 않는다.
6. 전후 디자인 비교에서 이번 실증의 장점을 유지한다. 결함 수 감소만으로 미적 품질을 승인하지 않는다.
7. 후보 생략은 같은 고정 후보 집합의 승자를 바꾸지 않으며, 근거 없는 미평가 후보가 남으면 비교 완료로 승인하지 않는다.
8. 동일 상태의 중복 관찰과 확정본의 불필요한 재처리를 제거하되, 변경본 독립 재현 검증과 덱/export 고유 검사는 유지한다.

전체 생성 시간 감소율은 별도 비교 측정 전까지 약속하지 않는다.
이 설계 개정에서는 문서만 변경하며 제품 코드, 서버, DB, 기존 실증 파일을 변경하지 않는다.
