# 사용자 SVG 템플릿 구현 및 검증 기록

작업 브랜치: `codex/svg-user-templates-20261029`.
기준 커밋: `5b1de620d04ac3f0d0ed73426cbf2ead20a23439`.
요구사항 기준: [설계 revision 3](svg-user-template-layout-design-20261029.md).

## 구현 결과

- 기존 스타일 카탈로그는 기존 자유 디자인 경로를 유지한다. 새 사용자 PPT는 스타일 전용 또는 원본 양식이 있는 템플릿으로 등록한다.
- 원본과 고정 영역의 실제 미리보기를 확인한 양식 템플릿만 `template-redesign`을 제공하며 기본 선택한다. `free-design`도 선택할 수 있다. 스타일 전용에는 불필요한 방식 선택을 표시하지 않는다.
- 양식 재디자인은 실제 글꼴 바이트, 상하단, 배경과 로고를 서버가 합성한다. 본문은 원본 구성의 증거를 참고하면서 콘텐츠에 맞게 자유롭게 작성한다. 본문을 고정 슬롯으로 바꾸지 않는다.
- 변경된 캔버스에 고정 영역을 먼저 적응시킨다. 물리적 글꼴 크기와 로고 비율을 유지하며, 들어가지 않는 요소나 본문 영역 부족은 명시적으로 차단한다. 텍스트가 없는 빈 상자 영역만 필요한 범위에서 줄인다.
- 템플릿, 개정, digest, 프레임 선택, 캔버스를 생성 요청부터 저장된 문서와 내보내기까지 연결한다. 수정된 카탈로그 최신 버전으로 과거 문서를 자동 교체하지 않는다.
- 본문 자연어 편집과 직접 SVG 수정에도 고정 영역, 실제 글꼴 및 본문 그리기 영역 검증을 적용한다. 고정 영역 변경은 새 템플릿 개정이 필요하다. 페이지 순서 변경은 같은 프레임에서 안전한 재결합이 가능한 경우에만 번호를 갱신한다.
- 소유자·조직별 접근, 원본 자산의 보관, 불변 버전, 중복 준비 작업, 오래된 비동기 응답 무효화를 연결했다. 등록 분석은 기존 durable operation을 사용한다.
- 검증된 글꼴은 작업 소유 임시 manifest 파일로 격리 렌더러에 전달한다. 파일명·크기·digest·실제 face와 glyph를 다시 확인하며, 기존 SVG/HTML 및 요청 용량 정책을 전역 완화하지 않는다. PPTX에도 실제 사용한 family 이름으로 같은 글꼴 바이트를 포함한다.
- 내보내기 재사용의 증거에 프레임·글꼴·검증 코드의 digest를 포함한다.
- 여러 장표가 쓰는 원본 글꼴은 패키지에 한 번 저장한다. 프레임과 실행 snapshot의 캔버스 적응 결과는 같은 글꼴 표를 참조하며, 바이트와 메타데이터가 일치할 때만 복원한다. 개별 프레임·적응 결과의 digest와 기존 64MiB 한도는 유지한다.

## 제공 조건과 지원 범위

신규 admission은 `SVG_USER_TEMPLATES_ENABLED`가 기본 `false`인 배포 게이트로 보호한다. 신규 UI와 등록·선택·게시·캔버스 준비·새 생성이 함께 닫힌다. 이미 고정된 문서의 읽기·재개·편집·내보내기 경로는 유지한다. 마이그레이션 이전의 기존 자산 경로도 새 테이블을 요구하지 않는다.

운영 반영에는 새 API·컨트롤러·렌더러·프런트엔드 코드 및 `d8f0a2b4c6e9` 마이그레이션이 필요하다. 이 작업에서는 공유 서비스 DB, 실행 설정, 서비스 프로세스, 원격 브랜치를 변경하지 않았다.

지원하지 않는 그룹·회전·효과·그라데이션·잘린 이미지·텍스트 자동 맞춤 등은 원본 양식으로 근사 변환하지 않는다. 단색 도형, 선, 지원되는 텍스트와 비율이 맞는 PNG/JPEG를 우선 지원한다. 폰트의 설치 여부만으로 임베딩 권한을 인정하지 않으며 기존 글꼴 권한 정책을 유지한다. 가변·기울임·collection 글꼴과 현재 내보내기가 지원하지 않는 굵기는 차단한다. 허용되지 않는 원본 글꼴을 다른 글꼴로 자동 치환하지 않는다.

크기·비율 변경에는 해당 템플릿의 사전 준비와 실제 요소 맞춤 검사가 필요하다. 임의 크기에서 모든 원본이 항상 보존된다는 보장은 하지 않는다. 기존 source-content restyle/raster reconstruction과 새 사용자 템플릿의 결합은 명시적으로 지원하지 않는다.

원본 비교 미리보기는 소유권을 확인한 별도 PowerPoint 프로세스와 실제 설치 글꼴을 요구한다. 기존 PowerPoint 프로세스가 있으면 비교 작업을 시작하지 않으며, 해당 작업이 만든 프로세스의 PID와 생성 시각을 확인하여 정리한다. 서버는 원본과 프레임의 이미지 및 차이 관측을 제공하며, 최종 등록 승인은 사용자의 실제 비교 확인이다. 관측값을 자동으로 원본 일치 점수나 디자인 향상 점수로 바꾸지 않는다.

실제 맑은 고딕 비교 자료에서는 글꼴 바이트와 가로 위치·폭은 같았지만 글자의 세로 위치가 2px 차이 났다. 이는 96dpi에서 약 1.5pt로 설계의 엄밀한 0.5pt 목표를 넘으므로, 엄밀한 원본 일치가 검증되었다고 볼 수 없다. Office와 브라우저의 텍스트 배치 차이를 임의 보정하지 않았으며, 현재 제공 범위는 실제 두 미리보기를 비교하여 표시된 양식을 승인하는 방식이다. 원본과 픽셀 단위로 같은 배치나 모든 PPT 서식을 지원하는 변환기로 안내하지 않는다.

## 수행한 좁은 검증

공유 DB나 유료 provider 없이 임시 자료와 격리 SQLite로 기능 범위만 확인했다. 실패 시 해당 단계의 원인 수정 후 필요한 단계만 재확인했다. 검증을 위한 저장소 테스트 파일은 추가하지 않았다.

| 범위 | 확인 결과 |
| --- | --- |
| 요청 전달 | 신규 pin/mode round trip, 충돌 요청 거부, 기존 요청 호환 확인 |
| 프레임 | 임시 2장 PPT 추출, 글꼴 bytes, 원본 및 정사각형 적응, 합성·attestation, 본문 침범 거부 통과 |
| 실제 Chromium | 본문 이미지 슬롯과 상속된 선 두께를 포함한 렌더·실측 통과 |
| 대용량 원본 글꼴 | 13,457,164바이트 맑은 고딕의 실제 face 로딩과 한글 별칭 확인 |
| 여러 장표의 글꼴 공유 | 실제 맑은 고딕 4장 패키지 17,961,133바이트, 중복 바이트 제거, 복원 후 digest 유지, 잘못된 참조 3종 거부 통과 |
| PPTX | 임시 SVG를 편집 가능한 PPTX로 변환하고 실제 내장 font part 확인 |
| 저장·접근 | 격리 migration 4개 테이블 생성, owner/tenant 분리, 익명 거부 통과 |
| 게이트·보관 | 기본 off 신규 admission 거부, 미적용 schema의 기존 자산 경로, 적용 후 보관 유지 통과 |
| 정적 확인 | 변경 Python 63개 파일 구문 및 export 증거 fingerprint 확인; 마지막 글꼴 공유 변경 관련 5개 파일 구문·export 증거 확인 통과. 프런트엔드 각 최종 수정 범위 구문 검사 통과 |
| 원본 PowerPoint 비교 | Office 16.0의 원본 PNG와 Chromium 프레임 PNG 생성·비교 관측 통과. 상단 글자의 가로 잉크 범위 일치; 세로 2px 차이는 위 지원 한계에 명시 |

실제 서비스에서의 등록→유료 생성→배포 후 내보내기 전체 흐름이나 사용자 실제 원본 3종의 디자인 품질 수용 검증은 이 결과에 포함하지 않는다. 구문 검사와 임시 자료의 변환 성공을 최종 디자인 향상 또는 배포 완료로 보고하지 않는다.

## 다른 세션과의 분리

별도 작업트리에서만 구현했다. 다른 세션의 SVG round 4 통합 우선 순서를 확인했고 공유 main과 실행 중 스택을 보존했다. 다른 세션이 소유한 SVG driver `author.py`, `collect.py`, attempt cause와 checkpoint 파일을 변경하지 않았다. 공통 `render.py`는 템플릿 연결 부분만 수정했다.

프레임 엔진은 GPT-6 Astra high, 저장·API는 GPT-6.1 Sol high, UI는 GPT-6.1 Sol medium, 요청·렌더·내보내기 연결은 GPT-6.1 Terra high, 충돌 조사는 GPT-6 Luna medium으로 분담했다. 조정자가 실제 기능 검증과 통합 경계를 관리했다.
