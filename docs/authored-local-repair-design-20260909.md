# Authored 국소 보정 고도화 설계

- 작성일: 2026-09-09
- 문서 revision: 1.1 — 보정 실패 격리와 원본 포함 문서 완성 원칙 반영
- 상태: 구현을 위한 설계안. 이 문서 작성은 제품 코드 변경이나 실행 검증을 의미하지 않는다.
- 대상: 일반 Authored 생성 중 브라우저 기반 local-fit 및 승인·출력 증거 경계.
- 검토: Astra의 정책·품질 검토, Sol의 생성 경로 조사, Luna의 검증 자료 조사와 주 에이전트의 통합 검토.
- 선행 문서: [겹침·공간 재배치 및 9pt 설계](authored-local-fit-overlap-space-design-20260909.md), [원본 보존형 보정 설계](authored-local-fit-font-floor-design-20260908.md), [부모 영역 재배분 설계](authored-local-fit-parent-reflow-design-20260908.md).

## 1. 목적과 결정 상태

LLM이 생성한 Authored HTML의 내용과 디자인을 유지하면서 잘림·겹침·공간 부족을 국소적으로 수정한다.
실제 브라우저에서 후보를 측정하고, 오류를 해결한 후보 중 원본을 덜 바꾸는 결과를 선택한다.
지원하지 않거나 증거가 부족한 경우에는 그 이유를 정확히 남긴다.
보정 결과와 문서 생성 결과를 분리한다. 보정에 실패해도 출력 가능한 원본이 있으면
그 페이지를 검토 표시와 함께 포함하고 나머지 페이지 및 문서 생성을 계속한다.

### 1.1 사용자 요구

- Deck IR/source-native 또는 고정 템플릿으로 생성 구조를 되돌리지 않는다.
- 전체 재생성 없이 글자 크기, 여백, 박스 크기, 관련 요소 배치로 수정한다.
- 필요한 해당 텍스트는 최종 출력 기준 9pt까지 축소할 수 있다. 9pt는 목표 크기가 아닌 허용 하한이다.
- 막대 글자 잘림과 막대 간 겹침을 각각 해결한다. 일정의 가로 위치·길이는 의미가 있으므로 보존한다.
- 하단 공백을 활용하고, 의미를 보존할 수 있는 장식성 박스는 텍스트 형태로 단순화할 수 있어야 한다.
- 정상 페이지와 원문·수치·관계를 보존한다. 화면 보고는 페이지·조치·핵심 이유로 제한한다.
- 보정 실패, 보정 시간 초과, 후보 검증 불확실만으로 전체 문서를 실패시키지 않는다.
- 출력 가능한 원본은 미해결 상태 그대로 포함한다. 문서 완성과 품질 통과를 혼동하지 않는다.

### 1.2 이번 설계의 제안

실패 기록 형식, 수정 허용 범위, 후보 선택 방식, 상대 축소 제한 변경, 검증 기준은 구현 전 제안이다.
특히 기존 최대 10% 축소 제한을 선호 경계로 바꾸는 것은 실제 정책 변경이다.
9pt 사용자 허용과 이 정책의 구체 구현을 동일한 결정으로 취급하지 않는다.
새 폰트 정책은 잠정 `authored-local-fit/v1.5`로 분리하며 기존 v1.3/v1.4 결과를 재해석하지 않는다.
선행 문서의 10% hard cap과 공간 후보 우선 규칙은 해당 과거 정책의 기록으로 유지한다.
사용자가 이번 개정에서 확정한 것은 '출력 가능한 원본이 있으면 보정 실패와 무관하게 문서를 완성한다'는 원칙이다.
아래 상태·증거·예산·연결 방식은 그 원칙을 구현하기 위한 제안이며 아직 제품에 적용된 변경이 아니다.

## 2. 현재 구현과 실제 개선 지점

다음은 설계 직전 소스 대조 결과다. 파일 존재와 정적 경로 확인은 실제 생성·내보내기 성공의 증거가 아니다.

| 계층 | 확인된 동작 | 이번 변경 |
| --- | --- | --- |
| Authored 생성 | 첫 `fit=True` 캡처 후 `admit_local_fit_capture()`로 승인 | 기존 진입점 유지, 정책·진단 연결 보강 |
| 브라우저 fitter | baseline, 후보 적용·측정·원복, 비용 비교, commit, 전체 검사 존재 | 탐색기를 새로 만들지 않고 선택·거절 기록 정비 |
| 후보 선택 | 비축소 후보군 성공 시 조기 commit, 공간-only 우선 tier 존재 | 같은 문제의 폰트·공간 후보가 공통 비교에 참여하도록 변경 |
| 폰트 정책 | v1.4: `max(original_pt × 0.90, 9.0)` | 9pt 하한과 10% 선호 경계 분리 |
| 실패 분류 | 일부 후보 소진·상대 축소 위반도 `font_floor_unfit`으로 합쳐짐 | 관측·후보 거절·탐색 종료 분리 |
| 부모 공간 | 필요량·가용량·성장 상한, 일부 QID/속성 진단 존재 | 누락된 거절·commit 증거를 최종 receipt까지 연결 |
| 승인 | 전체 페이지 검사, 변경본의 fresh/fit-disabled 재현, 일부 원본 복원 존재 | 보정 후보 승인과 원본 출력 가능 판정을 분리하고 실패를 페이지 단위로 격리 |
| 수동 SlideSpec 검토 | 별도 IR·후보·OCR/VQA·게시 트랜잭션 사용 | 생성 local-fit에 전체 엔진을 이식하지 않음 |
| Authored Hybrid | HTML 결과를 PPTX로 전달하는 export 전략 | 생성 보정과 구분하고 최종 산출물 일치를 검증 |

선행 문서 §9에는 7·16페이지 복구와 14페이지 원본 보존 결과가 기록돼 있다.
14페이지는 필요 성장량 29.172px, 가용량 31.172px 이후 보존 검사 거절로 기록됐지만,
이 수치는 과거 제한적 재생 기록이다. 현재 실패의 동일 원인 또는 새 검증 성공으로 주장하지 않는다.

`artifacts/authored-run49-exact-rerun-20260909/result.md`에는 7·14·16페이지를 검토 표시로
보존하고 20장 전체를 게시한 결과가 기록돼 있다. 원본 보존 기능이 전혀 없는 상태는 아니다.
현재 `PUBLISHABLE_VISUAL_REASONS`는 `parent_region_unavailable`, `parent_geometry_unsupported`,
`parent_preservation_failed`만 허용한다. 다른 local-fit 예외는 `AuthoredStageError`로 전파될 수 있다.
이번 개정은 이 제한적 경고 보존을 원본 출력 가능 여부에 따른 일반적인 보정 실패 격리로 확장한다.

> **2026-09-11 갱신:** 위 확장은 반영됐고 화이트리스트는 더 이상 참조되지 않아
> `PUBLISHABLE_VISUAL_REASONS` 상수를 삭제했다(`453bece2d`). 미해결 사유는 제한 없이
> 영수증에 보존되며, `accept_unchanged_capture`가 모든 미해결 보고를
> `reconstruction_mismatch`로 덮어쓰던 문제도 고쳐 fitter 자신의 종료 코드가 남는다(`58e70b6d5`).
> 2026-09-09 덱 7개·56장 실측에서 미해결 12장은 전부 `candidates_exhausted`였다.

## 3. 설계 평가와 해결해야 할 위험

직전 설계 검토 점수는 78/100이다. 정성적 설계 평가이며 복구율·성능 측정 점수가 아니다.

| 항목 | 점수 | 보완 사항 |
| --- | ---: | --- |
| 기존 구조 활용·범위 | 18/20 | 생성 경로와 수동 검토 경로를 분리 |
| 실패 분류·추적 | 16/20 | 추정 원인과 입증된 거절을 구분 |
| 디자인·가독성 | 13/20 | 과도한 국소 축소와 광범위 이동을 비교 |
| 후보 탐색·선택 | 12/15 | 조기 선택 편향과 공유 공간의 중복 사용 방지 |
| 검증·출력 일치 | 11/15 | 동일 HTML 확보, PPTX까지 검증 |
| 시간·복구 운영 | 8/10 | 최종 검증 시간 확보와 전체 지연 분리 |

이 문서가 보완안을 제시했다고 점수를 자동 상향하거나 미적 최적해를 입증했다고 기록하지 않는다.
위 78점은 최초 설계안의 평가다. 문서 v1.0에 대한 후속 정성 평가는 84점이었으며,
주요 보완점은 문서 완성 우선 원칙의 적용 범위였다. v1.1 작성 자체를 추가 점수 상승의 증거로 삼지 않는다.

## 4. 처리 흐름과 원본 관리

1. 원저작 HTML·자산·정책·출력 크기를 식별하고 보정과 독립된 원본 복원 자료를 보존한다.
2. 폰트 로딩 완료 후 baseline과 결함을 수집한다.
3. 결함 간 의존 관계와 수정 허용 범위를 정한다.
4. 기존 폰트·공간·관련 그룹 후보를 같은 기준 상태에서 적용·측정·원복한다.
5. 필수 조건을 통과한 후보를 비교하고 한 후보를 commit한다.
6. 페이지 전체 내용·폰트·geometry를 검사한다.
7. 기존 admission에서 전체 품질과 fresh/fit-disabled 재현을 확인한다.
8. 변경본 승인에 실패하면 보정 후보를 버리고 원본의 출력 가능 여부를 판정한다.
9. 출력 가능한 원본은 검토 표시와 함께 포함하고 다른 페이지를 계속 처리한다.
10. 내보내기 시 선택한 페이지 revision과 실제 PPTX/PDF 산출물의 연결을 확인한다.

원저작 HTML과 서버의 필수 정규화 이후 baseline을 구분한다. 정규화 변경은 별도로 기록한다.
후보 반복, 부모 확장, checkpoint 재개로 폰트·이동 기준을 새로 설정하지 않는다.
기존의 하한 미만 텍스트 정규화 역시 일반적인 축소 성공으로 집계하지 않는다.
정책에 부합하는 정상 페이지는 보정으로 HTML 바이트·스타일·위치를 변경하지 않는다.

## 5. 실패 기록 계약

기존 fit report와 receipt에 bounded 구조형 진단을 추가한다. 새 DB나 별도 로그 서비스는 만들지 않는다.
원문 전문을 진단에 복사하지 않고 QID·수치·증거 참조를 사용한다.

| 기록 축 | 필수 정보 | 예시 코드 |
| --- | --- | --- |
| 관측 결함 | issue ID, 페이지, 대상 QID, metric, 실제값, 허용값, 증거 | `defect.text_clipped`, `defect.content_occluded`, `defect.off_canvas` |
| 원인 | 원인 코드, 증거 수준, 연결된 issue | `cause.fixed_height_insufficient`, `cause.font_fallback`, `cause.unknown` |
| 후보 거절 | candidate ID, 단계, 대상·root QID, 속성, 전후값, 변화량, 규칙·한도 | `reject.content_changed`, `reject.scope_exceeded`, `reject.new_defect` |
| 폰트 거절 | original/final pt, 절대 하한, 적용 revision, 상대 제한 | `reject.font_floor`, `reject.relative_shrink_limit`, `reject.font_unverifiable` |
| 탐색 종료 | 평가·미평가 후보 수, 시간, 관찰 횟수, 남은 issue | `search.budget_exhausted`, `search.candidates_exhausted`, `search.no_supported_operator` |
| 최종 처리 | 페이지 선택 상태, HTML digest, 보정 검증 상태, 출력 가능 여부, 원인 참조 | `accepted_repaired`, `preserved_original_review`, `no_output_artifact` |

원인 증거 수준은 `observed`, `confirmed_by_probe`, `hypothesis`, `unknown`으로 구분한다.
임의의 신뢰도 백분율은 부여하지 않는다. 후보 거절 이유를 원저작 실패 원인과 동일시하지 않는다.

### 5.1 분류 규칙

- 크기 측정이 유효하지 않으면 `font_unverifiable`이다.
- 측정된 글자가 실제 9pt 미만이면 새 정책의 `font_floor` 위반이다.
- 과거 정책에서 9pt 이상이지만 상대 10% 제한을 넘으면 `relative_shrink_limit`이다.
- 후보를 모두 시도했어도 지원 연산 전체의 불가능이 증명되지 않으면 `candidates_exhausted`다.
- 시간·측정 횟수·영역 수 종료는 각각 예산 원인으로 기록한다.
- `infeasible`은 명시된 연산·제약 범위 내의 불가능을 입증한 경우에만 사용한다. 일반 HTML 전체에 대한 판정으로 확대하지 않는다.
- 마지막 후보의 거절 하나로 전체 탐색을 요약하지 않는다. 주요 거절 집계와 대상 issue 연결을 유지한다.

현재의 `font_floor_unfit` 같은 public/legacy reason은 호환 경계에서만 매핑한다.
새 내부 코드를 기존 경고 게시 allowlist에 일괄 추가하는 것으로 실패 격리를 구현하지 않는다.
보정 후보의 폰트·내용·baseline·증거 무결성 실패는 후보 거절로 유지한다.
그 실패 때문에 별도로 보존된 원본까지 사용 불가라고 단정하지 않는다.
원본 자체의 출력 가능 여부를 독립 판정해 가능하면 경고와 함께 전달한다.
선택한 원본의 identity가 확인되지 않거나 파일을 출력할 수 없으면 실제 생성 실패 원인으로 구분한다.

## 6. 수정 허용 범위와 공간 소유

후보 적용 전에 scope를 확정한다. scope에는 대상·관련 요소, 허용 CSS 속성,
이동 가능한 축·범위, 고정 요소, 보존할 정렬·읽기 순서·축 매핑을 포함한다.

- 같은 부모, 이동하는 후속 형제, 동일 여백 공급원을 공유하는 결함은 하나의 의존 그룹으로 평가한다.
- 중첩 부모의 padding과 자식의 여백을 같은 공간으로 두 번 계산하지 않는다.
- 아래 공간이 보여도 푸터·페이지 번호·다른 그룹의 예약 공간이면 사용할 수 없다.
- 일정 막대는 가로 위치·길이·연결 관계를 유지하면서 세로 레인을 분리한다.
- 외부 영역 보호는 계속 hard gate로 둔다. 실패했다고 root나 이동 한도를 자동 확대하지 않는다.
- scope가 커져 기존 영역·측정 예산을 넘으면 지원 또는 예산 제한으로 종료한다.

보존 검사 거절은 정상 보호 거절, 잘못 계산된 허용 범위, 측정 불확실로 조사한다.
필요량보다 가용 공간이 크다는 산술 결과만으로 배치 가능성을 확정하지 않는다.
줄바꿈과 flex/grid 재분배는 불연속적이므로 계산한 이동량은 후보이며 렌더 결과가 최종 근거다.

## 7. 후보 구성과 선택

### 7.1 기존 후보의 공통 비교

기존 폰트·spacing·parent·scope 후보와 비용 계산을 재사용한다.
비축소 후보군의 첫 성공 후 조기 commit, 공간-only 강제 우선 tier를 제거하는 방향으로 수정한다.
유효한 후보가 있는 종류는 같은 제한된 비교에 참여하도록 하며, 한 종류가 예산을 독점하지 않게 순서를 배치한다.
동일 선언의 후보는 제거한다. 기존 지원 후보를 임의의 더 작은 고정 후보 수로 잘라내지 않는다.

| 후보 종류 | 예 | 보존 조건 |
| --- | --- | --- |
| 국소 글자 | 막대 라벨 소폭 축소, 해당 서식 그룹의 줄간격 조정 | 동일 그룹 비율, 역할별 위계, 가독성 |
| 국소 공간 | 카드 확장, padding/gap 회수, 하단 여백 사용 | 보호 경계, 최소 간격, 외부 요소 |
| 관련 그룹 | 막대 레인 분리, 카드와 결론 밴드의 공동 이동 | 읽기 순서, 일정 의미, 그룹 관계 |
| 제한된 단순화 | 동일 장식 칩의 인라인 텍스트화 | 범주·상태·강조 의미가 없는 경우만 |

### 7.2 필수 조건과 비용

먼저 대상 결함 해소, 새로운 결함 없음, 내용·수치·관계 보존,
폰트 계약, scope, 충분한 측정 범위를 모두 확인한다. 비용으로 hard gate 위반을 상쇄할 수 없다.
필수 조건 통과 후보에서 다른 후보보다 모든 비교 지표가 같거나 나쁘고 하나 이상 나쁜 후보를 제외한다.
동일 비교 가능 조건에서 기존 `0.60T + 0.30S + 0.10D`를 출발점으로 사용한다.

기록·비교 지표는 최초 원본 대비 글자 축소, 간격 압축, 이동·크기 변화,
변경 텍스트·요소 수, 영향 면적, 정렬·그룹 관계 변화다. 단위와 정규화 기준은 정책 revision에 고정한다.
T/S/D의 기존 정의를 소리 없이 바꾸지 않는다. 새 지표의 가중치는 동일 사례 비교 후 별도 변경한다.
동률에는 기존의 결정론적 tie-break를 유지한다. 최소 비용을 미학적 최적해라고 표현하지 않는다.

### 7.3 원자성과 예산

후보마다 동일 기준 snapshot에서 평가·원복한다. 공유 영역의 중간 변경을 다음 후보의 원본으로 삼지 않는다.
commit 재검사에서 거절되면 해당 단계와 실제 변화량을 기록한다.
페이지 일부가 미해결일 때의 전체 보정 원복 정책을 유지한다. 부분 승인 도입은 이번 범위가 아니다.
여기서 전체 원복은 해당 페이지의 보정 후보를 되돌린다는 뜻이며, 다른 페이지나 문서 전체의 실패를 뜻하지 않는다.

기존 최대 fit 탐색 6초, 160회 관찰, 16개 영역 상한과 job deadline을 출발점으로 유지한다.
6초는 전체 페이지 처리나 내보내기 시간 보장이 아니다. 변경본 검증 또는 원본 복원에 사용할 시간을 먼저 예약한다.
예산 종료 시 비교 범위와 미평가 후보를 기록하고 전역 최적화 완료로 보고하지 않는다.
admission 실패 후 추가 LLM 호출이나 무제한 재탐색을 시작하지 않는다.
품질 평가가 원본 전달에 필요한 시간까지 소비하지 않도록 제한한다. 사용 가능한 원본 결과가 있으면
보정 timeout 후에도 그 결과로 계속한다. 원본 render가 필요한 경우 예약 예산 안에서 수행한다.
사용자 취소나 작업 전체의 강제 종료를 보정 실패로 바꿔 무시하지 않는다.

## 8. 폰트 정책 제안

| 항목 | v1.4 현재 정책 | 잠정 v1.5 제안 |
| --- | --- | --- |
| 출력 절대 하한 | 9pt | 9pt |
| 상대 축소 | 원본 대비 10% 초과 금지 | 10% 이내 선호, 초과 시 강화된 후보 채택 조건 |
| 대상 | 결함 텍스트의 원래 서식 그룹 | 동일 |
| 기준 | 원본 baseline | 동일, 재시도 누적 기준 불변 |
| 과거 산출물 | 해당 revision으로 검증 | 과거 revision 해석 유지 |

14pt는 현재 12.6pt까지만 줄일 수 있다. 새 정책에서는 그 아래도 후보로 만들 수 있지만
9pt 미만은 거절한다. 20pt를 9pt로 줄이는 큰 변화가 작은 이동보다 자동 우선하지 않는다.

10% 초과 후보는 대상 결함을 해결하고 역할별 위계·가독성 조건을 지켜야 하며,
비교 가능한 공간·관련 그룹 후보에 대해 변경 영향이 더 작다는 근거가 있어야 한다.
필수 비교가 예산 종료나 측정 불가로 누락된 경우 강화 조건을 충족한 것으로 간주하지 않는다.
제목·본문·보조문구 크기 관계를 유지할 수 없으면 9pt 이상이어도 거절할 수 있다.

실제 pt는 출력 물리 크기, CSS px, 실제 텍스트 배율로 계산한다. DPR을 글자 배율로 쓰지 않는다.
브라우저·Python 승인·export/readback이 같은 정책을 사용해야 한다.
새 정책은 render/acceptance key에 포함하고 과거 receipt를 새 revision으로 덧씌우지 않는다.
source-locked/exact-reconstruction 및 별도 composition/capability 기준은 일괄 완화하지 않는다.
이 절의 폰트 hard gate는 변경본을 '보정 성공'으로 승인하는 기준이다.
원본이 이미 9pt 미만이거나 글자 크기 측정이 불확실해도 출력 가능한 원본의 전달 자체를 막는 조건으로 사용하지 않는다.
이 경우 원본 상태와 폰트 미달/미확인을 경고로 남기며, 9pt 준수 또는 품질 통과라고 표시하지 않는다.

## 9. 의미·시각 평가와 생성 계약

원문 문자열이 DOM에 남아 있다는 사실만으로 내용 보존을 통과시키지 않는다.
실제 가시성과 읽기 순서, 숫자·단위·관계까지 필요한 증거로 확인한다.

칩 단순화는 색상·형태가 상태·범주·선택·강조를 전달하지 않고, 문구·순서·구분 관계를 유지할 때만 허용한다.
가능하면 기존 DOM/QID를 보존하는 스타일 변경으로 수행한다. 구조 identity 변경을 요구하는
새 변환은 별도 mapping 계약과 검증 없이는 이번 후보에 추가하지 않는다.
의미를 확인할 수 없으면 해당 변환을 생략한다.

생성 모델의 role/group/intentional-overlap 표시는 보조 정보다.
모델 표시만으로 수정 권한을 만들거나 콘텐츠 가림을 면제하지 않는다.
폰트 로딩·실측 소유 관계·보호 영역과 대조한 결과를 사용한다.
역할·CSS 변수 등 생성 프롬프트 변경은 후속 단계로 분리해 초기 A/B에서 디자인 변화 요인을 늘리지 않는다.

수동 SlideSpec의 VQA 개선 필수 조건 수정은 별도 정책 과제다. 이번 local-fit에 이식하지 않는다.
현재 경로에서 필수인 품질 센서가 불확실하면 그대로 불확실 상태를 유지한다.
이는 변경본의 품질 통과를 보류한다는 뜻이다. 별도로 출력 가능한 원본이 있으면
원본 전달과 나머지 페이지 처리는 계속한다.
센서 통과를 미학 보존의 수학적 증명으로 표현하지 않는다.

## 10. 승인·복원·출력 상태

### 10.1 최상위 완료 원칙

보정 실패와 문서 생성 실패는 별개다. 원본을 출력할 수 있으면 미해결 페이지를 그대로 포함하여 문서를 완성한다.
9pt·겹침·잘림·시각 평가 등 품질 조건을 통과하지 못한 사실은 경고로 남기고 품질 성공으로 집계하지 않는다.
일부 페이지 보정 실패 때문에 정상 페이지를 폐기하거나 전체 재생성을 시작하지 않는다.

### 10.2 원본의 출력 가능 판정

출력 가능한 원본은 보정 이전에 보존된 해당 페이지의 HTML·자산 또는 일치하는 렌더 결과이며,
페이지 identity와 실제 출력 경로에 필요한 자료를 확인할 수 있는 상태다.
폰트·겹침 등 보정 품질 검사를 모두 통과해야만 원본을 사용할 수 있는 것은 아니다.
단순히 PNG 헤더가 존재하거나 HTML 문자열이 비어 있지 않다는 사실만으로 출력 가능을 확정하지 않는다.

- 기존 원본 캡처가 있으면 동일 페이지·revision·자산·출력 크기와 연결되는지 확인하고 재사용한다.
- 후보 HTML·metrics·PNG가 실패한 경우 이를 원본의 증거로 재사용하지 않는다.
- 원본 HTML만 있으면 예약 시간 안에서 보정을 끈 별도 render로 출력 자료를 만든다.
- 품질 센서가 불확실해도 원본 identity와 출력 가능성을 확인했다면 검토 표시로 전달한다.
- 원본 결과 자체가 없거나 identity를 확인할 수 없고 출력 자료를 만들 수도 없으면 실제 페이지 생성 실패다.
- 페이지를 조용히 삭제하거나 빈 슬라이드·임의 placeholder로 채워 요청한 장수를 맞추지 않는다.
- 원본 보존은 현재 선택된 export 형식으로 출력할 수 있는 범위다. export 방식의 임의 변경은 별도 정책이다.

### 10.3 페이지별 처리와 문서 집계

진단과 후보 선택은 승인 전에 끝낸다. 검토 표시만 제거하여 수정 성공으로 만들지 않는다.
변경본에는 기존 admission과 fresh/fit-disabled 재현을 유지하며 HTML·PNG·metrics·receipt revision을 일치시킨다.
후보가 거절된 경우 상세 원인은 원본 복원 이후에도 bounded 요약으로 남긴다.
원본 출력 가능 판정은 후보 거절 사유 allowlist와 분리한다. 보정 후보가 통과하지 않은 사실을 receipt에 유지한다.

| 상황 | 페이지·문서 처리 | 품질/보정 표시 |
| --- | --- | --- |
| 정상 원본 | 그대로 포함하고 계속 | 정상, 복구 대상 분모 제외 |
| 보정 성공 | 검증된 변경본 포함하고 계속 | 자동 수정 완료 |
| 보정 실패·후보 소진·미지원, 원본 출력 가능 | 원본 포함하고 계속 | 검토 필요, 복구 성공 제외 |
| 보정 timeout·품질 센서 불확실, 원본 출력 가능 | 원본 포함하고 계속 | 보정 미완료/검증 불확실 |
| 후보 내용·증거 불일치, 독립 원본 출력 가능 | 후보 폐기, 원본 포함하고 계속 | 후보 거절 사유 유지 |
| 원본 페이지 자료 없음 또는 복원·출력 불가능 | 해당 실패 원인 유지 | 실제 생성 실패; 완전한 문서 완료로 표시 금지 |
| 페이지가 준비됐지만 PPTX/PDF 파일 작성·저장 실패 | 페이지 결과는 보존, 파일 출력 실패 | 문서 전달 실패 |

모든 요청 페이지에 정상 원본·승인 변경본·검토 대상 원본 중 하나가 있고 파일 출력을 완료하면
문서 생성은 완료다. 검토 대상이 있으면 사용자에게 '검토 필요 페이지가 있는 생성 완료'로 안내한다.
사용 가능한 원본이 있는 보정 예외는 worker·dispatcher·최종 품질 gate를 거치면서 다시 전체 실패로 승격되지 않아야 한다.
반면 실제 페이지 누락이나 파일 출력 실패를 completed로 덮어쓰지 않는다.

operation 완료 상태, 파일 출력 상태, 페이지별 보정·품질 상태를 별도로 기록한다.
기존 public 완료 enum은 가능하면 유지하고 warning/page metadata로 투영한다. 새 wire enum 추가는 이 설계의 자동 전제가 아니다.
정상·보정 완료·검토 대상 수는 선택된 최종 페이지 기준으로 중복 없이 합산하고,
검토 대상을 gate 대상에서 제외했다는 이유로 남은 품질 문제 0건 또는 전체 품질 통과로 안내하지 않는다.

### 10.4 출력 증거와 화면

fidelity 출력은 raster의 물리 크기와 승인 이미지 일치를,
hybrid 출력은 실제 편집 텍스트 크기·레이어 중복·가시성을 해당 경계에서 확인한다.
PPTX가 확인되지 않은 HTML 성공은 PPTX 품질 검증 완료가 아니다.
파일 생성·열림·장수·선택 revision 일치 확인과, 미해결 품질의 존재를 분리해 보고한다.
화면에는 예를 들어 '문서 생성 완료 — 20페이지 / 정상 15 · 자동 수정 3 · 검토 필요 2'로 표시하고,
페이지에는 '14페이지: 배치 보존 조건으로 원본 유지, 검토 필요'를 표시한다. 이 수치는 표시 예시다.
상세 소스, QID 목록, 후보별 로그는 사용자 화면에 자동 출력하지 않는다.

| 1A. 실패 격리 | `services/authored_local_fit_admission.py`, `authored_local_fit_evidence.py`, `authored_presentation_pipeline.py`, `authored_presentation_generation.py` | 원본 출력 가능 판정 분리, 보정 예외의 원본 fallback, 최종 gate·checkpoint 경고 보존 | 보정 실패 페이지를 포함한 문서 완성 |
| 2. 허용 범위 | 기존 scope/parent 검사와 위 파일 | 공유 공간·연관 그룹, QID/축/속성/한도 기록, 잘못된 범위 계산 수정 | 보호 거절과 모델링 오류 구분 |
| 3. 후보 비교 | `utils/slide_capture_fit_search.py`, 기존 spacing/parent helper | 공간 강제 tier와 조기 commit 조정, 동일 baseline 비교, 중복 제거 | 같은 정책에서 선택 개선 |
| 4. 폰트 정책 | `services/authored_local_fit_policy.py`, 브라우저 font 검사, `authored_local_fit_evidence.py`, 관련 export helper | hard floor/선호 경계 분리, 강화 조건, revision 호환 | v1.4와 구분되는 새 정책 |
| 5. 승인 연결 | `services/authored_local_fit_admission.py`, `authored_presentation_pipeline.py`, `authored_presentation_generation.py` | 복원 후 상세 원인 보존, 선택 tuple·checkpoint 일치, 완료·품질 상태 별도 집계 | 정책별 승인·보존 receipt와 완료 안내 |
| 6. 근거 검증 | 기존 local-fit 테스트·HTML replay·export 검증 | 아래 단계별 최소 검증 | 실패·수정·미확인 범위 보고 |

1~2단계에서 확인된 원인 없이 이동 상한이나 보호 조건을 풀지 않는다.
1A는 후보 선택과 폰트 정책 확대보다 먼저 적용할 핵심 단계다. admission뿐 아니라
생성 task의 예외 전파, 재개 시 receipt 해석, 최종 gate와 export까지 원본 전달 상태가 유지되는지 확인한다.
`utils/slide_capture_local_fit.py`는 현재 fit report를 운반하므로 불필요한 transport 교체를 피한다.
새 모델 API, 보정 큐, DB, 별도 IR 또는 전역 재배치 엔진을 만들지 않는다.
작은 helper 추출이 필요한 경우 저장소의 파일 크기 기준을 따른다.

후속 병렬 구현 시에는 진단 스키마를 먼저 고정한다. search/runner 공동 편집은 한 담당자가 맡고,
폰트 정책·Python 증거 경계와 검증 fixture 작업을 분리한다. Astra는 권한·품질 정책 검토,
Sol은 브라우저 보정·승인 구현, Luna는 범위가 명확한 fixture·문서 확인에 배치하는 안이다.

## 12. 검증 계획과 완료 기준

### 12.1 자료 확보

run49의 지정 결과 폴더에는 PPTX·결과 문서·로그가 있으며 HTML/metrics fixture는 없다.
동일 run49 재생에는 별도 checkpoint에서 정확한 HTML·자산·baseline을 확보해야 한다.
PPTX에서 재구성한 HTML은 동일 원저작 바이트 fixture라고 부르지 않는다.

현재 재사용 후보는 `tests/fixtures/authored_fit/run42-s12.html`, `run42-s20.html` 및 대응 metrics,
`tests/integration/test_authored_infographic_fit_chrome.py`의 grid·부모 reflow·footer-safe·terminal-card 사례다.
이들은 run49와 다른 사례다. 실패 fixture를 임의로 정상 대조군으로 간주하지 않는다.
7·14·16과 사용자 제공 19·20페이지 이미지는 요구 사례로 유지하되, 정확한 HTML이 없으면
동일 구조 재현과 원본 재생을 명시적으로 구분한다.

### 12.2 비교를 분리

| 비교 | 고정 조건 | 바꾸는 항목 | 판정 목적 |
| --- | --- | --- | --- |
| A | 동일 HTML·자산·Chrome·출력 크기·v1.4 폰트 정책·예산 | 후보 선택 | 선택 개선 자체의 효과 |
| B | 동일 HTML·렌더 환경·개선된 선택기·예산 | v1.4와 새 폰트 정책 | 추가 축소 허용 효과와 손상 |

viewport, DPR, font fallback, export scale, renderer/probe/policy revision을 기록한다.
정책이 다른 B에서 같은 revision인 것처럼 표시하지 않는다.
후보 비교에 의해 복구됐는지 정책 완화에 의해 복구됐는지 분리한다.

### 12.3 최소 사례

- 정상 페이지: HTML 바이트 동일, 보정 작업 0.
- 짧은 막대 라벨: 국소 축소가 큰 이동보다 적합한 후보로 비교되는지.
- 막대 겹침: 가로 위치·길이 유지, 세로 레인 분리.
- 카드·하단 결론: 여유 공간 활용, 푸터 보호, 같은 공간 이중 할당 방지.
- 14페이지 유형: 가용 공간 이후 보존 실패의 정확한 요소·속성 식별.
- 폰트 경계: 9pt 미만 거부, 기존 revision의 10% 한도 유지, 새 revision의 강화 조건.
- 반복 실행: 원본 baseline 불변, 누적 축소·이동 제한 우회 방지.
- 의미 있는 칩·의도된 장식 겹침: 위험한 단순화 거부, 콘텐츠 가림 면제 금지.
- 시간 종료·미지원·센서 불확실: 거짓 불가능 판정이나 성공 처리 없음.
- 원본 출력 가능 상태에서 후보 거절·보정 예외·timeout을 각각 주입: 원본 포함, 다른 페이지 계속, 최종 파일 생성.
- 후보 내용·receipt 불일치: 실패 후보 재사용 금지, 독립 원본으로 복원하면 생성 계속.
- 원본 품질 미달 또는 폰트 측정 불확실: 출력 가능하면 경고 전달, 품질 통과와 9pt 준수 주장은 금지.
- checkpoint 재개·최종 gate: 원본 경고 페이지를 다시 자동 보정하거나 전체 실패로 승격하지 않음.
- 원본 자료 없음·원본 출력 실패·파일 쓰기 실패: 실제 실패 유지, 누락·빈 페이지로 거짓 완료 금지.
- 사용자 취소: 원본 fallback으로 취소를 무시하지 않음.
- 변경본의 fresh/fit-disabled 재현과 실제 출력 revision 일치.

### 12.4 합격과 지표

보정 성공으로 승인한 변경본의 내용·수치·identity 손실, 9pt 하한 위반, 보호 영역 침범,
정상 페이지 불필요한 변경, 새 blocking 결함, unknown의 불가능 오분류가 선정된 검증 사례에서 각각 0이어야 한다.
원본 경고 전달은 원본과 동일한 페이지·내용·출력 자료를 유지해야 하며, 원본에 남은 품질 문제는 별도 집계한다.
지원 대상으로 선언한 복구 가능 사례는 대상 오류를 해소해야 한다.
미지원 사례를 검토 표시로 보존한 결과를 해당 복구 기능 완료로 집계하지 않는다.
문서 생성 완료율과 자동 복구율은 별도 지표다. 출력 가능한 원본이 있는 보정 실패 사례는
요청 장수와 순서를 유지한 파일 전달까지 완료해야 실패 격리 기능의 합격으로 인정한다.

복구율 외에 변경 요소 수·면적, 최저 pt·축소율, 정렬 변화,
원인별 거절·검토 수, first render/fit/검증 대기/검증 render/export 시간을 나눠 보고한다.
전체 시간 개선이나 일반 문서의 무오류 보장은 측정 전 주장하지 않는다.
성능 허용치는 별도 비교 실행 전에 고정하고 결과를 본 뒤 조정하지 않는다.

구현 후 변경층에 맞는 가장 작은 기존 검증 하나를 선택한다. 렌더 계층 변경에는
`uv run pytest tests/integration/test_authored_infographic_fit_chrome.py -q`가 직접적인 후보다.
정책·증거 계층만 바뀌면 해당 기존 좁은 테스트를 선택한다. 위 모든 검증을 자동 연속 실행하는 지침은 아니다.
기존 테스트에 실제 계약의 빈틈이 있을 때만 필요한 사례를 추가하며 형식적 테스트를 늘리지 않는다.
전체 테스트·새 20장 생성·성능 측정·E2E·광범위 시각 비교는 별도 실행 범위다.
PPTX 검증이 실행되지 않았다면 제품 출력 품질 완료는 미확인으로 남긴다.

## 13. 적용과 되돌리기

첫 단계는 진단을 추가하고 변경본의 품질 승인 기준을 유지한다.
이어 보정 실패 격리를 적용하여 원본 출력 가능 여부로 문서 계속 여부를 결정한다.
후보 선택 개선을 기존 폰트 정책에서 검증한 후 새 폰트 정책을 평가한다.
이미 게시된 산출물은 변경하지 않는다. 진행 중 작업·checkpoint는 시작 시 고정된 정책을 따른다.
되돌리기는 새 작업의 보정 정책 선택에 적용하며 기존 결과를 덮어쓰거나 삭제하지 않는다.
새 정책의 증거를 과거 정책의 성공으로 재사용하지 않는다.
원본 전달 결정에도 별도 revision을 부여해 변경본 품질 승인 receipt와 구분한다.
구 정책이 이해하지 못하는 원본 경고 receipt를 과거 품질 통과 receipt로 바꿔 재개하지 않는다.

## 14. 이번 문서의 완료 범위

기존 코드·선행 문서와 검토 결과를 바탕으로 구현 단계, 실패 계약, 후보 선택, 폰트 정책,
보호 조건, 검증·출력 기준을 작성했다. 새 알고리즘의 복구율·디자인 품질·성능은 아직 검증되지 않았다.
v1.1에서는 사용자 확정 원칙에 따라 출력 가능한 원본이 있는 보정 실패를 문서 생성 실패와 분리했다.
이 문서 작성으로 제품 코드·서버·DB·기존 발표 자료는 변경하지 않는다.
확정되지 않은 정책 제안을 장기 확정 계약으로 자동 기록하지 않는다.
