# 범용 SVG 생성·게시·내보내기 마무리

현재 공통 구현과 추가 제품 provider 호출 없는 정상 API·최종 PPTX·실제 PowerPoint 검증은 완료했다. 신규 v8 디자인 후보 6장과 캔버스 미완료 3개 사례의 실생성·품질·속도·비용 비교 및 기본값 반영은 추가 예산 승인 뒤 남아 있다. 전체 목표를 완료로 표시하지 않는다.

상태: 공통 기능 구현 및 좁은 검증 완료, 실제 제품 경로·디자인·잔여 캔버스 검증 진행 중.

## 사용자 확정 원칙

- 모든 개발은 범용 제품 경로에 반영한다. 특정 템플릿·프레젠테이션·페이지·샘플에 따른 신규 생산 분기를 만들지 않는다.
- 템플릿은 시각적 정체성과 참고 자료를 제공한다. LLM은 각 페이지의 전체 SVG 구도를 직접 선택한다.
- 샘플 전용 수동 보정의 성공을 범용 기능 완료로 보고하지 않는다.

## 구현과 호환성

- 신규 `art-direction-v1@8`은 공통 스타일·마스터·업로드 참고 투영을 사용한다. 브랜드·사용자 지시·원본 내용·시스템 요소의 계약은 보존하고, 참고 자료의 배치 조언은 선택 사항으로 다룬다.
- v0~v7의 동결 입력은 기존 경로로 재개한다. 기존 기록을 새 프로필로 바꾸지 않는다. 새 프로필의 제품 기본 전환은 실제 디자인·내용·내보내기 평가 이후에 결정한다.
- v8 수정에는 기존 유효 SVG를 전달하고 입력 해시를 기록한다. 구도 보존은 모델 지침이며 좌표 고정이나 품질 개선의 증명으로 해석하지 않는다.
- v8은 기존 폰트 하한·관계·분류·가림·일정·측정 실패의 보호 규칙을 계승하며, 내용이 잘리는 대체 페이지로 실패를 성공 처리하지 않는다.
- 기존 미리보기·게시 작업에 공급자 호출 없는 `local_svg` 후보 입력을 연결한다. 소유권·기준 버전·원본 해시·정적 SVG·내용·자산·native 데이터·실제 측정을 검증하고 정상 작업 이력으로 게시한다. 증명할 수 없는 원본 보존 경로는 거부한다.
- 수정·페이지 번호 갱신의 측정·분류·PNG 해시를 최종 SVG에 연결한다. 오래된 VQA를 새 검토 결과로 복사하지 않는다.
- 내보내기 계보는 실제 성공한 기존 게시 작업만 인정한다. 소유자·테넌트·연속 버전·현재 원본 검증을 유지한다.
- 생성 근거가 있는 SVG의 순서 변경·버전 복원·문서 수정·슬라이드 수정·삭제는 기존 생성 근거의 인증 범위로 접수·재개한다. 기존 보호된 로컬 요청 연결을 재사용하며, 사용자 입력의 테넌트를 신뢰하거나 과거 작업의 소유권을 변경하지 않는다.
- 엄격한 공개 품질 영수증 스키마에 허용되지 않는 필드를 넣어 영수증이 누락되는 오류를 수정한다. 내보내기 정체성의 추가 증거는 기존 불변 체크포인트에 보존한다.
- native 차트 계산 전에 유한한 숫자 값을 검사한다. 범용 SVG 계약이 지원하지 않는 효과는 임의로 허용하지 않는다.

## 실제 검증 기록

- 작성 계층: 기존 관련 검사 13개 통과. 39개 스타일의 v0~v7 입력·규칙 312개 비교가 일치했다. 프롬프트 비교에서는 공급자를 호출하지 않았다.
- 생성 드라이버: 기존 terminal 검사 7개 통과. v6~v8의 손실 대체 금지를 함께 확인했다.
- 차트 변환: 기존 관련 검사 15개 통과.
- 게시 계보: 기존 테넌트 권한 검사 1개 통과. 실제 게시 종류와 소유권·테넌트·버전·원본 불일치 거부를 확인했다.
- SVG 변경 작업의 인증 범위: 기존 단일 principal 검사 108개 사례 통과. 다른 사용자·테넌트·잘못된 로컬 인증 연결을 차단하고, 기존 비SVG·재개 원본 기록을 보존했다.
- 게시 담당의 후보·측정·영수증 검증 및 실제 경로 결과는 해당 최종 보고서에 기록한다.

위 숫자는 서로 다른 좁은 검사와 저장 입력 비교다. 전체 테스트나 실제 디자인 향상 인증으로 해석하지 않는다.


### 실제 순서 변경 어댑터 보완

- 편집기 PATCH 어댑터의 최초 요청과 실패 후 재시도 모두 기존 Request 기반의 보호된 로컬 개발 principal bridge를 전달한다. 요청 본문이나 임의 헤더로 허용 여부를 설정하지 않는다.
- 정식 생성 principal을 확인한 범위 안에서만, 어댑터가 앞서 기록한 인증 tenant context를 정식 tenant로 맞춘다. 다른 tenant 값은 그대로 남아 충돌 검사를 통과하지 못한다.
- 기존 실패 작업의 기록을 보존하고 재시도 자식의 tenant context만 기존 principal과 일치할 때 정합성을 맞춘다. 비 SVG의 기존 경로는 보존한다.
- 관련 기존 두 테스트 노드의 112개 조합이 41.15초에 통과했다. 전체 검사 결과가 아니다. 실제 API 순서 변경과 최종 내보내기 검증은 계속 진행 중이다.


### 추가 생성 없이 실제 게시·내보내기 확인

- 기존 생성 샘플을 정상 API로 수정하여 실제 버전 2→3을 게시하고, 순서를 실제로 변경·복원하여 3→4→5로 진행했다. 변경 없는 3→3 작업은 버전 진전 계보에서 제외했다.
- 편집기 PATCH의 동기 응답 대기 제한 이후에도 이미 접수된 작업을 조회해 성공을 확인했다. 같은 변경 요청을 재전송하지 않았다.
- 최종 버전 5의 실제 PPTX는 12장·편집 가능한 개체 629개이며, 다운로드 파일 해시와 실제 아티팩트·공개 QualityReceiptV3의 해시가 일치한다. 원본 100장과 이전 비교자료는 보존했다. 새 제품 provider 호출은 0회다.
- 12장 모두 정식 SVG/source·측정 PNG의 일치와 소유자·tenant·연속 계보를 확인했다. geometryFont/authoring은 passed다. 수정 전 시각 검토는 재사용하지 않아 visualReview는 stale로 failed, releaseReadiness는 blocked다. 성능 및 OOXML 자동 인증의 미측정·미수집 상태도 그대로 유지한다.
- 실제 PowerPoint 16.0 렌더 12장과 native 표·차트 readback을 별도 Sol medium 작업으로 확인했다. 629개 도형·그림 0개·표 2개·차트 1개와 6개 차트 수치 및 연결 XLSX를 보존했다. 초기 축/네이티브 plot 주의점은 별도 Sol high의 좌표 실측으로 공통 변환 오류임을 확인해 수정했다. 이번 결과는 기존 샘플의 게시·이동·복원·내보내기 검증이며, 신규 v8 디자인 비교 결과가 아니다.


### 원본 축과 실제 네이티브 차트의 정렬 수정

- 실제 PowerPoint 좌표로 비교하여 원본 SVG 축 자체는 정확한 선형 0~7이고, 이전 PPTX의 자동 0~8 축과 잘못된 plot/category 영역이 약 23픽셀 기준선 오차를 만들었음을 확인했다. 기존 중간 눈금 비율 관련 주의점은 이 측정 결과로 해석을 정정한다.
- 그룹 밖에 그려진 축과 막대의 비례를 객관적으로 확인할 수 있을 때만 네이티브 plot 영역과 범위에 반영한다. 새 로직은 템플릿·문서·페이지·특정 수치에 의존하지 않는다. 관련 기존 테스트 노드의 4개 조합이 4.80초에 통과했다.
- 수정 후 같은 정식 source의 실제 영향 차트 렌더에서 기준선 445, scale 25px/M/M, 월별 위치와 6개 수치가 일치하고 이중 축선이 사라졌다. 임시 단일페이지 진단 파일과 실제 API 산출물 증거는 분리해 보존한다.
- API와 export controller만 관리 스크립트로 반영하고, 원본 문서와 source 버전을 그대로 유지한 정상 v2 API의 새 12장 export를 성공했다. 새 exporterVersion은 chart-furniture.10, sourceRevision은 5다. 실제 파일과 공개 receipt의 SHA256이 일치하며 추가 제품 provider 호출은 0회다.
- 최종 새 파일은 artifacts/svg-general-completion-20261004/chart-axis/api-export-after-fix/editable-after-fix.pptx다. 이 정확 파일을 실제 PowerPoint로 읽고 영향 차트만 재렌더하여 축 0~7·기준선 445·scale 25px/M/M·월별 위치와 6개 값의 일치를 확인했다. 일반 편집형 도형 635개·그림 0개·표 2개·차트 1개·연결 XLSX 1개를 확인했다. 증가한 6개 도형은 원본 M1~M6 라벨이며, 차트 외 1~11번 슬라이드 XML은 이전 아티팩트와 동일하다. 이번 최종 확인에서는 1~11번을 재렌더하지 않았고 이전 PNG를 새 파일의 PNG로 재라벨하지 않았다.


### 느린 순서 저장의 화면 연동

실제 순서 PATCH는 동기 대기 제한 이후 503을 반환했지만 서버 작업은 정상적으로 완료했다. 기존 편집기 호출자는 이를 일반 저장 실패로 표시해 오래된 revision을 유지할 수 있었으므로, 접수 작업에 바인딩된 조회로 완료·실패·미확인을 구분하고 기존 UI 변경을 보존하는 공통 처리를 구현했다. 기존 503 오류 계약과 보호된 작업 ID 헤더를 유지하고, 같은 작업의 타임라인을 최대 60초 조회하며 PATCH를 재전송하지 않는다. 백엔드 기존 4개 조합과 프런트엔드 기존 7개 검사가 통과했다. 실제 SidePanel 소스 실행은 React/Redux 의존성을 모의 환경에서 확인했고 실제 브라우저 조작은 수행하지 않았다. API만 관리 스크립트로 반영했고 Next.js는 HMR을 사용한다. PATCH를 다시 보내서 확인하지 않는다. 원본과 현재 문서 버전 5 및 최종 PPTX는 이 작업에서 수정하지 않는다.

## 남은 실제 검증과 비용

- 기존 대표 캔버스 기록: 13종/56장 중 10종/36장 수락. A4 가로 12장·21:9 4장·사용자 지정 정사각형 4장이 미완료다.
- 새로운 디자인 후보: 같은 원문에서 대표 4장과 다른 스타일의 2장을 준비했다. 저장된 기준 결과와 비교하되 모델·실행·수정·지시 차이를 명시하고 인과적 우위를 주장하지 않는다.
- 추가 호출 제안 상한: 잔여 캔버스 8회, 후보 4장 10회, 다른 스타일 2장 6회, 총 24회. 이전 12장 샘플의 상한과 별개다. 사용자 예산 답변 전 공급자 호출은 허용되지 않는다.
- 기존 결과가 불확실한 요청은 보존한다. 명시적 재호출 승인과 현재 소유권·버전·체크포인트·원격 결과·호출 한도 확인 없이 재구매하지 않는다.
- 최종 판정은 실제 파일의 내용·가독성·PowerPoint·native 데이터·디자인·시간·비용 근거를 구분한다. 품질 영수증의 존재를 전체 자동 릴리스 인증으로 확대하지 않는다.
