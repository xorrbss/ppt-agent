# PPT 문구 정책 실제 생성 검증

## 결과

2026-10-14 정상 로컬 웹 생성 경로에서 `ppt-writing-policy/v1`이 고정된 5페이지를 생성하고 게시된 편집형 PPTX를 내려받았다. PowerPoint에서 검증용 복사본의 텍스트를 수정하고 저장한 뒤 다시 열어 수정 보존을 확인했다. 원본 파일과 이미 열려 있던 사용자 문서는 보존했다.

이 결과는 문구 정책의 제품 경로 검증이다. 최종 PPTX 시각 검토가 없어 `releaseReadiness=blocked`인 상태를 출시 승인이나 디자인 품질 완료로 바꾸지 않는다. 문장에 남은 어색함과 제목/설명 반복은 별도의 정성 개선 여지다.

## 호출과 시간

최종 사례의 PostgreSQL 영수증에는 실제 모델 `codex:gpt-6.1-sol`만 있다. 작성 5회, 기존 후보 수정 2회, 내부 시각 검토 2회로 총 9회이며 모두 succeeded, UNKNOWN 0이다. 캐시 복구 구간에서는 새 author 호출 없이 시각 검토 1회만 추가됐다. 별도 문구 편집 제공자 호출은 도입하지 않았다.

최종 사례의 최초 operation 생성에서 PPTX 내보내기 완료까지 9분 35.5초였다. 여기에는 최초 실패 후 정상 복구를 준비하는 약 4분 53초가 포함된다. 생성 job의 최초 실행 구간은 약 200초, 캐시 복구 실행에서 게시까지는 약 59.5초였다. provider latency 합계는 병렬 실행과 겹치므로 전체 완료 시간으로 사용하지 않는다.

앞선 원문 복사 지침 사례와 선택적 이미지 사례도 실제 실패 기록과 영수증을 보존했다. 각각 10회와 14회의 성공 영수증이 있어 이번 조사 전체는 총 33회다. 이 호출을 최종 사례의 9회 안에 숨기거나 결과 불명으로 재분류하지 않았다. 기존 12페이지 문서의 UNKNOWN 최종 검토는 실행하지 않았다.

## 비교 범위와 남은 품질 경계

비교 자료는 `canonical-five-request.json`과 `canonical-five-editable.pptx`로 고정했다. 최종 사례는 같은 content와 5개 slides_markdown을 사용하지만, 원문 표현을 그대로 유지하라는 이전 지시를 일반 문구 편집 허용으로 변경했다. 새 사진과 장식 삽화도 금지했다. 따라서 동일 조건의 속도 실험이나 문구 정책 하나의 인과 효과로 해석하지 않는다.

이전 PPTX에는 가운데 점 총 92건과 의미 있는 월 범위 긴 대시 2건이 있었다. 원본 표 데이터에 필요한 가운데 점과 월 범위 대시는 최종 파일에서도 보호한다. 단순 기호 개수 감소를 문장 품질 점수로 대체하지 않는다.

문구가 더 구체적으로 바뀌어도 모든 문장이 사람이 쓴 것처럼 자연스럽다고 보장할 수 없다. 제목 중복, 추상적 설계 제목, 구성/상태 요약 반복과 일부 어색한 용어 결합은 남은 검토 항목이다. 최종 PPTX `visualReview`는 unavailable이고 `releaseReadiness`는 blocked다. 사용자의 최종 문구 평가와 전체 디자인/출시 승인은 이 검증의 완료 주장에 포함하지 않는다.

독립 문구 검토에서 최종 PPTX의 가운데 점은 3페이지 원본 역할 범위의 1건, 긴 대시는 5페이지 월 범위의 2건뿐이었다. 슬래시는 M/M 단위와 UX/UI 역할에 사용되어 장식 나열로 보이지 않았지만, 자동 검사의 ambiguous 2건은 그대로 보존했다.

원본 실행 증거, 페이지 체크포인트, API 타임라인, 다운로드 영수증과 Office 증거는 저장소 밖 `C:\project\PPT-agent\delivery-backups\ppt-writing-acceptance-20261014\source-only-final`에 보존한다. 원문 자료, 비밀 설정, runtime 데이터와 생성 파일은 Git에 넣지 않는다.
