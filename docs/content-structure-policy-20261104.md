# 내용 구조 표현 정책: 표와 연결선 (2026-11-04)

`utils/content_structure_policy.py`. 표와 연결선(화살표)을 쓰는 조건을 한곳에서 정의한다.
기본값은 **꺼짐**이다. 켜는 방법과 켜면 안 되는 이유는 아래 "측정"에 있다.

## 배경: 흩어져 있던 세 지시

| 지시 | 위치 | 이력 |
|---|---|---|
| 아웃라인의 표 요청 줄(`Must have content either in bullet points or table or both`)이 주석 처리됨 | `utils/llm_calls/generate_presentation_outlines.py` | 2025-07 업스트림 시절부터 있었고, 2026-04-15 업스트림의 215개 파일 일괄 커밋 `c7860127f`에서 주석 처리됨. 이유는 커밋 메시지에도 문서에도 없다. 이 포크가 끈 것이 아니다 |
| 작성 정책(`ppt-writing-policy/v1`)이 "파이프 구분자를 피하라"고 지시함 | `utils/ppt_writing_prompt.py` | 2026-10-13 `4dec21eb6`. 기호 제한이 목적이고 표 지시문은 건드리지 않았다. 다만 마크다운 표도 파이프로 쓰므로 표 생성을 막는다 |
| 작성 규칙 "독립 항목 사이에 화살표를 넣지 말라" | `services/generation_core/authoring/author_slide_svg.py` (`SVG_AUTHOR_RULES`) | 2026-09-17 `5f2e837ea`. 설계 근거는 `docs/svg-generation-mode-design-20260916.md` §7.1(근거 없는 순서·인과·계층을 만들지 않는다)과 §12.1(실험에서 근거 없는 화살표 관찰) |

세 곳이 따로 정해져 있어서, 근거가 있는 흐름과 표도 그리지 못했다.

## 구조

`StructurePolicy(tables, connectors)` 하나를 아웃라인과 작성 규칙이 같이 쓴다.
정책이 없으면(`None`) 모든 호출부가 기존 문장을 그대로 쓴다(바이트 동일).

- 아웃라인: 표 요청 줄을 복원하고, 작성 정책 뒤에 "표의 파이프는 필수 문법"이라는 문장을 붙인다.
- 작성 규칙: 연결선 규칙을 "소스가 순서·흐름·계층·의존·인과를 명시한 항목만 연결하고, 독립 항목이나 근거 없는 관계는 만들지 않는다"로 바꾼다. 표가 켜져 있으면 셀 글자 속성 문장을 붙이고, 템플릿 덱이면 네이티브 표 그룹 ID를 `body-` 접두어로 쓰게 한다.
- 범위: 환경 변수 `CONTENT_STRUCTURE_POLICY_SCOPE` = `off`(기본) / `template`(template-redesign 덱만) / `svg`(모든 svg 덱).
- 부분: 환경 변수 `CONTENT_STRUCTURE_POLICY_PARTS` = `tables`, `connectors`의 쉼표 목록. 비어 있거나 아는 이름이 없으면 둘 다(나누기 전과 같다). 범위가 `off`이면 효과가 없다. `connectors`만 켜면 아웃라인은 바뀌지 않고 작성 규칙의 화살표 문장만 바뀐다.
- `SVG_AUTHOR_RULES` 상수는 고치지 않는다(헤더 설계 호출의 digest 입력이다). 범위 안의 덱에서만 호출마다 치환한다. 문장이 사라졌으면 조용히 건너뛰지 않고 규칙을 덧붙인다.

## 측정 (실제 템플릿 덱, 원본 10페이지 텍스트 입력, `verbosity=text-heavy`, 모델 `claude-sonnet-5-5`)

**아웃라인만 (2회씩, 가설 검증)**

| 조건 | 표 개수 |
|---|---|
| 현재 상태 (작성 정책 켜짐, 표 요청 줄 꺼짐) | 0 |
| 표 요청 줄만 켬 | 0, 0 |
| 표 요청 줄 + 파이프 예외 | 3, 2 |
| 파이프 예외만 | 2, 2 |

작성 정책의 파이프 금지가 표를 막고 있었고, 표 요청 줄의 주석 처리는 원인이 아니었다. 파이프 예외만으로 표가 나온다.

**전체 생성 (템플릿 덱, 10페이지)**

| 실행 | 품질 게이트 | 표가 있는 페이지의 결과 |
|---|---|---|
| 정책 꺼짐 (`text-heavy`) | 6 통과 / 4 검토 | 해당 없음 (네이티브 표 0개) |
| 정책 켜짐 (1차) | 2 통과 / 8 검토 | 5 / 5 폴백 |
| 정책 켜짐 + 표 문장 보강 (2차) | 3 통과 / 7 검토 | 5 / 5 폴백 |

- 모델은 `data-native-table` 선언까지 쓰지만 검증에서 거절된다. 1차의 원인은 셀 글자 속성 누락(`svg_contract_explicit_text_attributes_required`)과 ID 충돌(`svg_template_body_namespace_required`: 템플릿은 `body-` 접두어를, 네이티브 표 규칙은 `native-table-SLUG`를 요구)이었다. 2차에서 ID 충돌은 사라졌고 `native_requested_table_missing`, `text_overlap`, `svg_template_font_unavailable`이 남았다.
- 표 없는 페이지에서도 속성 누락이 나와서 폴백 증가가 전부 정책 때문이라고 단정할 수 없다. 정책을 끈 대조 실행이 같은 조건으로 한 번 더 필요하다. 실행 간 변동이 크다(같은 입력에서 폴백 3건 → 7건).
- 연결선의 효과는 측정하지 못했다. 통과한 페이지가 2~3개뿐이고, 그 페이지의 `polyline`이 아이콘인지 연결선인지 구분하지 않았다.

## 결론과 다음 작업

1. 정책은 기본 꺼짐으로 둔다. 켜려면 `CONTENT_STRUCTURE_POLICY_SCOPE=template`.
2. 켜기 전에 템플릿 모드의 네이티브 표 작성을 고쳐야 한다. 표 페이지가 10 / 10 폴백이다. 우선 `native_requested_table_missing`의 원인(선언은 있는데 요구와 맞지 않는지)부터 본다.
3. ~~속성 누락(`svg_contract_explicit_text_attributes_required`)~~ → 해결함. 아래 "텍스트 fill 내려주기" 참고.
4. 정책을 끈 대조 실행으로 폴백 변동의 몫을 분리한다.
5. 연결선은 근거 없는 화살표가 늘지 않는지(설계 문서 §12.1) 페이지별로 확인한 뒤에 켠다. → 확인함: 아래 "연결선만 켠 측정".

## 텍스트 fill 내려주기 (속성 누락 폴백의 원인과 수정)

`svg_contract_explicit_text_attributes_required`는 표와 무관하게 가장 흔한 폴백 원인이었다(정책을 끈 실행에서도 7페이지).
실패한 저장 응답 20건에 기존 `push_down_container_font_attributes`(그룹의 폰트 속성을 텍스트로 내려줌)를 적용해 보니,
**여전히 실패하는 15건이 모두 `fill`만 빠진 경우**였다(한 페이지에서 텍스트 12~68개). 모델이 `<g font-family=".." fill="#..">`로
색을 한 번만 쓰고 텍스트에는 생략했는데(SVG 상속으로는 올바름), 서버가 `fill`은 내려주지 않았다. 재시도도 같은 습관을 반복했다.

`services/svg_text_defaults.py`의 `push_down_container_fill`이 가장 가까운 `svg`/`g`의 fill을 fill이 없는 `<text>`에 복사한다.
컨테이너의 fill은 그대로 두므로(도형도 칠한다) 렌더링은 같다. 가장 가까운 선언이 우선하고, 안쪽의 `none`이나 `url(...)`은
바깥 색을 가린다. 모든 텍스트에 fill이 있는 페이지는 변화가 없다(이미 통과한 페이지는 바뀌지 않는다). 생성 시점과 저장 응답 재생
(`parse_author_response`)이 같은 함수를 호출해 재생이 일치한다. 영수증에 `container_fill_pushed`로 기록한다.

측정:
- 오프라인: 속성 누락으로만 실패하던 응답 10건이 전부 통과했다.
- 라이브(정책 꺼짐, 같은 입력, `text-heavy`): 속성 누락 실패 4~7건 → **0건**, 폴백 페이지 3~7개 → **1개**, 10페이지 중 5페이지가
  재시도 없이 첫 시도에 통과했다. 페이지별 측정 품질은 10 / 10 통과(실패 0건)다.
- 그런데 품질 게이트는 이 실행에서 0 통과 / 10 검토 필요였다. 모든 페이지가 `verified=False`였고, 원인은 덱 전체의
  흐름 검토(`repetition_deck_flow`)가 전 페이지에서 "검토 불가"로 끝난 것이다(`designReview.flowUnreviewedPages`가 10개).
  이 검토는 모델이 준 평가 문자열 중 하나라도 형식에 안 맞으면 통째로 버려지는 기존의 취약한 단계이고, 이번 수정과는 무관하다.
  같은 입력의 이전 실행은 4개만 미검토였다. 이 단계의 실패율은 별도 과제다.

속성 누락은 한 번도 없었다. 실행 간 변동은 여전히 크다(폴백 1~2개, 첫 시도 통과 5~7페이지).

수정 후 1회의 게이트가 0 통과였던 이유(진단):
- 덱 9개를 다시 보면 대부분의 덱에서 "검토 필요" 페이지는 검토에서 제외된 페이지(폴백 등) 자체다. 제외 페이지가 있으면 덱 흐름은 설계대로
  항상 `evaluated=False`로 봉인된다(`services/generation_core/drivers/svg/quality.py`의 `seal_review`). 흐름 검토 불가 페이지 수와
  제외 페이지 수가 같았다(1, 1, 1, 4, 7, 7).
- 이상치는 한 덱뿐이었다. 전역 흐름 검토의 모델 응답이 `global_intentional_evidence`로 통째로 거절됐다. 모델이 "의도적 반복"이라
  주장하면서 근거 문장을 비웠거나 해당 페이지의 비교 근거가 없었던 경우다(`services/generation_core/quality/vision_advisory.py`의
  두 곳). 11-02 `beaec83f8`이 증거 문자열 길이만 보정하고 의미 검사는 계속 거절하도록 남겨 둔 부분이다
  (`tests/unit/test_vision_evidence_bounds.py`의 "stays a semantic rejection").
- 빈도는 첫 9개 덱 중 1개였고, 이후 3회 중 1회에서 다시 나타났다. 저장된 모델 원본 응답이 없어서 같은 응답을 재현하지는 못했다.
- 수정: 근거 없는 의도적 반복 주장은 **그 페이지(그룹)의 흐름만 `unreviewed`로 두고 나머지 검토를 살린다**
  (`vision_advisory.py`의 두 파서, 메모 `intentionalEvidence`가 `evidenceNormalization`에 기록된다). 근거 없이 통과시키지 않으므로
  더 느슨해지지 않고 영향 범위만 줄어든다. 근거와 비교 기준이 있는 주장은 이전처럼 받아들인다. 11-02 `beaec83f8`이 남긴
  `test_vision_evidence_bounds.py`의 "stays a semantic rejection" 기대값은 새 동작으로 바꾸고 두 파서 각각 테스트를 추가했다.
  라이브에서 이 거절은 드물게만 나와서 수정 효과를 직접 재현해 확인하지는 못했다.

  이관 활동(추출→정제→적재→검증→승인 셰브론, 6덱 중 5덱은 "불일치율 초과 시 정제로 되돌아감"을 되돌아가는 선으로 그림).
  일정 페이지는 6덱 중 5덱이 기간 막대(타임라인)로 그렸다(흐름 요소로 세지 않음).
- **소스에 없는 관계를 이은 화살표는 0개**다. 독립 항목(역할 카드, 위험 카드, 운영 지표)에는 한 번도 연결선이 없었다.
  현재→목표 수치의 →는 소스가 "6일에서 2일로" 줄인다고 쓴 관계라 근거가 있다.
- **방향이 거꾸로인 화살촉: 두 변형 모두 18개 흐름 페이지 중 1페이지씩**(connectors-only: 계층 사이 삼각형 3개가 위를
  가리킴, 바로 옆 문장은 "바로 아래 계층만 호출"; connectors-direction: 5단계 사이 삼각형 4개가 왼쪽을 가리킴). 원본 응답을
  보면 모델이 꼭짓점 좌표를 반대쪽에 쓴 것이다(`points="282,340 298,332 298,348"`, 간격 왼쪽에 꼭짓점). 의미를 잘못
  고른 것이 아니라 손으로 쓴 삼각형 좌표의 실수라서, 방향 문장을 넣어도 줄지 않았다(1 → 1). 그래서 방향 문장은 되돌렸다.
- 가독성: 단계 사이 연결 표시는 6~16px 간격에 들어가 작게 보이고(6덱 모두), 한 덱은 화살촉 없는 짧은 선이었다. 연결선 라벨이 상자 외곽선 위에 겹친 곳 1곳
  (계층 페이지, 심사도 같은 지적), 마지막 단계 뒤로 빠져나간 배경 선 1곳. 글자끼리 겹친 곳은 없었다.
- 폴백 3건(변형 6덱 중)은 모두 **표지**였고 표지에는 연결선이 없다. 원인은 두 시도 모두 `svg_template_font_unavailable`
  (표지 응답이 `font-weight="bold"`를 썼다. 이것이 원인인지는 확인하지 않았다), 한 건은 재시도에서 표지 라벨의 파이프 구분자(`writing_policy_visible_symbols`)까지 겹쳤다.
  같은 표지 첫 시도 실패가 기준선에서도 3덱 중 1덱에 있었지만(재시도로 통과) 변형에서는 6덱 중 5덱이었다. 연결선 문장이
  표지의 글꼴 굵기 선택에 영향을 줄 경로는 보이지 않으나, N=3씩으로는 우연인지 가릴 수 없다.

**판단**

성공 기준 중 흐름 페이지(10페이지 중 3 이상)와 근거 없는 관계 0, 심사 구조·시각 요소(구조 +0.1/0, 시각 −0.13/0, 잡음 범위)는
만족한다. 거꾸로 된 화살촉(흐름 페이지의 1/9)과 표지 폴백 증가(0 → 0.33~0.67)는 기준을 넘지 못했다.

권고: 기본값은 꺼진 채로 둔다. 연결선은 근거 없는 관계를 만들지 않았으므로 표보다 켜기에 훨씬 가깝다. 켜기 전에 (1) 표지의
글꼴 굵기 실패를 따로 고치고 정책을 끈 덱으로 빈도를 다시 재고, (2) 화살촉 방향을 결정적으로 막는다: 모델이 삼각형 좌표를
쓰지 않게 서버가 방향 있는 화살표 부품을 제공하거나, 순서가 있는 두 항목 사이의 화살촉이 읽는 방향(또는 소스가 말한 방향)을
가리키는지 검사한다(검증을 느슨하게 하는 것이 아니라 더하는 것). 그 뒤 `CONTENT_STRUCTURE_POLICY_SCOPE=template
CONTENT_STRUCTURE_POLICY_PARTS=connectors`로 N=3 이상 다시 잰다.

## 환경 메모

- 넓은 범위의 pytest(수천 개)를 돌리면 로컬 PostgreSQL과 백엔드 프로세스가 같이 죽는다(이 세션에서 여러 번 재현). 라이브 실행과
  pytest를 동시에 돌리지 말고, pytest 뒤에는 둘을 다시 띄운다.

- 로컬 `public-artifacts` 저장소에서 등록한 템플릿의 저장 객체 파일이 시간이 지나면 사라져(`artifact.object_missing`, DB에는 행이 남음) 생성이 `svg_template_adaptation_material_unavailable`로 실패했다. 등록 직후 생성하면 재현되지 않는다. 원인은 조사하지 않았다.
