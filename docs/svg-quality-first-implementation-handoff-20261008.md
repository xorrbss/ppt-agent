# SVG 품질과 속도 개선 구현 인계

새 세션에서 기존 SVG 생성 경로의 품질과 속도를 개선한다. 품질이 최우선이며, 최종 검사와 PPTX 내보내기까지의 완료 시간이 두 번째 목표다. 사용자는 최신 설계에 따른 구현과 멀티 에이전트 작업을 승인했고, 작업 에이전트 모델은 난이도에 맞게 Sol 이하로 제한했다.

이 파일은 착수 때 작성한 인계 지침이다. 이후 사용자 지시에 따라 현재 오케스트레이터가 독립 문맥의 Sol 이하 에이전트와 격리 워크트리에서 구현을 진행했다. 현재 구현 범위와 검증 결과는 [SVG 품질과 속도 개선 구현 현황](svg-quality-speed-implementation-status-20261008.md)을 따른다. 새 대화창을 만들었다고 해석하지 않는다.

## 모델과 역할

아래 이름은 현재 협업 도구가 제공하는 작업 에이전트 모델 식별자다. 새 세션에서 가용성을 확인하며, 요청된 모델이 없으면 같은 제한 안의 대안을 알린다. Sol보다 상위 모델로 자동 승격하지 않는다. 이 제한은 구현 에이전트에 적용하며 제품의 PPT 생성 모델 설정을 바꾸라는 지시가 아니다.

주 에이전트를 포함해 최대 5개를 동시에 실행한다. 하위 에이전트는 독립적인 새 작업 문맥에서 설계·현재 계약·소유 파일을 명시적으로 전달받는다. 주 에이전트의 허용 없이 추가 에이전트를 만들거나 다른 소유 파일을 수정하지 않는다. 새 영수증 필드와 함수 연결은 편집 전에 합의하고, 파일 소유권 이전이 필요하면 현재 소유자의 작업 종료를 확인한다.

모든 에이전트는 한국어로 간결하게 보고한다. 사용자에게 소스 코드, 패치·diff, 문서 본문, 원문 로그와 명령 출력 전문을 전달하지 않는다. 결과·변경 파일·실제 검증·차단 사유만 보고한다.

## 구현의 필수 계약

1. 일반 작성은 LLM 전체 SVG 자유 설계를 유지한다. 충분한 디자인 지침과 내용에 맞는 서로 다른 좋은 표현 예시를 첫 작성부터 전달한다.
2. 화면은 정상이나 디자인이 미달이면 전체 재작성한다. 국소 오류는 관련 영역만 수정하며, 전체 구도 결함과 오류가 함께 있으면 불필요한 중복 수정 호출을 피한다.
3. 화면 오류가 해결되지 않은 페이지만 적합한 검증 SVG를 바탕으로 필요한 부분을 수정한다. 참고 PNG만 제공한 새 자유 작성을 안정적인 복구로 간주하지 않는다.
4. 이전 유효 후보를 보존하고 더 나빠진 결과를 채택하지 않는다. 이전 후보가 미달이면 완료 처리하지 않는다.
5. 적합성·가독성·디자인 기준을 충족한 후보군 안에서 실제 구도 유사성과 사용 빈도를 반영한다. 후보 이름 변경이나 강제 순환으로 다양성을 만들지 않는다. 원본 근거가 있는 비교·연속 자료의 반복은 허용한다.
6. 검사·수정은 기존 한도에서 병렬 진행하고, 변경 없는 증거는 권한·입력·정책·문맥이 일치할 때 재사용한다. 기존 단계별 승인 경계와 UNKNOWN 중단을 유지한다.
7. 중간 SVG 후보에는 필요한 구조·보존·가독성 검사를 적용하고, 최종 선택한 결과의 실제 PPTX에서 출력 일치·내용·편집성을 확인한다.

Deck-IR 신설·확장, 새 레이아웃 엔진, 좌표를 담은 별도 중간 표현, 새 DB 테이블, 일반 생성의 고정 패턴 순환을 추가하지 않는다. 이미지 수를 임의로 제한하거나 내용 삭제·글자 축소로 검사를 통과시키지 않는다. 원본 수치·관계·이미지 그룹·페이지 수·출력 캔버스와 표·차트 바인딩을 보존한다.

새 정책은 새 요청에 고정하며 과거 프로파일 0–8, 기존 요청·체크포인트·부모 영수증·실패·UNKNOWN·비용 이력을 재해석하지 않는다. 기존 계약상 대체가 금지된 모드의 제한을 유지한다. 실제 구현 완료 범위와 아직 비활성화된 계약을 명확히 구분한다.

## 착수와 진행 순서

1. 현재 브랜치·통합 기준·워크트리 소유권과 설계 파일을 확인한다. 직접 연결된 코드와 좁은 검증 후보만 조사한다.
2. 작성 입력·평가 결과·수정 전후 선택의 가장 작은 기존 확장 지점과 파일 소유권을 정한다. 새 정책 없는 과거 요청은 기존 동작을 유지하도록 분리한다.
3. 첫 작성의 지침 누락과 참고 선택을 먼저 개선한다. 품질 에이전트는 동시에 판정 계약을 준비하고, 자료 조사 에이전트는 실제로 사용 가능한 검증 SVG와 대표 자료를 확인한다.
4. 주 에이전트가 디자인 재작성·국소 수정·이전 결과 선택을 연결한다. 자동 대체는 실제 검증된 SVG와 적합 범위가 확인된 경우에만 연결한다.
5. 병렬 검사·수정, 고정된 후보 선택, 증거 재사용을 기존 예산·권한·취소·재개 계약 안에서 연결한다. 후보 선택은 제공자 완료 순서에 좌우되지 않게 하고 실제 작성은 가능한 범위에서 병렬화한다.
6. 통합 완료 뒤 구현 범위를 직접 검증하는 가장 작은 확인 하나를 수행한다. 실제 제공자 생성과 시각 품질·속도 비교는 별도의 승인된 범위에서 진행한다.

후보가 없는 상황을 숨기려고 검증되지 않은 양식을 자동 대체에 등록하지 않는다. 데이터만 모형으로 만든 확인이 성공해도 실제 생성·렌더·PPTX·Office·배포 검증을 완료했다고 보고하지 않는다.

## 기존 사건과 권한 경계

실패한 프레젠테이션 `55798091-3ed9-4566-9319-c50cff9e1ead`와 작업 `86d05a38-7c7a-4eed-8d3b-076e0f5372a5`는 과거 진단 자료다. 실패 작업을 자동 재시도·재구매하거나 DB 상태를 수정하지 않는다.

이번 승인은 로컬 구현과 필요한 좁은 검증에 대한 것이다. 새 유료 PPT 생성·리뷰 작업, 제공자 호출 한도 증가, 게시·배포·외부 전송은 해당 범위가 승인되기 전 실행하지 않는다. 코드 구현을 위한 이번 멀티 에이전트 요청과 제품의 실제 생성·리뷰 호출 권한을 혼동하지 않는다. 이전에 완료한 워크트리 통합 요청이 앞으로 생길 변경의 무조건적인 푸시·머지 승인이라고 가정하지 않는다.

## 검증과 최종 보고

구현이 끝난 뒤 통합 변경을 직접 확인할 수 있는 가장 작은 검증 하나를 선택한다. 관련 없는 전체 테스트·빌드·린트·E2E·성능 측정을 실행하지 않는다. 하위 에이전트는 각자 검증 명령을 중복 실행하지 않고 주 에이전트에 후보를 보고한다. 고영향 계약 변경이 있으면 해당 계약에 필요한 확대 범위만 별도로 판단한다.

실제 품질·속도 비교에서는 모델·추론 설정·입력·스타일·캔버스·장수·동시성·품질 기준을 맞춘다. 대표 페이지에서 첫 작성 품질을 확인하고 같은 조건의 12장 비교를 거쳐 A4·긴 덱을 검증한다. 디자인, 원본 보존, 편집성과 최종 완료 시간, 첫 작성 통과율, 수정·리뷰 호출, 입력·출력 토큰, 실패·미완료 건수를 함께 보고한다.

최종 보고에는 실제 변경, 좁은 검증 결과, 실제 생성·PPTX 확인 여부, 남은 작업과 런타임 반영 여부를 구분한다. 구현의 좁은 확인만 수행했다면 이전 수준의 PPT 품질이 복구됐다고 보고하지 않는다. 서버 반영이 필요하면 관리 스택과 기존 실행 환경을 유지하며 영향을 받은 구성 요소만 재시작한다.

프로젝트 지침의 compiled-spec-memory 스킬은 이전 세션에서 찾지 못했다. 새 세션에서 가용성을 확인하고, 없으면 자동 기록을 완료했다고 표시하지 않는다. 별도 사용자 메모리는 명시적인 기록 요청 없이 수정하지 않는다.
