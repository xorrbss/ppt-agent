- 작성일: 2026-09-08
- 제안 revision: `authored-local-fit/v1.3`
- 상태: **설계안. 범용 구현·제품 정책 전환·회귀 검증은 미실행.**
- 기준: [v1.2 원본 보존형 비LLM 보정 설계](authored-local-fit-font-floor-design-20260908.md)
- 요청 범위: ① 보정 범위 설계 ② 범용 로직 설계 ③ 저장 실패본 검증 계획. 전체 20장 생성·PPTX 검증은 후속 작업이다.

## 1. 목표, 근거, 변경하는 계약

기존의 카드 단위 A/B/C 보정이 모두 실패하면, 제한된 상위 영역의 외곽과 가로 배치를 유지한 채
내부 세로 여백을 줄여 텍스트 카드의 높이를 확보한다. 새로운 저작이나 내용 요약 없이 처리한다.
v1.2의 자유로운 HTML/CSS 저작, 최소 9.5pt, 최초 저작 대비 최대 10% 축소, 추가 기하 LLM 호출 0회는 유지한다.

### 1.1 확인된 실험과 아직 확인하지 않은 범위

이전 대화의 단일 실패본 진단에서 확인한 값이다. 이번 문서 작성 중 실험을 다시 실행하지 않았다.

| 항목 | 관찰 결과 |
| --- | --- |
| 고정 입력 | 20장 생성 실패본의 10번 슬라이드, `s9-data` 카드 |
| 본문 배치 | 18px 행간의 3줄, 텍스트 상자 높이 54px |
| 카드 높이 | 55px → 81px |
| 조정 | 상위 시스템 영역의 세로 padding/gap, 연계 영역·카드 높이, 카드 내부 세로 padding |
| 독립 렌더 결과 | 차단 이슈 0건. 별도 우측 카드 결함은 기존 여백 보정으로 처리 |
| 보존 측정 | 모든 owned text와 computed font size 동일, 두 보정 영역 외곽 및 영역 밖 요소 bbox 동일 |

위 결과는 수작업으로 지정한 CSS 후보의 가능성 실험이다. `81px`는 관찰값이지 알고리즘 상수가 아니다.
최초 저작 baseline을 이어받는 제품 receipt, 범용 후보 선택, 이미지 미적 비교, PPTX readback을 검증한 결과가 아니다.
브라우저 차단 이슈 0건만으로 완성도나 모든 디자인의 안전성을 보장하지 않는다.

### 1.2 v1.2와의 차이

| 계약 | v1.2 | v1.3 제안 |
| --- | --- | --- |
| 보정 경계 | 최소 카드/흐름 영역 외곽 고정 | 기존 실패 시 한 번 선택한 상위 영역 외곽 고정 |
| 내부 카드 높이 | 디자인 높이 자동 변경 제한 | 텍스트 중심 카드의 검증된 높이 증가만 제한적으로 허용 |
| 가로 배치 | 변경 금지 | 변경 금지. 내부 요소 x·width도 검사 |
| 후보 | A/B/C 최대 14개 | 기존 후보 + 상위 영역별 E 후보 최대 6개, 탐색 예산 공유 |
| 실패 해석 | 기존 후보에서 미해결 | 국소 공간 부족·상위 영역 부적합·예산 부족 등을 내부 증거로 구분 |

상위 보정은 기존 후보에서 성공한 결과를 교체하기 위한 품질 최적화가 아니다. A/B/C가 통과하면 E를 실행하지 않는다.
이는 v1.2의 결과를 보존하면서 복구 범위만 넓히려는 초기 선택이다. E와 B/C 전체의 공통 최적해를 주장하지 않는다.
자동 LLM 재생성, 프롬프트 변경, 모델·동시성 변경, 다른 생성 엔진 도입은 포함하지 않는다.

## 2. 단계 1 — 보정 범위와 안전 경계

### 2.1 진입 조건

다음 조건을 모두 만족한 경우에만 상위 보정을 검토한다.

1. 대상이 일반 authored 경로이며 최초 저작 run·폰트·출력 배율의 기준 증거가 완전하다.
2. 기존 A/B/C가 예산 안에서 전부 평가되거나 근거 있게 제거됐고 통과 후보가 없다.
3. 남은 결함이 정상 흐름 텍스트의 세로 넘침 또는 실제 다음 영역 침범이다.
4. 변경본 독립 검증 시간을 제외하고 영역 선정과 E 후보 탐색 예산이 남아 있다.

폰트/이미지 증거 부재, 내용 불일치, 가로 넘침, 헤더·푸터 슬롯 실패, 미완료 탐색을
공간 부족으로 바꿔 이 경로에 넣지 않는다. 그림·차트·이미지의 높이를 줄여 공간을 얻지 않는다.

### 2.2 ‘상위 한 단계’의 정확한 뜻

DOM의 직계 부모 하나로 한정하면 카드 → 그리드 → 연계 영역 → 시스템 영역 구조를 처리하지 못한다.
여기서 한 단계는 **하나의 확장된 보정 트랜잭션**을 뜻한다. 상위 영역 선택은 다음으로 제한한다.

- 실패 카드부터 실제 DOM 부모 링크 최대 4개만 읽는다. 숨은 래퍼도 깊이에 포함한다.
- 후보 root는 QID가 있고, 고정된 외곽 높이를 측정할 수 있는 정상 세로 block/flex-column/단일 열 grid 영역이다.
- `body`, `html`, 슬라이드 전체 wrapper, 서버 헤더·푸터, source-locked 경계를 넘지 않는다.
- 세로 예산을 나눌 수 있는 하위 행·스택 관계가 명확해야 한다. 이름·문구 의미로 레이아웃 역할을 추론하지 않는다.
- 가까운 root부터 최대 압축 후보의 수용 가능성을 측정한다. 모든 관련 결함을 수용할 첫 root 하나를 선택한다.
- 공간이 부족하면 더 가까운 root를 탈락시킬 수 있으나, 보호 경계·미지원 구조를 만나면 탐색 자체를 중단한다.
- root 선택 이후 후보가 실패해도 다른 root로 재확장하지 않는다. 페이지 전체까지 반복 확대하지 않는다.

수용 가능성 측정도 가역적인 실제 브라우저 관찰이다. `height=부족분` 같은 산술만으로 root를 승인하지 않는다.
seed 하나의 상위 root 선정에 사용하는 사전 측정은 합계 최대 4회이며 측정 예산에 포함한다.
같은 root/후보/revision의 결과는 E 평가에서 재사용한다.
이 작은 지원 범위를 벗어나는 grid span·중첩 관계는 초기 버전에서 미지원으로 남긴다.

### 2.3 바꿀 수 있는 것과 잠글 것

| 대상 | 허용/검사 |
| --- | --- |
| 선택 root | x/y/width/height 유지. 세로 padding·gap만 변경 가능 |
| 정상 세로 흐름 | 양수 margin-top/bottom, padding-top/bottom, row-gap 감소 |
| 텍스트 카드/행 | 필요한 높이 증가, 내부 스택·세로 행 track 재계산 |
| 같은 그리드 행의 카드 | 행 소속이 측정으로 확인되면 공통 행 높이 유지. DOM 순서·열 수 유지 |
| 모든 내부 요소 | x·width 유지, 허용된 y·height 변화만 인정 |
| root 밖 요소 | bbox 유지. 루트 크기가 같아도 외부 흐름이 바뀌면 거절 |
| 텍스트와 자산 | 문자열·run/QID·폰트·행간·자산 identity·색·굵기·정렬 유지 |

세로 여백은 기존 값이 2px 초과일 때만 줄이며 `max(2px, original × factor)`를 적용한다.
원래 0/음수/2px 미만인 값과 겹침 의도를 재해석하지 않는다. 수평 padding/gap, width, 열 비율,
글자 폭·letter-spacing·줄바꿈 규칙은 수정하지 않는다.

새 E 단계는 하한 정상화 이후의 폰트·행간을 유지한다. 추가 폰트 축소와 E의 조합은 초기 버전에 넣지 않는다.
baseline을 새로 만들거나 기존 축소 위에 축소를 누적해 공간을 얻지 않는다.

높이 변경 대상은 배경/테두리가 있어도 텍스트 중심 카드임을 확인할 수 있는 상자다.
이미지·차트·비디오·그림 크기, 고정 종횡비, connector의 양 끝 관계를 변경해야 하면 미지원이다.
일반 절대좌표 텍스트·변환 텍스트는 이동/수정하지 않으며, 영향 범위에서 안전성을 증명하지 못하면 거절한다.
텍스트 없는 부착 장식은 크기·변환·소유 부모와의 상대 위치가 보존되고 새 가림이 없을 때만 부모와 함께 이동한다.
장식과 절대좌표 요소를 **수정 대상에서 제외하는 것과 전체 검사에서 제외하는 것은 다르다.**

초기 변경량 상한 제안:

- 카드별 높이 증가는 `min(원래 카드 높이 × 0.50, root 높이 × 0.10)` 이내.
- 내부 요소별 세로 이동은 root 높이의 10% 이내.
- 세로 흐름 상자 높이의 감소는 줄인 padding/gap으로 설명되는 범위로 제한하고 실제 콘텐츠 최소 높이 아래로 내리지 않는다.

이 수치는 사용자 확정 계약이나 미적 품질 보장이 아니다. 단계 3 결과로 검토할 제안값이며,
통과할 때까지 자동으로 확대하지 않는다. 55→81px 사례는 카드 증가 한도 안에 들어가지만 범용 복구 성공은 별도 검증한다.

## 3. 단계 2 — 범용 로직과 구현 연결 설계

### 3.1 공간 계산과 후보 구성

원본 DOM/스타일과 하한 정상화 상태를 스냅샷으로 고정한다. 실제 폰트·실제 폭에서 텍스트 및
행 box를 측정하고, border·padding·margin·gap·grid track·flex shrink를 포함해 필요한 세로 공간을 계산한다.
ink 높이만으로 line box 높이를 대체하지 않는다. 부모가 자식을 몰래 줄이는 flex shrink도 검출한다.

```text
available(root) = root 고정 높이 - border - 후보 세로 padding
required(stack) = Σ(자식의 필요한 border-box 높이) + 실제 gap/margin
required(grid row) = max(같은 행 카드들의 필요한 높이)
surplus = available - required
```

margin collapse·다중 row span·순환 percentage height 등으로 위 분해를 보수적으로 계산할 수 없으면
`parent_geometry_unsupported`다. 여백에서 확보한 공간을 중첩 레벨마다 중복으로 세지 않는다.
`surplus >= 0`은 후보 생성 조건일 뿐이며 브라우저 재배치 이후의 전체 검사가 최종 판단이다.

E 후보의 세로 여백 배율은 `(1, .85, .70, .55, .50, .40)` 여섯 개로 고정한다. 각 후보는 다음을 한 번 수행한다.

1. 동일한 하한 정상화 기준 상태에서 후보 여백을 투영한다.
2. 고정 폭의 콘텐츠 최소 높이를 아래에서 위로 계산한다. 같은 행 카드는 공통 높이를 사용한다.
3. 필요한 카드 높이와 상위 흐름 높이를 계산하되 root 외곽은 고정한다. 최소 높이는 출력 정밀도로 올림한다.
4. 감소한 여백으로 필요한 높이를 충당하지 못하거나 변경량 한도를 넘으면 후보를 제거한다.
5. QID별 선언을 한 번에 적용하고 실제 geometry를 측정한다. 부족하면 반복 증가시키지 않고 후보를 거절한다.
6. 검사 후 원복한다. 모든 후보 평가가 끝나면 가장 작은 변경 비용의 통과 후보만 채택한다.

특정 슬라이드/QID/문구/CSS 클래스명/81px를 제품 조건으로 넣지 않는다. 명시적인 구조와 실제 측정값만 사용한다.
최종 결과는 기존 byte-preserving QID style append로 재구성한다. 진단 실험처럼 전체 CSS를 덧붙이거나 HTML을 재직렬화하지 않는다.

E 비용은 원본 기준 `0.50*S + 0.25*D + 0.25*H`를 초기 제안으로 사용한다.
S는 최대 여백 감소율/0.60, D는 최대 세로 이동/root 높이, H는 최대 카드 증가/root 높이다.
동률은 작은 H → 작은 D → 적은 변경 속성 → 고정 후보 순서로 해소한다.
E 내부에서만 비교하고 기존 B/C 비용과 섞지 않는다. 비용은 미적 점수가 아니며 초기 버전은 여섯 후보를 모두 평가한다.

### 3.2 중첩 영역과 원자적 적용

기존 runner의 첫 국소 실패 즉시 종료 대신, 복구 가능한 실패와 독립 영역 결과를 임시로 모은다.
확장 root가 앞서 성공한 내부 카드를 포함하면 그 카드의 **임시** 수정도 함께 기준 상태로 되돌리고
root 전체를 한 후보로 재평가한다. 이때 해당 root 안의 모든 원래 결함이 해소돼야 한다.
이미 저장된 다른 슬라이드나 root 밖에서 승인된 수정은 변경하지 않는다.

겹치는 확장 root는 중첩이면 바깥 root 한 개로 묶되, 모든 seed에서 4개 부모 링크 한도와 보호 경계를 만족해야 한다.
한도를 넘으면 충돌하는 확장을 거절한다. 선택한 root 안의 seed들은 한 번만 처리한다.
독립 root는 최초 DOM 순서로 처리하고, 결과에 따라 root를 다시 선택하거나 재귀 보정하지 않는다.
폰트 그룹/run identity는 원래 기준을 유지하며 root 확장을 이유로 다시 생성하지 않는다.

### 3.3 검사와 원복

후보별로 다음 조건을 모두 확인한다.

- root와 외부 bbox 보존(기존 0.5px 기하 허용 오차), 내부 x·width 보존, y·height 상한 준수.
- 문자열·run/QID·DOM 순서·자산 identity 동일. 원래 스타일 중 허용하지 않은 속성 불변.
- 모든 텍스트의 최초 기준·9.5pt/10% 계약 유지. E 단계 전후 computed font/line-height 동일.
- root 안 원래 차단 결함 전부 해소, 새로운 카드 넘침·텍스트/도형 가림·clipping·off-canvas 없음.
- 일반 절대좌표 텍스트와 이미지 텍스트도 독립 전체 검사에 계속 포함.

실패/취소/예산 초과 시 해당 후보 DOM과 임시 style을 원복한다. 슬라이드 최종 실패 시 부분 수정본을
완료 HTML/scene/receipt로 저장하지 않는다. 내부 중간 성공과 사용자에게 제공하는 완료 상태를 분리한다.
최종 변경본은 fit-disabled 독립 렌더에서 재현·전체 검사를 통과해야만 확정한다.

### 3.4 예산과 실패 이유

기존 6초 검색·160회 측정·16개 seed 영역·변경본 검증 시간 예약을 공유한다. E 때문에 deadline을 새로 시작하지 않는다.
기존 seed별 14개 후보에, seed별 root 선정 사전 측정 합계 최대 4회와 선택된 root별 E 최대 6개를 추가할 수 있으나
슬라이드 전체 측정/시간 상한이 우선한다. 사전 측정과 후보의 동일 상태 관찰은 한 번만 센다.
노드별 style 조회를 각각 한 측정이라고 하지 않고, 선언 적용 후 layout 결과를 관찰하는 회차를 센다.
E 비교가 끝나지 않으면 첫 통과 후보를 최선으로 채택하지 않고 `budget_exhausted`로 남긴다.

기존 public 오류 envelope를 유지하고 내부 fit report에 다음 사유를 추가할 계획이다.

| 내부 사유 | 뜻 |
| --- | --- |
| `parent_region_unavailable` | 보호 경계 또는 깊이 한도 안에 적격 root 없음 |
| `parent_geometry_unsupported` | 흐름/자산/anchor 관계를 안전하게 계산할 수 없음 |
| `parent_space_unfit` | 평가한 후보·변경량 한도에서 필요한 높이를 수용하지 못함 |
| `parent_preservation_failed` | 외부/가로 배치·내용·폰트 보존 검사 실패 |
| `budget_exhausted` | 영역 선정 또는 전체 후보 비교 미완료 |

`parent_space_unfit`을 “가능한 모든 디자인에 해가 없음”으로 설명하지 않는다.
기존 `font_floor_unfit` public 코드로 매핑하더라도 실제 후보 거절 사유와 범위는 유지한다.

### 3.5 변경 예정 위치와 증거 identity

| 파일/계층 | 구현할 책임 |
| --- | --- |
| `services/authored_local_fit_policy.py` | v1.3 정책 identity, 깊이·후보·변경량 한도 중앙 정의 |
| `utils/slide_capture_fit_script.py` | 영역과 seed 관계, 보호 경계, 상위 root 후보 탐색 |
| `utils/slide_capture_fit_spacing.py` | 실제 세로 예산, 카드/행 높이와 허용 style plan 생성 |
| `utils/slide_capture_fit_search.py` | E 후보 평가·보존 검사·비용 비교 |
| `utils/slide_capture_fit_runner.py` | 국소 실패 수집, 중첩 임시 결과 원복, root별 한 번 실행, 최종 원자적 확정 |
| `utils/authored_fit_edits.py`, 기존 fit 검증/receipt 소비 경로 | 허용 선언 재구성·재현과 확장 root 기준 외부 보존 검사 연결 |

제품 함수를 복제한 별도 보정 엔진은 만들지 않는다. v1.3에서는 기존 작은 card qid가 아니라 확장 root를
geometry 검사와 영향 범위 identity에 전달해야 한다. 단순히 `_hardRegion`의 외곽 비교만 끄는 구현은 금지한다.

기존 report에 seed qids, root qid, ancestor 거리, root 선택/거절 사유, 공간 전후값, 수정 QID/속성,
E 후보 수·비용·검사 결과·공유 예산 소비를 연결한다. 기존 HTML/폰트 baseline digest는 그대로 유지한다.
v1.2 승인 receipt를 v1.3 승인으로 취급하지 않으며 render key와 acceptance key 모두 새 정책을 반영한다.
캐시된 PNG만으로 통과 판정을 복구하지 않는다. 원저작 revision 없는 체크포인트는 명시적으로 건너뛰거나 거절한다.

## 4. 단계 3 — 저장 실패본 검증 계획

### 4.1 고정 입력과 실행 방식

기존 보관 HTML과 원저작 baseline을 읽어 같은 입력으로 v1.2/v1.3을 비교한다. 실패 체크포인트의
HTML projection에 기존 수정이 들어 있다면 최초 저작본과의 관계부터 확인하고 기준을 재설정하지 않는다.
내용·폰트·viewport·DPR·출력 scale·자산 identity와 입력 digest를 고정한다.

회귀 대상은 다음으로 한정한다. 입력이 없으면 다른 생성본으로 대체하지 않고 미확인으로 보고한다.

| 사례 | 고정 입력 식별 | 기대 결과 |
| --- | --- | --- |
| 상위 공간 재배분 | job `e95ca4e8-c13a-4993-a88b-db83d7922adb`, index 9 | `s9-data` 결함 복구, 추가 폰트 축소 없이 전체 통과 |
| 절대 배치 배지 | job `099b9b32-c947-41b7-b80e-fd3ed7a0ea47`, index 2 | 정상 배지를 수정하지 않고 기존 통과 유지 |
| 회전 장식 | job `5a0ca797-9be7-4549-9cd5-54cce505b030`, index 4 | 장식 anchor 보존, 기존 통과 유지 |
| 서버 카드 구조 | job `05a13f76-624f-412a-bd71-1c71813114e3`, index 8 | 불필요한 E 없이 기존 보정 결과 유지 |
| 하단 band 충돌 | job `3b1d0fec-604b-49b4-86b7-827abf2a3f88`, index 3 | 실제 sibling 침범을 놓치지 않고 통과 유지 |
| 정상 대조군 | 기존 보관본 중 새 폰트 정책까지 통과한 장 | 입력 HTML 바이트 동일, E 후보 0개 |

입력 경로는 로컬 manifest에서 해결하고 임시 디렉터리·소유자·자격 증명을 제품 코드에 넣지 않는다.
고객 원문을 새로 커밋하지 않는다. 영속 baseline이 없는 과거 사례는 geometry 참고군으로만 구분하고
최초 크기 계약까지 통과한 것으로 집계하지 않는다.

기존 `scripts/authored_fit_replay.py`는 전체 글자 축소 ladder를 사용하는 별도 평가기다.
그 기본 실행 결과를 이 정책 검증으로 재사용하지 않는다. 기존 로더·리포트만 재사용할 수 있으며,
실제 제품 local-fit 진입점과 원저작 baseline을 사용하는 좁은 재생 경로로 연결한다.

### 4.2 통과·거절 기준

고정 코호트의 성공 기준은 아래와 같다.

1. 10번 실패본이 범용 E 후보로 복구되고, 독립 렌더의 차단 이슈가 0건이다. 정확히 81px일 필요는 없다.
2. 복구본의 텍스트·폰트/행간·자산, root 외곽·외부 bbox·내부 가로 배치가 보존된다.
3. 기존 성공 사례와 정상 대조군에 회귀가 없다. 정상 대조군은 byte-identical이다.
4. 모든 보고된 통과본은 같은 최초 baseline의 폰트 계약을 충족한다. 추가 provider 호출·DB 쓰기는 0회다.
5. 후보별 실패 사유, 최종 선택, 정상 원복을 재생 보고서로 추적할 수 있다.

거절 경계는 해당 계층의 기존 좁은 fixture를 우선 사용한다. 적절한 fixture가 없으면 단발성 인메모리
재생으로 확인하고 검증만을 위해 별도 테스트 체계를 만들지 않는다.

| 경계 | 기대 동작 |
| --- | --- |
| 상위 여백까지 부족한 경우 | `parent_space_unfit`, 추가 확장·추가 축소 없이 원복 |
| 가로 재배치/보호 자산 이동이 필요한 경우 | 미지원 또는 보존 실패로 원복 |
| root 선정 4개 부모 링크 초과 | 영역 탐색 종료 |
| 내부 임시 성공 카드와 확장 root가 겹침 | 같은 기준에서 한 번 재계산, 누적 수정/축소 없음 |
| 서로 독립인 root | DOM 순서대로 처리, 외부 승인본 변경 없음 |
| 남은 예산/독립 검증 시간 부족 | `budget_exhausted`, 부분 성공을 완료로 저장하지 않음 |
| reconstruction 또는 폰트/자산 identity 불일치 | 승인/캐시 재사용 거절 |

### 4.3 실행 단위와 이번 요청의 완료 조건

구현 완료 뒤 제품 경로를 호출하는 **하나의 좁은 고정 코호트 재생 검사**를 선택해 위 결과를 보고한다.
테스트·타입 검사·린트·전체 빌드·20장 생성을 묶어서 실행하지 않는다. 같은 검사는 코드 수정 근거가 있을 때만 다시 실행한다.
시간은 진단용으로 기록할 수 있으나 이 코호트로 전체 생성 속도 개선율·일반 복구율을 주장하지 않는다.
시각적 일치가 별도 완료 조건으로 지정되기 전에는 screenshot 비교를 자동 추가하지 않는다.
후보의 미적 선호 검토와 최종 PPTX 검증은 별도 후속 단계이며 DOM 통과로 대체하지 않는다.

이번 요청의 완료는 1~3단계의 범위·알고리즘·검증 계약을 문서로 정리하는 것이다.
구현, DB/서버 변경, 실패 작업 재개, 전체 덱 생성, export, 기본값 전환은 이 문서 작성에 포함하지 않는다.
세부 한도·비용·지원 구조는 agent 제안이며 구현과 좁은 검증으로 확인되기 전에는 검증된 제품 계약으로 취급하지 않는다.
